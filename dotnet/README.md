# Limited .NET host

The root `dotnet/Foxwarm.sln` contains three .NET 10 projects. They are separate from the production Node.js runtime and its normal build/test graph:

- `Foxwarm` is the localhost Web executable. Its `Sessions`, `Models`, `Tools`, `Channels/WebUi`, and `Memory` folders organize the existing Message JSON, Session turns/persistence/compaction, Responses HTTP/WebSocket and Chat Completions client/stream/model selection, and interactive Chat host in one assembly.
- `Foxwarm.Tests` contains memory, streaming/client, storage and Session contract tests, including current admitted-state and persisted compatibility checks.
- `Foxwarm.DevTools` runs the original development probes through explicit `conditional-memory`, `responses-request`, `responses-stream`, and `session-restart`, and explicit `catalog-import-dotnet-v1` subcommands. Its corpus JSON and process-restart result shape are unchanged.

## Current tool authorization boundary

Main-local model tools use ordered `state/tool-authorization.yaml` v1 rules for concrete builtin, node-master and official SDK MCP calls. Default schemas and discovery filter the same current authority; neutral `call_tool` does not bypass its leaf permissions. Missing policy alone retains compatibility allow; an unavailable policy terminates the current turn only after complete paired responses, retaining queued input for later explicit/new-input processing. Source isolated exact/default rules and handler guards remain an additional layer, not OS isolation.

The non-default `set_tool_rules` builtin requires current setter and node-master/read permissions, captures a bounded regular YAML file through the current read resolver and atomically publishes its exact validated bytes. It shares the [native path/cwd contract](../docs/code-index/units/dotnet.md#main-native-paths-and-cwd); the [authorization contract](../docs/code-index/units/dotnet.md#main-tool-authorization-and-default-projection) owns physical/target facts, cache/retry and special compact proposal handling.

Adjacent exact direct `exec` calls run in bounded segments of at most four. All other calls, including neutral exec dispatch, remain serial barriers. Raw context capture, current concrete authorization and ordered cwd replay follow the [native path/cwd contract](../docs/code-index/units/dotnet.md#main-native-paths-and-cwd). A segment emits one model-order complete paired row only after started invocations settle; activity is aggregate and attribution/timing is per call. Stop/unavailable do not kill launched shells. See [the direct-exec contract](../docs/code-index/units/dotnet.md#adjacent-direct-exec-segments) for preparation and settlement; no remote platform is added.
