# Limited .NET host

The root `dotnet/Foxwarm.sln` contains three .NET 10 projects. They are separate from the production Node.js runtime and its normal build/test graph:

- `Foxwarm` is the localhost Web executable. Its `Sessions`, `Models`, `Tools`, `Channels/WebUi`, and `Memory` folders organize the existing Message JSON, Session turns/persistence/compaction, Responses client/stream/model selection, and interactive Chat host in one assembly.
- `Foxwarm.Tests` contains the existing memory, streaming/client, storage, and Session tests without replacing their assertions.
- `Foxwarm.DevTools` runs the original development probes through explicit `conditional-memory`, `responses-request`, `responses-stream`, and `session-restart` subcommands. Its corpus JSON and process-restart result shape are unchanged.

## Interactive experimental HTTP host

Build `dotnet/Foxwarm/Foxwarm.csproj`, choose **new separate** data/workspace directories, and set explicit environment variables. Do not point the data root at a Foxwarm production/test installation. The host binds only to `127.0.0.1`; use a local scripted Responses server when validating without provider spend:

```sh
export FOXWARM_EXPERIMENT_DATA_ROOT=/path/to/new/experiment-data
export FOXWARM_EXPERIMENT_TOOL_ROOT=/path/to/new/tool-workspace
export FOXWARM_EXPERIMENT_PORT=39091
export FOXWARM_EXPERIMENT_API_TOKEN='private-local-api-token'
export FOXWARM_EXPERIMENT_RESPONSES_BASE_URI='http://127.0.0.1:39092'
export FOXWARM_EXPERIMENT_PROVIDER_TOKEN='private-provider-token'
export FOXWARM_EXPERIMENT_REQUEST_MODEL='local-scripted-model'
export FOXWARM_EXPERIMENT_CONCRETE_MODEL='local-scripted-model'
# Optional: the experimental Chat build from this repository.
export FOXWARM_EXPERIMENT_WEBUI_DIST="$PWD/packages/webui/dist"
# Optional: FOXWARM_EXPERIMENT_INSTRUCTIONS and FOXWARM_EXPERIMENT_MAX_OUTPUT_TOKENS.
dotnet run --no-build --project dotnet/Foxwarm/Foxwarm.csproj
```

The previous single-model environment variables remain a fallback when `FOXWARM_EXPERIMENT_MODELS_FILE` is absent. To select multiple concrete Responses models instead, set that variable to a **separate JSON file** with the following experiment-only subset (replace URLs and credential-environment-variable names with locally controlled values):

```json
{
  "default": "local-a/model-a",
  "providers": {
    "local-a": {
      "providerType": "openai",
      "baseUrl": "http://127.0.0.1:39092",
      "apiKeyEnv": "FOXWARM_LOCAL_A_TOKEN",
      "contextLimit": 18000,
      "effort": { "allowed": ["none", "low", "high"], "default": "low" },
      "models": [{ "id": "model-a" }]
    },
    "local-b": {
      "providerType": "openai-responses",
      "baseUrl": "http://127.0.0.1:39093",
      "apiKeyEnv": "FOXWARM_LOCAL_B_TOKEN",
      "contextLimit": 24000,
      "effort": { "allowed": ["none", "low", "high"], "default": "none" },
      "models": [{ "id": "model-b" }]
    }
  }
}
```

Set `FOXWARM_LOCAL_A_TOKEN` and `FOXWARM_LOCAL_B_TOKEN` in the host environment before startup; `apiKeyEnv` names an environment variable and deliberately **is not** the TypeScript config's `apiKey` value. Credentials are resolved only in host memory, never serialized into Session JSON or browser model metadata. This is not a `models.yaml` parser or direct production configuration import. Only concrete `openai`/`openai-responses` HTTP loopback providers are admitted; unknown/virtual/hosted/WS/failover providers fail at startup. Provider/model `contextLimit` and `effort` defaults/allow-lists follow this explicit JSON subset; there is no Setup save or hot reload. Each provider request captures one selected model URI, credential, wire ID and effort before sending. Explicit per-Session model/effort changes use its ordered save lane and survive clean restart; changing one while a request is in flight affects only later requests.

The API is an **experiment subset**, not the whole WebUI backend. API calls, including `/health`, accept `Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN`; when the optional WebUI dist is configured, the root page and its static assets can load before login, and the experiment-only `/api/auth` exchanges a manually entered token for a same-origin, HTTP-only, SameSite-Strict cookie. No token goes into the URL, localStorage, built assets, or provider request. A minimal CLI interaction after startup is:

```sh
curl -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" -H 'Content-Type: application/json' \
  -X POST "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions"
# Use the returned safe generated sessionId as ID:
curl -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"text":"hello"}' "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions/ID/message"
curl -N -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" \
  "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions/ID/stream"
```

Supported CLI routes are `GET/POST /api/agents`, `GET/POST /api/sessions`, `GET /api/sessions/{id}/state|history|stream`, `POST /api/sessions/{id}/message|stop|model|children|refresh-memory`, exact `GET /api/sessions/{id}/archive/messages/{seq}`, one-layer `GET /api/sessions/{id}/context-blocks/{blockId}/expand`, `POST /admin/shutdown`, and `GET /health`. Message accepts nonempty text and optional `clientMessageId`; HTTP 202 acknowledges an ingress queue-save **attempt**, not guaranteed durability or processing. `/compact` explicitly starts an idle synchronous planner under a durable busy claim; `/stop compact` cancels that planner without discarding ordinary queued input. `/stop` still controls a normal turn. Busy background compaction is not supported. Graceful shutdown stops admission and active provider requests, waits for processor/save completion, and reports persistence failures; an already-launched local shell is not killed. Only host-owned JSON files load on restart; Archive IDs detect missing authority but cannot rebuild it. Persisted busy/stopping state fails closed rather than attempting crash repair.

Build the **same original App/Sidebar/Workbench** with `VITE_FOXWARM_DOTNET=1 npm --prefix packages/webui run build`; set `FOXWARM_EXPERIMENT_WEBUI_DIST` to its `packages/webui/dist`. Open `http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/`, enter the local API token in the small login gate, then use the ordinary Agent/Session creation menu, Sidebar and Chat tabs. There is no second App shell. The build flag adds only login and the existing text-only Chat option; it does not probe backend features or hide unimplemented App entry points. Setup, Code, Terminal, inheritance, pin, destructive Session/Agent operations and global history search may return errors until their backend is ported.

The channel implements the real bounded `/api/session-list/sidebar`, `/children`, `/by-id`, `/architecture`, `/descendants/{id}`, `/descendant-activity`, and `/search` metadata projections. Root/child keyset pages, focus paths, exact misses and structural revision resets use small metadata snapshots, never serialized full history. `WS /api/webui/stream` carries the original revisioned list+Chat union, actual v2 request drafts, canonical messages, queue state, list deltas/invalidation and reconnect snapshots; CLI SSE remains separate. `POST /api/sessions/{id}/name` strictly updates the existing display name. `GET/POST /api/webui/settings` read and persist real local branding. History tail/prefix/afterSeq/version, models/effort, queued previews, `/compact`, `/stop compact`, `/stop` and exact archived CTX expansion retain their previous semantics. Unsupported commands receive an explicit error. Cookies remain local HTTP-only loopback authentication, not production authentication.

Program now only assembles and starts the host. HTTP infrastructure, WebUI channel/DTO/realtime, MessageRouter, SessionManager/Runtime, turn/save/storage/compaction owners and Models/Tools are separate. The canonical [source-port map](../docs/code-index/units/dotnet.md#source-port-map) records the fixed TypeScript reference and intended continuous porting boundaries; no whole-branch merge or production configuration import is needed.

The host advertises fixed `read`, `write`, `edit`, `apply_patch`, `exec`, `read_exec`, exact-`msg#N` `recall`, `create_agent`, `create_session`, `create_child_session`, `send_to_session`, `refresh_session_snapshot`, and `submit_compact_plan` Responses definitions. The ordinary turn operates on UTF-8 regular files relative to the separate tool workspace (1 MiB, no symbolic-link components, create-new `write` default). `edit` replaces one exact occurrence; `apply_patch` adds, updates or deletes in order and reports earlier changes if a later operation fails, **without transaction or rollback**. Added files may create missing workspace-parent directories. The existing recall reads one immutable Archive `message_json` by exact seq (up to 12,000 Unicode code points per call). The planner accepts only a single `submit_compact_plan` call and does not execute ordinary tools. An unauthenticated/fabricated cross-Session target cannot be supplied to recall or `read_exec`. These path-level limits are not an OS sandbox. `write_fixture` remains only in earlier test harnesses; no production provider/config, full Agent/catalog platform, other external Channels, Worker, Node, MCP, general tool registry, images, routing/retry, crash or busy recovery, generic effect receipts, or full WebUI frontend compatibility is claimed.

### Agents, memory, and fresh children

The host keeps existing `s_<GUID>` Sessions under implicit Agent `main`, using the original workspace root and unchanged JSON/Archive/exec receipts. It does **not** invent a canonical `main` Session at startup or reinterpret an arbitrary old Session as one. To create one explicitly, call `POST /api/sessions` with `{ "agentId":"main", "sessionId":"main" }`. New Agent names use ASCII letters, digits, `_` and `-`; a named Agent's Session ID is `agent/sessionName`, where the session name cannot be empty or contain `/`. A child created from an old flat ID can still own Agent `main` with a flat ID. For HTTP paths, encode the complete ID as a single segment (for example `beta%2Fmain`); one decoded layer is used, so a flat name containing the literal characters `%2F` stays distinct from a slash. WebSocket messages use the literal Session ID.

`POST /api/agents` uses the original browser DTO: `agentId`, with a null/omitted `inheritAgent` (inheritance is not implemented), and creates a real main Session returned as `sessionId`. `GET /api/agents` returns `{ agents: [{ id, inherit: null }] }`. `POST /api/sessions` accepts `agentId` and optional `sessionId`; bare/empty main creation retains the old generated flat ID. Model tools keep their independent `agentName` and `createMainSession` schema, including creating an Agent with no main Session. Initial memory is edited through the existing Agent-bound file tools, not a browser-only memory field. New Agent workspaces live at `<tool-root>/agents/<name>`, with `memory/*.md` inside; `main` remains at `<tool-root>`. The common Agent-root `00_SYSTEM.md` supplies framework memory, with `main/memory/00_SYSTEM.md` as fallback. Existing explicit `FOXWARM_EXPERIMENT_INSTRUCTIONS` are retained **before** this stored memory snapshot, not replaced. Agent memory sources are sorted and wrapped individually; YAML `include-session`/`exclude-session` headers and full-line `foxwarm-if` blocks are applied to the selected concrete model/Session. Unknown front-matter keys do not discard the ordinary body. Edit a memory file using the existing bounded file tools relative to that Agent folder. The same model identity reuses exactly the stored snapshot bytes, so explicitly call `refresh_session_snapshot` or `POST /api/sessions/{id}/refresh-memory` to see a same-model file change. A changed concrete model rebuilds and strictly saves its snapshot **before** calling the provider. A failed pre-rename save sends no provider request; a postrename error retains the committed snapshot while still failing that request. No custom system-prompt files, inherited Agent memory, skill scanning, automatic refresh, virtual models, or full Agent Setup APIs are supported.

`create_child_session` creates only a fresh child (no fork), optionally in an existing different Agent; it persists the real `parentSessionId`, a child boundary and any initial delivery. Child model/effort are copied once from a requested `forceModel`, the parent's previously recorded child defaults if present, or the parent's current raw pair. The child gets no inherited future-child defaults. If the child was already committed but a later boundary/delivery step fails, the error reports its actual committed ID instead of claiming total rollback. `send_to_session` can deliver to any existing non-self Session because no Agent isolation/rules platform is implemented; `<parent>` and `<main>` only resolve when the target truly exists. Delivery persists the target's inter-Session queue item strictly and triggers its existing one-processor loop only if idle; ordinary user ingress keeps its prior best-effort policy. `afterSend=finish` completes the caller after the entire assistant tool batch has persisted its paired responses, even if a sibling tool returns an error. It does not stop a recipient and does not implement wait/managed handoff or child reminders. The old main workspace contains new Agent directories, and a same-UID shell can access paths outside any Agent's workspace: these are identity/default-cwd boundaries, **not** filesystem or OS isolation.

Linux-local `exec` runs one trusted shell command with its owning Agent's workspace-root initial cwd, or an explicitly requested existing relative workspace directory. A command's `cd` does **not** change any later exec or file-tool default; this experiment does not port TypeScript's persisted Session-cwd synchronization. The child receives only selected PATH/HOME/locale/user variables, not the host's API token or provider credential variables by default. That reduces accidental environment leakage, **not** security isolation: a shell running as the host's UID can read or modify arbitrary accessible filesystem paths, including locations outside the workspace. Use only a disposable workspace on an installation you trust. Neither `timeout`, `/stop`, nor graceful host shutdown kills an already-launched command. The default foreground wait is 15 seconds; a finite value above 60 seconds clamps to 60 with a warning, and the command continues as background on a wait timeout. No model-facing wait/list/kill or arbitrary process-control API is provided.

Each exec owns an actual petname `execId`, a complete raw-byte stdout/stderr log, and a separate atomic status under the **data** root's `state/exec/<Session key>/<execId>/`, not inside the tool workspace. The immediate result shows only a bounded preview. `read_exec({execId,offset?})` accepts only a current-Session ID and reports running/finished status, exit code when known, total log bytes, and at most 16 KiB of original bytes per call; `nextOffset` is the byte offset actually consumed. Broken UTF-8 sequences and unprintable bytes are escaped explicitly rather than silently dropped. The log on disk is complete, but the tool response remains bounded. Historical flat `s_<GUID>` owners keep their original directory name; new namespaced IDs map to one encoded directory segment without rewriting Session identity or receipts. Foreground completion closes tracking while retaining the log; background completion strictly persists one same-Session system queue event and a newest-32 exact-exec receipt, then the ordinary processor can read that result. On a clean-idle restart, pending tracking is reloaded before notifications resume, and an already accepted event is not re-enqueued. If a process disappears without a status file, local PID/start-time observation reports an unknown exit rather than killing any process; tracking older than 24 hours expires without removing logs or killing a command. This is not general crash recovery: a crash while busy or a failure between launching a process and recording its active tracking still fails outside this supported path.

Bare `POST /api/sessions` and `{}` keep the historical generated `s_<GUID>` and main workspace. If its JSON rename already committed but a later durability step failed, the response includes that committed ID and the still-running host retains a usable owner; the error does not pretend the Session never existed.

`host-e2e.py` retains CLI/SSE and clean restart checks. This branch’s `packages/webui/test/` contains `experimentHostChat.e2e.mjs` (original Chat/queue/Stop regression), `experimentHostModelCompact.e2e.mjs` (two browser-visible concrete models/effort, layered compaction and exact Archive/CTX recovery), and `experimentHostDevTools.e2e.mjs` (model-directed read/edit/patch/exec and paginated binary-boundary-aware logs, partial patch failure, Stop while exec waits, background completion into the same Session after clean two-PID restart), plus `experimentHostAgents.e2e.mjs` (browser-created Agents/Session/child, model-created Agent/Session/cross-Agent child and non-parent handoff, real per-Agent memory/workspace, same-Agent concurrency, strict snapshot failure and two-PID JSON/SQLite restart). All drivers use disposable roots and scripted localhost Responses replies, not paid providers. Run the .NET test drivers inside a verified hard process-tree limit; they launch shell commands in their **own** temporary workspace and clean up after completion.

## Session persistence C1/C2/D experiment

The `Foxwarm/Sessions/Storage` code accepts one explicitly bound Session ID and the current bounded ordinary v1 authority subset. It preserves open unknown top-level, queue-item/source, Message, part, metadata and provider JSON. The host additionally admits supported CTX-BLOCK metadata, preserved raw flags, `nextBlockId`, and the strict Agent/parent binding for fresh children; it still rejects fork/alias state, wait/managed/child-handoff reminder/indexing state, Worker mailbox progress, images and unimplemented structured queue kinds. Active JSON is the sole active-history authority; Archive is immutable audit/recall data and is never used to rebuild active history.

The SQLite store pins `Microsoft.Data.Sqlite` 10.0.12. It admits the exact six-column TypeScript `archive_messages` and 15-column `archive_blocks` table layouts (including source IDs, raw seq/time ranges, summary, memory facts, creation time). Archive insertion is immutable/byte-exact on replay with inserted-only rollback. The Session save lane stages a compaction rewrite from active history only; it writes blocks plus a completion raw row to Archive, atomically replaces authority JSON, then publishes only its owned hot history/version/nextSeq/nextBlock delta without rolling back concurrent queue/Stop/model settings. Pre-rename failure removes only newly inserted rows; postrename failure retains and publishes committed authority and throws. Only historical tool-response pruning reads Archive to verify exact original provenance before reducing active output, and that path commits only when the estimated session fits 50% of the selected context limit. One Agent directory index is written atomically; this does not introduce a full catalog, cross-store transaction or crash-repair protocol.

Stored `message_json` read from SQLite retains its original string and is never silently reserialized. New C# rows use a bounded ECMAScript-compatible projection over owned JSON. Object keys follow ECMAScript array-index ordering; strings preserve the verified JSON escaping boundary; finite binary64 numbers use .NET's shortest round-trip digits plus ECMAScript's fixed/scientific thresholds, lowercase exponent style, explicit positive exponent sign, and `-0` → `0`. JSON-parsed numbers and CLR `double`/`float` are supported. Integral CLR values are accepted only when exactly representable as a binary64 Number; over-precise integers and CLR `decimal` values fail before database insertion rather than being silently rounded. Actual `JSON.stringify` checks cover non-ASCII, U+2028/U+2029, a literal `\\u2028`, quotes, backslashes, controls, numeric-key ordering, `-0`, the `1e-6`/`1e21` thresholds and adjacent representable values, fractional timing, binary64 extrema, and a finite 512-value seeded sample. This remains a tested projection, not a general custom ECMAScript runtime.

The JSON authority writer writes a unique same-directory UTF-8 temp file, calls `Flush(true)`, atomically renames it over the target, and fsyncs the Linux parent directory. Matching the current TypeScript portability rule, directory-open/fsync errors `EPERM`, `EISDIR`, `EINVAL`, `ENOSYS`, and `ENOTSUP` are reported as unsupported rather than durable; other errors fail. Failures before rename remain precommit and remove the temp file. Failures after rename throw `AuthorityCommittedException` and leave the new authority visible, so a later caller cannot misclassify the operation as rollback-safe. File fsync and directory fsync are separate durability boundaries; injected failures and normal reopen do not prove power-loss or cross-SQLite/JSON atomicity.

The C1 tests use only fresh temporary roots. An actual current TypeScript helper writes one source-derived v1 JSON/full Archive fixture for C# read/rewrite/TypeScript reread, and reads a C#-created limited fixture in the opposite direction. The C#-created path also invokes actual `writeArchiveMessages` with the same semantic records and requires zero inserted rows, proving exact immutable replay rather than read-only semantic acceptance. Run against the intended current TypeScript build explicitly:

```sh
FOXWARM_TS_ROOT=/path/to/current/foxwarm \
  dotnet test dotnet/Foxwarm.Tests/Foxwarm.Tests.csproj --no-restore
```

C2 adds `PersistentSessionAuthorityStore` in the SessionTurns leaf. Ordinary queue/busy/Stop snapshots and canonical appends share the existing ordered per-Session save lane. The lane lock only reserves and links the next tail; a separately completed asynchronous launch signal starts prior-wait and operation execution after the lock is released, so synchronous SQLite/file fsync cannot hold `laneGate`. A canonical append captures selected queue object identities and an owned staged v1 snapshot under the short state gate, assigns contiguous `seq`/finite timestamps without accepting caller-supplied `seq`, then performs Archive insertion followed by atomic JSON replacement without holding either gate. Timestamp `0` and `-0`, like missing/null, use the injected/current clock to match TypeScript's `timestamp || Date.now()`; other supported finite timestamps are retained. Ordinary append preserves persisted `historyVersion` exactly—compact/clear structure rewrites own that field. Only after authority commit does the append publish its queue/history/next-seq/meta delta to hot state. Newer ingress and Stop/meta changes remain hot and are persisted by their already-ordered saves; ordinary ingress acknowledgement waits for its own save attempt. In-memory tests use the same staged publish path without claiming filesystem durability.

Before rename, a JSON failure rolls back only the rows newly inserted by that operation; byte-identical preexisting replays are never deleted and hot staged state is not published. After rename, `AuthorityCommittedException` retains Archive plus new JSON, publishes the corresponding hot delta, and reports the postcommit problem without provider/tool retry or rollback. Directory-sync `Unsupported` remains observable on the persistent store and is not described as full durability. Missing or malformed active JSON fails closed when Archive rows exist; Archive never reconstructs active history. A default fire-and-forget trigger records its process-local failure count and last error instead of dropping the fault or automatically retrying. The durable queue remains available, but recovery requires an explicit trigger or later admitted input; there is no background spin or persistent retry state. Slice D proves one bounded clean-idle restart: process A exits after a persisted four-row tool turn, then a distinct process B loads the same explicit Session ID from JSON and commits rows 5/6 without repeating the file effect. A busy-claim postrename failure intentionally retains committed `busy` and fails closed in that process; D does not cover that state, arbitrary crash points, power loss, or production restart orchestration.

The Responses collector uses native async `Stream.ReadAsync`, incremental UTF-8 decoding, source-equivalent narrow SSE framing, and explicit `StreamOwnership.Dispose` (the default) or `LeaveOpen`. The accumulator owns retained input JSON by deep clone and emits cumulative progress, meaningful-progress, safety-buffering, decoded-text, and complete-block callbacks. Typed semantic terminal, malformed-event, read, EOF, and normal .NET cancellation categories are covered by independent xUnit tests. The loopback cancellation test proves accepted/requested/held/cancelled/connection-closed milestones without sleep-based synchronization; it does not contact a provider and does not restart a runtime.

## Responses HTTP client experiment

The `Foxwarm/Models/Responses` client accepts an explicit base URI, request model name, concrete model identity, bearer token, instructions, and output cap. It POSTs `/responses` with `ResponseHeadersRead`, `store:false`, streaming enabled, and one fixed `write_fixture` function definition using the current Responses function protocol (`strict:false`, `tool_choice:auto`, and parallel-call capability). It never reads Foxwarm live configuration or credentials. Non-success bodies are captured up to 64 KiB; cancellation flows through send, body read, the SSE collector, and owned response-stream disposal.

The request serializer clones canonical input and filters only exact `modelVisible:false`. Its supported subset is user/model text, canonical Foxwarm system wrappers, plain system text wrapping, recognized assistant phases, compatible reasoning replay, same-model output-text annotations, function calls, and paired tool outputs. Multi-field parts follow the TypeScript field order `system`, reasoning metadata, `text`, then function call; a model message containing a call uses the current commentary phase fallback. Stable provider call IDs, exact raw argument text, parse-error metadata, safe malformed-argument replay, and current tool-response text formatting are preserved. Tool output follows its saved call, and newly queued ordinary inputs consumed during tool execution are appended only after the paired tool row and before the next request. System wrapping uses ECMAScript trim characters and ASCII word-boundary behavior, including FEFF trimming, NEL preservation, whitespace-only self-closing tags, and non-ASCII characters immediately after `foxwarm-system`. Open property bags remain open: unrelated message, part, and provider metadata is ignored rather than rejected or mutated. Inputs requiring unimplemented semantic conversion fail by name, including missing stable call IDs, image data/references, native Responses output-item replay, and legacy system-text normalization.

Completed Responses output is converted to one owned canonical assistant Message containing reasoning, text/refusal, function calls, recognized phase, compatible annotations, token usage, concrete model identity, and canonical request timing. The persisted `completedAt` is the completion wall clock, `durationMs` is monotonic and may be fractional, and `startedAt` is derived as `completedAt - durationMs` so a wall-clock jump cannot contradict the measured duration. `IChatService` returns this owned optional assistant Message; only `LocalSessionTurnHost` strictly appends assistant and tool rows. A committed call is executed only after its assistant save succeeds, its paired tool row must save before another provider request, and neither assistant-save nor tool-row-save failure retries HTTP or executes the tool again. If the external file effect succeeded but the tool-row save failed, processing stops while the file remains; this bounded slice has no receipt journal and does not claim to roll back external effects. Empty completed output produces no fabricated assistant row.

The injected `WriteFixtureToolExecutor` accepts only `write_fixture`, requires exactly string `fileName` and `content`, rejects empty/dot/parent/absolute/path-component/NUL names, and uses atomic create-new UTF-8 writes under a test-owned temporary root. Existing files and symlinks are not overwritten. A create collision remains `file_exists`; another open/write/flush `IOException` returns the general `tool_io_error`. The executor does not retry or delete a possibly partial file and does not describe that outcome as rollback. The root is a test boundary, not an OS sandbox against a malicious process. Unknown tools, invalid schemas, and argument parse failures produce paired error responses with the original stable call ID and no file effect. The default tool-loop cap matches the current 500-iteration contract and tests can inject a smaller explicit cap.

The localhost integration suite proves two real POSTs around one real file effect, second-request call/output order, four canonical history rows, one processor claim, request receipt and fragmented SSE completion, held-body Stop cancellation with no tool start, bounded non-2xx capture, malformed/early-EOF rejection, missing-call-ID rejection, no effect after assistant-save failure, and one non-replayed effect with no second request after tool-row-save failure. Deterministic fake boundaries prove queued input ordering, malformed/unknown paired errors, the loop cap, general open/write I/O classification, and preservation of an injected partial file. `responses-request-corpus.json` is compared against the actual TypeScript `convertToOpenAIResponsesFormat` implementation for system/text, open metadata, empty assistant/user fields, phases, exact-false display exclusion, reasoning, annotations, raw and malformed call arguments, commentary fallback, paired tool output formatting/order, and the bounded error scalar domain. The latter includes single quotes, commas, line breaks, tabs, NUL, and NEL and requires exact `js-yaml` output; native V8/.NET parser diagnostics are still compared only through their existing compatibility category. The translation references current `src/sessionTurnRunner.ts`, `src/llmProviders/openai.ts`, `src/toolCallArgs.ts`, and `packages/shared/src/toolResponseFormatting.ts` behavior.

This client remains experiment-only. Its fake boundary can still use the in-memory authority substitute, while the C2/D localhost integration uses test-owned JSON/SQLite authority, exact Archive replay, and one explicit clean-idle two-process continuation. It excludes a general tool registry, MCP, Node execution, permissions, runtime Agent configuration, images and hosted tools, model routing/failover/retries, provider request compression, prompt-cache headers, WebSocket transport, streaming UI callbacks, effect receipts, request journaling/IDs, Channel delivery, Worker placement, crash/busy recovery, Session discovery, and production integration.

## Session-turn experiment

`Foxwarm/Sessions/Turns` is an experiment-only translation of the current Main-local `sessionWorkers:false` path. `SessionState` keeps bounded queue/history records, `nextMessageSeq`, `historyVersion`, and an owned v1 authority envelope using open JSON. `SessionEntry` protects short synchronous state mutations with a per-Session gate, serializes all authority work through a separate async save lane, claims one processor atomically, and transfers one active cancellation handle to Stop. `SessionIngress` awaits a best-effort save attempt before acknowledging ordinary input, and the owned processor makes another ordered best-effort snapshot attempt immediately before selecting an ordinary prefix. Busy claims and releases remain strict snapshots with precommit-only operation-scoped rollback; postrename failures retain the committed hot meaning.

`SessionTurnRunner` consumes the complete leading ordinary queue prefix in canonical order regardless of source platform, channel, or conversation, while preserving one canonical history row and `clientMessageId` per logical input. `QueueSource` retains provenance only and does not select a turn or reply target. `LocalSessionTurnHost` binds one exact Session entry and owns the complete provider/tool loop under that processor claim: canonical assistant commit, injected tool execution, canonical paired tool-row commit, post-tool ordinary-prefix consumption, then the next provider request. User batches, model calls, tool results, and final assistants all use the same contiguous sequence/timestamp builder. Stop sets the boundary, takes and cancels the active request before waiting for its later best-effort save, and finalizes accepted queued inputs without another model call. Canonical appends do not mutate hot history/queue before Archive→JSON commit, so precommit failure needs no broad snapshot restoration; postcommit publication removes only the captured queue identities and preserves later ingress/Stop state. Queue-prefix and Stop-finalization batch notifications remain non-poisoning and observable. Other assistant/busy/release callback behavior is unchanged.

The first committed nonempty input in a bounded turn controls parts preparation: a prebuilt message consumes that boundary without preparation, an empty row does not consume it, and a parts item prepares numeric `lastMessageTime` only when it is first. History-empty first-parts preparation also prepends the canonical `<foxwarm-system kind="session" currentSessionId="..." />` marker after Foxwarm attribute normalization and ECMAScript-whitespace collapsing. Later parts after a leading prebuilt message therefore receive no marker and do not change the timestamp. Caller-supplied `seq` is rejected; C2 owns contiguous sequence assignment. This remains a bounded owned-Message/persistence experiment, not crash recovery or production integration.

The component intentionally excludes any tool beyond the injected bounded executor, a general registry or placement layer, compact execution, retry, waits, managed state, child-handoff state transitions, channel delivery, Worker IPC or placement, crash/busy recovery, Session discovery, performance equivalence, and production runtime integration. The in-memory authority store remains a snapshot-ordering substitute; the persistent adapter and clean-restart harness are restricted to test-owned roots and the one explicitly bound Session ID.
