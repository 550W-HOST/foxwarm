# .NET Main host

The .NET 10 solution provides managed Main, a standalone CLI Node, shared native/browser libraries, tests and development tools. The source package/directory, npm, tmux, Windows background entries and production/test Docker select managed Main. Default CI/test lanes include managed execution and the retained TypeScript reference.

- `Foxwarm` is the console host, with an optional HTTP listener (ordinary default `0.0.0.0:3001`). Its `Sessions`, `Models`, `Tools`, `Channels/WebUi`, and `Memory` folders organize the existing Message JSON, Session turns/persistence/compaction, Responses HTTP/WebSocket and Chat Completions client/stream/model selection, and interactive Chat host in one assembly.
- `Foxwarm.Tests` contains memory, streaming/client, storage and Session contract tests, including current admitted-state and persisted compatibility checks.
- `Foxwarm.DevTools` runs the original development probes through explicit `conditional-memory`, `responses-request`, `responses-stream`, and `session-restart`, and explicit `catalog-import-dotnet-v1` subcommands. Its corpus JSON and process-restart result shape are unchanged.

## CLI Node

`Foxwarm.CliNode` is a separate .NET 10 executable for authenticated, file-capable remote Nodes. It references the small BCL-only `Foxwarm.NodePrimitives` library, not Main's executable. Build the solution, then run:

```sh
dotnet run --no-build --project dotnet/Foxwarm.CliNode -- \
  --host https://example.invalid/foxwarm --id my-node --token '<pairing-token>' \
  --credentials-file /path/to/owned-state/node-credentials.json
```

Use the normal Main Node approval flow. Later starts can use only `--host` and `--credentials-file`; explicit `--id` plus `--auth-token` overrides a stale credential file. The credential JSON shape remains compatible with the TypeScript client and is owner-only on Unix. Environment proxy lookup follows the existing CLI precedence and `NO_PROXY`; credential-bearing connection URLs are not logged.

The client implements file/transfer tools, persistent exec, external-owner execution, fixed Code filesystem/Git and optional terminal services, the local trigger and Session client API, plus five CLI browser tools. CLI browser calls use their own process-owned tabs and the existing Main policy/image owners. Main has separate local browser behavior, described below. `--interactive` adds the approval, history and send interface; existing bootstrap commands still select the TypeScript client. See the [CLI implementation contract](../docs/code-index/units/dotnet-cli-node.md) for the complete boundaries and interoperability fixtures.

Browser support pins `PuppeteerSharp.Cdp` exactly to 25.14.0. Supply an installed Chromium executable through `PUPPETEER_EXECUTABLE_PATH` or `CHROME_PATH`; the Source-compatible fallback is `/usr/bin/chromium-browser`. The CLI does not download a browser. The Linux x64 Native AOT graph has the existing full host browser corpus with Chromium 145.0.7632.109, plus a representative Debian 13 no-CLR-container ARIA/evaluate proof with Chromium 155.0.8059.79. Upstream analysis diagnostics remain visible; this does not qualify every browser distribution or Windows/macOS. See the canonical browser contract for caller and serializer limits.

For the CLI-only native build, use the [UBI 9 Linux x64 recipe](../scripts/native-aot/README.md). Its [measured compatibility table](../docs/code-index/units/dotnet-cli-linux-aot.md) distinguishes successful Ubuntu 22.04/24.04, Debian 12/13, UBI 9/10 and Fedora 43 userspaces from the failed UBI 8 build/runtime, optional dependencies and unmeasured minimum-kernel/CPU limits.

## Current tool authorization boundary

Main-local model tools use ordered `state/tool-authorization.yaml` v1 rules for concrete builtin, node-master and official SDK MCP calls. Default schemas and discovery filter the same current authority; neutral `call_tool` does not bypass its leaf permissions. Missing policy alone retains compatibility allow; an unavailable policy terminates the current turn only after complete paired responses, retaining queued input for later explicit/new-input processing. Source isolated exact/default rules and handler guards remain an additional layer, not OS isolation.

The non-default `set_config` builtin requires an explicit `config`, `models`, or `tool-rules` target plus current setter and node-master/read permissions. It captures a regular UTF-8 candidate through the current read resolver and atomically publishes its exact validated bytes. The removed `set_tool_rules` name has no callable alias; policies naming it need deliberate target-aware permission migration. It shares the [native path/cwd contract](../docs/code-index/units/tools-local-io.md); the [authorization contract](../docs/code-index/units/tool-authorization.md) owns physical/target facts, cache/retry and special compact proposal handling.

Adjacent exact direct `exec` calls run in bounded segments of at most four. All other calls, including neutral exec dispatch, remain serial barriers. Raw context capture, current concrete authorization and ordered cwd replay follow the [native path/cwd contract](../docs/code-index/units/tools-local-io.md). A segment emits one model-order complete paired row only after started invocations settle; activity is aggregate and attribution/timing is per call. Stop/unavailable do not kill launched shells. See [the direct-exec contract](../docs/code-index/units/tools-local-io.md) for preparation and settlement; no remote platform is added.

## Settings and ordinary startup

Build `dotnet/Foxwarm/Foxwarm.csproj` for backend-only work, or use the complete delivery build above. The application base is the installation/executable directory, not the shell cwd. A caller that knows a different installation base may set `FOXWARM_APP_ROOT`; resource templates/native helpers still come from the binary resource directory. No ancestor search adopts another installation's state. For source-checkout development, use an owned disposable data root and controlled local providers:

```sh
export FOXWARM_APP_ROOT="$PWD"
export FOXWARM_DATA_DIR=/path/to/new/data
export FOXWARM_HTTP_PORT=39091
export FOXWARM_BIND_ADDRESS=127.0.0.1
# Use build:delivery above for a complete original browser UI payload.
dotnet run --no-build --project dotnet/Foxwarm/Foxwarm.csproj
```

Ordinary startup requires neither an experiment tool root nor a disjoint workspace. Data selection is `FOXWARM_DATA_DIR`, installation `data_dir`, then application root. Data/pointer values trim whitespace, expand `~`/`~/`, and resolve relative to the application root. Explicit `FOXWARM_CONFIG_PATH`, then `CONFIG_PATH`, select the app YAML; relative explicit config filenames resolve against the application root. Otherwise app YAML is selected `state/config.yaml`, and models are selected `state/models.yaml`.

`paths.agentsDir` defaults to selected `agents`; all canonical Agent folders, including main, live beneath it. `paths.skillsDir` defaults to application `skills`. `MCP_CONFIG_PATH`, then `paths.mcpConfigPath`, then selected `state/mcp.json` selects the existing outbound MCP configuration owner. Configured path values support installation-relative and home-expanded paths. `${workspace}` in tool policy means the Agents directory, not the data root or process cwd.

Existing C# data retain their original physical workspace through the known Desktop caller or existing `FOXWARM_EXPERIMENT_TOOL_ROOT` override. Version 1/2 Agent catalogs remain readable/writable in that single retained file, with main memory/files still at the old workspace. Normal entry rejects an old envelope without its original workspace rather than creating another main tree or relocating files. Main-only retained callers without an Agent envelope must likewise keep their explicit original workspace. Session authority is shared with Source and does not identify an old C# layout. Without an identified legacy envelope or explicit retained caller, ordinary entry follows Source canonical paths and missing-only bootstrap; it cannot discover an unrecorded old workspace. Existing experiment data/port/bind/skills/dist/instruction overrides remain only for retained automation; they are not normal startup prerequisites. Any physical conversion of existing data is a separate operation.

Models use the canonical `state/models.yaml` under the selected data root. The packaged `templates/models.example.yaml` is read only when the active file is missing. Open the original Models Setup editor to create the active file, or create it before startup with locally controlled provider settings:

    providerType: openai-responses

    apiKey: synthetic-local-test-key
    contextLimit: 18000
    effort: { allowed: [none, low, high], default: low }

Authenticated Setup intentionally exposes raw configuration for editing; routine model DTOs and provider errors do not expose credentials. A single-model provider displays as `local-a`, while `local-a/model-a` remains a valid qualified lookup. Multiple models display qualified keys; model IDs may contain slashes.

  "http://127.0.0.1:$FOXWARM_HTTP_PORT/api/sessions/ID/stream"

### Optional Vector storage and recall

Validated `vector` configuration enables the pinned LanceDB-derived index; absent/false state stays lazy unless the existing legacy embedding URL explicitly enables it. `dbWorkers` defaults true: one supervised local child owns native state. False selects one in-process owner, never an automatic fallback. Both placements share indexing/search code. Authoritative migrations precede owner open, while readiness is distinct from startup backfill. Disabled/unavailable History search returns an explicit 503.

Committed append/compaction hooks schedule raw/block indexing and direct memory facts after active authority publication. A derived error cannot turn a committed append into a failed commit. Raw retries retain Source's delete-before-embedding/checkpoint ordering; blocks/facts merge deterministic IDs. `/session index` uses current sequence/block hints and saves legacy index-position fields through the ordinary save lane. Clear/deletion retain committed Archive sources; uncommitted creation/fork compensation resets its derivative state.

Model `recall` supports `vector_query`, `limit`, `scope`, `agentName` and `preferBlocks`, then reloads authoritative Archive blocks/ranges before preview. Isolated scope stays current Session; nonisolated model scope stays current Agent. Canonical alias resolution is rechecked before Archive or stored-text fallback, closing stale-metadata cross-Agent exposure. Allowed captured fork lineage/caps, exact Archive reads and administrator global scope retain their existing authority. Administrator `GET /api/history/search` uses bounded authoritative windows; restricted WebUI identities cannot call it.
