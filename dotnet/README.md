# Limited .NET host

The root `dotnet/Foxwarm.sln` contains three .NET 10 projects. They are separate from the production Node.js runtime and its normal build/test graph:

- `Foxwarm` is the localhost Web executable. Its `Sessions`, `Models`, `Tools`, `Channels/WebUi`, and `Memory` folders organize the existing Message JSON, Session turns/persistence/compaction, Responses/Chat Completions client/stream/model selection, and interactive Chat host in one assembly.
- `Foxwarm.Tests` contains memory, streaming/client, storage and Session contract tests, including current admitted-state and persisted compatibility checks.
- `Foxwarm.DevTools` runs the original development probes through explicit `conditional-memory`, `responses-request`, `responses-stream`, and `session-restart` subcommands. Its corpus JSON and process-restart result shape are unchanged.

## Interactive experimental HTTP host

Build `dotnet/Foxwarm/Foxwarm.csproj`, choose **new separate** data/workspace directories, and set explicit environment variables. Do not point the data root at a Foxwarm production/test installation. The host binds only to `127.0.0.1`; use a local scripted Responses or Chat Completions server when validating without provider spend:

```sh
export FOXWARM_EXPERIMENT_DATA_ROOT=/path/to/new/experiment-data
export FOXWARM_EXPERIMENT_TOOL_ROOT=/path/to/new/tool-workspace
export FOXWARM_EXPERIMENT_PORT=39091
export FOXWARM_EXPERIMENT_API_TOKEN='private-local-api-token'
# Optional: the experimental Chat build from this repository.
export FOXWARM_EXPERIMENT_WEBUI_DIST="$PWD/packages/webui/dist"
# Optional: FOXWARM_EXPERIMENT_INSTRUCTIONS.
dotnet run --no-build --project dotnet/Foxwarm/Foxwarm.csproj
```

Models use the canonical `state/models.yaml` under the selected data root (`FOXWARM_DATA_DIR` may select that root instead). The packaged `templates/models.example.yaml` is read only when the active file is missing. Open the original Models Setup editor to create the active file, or create it before startup with locally controlled provider settings:

```yaml
default: local-a
providers:
  local-a:
    providerType: openai-responses
    baseUrl: http://127.0.0.1:39092/v1
    apiKey: synthetic-local-test-key
    contextLimit: 18000
    effort: { allowed: [none, low, high], default: low }
    models: [model-a]
```

`apiKey` is the canonical configuration value, not an environment-variable name. The old experiment-only JSON registry and single-provider environment fallback have been removed. Authenticated Setup intentionally exposes raw configuration for editing; routine model DTOs and provider errors do not expose credentials. A single-model provider displays as `local-a`, while `local-a/model-a` remains a valid qualified lookup. Multiple models display qualified keys; model IDs may contain slashes.

One immutable catalog and concrete leaf are captured before snapshot/cache persistence and provider awaits. Current and future-child settings keep their existing ordered publication; a config/model change affects later requests, not a held request. Both OpenAI executors consume merged headers/fields, first-class effort, context/max-output settings, nested cache/turn placeholders, content-inactivity timeout and gzip/Brotli compression. A strictly persisted Session UUID is reused as its prompt cache key; each logical tool turn receives one UUID across provider iterations. The compact planner has its own captured logical turn identity and the same Session cache lineage.

Original `GET /api/setup/status` and raw/form `POST /api/setup/models` share the validator. Raw saves retain the submitted UTF-8 text exactly after validation; form saves retain compatible overrides and write JSON text, which is valid YAML. Invalid saves leave the live catalog unchanged; a post-rename durability failure retains the committed catalog and returns an observable error. App-config diagnostics project actual configured channel counts/raw values without claiming an external Channel runtime. App save, provider list/test actions, and external Channel execution remain unimplemented.

The pinned YamlDotNet reader converts mappings, sequences, scalar values and ordinary aliases/merge keys into owned JSON. It is not full `js-yaml DEFAULT_SCHEMA` parity: timestamps/custom tags and non-JSON YAML types are not claimed equivalent, cyclic aliases and nonfinite numeric values are explicitly unsupported. Normal source configuration uses the preferred `providers` and legacy `models` readers, concrete aliases/display keys, effort/media normalization and validated virtual graph metadata. Responses, Chat Completions and Anthropic-compatible Messages have real executors; recognized WS transport and virtual execution remain staged work. Missing executors and enabled native image generation fail before provider effects. Responses web search/reasoning recovery is also unimplemented; Completions and Messages ignore those options without committing partial output. `asyncCompact` does not reject the existing synchronous path. Responses native image generation cannot be smuggled through extra tool declarations; ordinary tool overrides remain available.

The concentrated original Setup/Chat workflow is `node packages/webui/test/experimentHostModels.e2e.mjs`; it uses synthetic loopback providers and separate owned roots, tests real raw editor/form saves, held configuration changes, paired effects/cache identity, compression/effort precedence, timeout/empty/media boundaries and clean restart.

The API is an **experiment subset**, not the whole WebUI backend. API calls, including `/health`, accept `Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN`; when the optional WebUI dist is configured, the root page and its static assets can load before login, and the experiment-only `/api/auth` exchanges a manually entered token for a same-origin, HTTP-only, SameSite-Strict cookie. No token goes into the URL, localStorage, built assets, or provider request. A minimal CLI interaction after startup is:

```sh
curl -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" -H 'Content-Type: application/json' \
  -X POST "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions"
# Use the returned safe generated sessionId as ID:
curl -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"text":"hello"}' "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions/ID/message"
curl -N -H "Authorization: Bearer $FOXWARM_EXPERIMENT_API_TOKEN" \
  "http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/api/sessions/ID/stream"
```

Supported CLI routes are `GET/POST /api/agents`, `GET/POST /api/sessions`, `GET /api/sessions/{id}/state|history|stream`, `POST /api/sessions/{id}/message|stop|model|child-model|children|refresh-memory`, exact `GET /api/sessions/{id}/archive/messages/{seq}`, one-layer `GET /api/sessions/{id}/context-blocks/{blockId}/expand`, `POST /admin/shutdown`, and `GET /health`. Message accepts nonempty text and optional `clientMessageId`; HTTP 202 acknowledges an ingress queue-save **attempt**, not guaranteed durability or processing. `/compact` explicitly starts an idle synchronous planner under a durable busy claim; `/stop compact` cancels that planner without discarding ordinary queued input. `/stop` still controls a normal turn. Busy background compaction is not supported. Graceful shutdown stops admission and active provider requests, waits for processor/save completion, and reports persistence failures; an already-launched local shell is not killed. Only host-owned JSON files load on restart; Archive IDs detect missing authority but cannot rebuild it. Persisted busy/stopping state fails closed rather than attempting crash repair.

Open `http://127.0.0.1:$FOXWARM_EXPERIMENT_PORT/`, enter the local API token in the small login gate, then use the ordinary Agent/Session creation menu, Sidebar and Chat tabs. There is no second App shell. The build flag adds only login and the existing text-only Chat option; it does not probe backend features or hide unimplemented App entry points. Code, Terminal, pin, destructive Session/Agent operations and global history search may return errors until their backend is ported.

The channel implements the real bounded `/api/session-list/sidebar`, `/children`, `/by-id`, `/architecture`, `/descendants/{id}`, `/descendant-activity`, and `/search` metadata projections. Root/child keyset pages, focus paths, exact misses and structural revision resets use small metadata snapshots, never serialized full history. `WS /api/webui/stream` carries the original revisioned list+Chat union, actual v2 request drafts, canonical messages, queue state, list deltas/invalidation and reconnect snapshots; CLI SSE remains separate. `POST /api/sessions/{id}/name` strictly updates the existing display name. `GET/POST /api/webui/settings` read and persist real local branding. History tail/prefix/afterSeq/version, models/effort, queued previews, `/compact`, `/stop compact`, `/stop` and exact archived CTX expansion retain their previous semantics. Unsupported commands receive an explicit error. Cookies remain local HTTP-only loopback authentication, not production authentication.

Program now only assembles and starts the host. HTTP infrastructure, WebUI channel/DTO/realtime, MessageRouter, SessionManager/Runtime, turn/save/storage/compaction owners and Models/Tools are separate. The canonical [source-port map](../docs/code-index/units/dotnet.md#source-port-map) records the fixed TypeScript reference and intended continuous porting boundaries; no whole-branch merge or production configuration import is needed.

The host registers and default-injects `read`, `write`, `edit`, `apply_patch`, `exec`, `read_exec`, `wait`, `skill`, `set_agent_inherit`, `session`, `get_session_messages`, `set_goal`, `set_session_child_model`, `set_session_compact_threshold`, exact-context `recall`, `create_agent`, `create_session`, `create_child_session`, `send_to_session`, `refresh_session_snapshot`, and `submit_compact_plan` Responses definitions. These path-level limits are not an OS sandbox. `write_fixture` remains only in earlier test harnesses; no production configuration import, full Agent/catalog platform, other external Channels, Worker, non-master Nodes, images, routing/retry, crash or busy recovery, generic effect receipts, or full WebUI frontend compatibility is claimed.

### Agents, memory, and fresh children

The host keeps existing `s_<GUID>` Sessions under implicit Agent `main`, using the original workspace root and unchanged JSON/Archive/exec receipts. It does **not** invent a canonical `main` Session at startup or reinterpret an arbitrary old Session as one. To create one explicitly, call `POST /api/sessions` with `{ "agentId":"main", "sessionId":"main" }`. New Agent names use ASCII letters, digits, `_` and `-`; a named Agent's Session ID is `agent/sessionName`, where the session name cannot be empty or contain `/`. A child created from an old flat ID can still own Agent `main` with a flat ID. For HTTP paths, encode the complete ID as a single segment (for example `beta%2Fmain`); one decoded layer is used, so a flat name containing the literal characters `%2F` stays distinct from a slash. WebSocket messages use the literal Session ID.

`POST /api/agents` uses the original browser DTO: `agentId`, with optional `inheritAgent` for ongoing knowledge inheritance, and creates a real main Session returned as `sessionId`. `GET /api/agents` returns `{ agents: [{ id, inherit }] }` with actual configured inheritance. `POST /api/sessions` accepts `agentId` and optional `sessionId`; bare/empty main creation retains the old generated flat ID. Model tools keep their independent `agentName` and `createMainSession` schema, including creating an Agent with no main Session. Initial memory is edited through the existing Agent-bound file tools, not a browser-only memory field. New Agent workspaces live at `<tool-root>/agents/<name>`, with `memory/*.md` inside; `main` remains at `<tool-root>`. The common Agent-root `00_SYSTEM.md` supplies framework memory, with `main/memory/00_SYSTEM.md` as fallback. Existing explicit `FOXWARM_EXPERIMENT_INSTRUCTIONS` are retained **before** this stored memory snapshot, not replaced. Agent memory sources are sorted and wrapped individually; YAML `include-session`/`exclude-session` headers and full-line `foxwarm-if` blocks are applied to the selected concrete model/Session. Unknown front-matter keys do not discard the ordinary body. Edit a memory file using the existing bounded file tools relative to that Agent folder. The same model identity reuses exactly the stored snapshot bytes, so explicitly call `refresh_session_snapshot` or `POST /api/sessions/{id}/refresh-memory` to see a same-model file change. A changed concrete model rebuilds and strictly saves its snapshot **before** calling the provider. A failed pre-rename save sends no provider request; a postrename error retains the committed snapshot while still failing that request. Inherited knowledge, layered skills and one-owner stale refresh are supported below; custom system-prompt files, virtual models and full Agent Setup remain outside this host.

`create_child_session` creates only a fresh child (no fork), optionally in an existing different Agent; it persists the real `parentSessionId`, a child boundary and any initial delivery. Child model/effort are copied once from a requested `forceModel`, the parent's previously recorded child defaults if present, or the parent's current raw pair. The child gets no inherited future-child defaults. If the child was already committed but a later boundary/delivery step fails, the error reports its actual committed ID instead of claiming total rollback. `send_to_session` can deliver to any existing non-self Session because no Agent isolation/rules platform is implemented; `<parent>` and `<main>` only resolve when the target truly exists. Delivery persists the target's inter-Session queue item strictly and triggers its existing one-processor loop only if idle; ordinary user ingress keeps its prior best-effort policy. `afterSend=finish` completes the caller after the entire assistant tool batch has persisted its paired responses, even if a sibling tool returns an error. It does not stop a recipient. `afterSend=wait` records an activity wait after paired responses, while managed handoffs and child reminders remain outside this host. The old main workspace contains new Agent directories, and a same-UID shell can access paths outside any Agent's workspace: these are identity/default-cwd boundaries, **not** filesystem or OS isolation.

### Current and future-child settings

The original Composer supports current and future-child concrete model/effort controls, including follow-current mode. The two fixed settings tools inspect or update an existing Session (current by default). Clear removes only the child model override; effort default/unset clears that override. Explicit incompatible pairs fail, while switching models drops stale stored effort that the new leaf does not support. Children inherit one current pair, not the parent's future-child policy; existing children do not change retroactively.

The compact-threshold tool inspects when the supplied value is absent/invalid/nonpositive and floors positive overrides. A value of 0.9 is stored as 0, visibly distinct from the effective model-derived fallback. Clear uses the default max(1,floor(context window×0.85)). Setting the threshold does not start compaction; actual completed-response usage must exceed it at the normal request boundary. Raw/effective fields and policy ancestry are reported in DTO/status rather than invented UI defaults.

Settings normalize from the latest owner state inside the ordered save lane, strict-save only changed keys and skip no-op writes. Pre-rename failure leaves the old settings; postrename failure retains the committed settings and reports the durability failure. Held requests stay frozen and prompt identity is not rewritten by a future-child setting. The concentrated ModelCompact workflow now also drives real original child controls, disjoint model/effort pairs, fresh child/grandchild behavior, threshold-triggered automatic L1, faults/held ingress/Stop and restart.

### Local file reads and writes

`read` lists directories nonrecursively with default 50-entry pagination or reads physical lines selected by startLine/endLine. LF, CRLF and bare CR endings are retained, with line/byte metadata and a no-trailing-newline notice where applicable. Large files return bounded 5000-byte head/tail excerpts; explicit finite ranges stream only to their endpoint, and giant selected lines remain bounded. Small complete text uses UTF-8 replacement decoding; bounded excerpts identify escaped bytes or provide diagnostic hexadecimal samples. Read does not modify the source. Accessible absolute paths remain read-only; effects stay inside relative workspaces and reject symbolic links.

`write` keeps create-new protection unless overwrite is true. Set createDirs:true to create missing parents. A refusal caused by an existing file or missing parents can return a short-lived contentRef; retry it with overwrite:true, no content argument, and optionally a different permitted destination. Failed retries preserve the cached text; success consumes it. References belong to the exact Session and Agent, expire after 15 minutes and are lost on restart. The process cache holds at most 32 entries/8MiB with 2 MiB per payload; supplied writes are not capped at 1 MiB, but oversized refused content is not cached. Atomic temp→move writes are retained. This is ordinary trusted local execution, not an OS sandbox.

The concentrated `experimentHostFiles.e2e.mjs` drives actual tool calls and original Chat through large-file reads, directory/range edge cases, protected writes/cached retries, cache eviction and a clean-process restart. ### Continue and activity waits

Use the original **Continue** button or `/continue` for an idle interrupted turn. The backend rechecks committed-history availability and uses the same processor/provider path without adding a new user message. Busy, waiting and complete histories are rejected. Continuation never reruns an old tool effect or invents missing tool outputs. Stop during a continuation uses the existing cancellation/finalization path. Busy/crash startup recovery remains fail-closed.

`wait` ends the otherwise-finished turn after its full paired tool batch and records an idle wait. Declare at least one of `waitAnySessions`, a real `waitAllSessions` barrier, exact owned `waitExecIds`, `waitForInput:true`, or a positive one-shot `wakeIfNoActivityAfterSeconds`. Ordinary incoming activity can wake any/exec/input declarations even when the named work is still pending. A waitAll source report is persisted in its deferred queue until all listed Sessions respond; unrelated input releases the deferred reports plus a pending-source reminder. Explicit wait is canceled when a sibling tool errors; successful `afterSend=wait` handoffs still wait in that case, and `finish` still ends the batch. Child `afterSend=wait` requires a nonempty initial message. Fast replies already queued before arming use the same wake path.

Wait IDs, source declarations, waitAll deferred inputs and diagnostic fingerprints live in the same active Session JSON. Clean-idle restart restores them and rearms the internal one-shot deadline from startedAt + timeoutSeconds; no separate general timer/cron table is imported. Current-token timeout and source-quiescence events enter the existing strict save lane; stale tokens do not start another provider. Source-only waits have bounded, deduplicated diagnostics when their dependency graph shows no observed queued, active, timed, exec-backed, input-backed or transitive progress. The diagnostic does not prove deadlock or task completion. Idle waiting is not busy; Stop remains a no-op until an active turn exists, while new input wakes the wait. Runtime/list/Chat projections include only bounded wait details, never deferred message contents.

### Trusted local execution

Linux-local `exec` runs one trusted shell command with its owning Agent's workspace-root initial cwd, or an explicitly requested existing relative workspace directory. A command's `cd` does **not** change any later exec or file-tool default; this experiment does not port TypeScript's persisted Session-cwd synchronization. The child receives only selected PATH/HOME/locale/user variables, not the host's API token or provider credential variables by default. That reduces accidental environment leakage, **not** security isolation: a shell running as the host's UID can read or modify arbitrary accessible filesystem paths, including locations outside the workspace. Use only a disposable workspace on an installation you trust. Neither `timeout`, `/stop`, nor graceful host shutdown kills an already-launched command. The default foreground wait is 15 seconds; a finite value above 60 seconds clamps to 60 with a warning, and the command continues as background on a wait timeout. The activity `wait` tool can declare these exact owned exec IDs; no model-facing process list/kill or arbitrary process-control API is provided.

Each exec owns an actual petname `execId`, a complete raw-byte stdout/stderr log, and a separate atomic status under the **data** root's `state/exec/<Session key>/<execId>/`, not inside the tool workspace. The immediate result shows only a bounded preview. `read_exec({execId,offset?})` accepts only a current-Session ID and reports running/finished status, exit code when known, total log bytes, and at most 16 KiB of original bytes per call; `nextOffset` is the byte offset actually consumed. Broken UTF-8 sequences and unprintable bytes are escaped explicitly rather than silently dropped. The log on disk is complete, but the tool response remains bounded. Historical flat `s_<GUID>` owners keep their original directory name; new namespaced IDs map to one encoded directory segment without rewriting Session identity or receipts. Foreground completion closes tracking while retaining the log; background completion strictly persists one same-Session system queue event and a newest-32 exact-exec receipt, then the ordinary processor can read that result. On a clean-idle restart, pending tracking is reloaded before notifications resume, and an already accepted event is not re-enqueued. If a process disappears without a status file, local PID/start-time observation reports an unknown exit rather than killing any process; tracking older than 24 hours expires without removing logs or killing a command. This is not general crash recovery: a crash while busy or a failure between launching a process and recording its active tracking still fails outside this supported path.

Bare `POST /api/sessions` and `{}` keep the historical generated `s_<GUID>` and main workspace. If its JSON rename already committed but a later durability step failed, the response includes that committed ID and the still-running host retains a usable owner; the error does not pretend the Session never existed.

`host-e2e.py` retains CLI/SSE and clean restart checks. ## Session persistence C1/C2/D experiment

The `Foxwarm/Sessions/Storage` code accepts one explicitly bound Session ID and the current bounded ordinary v1 authority subset. It preserves open unknown top-level, queue-item/source, Message, part, metadata and provider JSON. The host additionally admits supported CTX-BLOCK metadata, preserved raw flags, `nextBlockId`, and the strict Agent/parent binding for fresh children and declared wait metadata/deferred inputs; it still rejects fork/alias state, managed/child-handoff reminder/indexing state, Worker mailbox progress, images and unimplemented structured queue kinds. Active JSON is the sole active-history authority; Archive is immutable audit/recall data and is never used to rebuild active history.

The SQLite store pins `Microsoft.Data.Sqlite` 10.0.12. It admits the exact six-column TypeScript `archive_messages` and 15-column `archive_blocks` table layouts (including source IDs, raw seq/time ranges, summary, memory facts, creation time). Archive insertion is immutable/byte-exact on replay with inserted-only rollback. The Session save lane stages a compaction rewrite from active history only; it writes blocks plus a completion raw row to Archive, atomically replaces authority JSON, then publishes only its owned hot history/version/nextSeq/nextBlock delta without rolling back concurrent queue/Stop/model settings. Pre-rename failure removes only newly inserted rows; postrename failure retains and publishes committed authority and throws. Only historical tool-response pruning reads Archive to verify exact original provenance before reducing active output, and that path commits only when the estimated session fits 50% of the selected context limit. One Agent directory index is written atomically; this does not introduce a full catalog, cross-store transaction or crash-repair protocol.

Stored `message_json` read from SQLite retains its original string and is never silently reserialized. New C# rows use a bounded ECMAScript-compatible projection over owned JSON. Object keys follow ECMAScript array-index ordering; strings preserve the verified JSON escaping boundary; finite binary64 numbers use .NET's shortest round-trip digits plus ECMAScript's fixed/scientific thresholds, lowercase exponent style, explicit positive exponent sign, and `-0` → `0`. JSON-parsed numbers and CLR `double`/`float` are supported. Integral CLR values are accepted only when exactly representable as a binary64 Number; over-precise integers and CLR `decimal` values fail before database insertion rather than being silently rounded. Actual `JSON.stringify` checks cover non-ASCII, U+2028/U+2029, a literal `\\u2028`, quotes, backslashes, controls, numeric-key ordering, `-0`, the `1e-6`/`1e21` thresholds and adjacent representable values, fractional timing, binary64 extrema, and a finite 512-value seeded sample. This remains a tested projection, not a general custom ECMAScript runtime.

The JSON authority writer writes a unique same-directory UTF-8 temp file, calls `Flush(true)`, atomically renames it over the target, and fsyncs the Linux parent directory. Matching the current TypeScript portability rule, directory-open/fsync errors `EPERM`, `EISDIR`, `EINVAL`, `ENOSYS`, and `ENOTSUP` are reported as unsupported rather than durable; other errors fail. Failures before rename remain precommit and remove the temp file. Failures after rename throw `AuthorityCommittedException` and leave the new authority visible, so a later caller cannot misclassify the operation as rollback-safe. File fsync and directory fsync are separate durability boundaries; injected failures and normal reopen do not prove power-loss or cross-SQLite/JSON atomicity.

The C1 tests use only fresh temporary roots. ## Session-turn experiment

`Foxwarm/Sessions/Turns` is an experiment-only translation of the current Main-local `sessionWorkers:false` path. `SessionState` keeps bounded queue/history records, `nextMessageSeq`, `historyVersion`, and an owned v1 authority envelope using open JSON. `SessionEntry` protects short synchronous state mutations with a per-Session gate, serializes all authority work through a separate async save lane, claims one processor atomically, and transfers one active cancellation handle to Stop. `SessionIngress` awaits a best-effort save attempt before acknowledging ordinary input, and the owned processor makes another ordered best-effort snapshot attempt immediately before selecting an ordinary prefix. Busy claims and releases remain strict snapshots with precommit-only operation-scoped rollback; postrename failures retain the committed hot meaning.

`SessionTurnRunner` consumes the complete leading ordinary queue prefix in canonical order regardless of source platform, channel, or conversation, while preserving one canonical history row and `clientMessageId` per logical input. `QueueSource` retains provenance only and does not select a turn or reply target. `LocalSessionTurnHost` binds one exact Session entry and owns the complete provider/tool loop under that processor claim: canonical assistant commit, injected tool execution, canonical paired tool-row commit, post-tool ordinary-prefix consumption, then the next provider request. User batches, model calls, tool results, and final assistants all use the same contiguous sequence/timestamp builder. Stop sets the boundary, takes and cancels the active request before waiting for its later best-effort save, and finalizes accepted queued inputs without another model call. Canonical appends do not mutate hot history/queue before Archive→JSON commit, so precommit failure needs no broad snapshot restoration; postcommit publication removes only the captured queue identities and preserves later ingress/Stop state. Queue-prefix and Stop-finalization batch notifications remain non-poisoning and observable. Other assistant/busy/release callback behavior is unchanged.

The first committed nonempty input in a bounded turn controls parts preparation: a prebuilt message consumes that boundary without preparation, an empty row does not consume it, and a parts item prepares numeric `lastMessageTime` only when it is first. History-empty first-parts preparation also prepends the canonical `<foxwarm-system kind="session" currentSessionId="..." />` marker after Foxwarm attribute normalization and ECMAScript-whitespace collapsing. Later parts after a leading prebuilt message therefore receive no marker and do not change the timestamp. Caller-supplied `seq` is rejected; C2 owns contiguous sequence assignment. This remains a bounded owned-Message/persistence experiment, not crash recovery or production integration.

The low-level runner remains separate from the host tool registry; the host injects its exact-owner resolved dispatcher. Structured retry/wait queue actions, managed state, child reminders, external channel delivery, Worker IPC, crash/busy recovery, performance equivalence and production integration remain excluded. The current host adds ordinary Continue, declared activity waits, bounded owner discovery and fixed tools as described above; those are not automatic retry/recovery or general scheduling.
