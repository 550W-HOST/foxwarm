# Experimental .NET prototype

This directory is a manual migration experiment and is not part of the Node.js build or test dependency graph. It currently contains a conventional .NET 10 solution with a behavior-equivalent port of the pure conditional-memory helpers.

## Run

From this directory, with a .NET 10 SDK installed:

```sh
dotnet test Foxwarm.DotnetSpike.sln
```

The prototype intentionally uses ordinary managed .NET targets. It does not enable Native AOT, trimming, browser/WASI targets, or additional workloads.

## Scope and oracle

`Foxwarm.ConditionalMemory` ports `filterConditionalMemorySource`, `buildCurrentModelSnapshot`, and `readCurrentModelSnapshotId` from `src/conditionalMemory.ts`. The focused xUnit tests independently assert representative expected strings. `parity-corpus.json` is a 30-case shared synthetic corpus covering every existing TypeScript test behavior plus deterministic probes for Unicode whitespace, non-ASCII tag boundaries, and line-separator wildcard behavior.

Run the differential oracle from the repository root after restoring the repository JavaScript dependencies, building the shared package, and selecting a private .NET SDK:

```sh
npm ci
npm --prefix packages/shared run build
export FOXWARM_TSX=./node_modules/.bin/tsx
export DOTNET_ROOT=/path/to/private/dotnet-sdk-10
export PATH="$DOTNET_ROOT:$PATH"
python3 experiments/dotnet/run-parity.py
```

The `npm ci` and shared build are required because the actual TypeScript source imports the generated `packages/shared/dist/foxwarmMarkup` module; the parity runner does not silently copy generated output from another checkout. The runner invokes the actual TypeScript helpers through `parity-ts.ts` and the actual C# helpers through the parity console project, then compares exact JSON results. Restore the .NET projects once before using `--no-restore` in the runner (`dotnet restore Foxwarm.DotnetSpike.sln`). `undefined` is represented explicitly as `{ "kind": "undefined" }`; no expected output is generated by C#. The TypeScript implementation and tests remain authoritative. This experiment is not required by existing Node CI and does not change TypeScript runtime behavior, persistence, model routing, or snapshot ownership.
