# Experimental .NET prototype

This directory is a manual migration experiment and is not part of the Node.js build or test dependency graph. It currently contains a conventional .NET 10 solution with a behavior-equivalent port of the pure conditional-memory helpers and a bounded Message/MessagePart JSON compatibility leaf.

## Run

From this directory, with a .NET 10 SDK installed:

```sh
dotnet test Foxwarm.DotnetSpike.sln
```

The prototype intentionally uses ordinary managed .NET targets. It does not enable Native AOT, trimming, browser/WASI targets, or additional workloads.

## Scope and oracle

`Foxwarm.ConditionalMemory` ports `filterConditionalMemorySource`, `buildCurrentModelSnapshot`, and `readCurrentModelSnapshotId` from `src/conditionalMemory.ts`. `Foxwarm.MessageJson` is a bounded compatibility leaf: owned `JsonObject`-backed canonical messages/parts for supported `user`/`model`/`tool` roles, exact property-presence and unknown-subtree preservation, separate exact-false visibility projection, and the `src/toolCallArgs.ts` argument parse/stringify helpers. It does not implement provider Responses conversion. The focused xUnit tests independently assert representative expected strings and ownership behavior. `parity-corpus.json` is a 54-case shared synthetic corpus covering every existing conditional-memory test behavior plus deterministic probes for Unicode whitespace, non-ASCII tag boundaries, line-separator wildcard behavior, owned Message JSON, visibility, and tool-argument parsing/stringification. Syntactically malformed argument strings permit native parser-detail suffix differences under the stable `Invalid tool arguments JSON:` prefix; args, raw text, result field presence, and syntactically valid top-level classification remain strict.

Run the differential oracle from the repository root after restoring the repository JavaScript dependencies, building the shared package, and selecting a private .NET SDK:

```sh
npm ci
npm --prefix packages/shared run build
export FOXWARM_TSX=/path/to/pinned/tsx
# Or use the runner's pinned fallback: unset FOXWARM_TSX (it invokes npx tsx@4.19.2).
export DOTNET_ROOT=/path/to/private/dotnet-sdk-10
export PATH="$DOTNET_ROOT:$PATH"
dotnet restore experiments/dotnet/Foxwarm.DotnetSpike.sln
python3 experiments/dotnet/run-parity.py
```

The `npm ci` and shared build are required because the actual TypeScript source imports the generated `packages/shared/dist/foxwarmMarkup` module; the parity runner does not silently copy generated output from another checkout. The runner invokes the actual TypeScript helpers through `parity-ts.ts` and the actual C# helpers through the parity console project. It reports strict semantic JSON matches, generated-JSON semantic matches, raw-text exact matches, scoped native-diagnostic compatibility for syntactically malformed JSON strings, and explicit unsupported non-string/non-object inputs separately; it rejects short runner output and does not silently zip-truncate results. Restore the .NET projects once before using `--no-restore` in the runner (`dotnet restore Foxwarm.DotnetSpike.sln`). `undefined` is represented explicitly as `{ "kind": "undefined" }`; no expected output is generated by C#. The TypeScript implementation and tests remain authoritative. This experiment is not required by existing Node CI and does not change TypeScript runtime behavior, persistence, model routing, or snapshot ownership.
