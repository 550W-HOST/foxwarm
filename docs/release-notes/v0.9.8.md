# Foxwarm 0.9.8

Foxwarm 0.9.8 turns first-run setup into a Models-only screen and adds **Authorization** and **MCP** tabs to Setup, so you can edit the tool authorization policy and manage outbound MCP servers in the WebUI. The System page moves to a list-and-detail layout with an Agent creator tree and views of each Agent's prompt and rule layers. Skills can now declare runnable ToolScript entries, including a bundled `advisor` skill, and restricted Agents can read, copy and run skills without filesystem access to `master`. The desktop apps switch between the local instance and remote Foxwarm instances and open native save dialogs for downloads. The chat composer now uses CodeMirror, switching to long Sessions is much faster, and the image viewer zooms, pans and steps through every image in the Session. New installations now listen only on loopback and send with Enter, and the optional handoff-confirmation checkpoint has been removed, so read the upgrade notes before updating.

## Upgrade notes

- Back up the data directory first, as usual.
- **New installations listen on loopback only.** Fresh server installations created by `install-foxwarm.sh` or `install-foxwarm.ps1` (a data directory with neither `state/config.yaml` nor `state/token`) now write `state/config.yaml` with `bot.httpHost: 127.0.0.1`, so only the local machine can connect, and the installer prints how to open it to other devices (`bot.httpHost: 0.0.0.0` and restart). Existing installations and updates never create, edit or replace `config.yaml`, so their bind address is unchanged. Running Main directly without the installer, Docker and the desktop apps are unchanged. Run `foxwarmctl link` at any time to print the WebUI sign-in link.
- **Enter sends by default on new installations.** Completing first-run model setup now records `sendKeyDefault: enter` in `state/webui.json`, so browsers that haven't chosen a send key send on Enter instead of Ctrl/Cmd+Enter. Existing installations keep Ctrl/Cmd+Enter as their default, and a browser's own choice always wins.
- **One Main process per data directory.** Foxwarm Main — both the server process and the desktop app's local instance — now takes an exclusive lock on `state/main.lock` before reading configuration. Starting a second Main on the same data directory exits immediately with an error naming the directory instead of sharing state. The operating system releases the lock when Main exits, and child processes don't inherit it. `foxwarm archive` commands (such as `export-jsonl`) and `foxwarm model` still run beside a running Main.
- **Handoff confirmation checkpoint removed.** The optional `handoffConfirmation` setting in `config.yaml` and the `handoffRecall` and `handoffConfirmation` arguments on `send_to_session` and `create_child_session` have been removed. Existing configurations that still set `handoffConfirmation` start normally with the key ignored, and existing scripts or Sessions that still pass `handoffRecall` or `handoffConfirmation` keep working with those arguments ignored.
- **Migrated legacy-isolated Agents.** For Agents whose rules were generated from legacy isolation and haven't been edited by hand, startup regenerates their rule layer so they can copy and run their own skills (except `advisor`, which forks the Session), matching the updated `restricted-worker` template. Hand-edited layers stay as stored.

## Highlights

### Setup and first run

- A new installation opens on a full-window **Connect a model** screen with **Save and continue** and no sidebar, tab strip, status bar or Setup rail; saving hands off directly to the welcome Session. In the Models form, **Other service** starts on Chat Completions, loaded models appear as one-click buttons filtered by the **Model ID** field (the first added becomes the default), presets move API type, provider name and base URL under **Advanced**, and an unreplaced placeholder key prompts "Enter your API key."
- **Setup → Authorization** edits the installation's global tool authorization policy (`state/tool-authorization.yaml`) in a schema-aware YAML editor. **Save policy** validates and applies from the next tool call without a restart. If the policy changed elsewhere while open, saving refuses and offers **Reload policy**. An unusable active file still opens with its parser error and warns that Agents can't respond until it is fixed.
- **Setup → MCP** lists, adds, edits, enables, disables, deletes and checks outbound MCP servers without editing files by hand. Literal credentials stay masked behind placeholders while `${secret:NAME}` references are shown and suggested, and OAuth servers show their account state and a **Sign in** button. Opening Setup never connects; **Check** and **Check all** test enabled servers on demand, and **Enable**/**Disable** and **Delete** (with inline confirmation) sit in each row's menu.
- In **Setup → Config**, Weixin login is now a collapsed **Connect Weixin** disclosure. **Test connection** in Models sends no tool definitions. `foxwarmctl link` (Bash and PowerShell) prints the installation's WebUI sign-in link, and the sign-in page points to the installer's sign-in link and `foxwarmctl link`. The first-run welcome explains that commands run without asking first and that you can ask the agent to add an approval rule.

### System redesign

- The **System** page keeps its header fixed and uses a compact list beside an always-visible, independently scrolling inspector in **Agents**, **Sessions**, **Timers** and **Webhooks**. On narrow panes and phones, selecting a row opens its details as a page with **Back**. The **Webhooks** tab appears once a webhook exists (`#webhooks` still opens it directly).
- **System → Agents** lists Agents in their creator tree with rule state, memory source, start Node, Session count and last activity. The inspector has four tabs: **Overview** (recent Sessions plus summaries of access and prompt layers), **Prompt** (the built-in framework prompt via **View**, installation additions in `agents/00_SYSTEM.local.md` with creation when absent, inherited memory and the Agent's own memory), **Rules** (the read-only installation rules and creator ancestor layers above a schema-aware YAML editor for the Agent's own rule layer) and **Settings**.
- **System → Sessions** uses compact one-line rows. **System → Nodes** is now a table showing connectivity beside Provider/upgrade warnings and protocol notes, expandable service versions, a row context menu and a Session count that opens **Sessions** filtered to that Node.

### Runnable skills, skill access and `advisor`

- A skill can declare a `run:` block in `SKILL.md` frontmatter (`entry`, `effect`, optional `mode`, `timeoutSecs` and an `args` JSON Schema subset). Agents run it directly with `ctl skill run <name> --args @args` without loading `SKILL.md` first, and `ctl skill run <name> --help` shows its effect, mode and arguments. The skill catalog marks runnable skills with `<run>` and shows compact `args` schemas (up to 1,000 characters) as `<args>`.
- The new bundled `advisor` skill (`ctl skill run advisor --args @args`) forks the calling Session to a stronger model (`args.model`, or the configured model key named `advisor`), archives the fork, asks it to investigate read-only and report back, and ends the caller's turn waiting for the advice. It refuses without creating a fork if the caller's context exceeds the advisor model's limit. Agents can also archive and unarchive Sessions with `ctl session archive` and `ctl session unarchive`.
- The skill catalog and `ctl skill list` now list only skills the caller's `skill` rules may allow, and show `<run>`/`<args>` only when `run_skill` may be allowed. Agents can read a skill's resource files through Main with `ctl skill load <name> <path>`, copy skill files to a Node with `ctl skill copy <name> <target-path>` (up to 200 files and 64 MiB) and run another ToolScript file of a skill with `ctl skill run <name> --script <path>`, without needing filesystem access to `master`. The `restricted-worker` template allows reading, copying and running its own skills except `advisor`; `channel-assistant` allows reading and copying them.

### Desktop apps

- Both the Windows and macOS desktop apps can add remote Foxwarm instances by URL and switch between them and the local instance, saved in `desktop-settings.json` in the desktop data directory. Open the native instance menu from the sidebar brand row, the **Instances** menu on macOS, or **Ctrl+Shift+F1** and **Switch instance…** in the Windows tray. Local Main starts on demand only when the local instance is selected; stopping it asks for confirmation with the number of running Sessions.
- Both desktop apps now ask where to save every download through the native save dialog (save-panel sheet on macOS, Save As on Windows), restricted to the selected instance's scope. On Windows, repeated downloads and Code folder downloads are now allowed for the selected instance's origin instead of being blocked silently.
- Both desktop hosts now set the local sign-in cookie with `SameSite=Lax`, fixing a WebKit issue on macOS 26 where switching from a remote instance back to the local instance landed on the sign-in page.

### WebUI

- The chat composer now uses CodeMirror 6 instead of a custom contenteditable editor, fixing lost carets, broken line-boundary navigation and iOS caret issues next to inline file and pasted-text chips, with standard key bindings, native theme caret color and full undo history. On desktop, the composer placeholder and Send button tooltip show the current send shortcut.
- Long timelines mount a window of rendered rows (starting with the newest 24 items and extending as you scroll), reuse sanitized assistant Markdown from a per-tab cache across mounts, and skip redundant layout reads during switches, making Session switching much faster. The startup splash now fast-forwards and leaves within 300 ms once the app is ready.
- The image viewer zooms around the pointer with Ctrl/Cmd + wheel and trackpad pinch, pans enlarged images by dragging with the mouse, and switches across every image in the Session (or in the draft) with arrow keys, side buttons and touch swipes. In desktop apps and installed PWAs, full-window layers — the image viewer, expanded artifacts and window-wide Tasks details — now use the window's title row cleanly around the window controls.
- In Conversation view, Task assignments, reassignments, notes and completions appear as standalone cards under **Show inter-agent messages**, showing the Task title, a collapsed preview starting at the description, note or result, and a Task ID button that opens Tasks. Notices to a previous owner stay in Activity. Deliveries from child initial messages, nested ToolScript runs and background runs are recorded too, and Session Sequence labels Task links by event.
- Every native `<select>` across the WebUI has been replaced with a shared Select component: a custom listbox matching Foxwarm's context menus on desktop, and the native picker on touch devices.
- In Detailed and Grouped views, the system prompt card now displays the exact persisted system prompt sent to the model verbatim, without a synthetic `<foxwarm-system kind="snapshot" ... />` tag, trailing newline or accidental tag styling.
- The sidebar brand row shows the configured instance emoji and name; on macOS under the window lights, a configured name that doesn't fit hides cleanly instead of truncating. In Chat, the session subtitle appears only when a working directory is set, and **Show user message metadata** and **Debug info** move under **Advanced** in the session menu. In **New session**, **Session ID** and **Runtime** sit behind **More options**. On packaged servers where Code isn't installed, the Code page shows the release download without source-checkout `npm` commands.

## Other changes

### Agents and models

- Both HTTP (`openai`, `openai-responses`) and WebSocket (`openai-ws`) OpenAI Responses transports now send the system prompt as a leading `developer` message in `input` instead of top-level `instructions`, keeping the prompt inside the cache prefix on GPT-6.2 and newer models.
- **Per-message effort on Anthropic.** Setting `perMessageEffort: true` on an Anthropic provider or model in `models.yaml` records effort changes in history and replays them as effort-only mid-conversation messages, keeping the prompt cache across effort changes. A change made during a tool loop takes effect on the next user input; switching models, switching to or from `none`, and fixed thinking modes (`between_tools` or `disabled`) keep the top-level path.
- The `compact-completed` marker now records the Session's current Node (`currentNode`) and working directory (`cwd`, when set), so agents keep their placement in view after history is compacted.
- `run_script`, `ctl tool search` and `ctl tool call <tool-id> --help` now guide agents to call MCP and Node tools directly with `call_tool("<tool-id>", args)` inside ToolScript rather than wrapping `ctl tool call`.
- The `foxwarm-maintenance` skill now runs self-updates as an ordinary `exec`.

### Fixes

- Stopping an idle Session or stopping a turn just as it finished no longer leaves the Session stuck in `stopping`, where it blocked later input, timers and Task notifications or spun retrying processors.
- SQLite connections in `TaskStore` and Session identity checks now open without connection pooling, fixing a leak where connection-pool prune timers kept disposed `SessionManager` instances and their database handles alive.
- On Linux and macOS, `foxwarmctl start` now captures fatal startup lines written right before tmux closes a pane, includes all fatal startup failure lines (such as an installation lock conflict) in its error output, and waits properly while a detached launcher starts Main. Both installers and `foxwarmctl` now read `bot.httpPort` and `bot.httpHost` only under the top-level `bot:` mapping, matching Main.
- In-session Search now highlights and scrolls to matches inside To/From and Task conversation cards instead of only counting them.
- Open Sidebar context menus and Delete/Archive dialogs no longer close or reset **Also delete descendants** when unrelated Sessions are created or deleted.
- User-created and user-assigned Tasks now notify the assigned Session by default unless opted out, matching the documented behavior.
- `ctl tool search` now hides commands denied by fixed-argument rules, matching `ctl --help`.
- Pending approvals now re-check a scoped WebUI approver against the current policy at decision time, not only the policy in effect when the approval was requested.
- Stateless inbound MCP file downloads (`GET /api/vscode-web/fs/read-file`) now evaluate Node ancestry on each check, matching ordinary MCP reads.
- Deleting an inbound MCP session now releases its capacity slot before returning `200`, preventing an immediate re-initialize from getting a `503` capacity error.
- Busy web pages no longer hold `browser_open` and settling actions past their call deadline until Puppeteer's 180-second timeout.
