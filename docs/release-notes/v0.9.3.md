# Foxwarm 0.9.3

Foxwarm 0.9.3 updates the bundled .NET runtime to fix a security vulnerability. It adds native CLI Node packages for Windows and Apple Silicon Macs, gives each Node its own Code window, bundles Code in the Desktop app, and adds a Timers section to System.

## Security

- Self-contained packages, the container image and the native CLI Node packages now use .NET runtime 10.0.14. It fixes a high-severity out-of-bounds write in .NET's Brotli decoder (CVE-2026-111497, GHSA-p3jp-9v83-76w9). Every earlier 10.0 runtime is affected.
- Framework-dependent packages use the .NET runtime installed on your machine. Update that runtime to 10.0.14 or later; updating Foxwarm alone does not fix it.

## Highlights

### Native CLI Node for Windows and macOS

- The standalone native CLI Node is now published for Windows x64 and macOS on Apple Silicon, alongside Linux x64. It needs no .NET or Node.js installation.
- On those platforms the onboarding command now installs the native package. If a server doesn't publish it, the command falls back to the previous setup.
- The packages are not code-signed or notarized yet.

### One Code window per Node

- Each Node now opens in its own Code tab with its own workspace, editors and terminals. Opening folders on one Node no longer adds them to another Node's workspace.
- A folder that is already inside an open workspace folder is shown in Explorer instead of being added again. Adding a parent folder replaces the folders it contains.
- Opening a file from a tool call shows and selects it in Explorer. If the file isn't inside any workspace folder, Code first adds the Session's working directory that contains it, or else the file's folder.
- Your existing workspace is split by Node the first time Code starts. The original file is kept next to the new ones with a `.migrated` suffix.
- Code can now open and save files on macOS Nodes.

### Code in the Desktop app

- The Desktop app now includes Code, so it works without a separate download.
- Server packages don't include Code. Each release now publishes `foxwarm-code-<version>.tar.gz`, listed in `SHA256SUMS`. If Code isn't installed, the Code page shows a command that downloads the matching version, checks it and unpacks it; reload the page afterwards.

### Timers in System

- System has a new Timers section listing every timer with its owner, schedule, target and recent results. You can edit, pause, resume and delete timers there, and a Session's inspector shows its own timers.
- Timers can be paused. A paused timer keeps its schedule; resuming continues from the next scheduled time without making up missed runs. A one-time timer whose time passed while it was paused runs once when resumed.
- `update_timer` accepts `paused`, and `list_timers` shows each timer's paused state and most recent result.

## Other changes

- Tool calls in a batch now show Running individually. Calls that are waiting or already finished no longer flicker while the batch runs.
- The status line under the chat shows the summary of the running command or script, and in Conversation view the current reasoning heading.
- Retry delays for failed model requests can be set with `retryIntervalsMs` in `models.yaml`, under `defaults`, a provider or a model. Changes apply to the next retry.
- Foxwarm warns when an Agent's memory takes up too much of the model's context window: in the WebUI, in a note at the end of the memory and in the server log. The limit is `llm.memoryWarningThresholdPercent` (default 0.15). When a request fails because the context is too large, the error now breaks down where the tokens went.
- Answers to `ask_user` questions render Markdown.
- On Windows Nodes, a file can be read while a running command is still writing to it.
- Images in formats that models don't accept, such as SVG, BMP and TIFF, are sent to the model as files instead of images. The original file is kept.

### WebUI app installation and sign-in

- The WebUI can be installed as an app again. The manifest and icons were not reachable before; installing works both for administrators and for restricted WebUI access.
- The WebUI, the Desktop app and the Code extension have a new fox icon.
- The sign-in cookie now uses `SameSite=Lax` instead of `Strict`, so opening Foxwarm from a link or as an installed app keeps you signed in. Each time the WebUI opens, the cookie is renewed for another 365 days. Revoking a token on the server still signs that browser out.

## Upgrading

- Back up the data directory first, as usual.
- If you use a framework-dependent package, install .NET runtime 10.0.14 or later; see Security above.
- If you run a server package and use Code, install `foxwarm-code-0.9.3.tar.gz` using the command on the Code page.
- The first time each browser opens the WebUI after updating, it replaces its old `Strict` sign-in cookie with the new one. You don't need to sign in again.
- An older Foxwarm version doesn't know about paused timers. If you downgrade, paused timers start running again.
