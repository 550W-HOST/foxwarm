# Foxwarm 0.9.7

Foxwarm 0.9.7 shows tool results to agents and in the WebUI as the same readable YAML, and failed calls as a plain error message. Built-in commands now return structured records. Agents can list and stop their background commands, switch their own model when one keeps failing, and open files in Code from links in their replies. Terminals keep running when you close their tab, and the sidebar lists them. The Windows desktop app has an installer, and the macOS desktop app includes Code. ToolScript runs on a newer Python interpreter, and the TypeScript Main backend has been removed from the source. Scripts that read the text of built-in results or the former error object need a change, so read the upgrade notes before updating.

## Upgrade notes

- Back up the data directory first, as usual.
- **macOS and Windows server packages.** 0.9.7 no longer publishes the native packages under the retired names `foxwarm-osx-arm64-self-contained.tar.gz` and `foxwarm-win-x64-self-contained.zip`. An installation that still uses a self-contained package from 0.9.5 or earlier can't `update` to 0.9.7; rerun the installer instead. It keeps the data and configuration. Installations updated to 0.9.6 already use the native package and update as usual.
- **Windows desktop app.** To move from the extracted ZIP to the new installer, exit Foxwarm from the tray, run `foxwarm-desktop-win-x64-setup.exe` and then delete the extracted folder. The installed app uses the same data, so your Sessions, models and settings carry over. To keep using the ZIP, replace the extracted folder as before.
- **Tool results and errors.** Agents now read tool results as readable YAML, with multi-line text as literal blocks instead of escaped one-line strings, and a failed call as `{error: "<message>"}` instead of `{error: {type, message}}`. A `code` field stays beside the error only for authorization denials, approval outcomes, skipped and cancelled calls, and the errors that already reported one, such as Task errors. Earlier results in a Session's history display in the new form too, so every existing Session resends its history once without the provider's prompt cache after the upgrade. ToolScript, timer and webhook scripts that read `error["message"]` or `error["type"]` from a failed result should read `error` as the message and `code` where they need one.
- **Built-in command results.** Lists, status, settings and action receipts of built-in commands now return one structured record to agents, the WebUI and ToolScript, without an `output` sentence that repeats their fields. For example, `timer list` returns `timers`, `session list` returns `sessions` and a `nextPage` command, `node list` returns `currentNode`, `nodes` and `providers`, and `script list` returns one short row per run. Records that used to be JSON text inside `output`, such as `node pending`, `node approve`, `node bootstrap-info`, `config set` and `config explain-auth`, are now the record itself. Scripts that parsed the `output` text of these commands need to read the fields instead. Documents such as `read`, `exec` output, `session view`, history recall, `memory read` and `--help` still return `output` text.
- **Background command receipts.** A background `exec` receipt and its completion event now start with the command's ID in brackets, for example `[quiet-river] Finished: exit code 0, 2.1s`, followed directly by the output. The receipt no longer has an `execId:` line. Scripts that matched that line should read the leading ID or the `execId` field.
- **ToolScript.** ToolScript runs on Monty 1.6.0. A script run that was paused under 0.9.6, waiting for input or a time budget, can't be continued after the upgrade and reports that it has to be started again. Finish or cancel paused runs before updating.
- **TypeScript Main removed.** The repository no longer contains the TypeScript Main backend; Foxwarm Main is the .NET host. Existing TypeScript installations still upgrade in place with the [TypeScript migration guide](https://foxwarm.net/docs/typescript-migration/), and the TypeScript CLI Node is unchanged. The Docker image no longer installs the npm packages that only the TypeScript Main used, such as `telegraf`, `pino` and `node-schedule`.
- **Former `/` commands.** As announced in 0.9.6, the 0.9.5 spellings `/search`, `/messages`, `/delete-messages`, `/verbose` and `/attach` no longer reply with their new form; they are now ordinary messages to the agent. Use `/history search`, `/session messages`, `/session delete-messages`, `/session verbose` and `/channel attach`, or `/help` for the full list. A bare number after `/session list` is now a search query rather than refused as a 0.9.5 page number; use `--start` and `--count` to page.

## Highlights

### Readable tool results

- Tool results appear to agents and in the WebUI as the same readable YAML: one top-level field per line, lists as block sequences, and multi-line text, such as file contents or command output, as literal blocks.
- Tool-call arguments use one inline layout on every surface: each argument on its own line as `key: value`, with nested values written as `[a, b]` or `{key: value}`. Expanded cards show multi-line arguments as blocks.
- Built-in commands return structured records instead of sentences that repeat their fields; see the upgrade notes.

### Background commands

- Agents list their running background commands with `ctl exec list` and stop one with `ctl exec stop <execId>`; you can run `/exec list` and `/exec stop` too. Stopping ends the command's process group, first with TERM and after 5 seconds with KILL; on Windows it ends the process tree. The completion event then says the command was stopped.
- While a Session has background commands, the Chat status row shows **N running commands**. Its list shows each command's summary, its Node and how long it has run, with a **Stop** button; select a row to see the full command with highlighting. **System → Sessions** shows the same list.
- A background command's completion event now includes the last lines of its output, at most 40.
- In a timeline, the command ID at the start of a background receipt or completion links to its counterpart.
- Commands on a Node can be stopped when the Node runs the native Node client of this version; other Node clients report that stopping isn't supported. Provider Nodes can support it through the new optional `exec-stop` operation, which the example providers implement.

### Terminals

- Closing a terminal tab or pane no longer ends the terminal: it keeps running, and opening it again restores its output. Running terminals no longer get a tab automatically.
- The sidebar **Terminal** entry shows how many terminals are running, and its menu lists them on every Node, with their folder, Node, process ID, shell and age. Select one to open it, or to switch to its tab if it already has one. On phones, **Workspace tools → Terminal** shows the same list.
- End a terminal with **×** in that list or with the new button in the terminal's header; both ask first. A terminal whose shell exits with code 0 closes its tab; otherwise the tab stays and shows the exit code, with **New terminal** to start another in the same folder.
- Shortcuts outside macOS: with a terminal focused, Ctrl+W asks before the browser closes the page and still reaches the shell, Ctrl+C copies a selection and otherwise interrupts, Ctrl+Shift+C and Ctrl+Shift+V copy and paste, Ctrl+Backspace deletes the previous word, and Ctrl+0 resets the terminal font size. The Windows desktop app gives Ctrl+W to the terminal without asking.

### Desktop apps

- The Windows desktop app now has an installer, `foxwarm-desktop-win-x64-setup.exe`. It installs Foxwarm for your Windows account without administrator rights, adds it to the Start menu and to **Settings → Apps**, and can start Foxwarm in the tray when you sign in. It shows its pages in Simplified Chinese on Chinese Windows.
- To update, run the setup of a newer release. Updating and uninstalling exit a running Foxwarm normally first. Uninstalling keeps your data in `%LOCALAPPDATA%\Foxwarm\Desktop`.
- Setup tells you when the WebView2 Runtime is missing and links to Microsoft's download page.
- `foxwarm-desktop-win-x64.zip` remains available as the portable app. It shares its data with an installed app, and only one of them runs at a time.
- Opening the Windows desktop app while it is already running now shows its window instead of a message.
- The macOS desktop app now includes Code, so it no longer needs a separate Code download.
- Code windows in both desktop apps use Code's own title bar for the window frame, and Code's menus open correctly over the editor on Windows.

## Other changes

### Agents and models

- Agents can switch the model or effort of their own Session or of a Session below them with `ctl session model`, for example when a model keeps refusing a request. The switch is checked as a Session settings change, so tool rules can restrict it.
- Agents can run `ctl node status` to see their current Node, whether it is connected, their working folder and the Node's default folder.
- **Idle compaction.** `idleCompactMinutes` in `models.yaml` compacts a large Session that has been idle for that many minutes, while the provider's prompt cache is still warm, so the next turn resends less. It is off by default and can be set in `defaults`, on a provider or on a model. `idleCompactMinContextPercent` (default `0.5`) sets how full the context must be.
- GPT models receive extra working rules in the framework prompt, adapted from OpenAI's Codex instructions: reply style for all GPT models, working style for GPT-6 models, and disclosure of blockers and unfinished work for GPT-6.2 models.
- The Setup presets and the bundled `models.yaml` example name current OpenAI and Anthropic models, and the OpenAI examples use the Responses API.
- ToolScript runs on Monty 1.6.0, which supports more of Python, including `%` formatting and `format()`. Scripts can now read the clock, use `random` without a seed and `sleep`. A sleep longer than the script's time budget pauses the run at the end of the budget, and continuing it waits only for the rest of the sleep.
- Previews of `ctl` calls in Session views and history recall name the command path, as the timeline does.
- The `toolscript-managed-controller` skill has been removed. It described a ToolScript controller that the .NET Main doesn't provide.

### WebUI

- Links to files in agent replies open in Code at the Node and folder of the agent's most recent tool call; `#L10` and `:10` select a line. In read, write and edit cards, the path is a Code link when the card is expanded; a collapsed card opens on click.
- A `ctl tool call` of an MCP tool shows the tool's arguments in its card, as a direct call does, including while the call streams.
- `ctl` takes an optional `summary`, which agents use to say what a call is for. It appears in the Chat status line, the Session list and Conversation's collapsed cards, as an `exec` summary does. A tool's own summary, such as that of an `exec` run through `ctl`, takes precedence. Without a summary, `session view` and history recall describe MCP and Node tool calls by their arguments.
- The composer's Node picker marks a remote Node that is offline or no longer available.
- Sending a message keeps the Chat at the latest message instead of jumping.
- The System page fits phones: it has a back button and a scrolling section bar, and the Usage tables scroll sideways with their first column kept in view. The running-commands list stays on screen on phones.
- The installed iOS app fills the whole screen and keeps its bottom controls above the home indicator.
- In an installed PWA with the window controls on the left, the sidebar's expand button can be clicked again instead of dragging the window.
- With text redaction on, tool arguments appear while they stream.

### Fixes

- Anthropic requests no longer fail with a 400 error when the history contains an empty text block.
- A Session no longer stops processing input after its turn ended at the same moment as a new turn started.
- A child Session that answers completion reminders with `[NO_ACTION]` at the start of its reply is no longer reminded again. After two reminders in a row that get only a text reply, the child isn't reminded further and its parent receives one notice with the child's last reply, so a child can no longer loop on reminders.
