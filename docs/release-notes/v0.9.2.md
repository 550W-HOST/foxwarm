# Foxwarm 0.9.2

Foxwarm 0.9.2 lets agents ask you questions and wait for the answer, makes history recall usable from scripts, and lowers the server's memory use.

## Highlights

### Agents can ask you questions

- The new `ask_user` tool lets an agent ask one to four questions at once, each with optional choices. You can pick options, write your own answer or skip.
- By default the Session pauses until you answer. An agent can also keep working and receive the answer later as a message. `wait` accepts `waitQuestionIds` to wait for specific answers.
- Open questions appear in a panel above the message box, and the Session list shows which Sessions are waiting on you. While a Session waits on a question, any message you send counts as the answer.
- Questions are saved with the Session and survive compaction and restarts.
- Channels such as chat integrations receive the question as plain text.
- The framework prompt tells agents to ask for decisions with `ask_user` instead of listing questions at the end of a reply, and not to use it to confirm work already authorized.

### Notifications

- Setup has a new Notifications tab. It shows whether the browser allows notifications, lets you grant permission, and chooses which Sessions notify you when they ask a question: all Sessions (the default), only Sessions with notifications turned on, or none.
- Question notifications are skipped for the Session you are currently viewing. Per-Session idle notifications are unchanged and stay in the Session menu.

### History recall

- `recall` can filter semantic results by time with `startTime` and `endTime` (UTC; the start is included, the end is not). The filter applies before results are ranked.
- In ToolScript, `recall` returns structured results: stable Session, message and time references, score details, and a `cursor` for the next page. Paging stays within a bounded set of top results; the result says when that set is used up.
- In ToolScript, reading an exact message (`msg#N` or `msg#A-B`) returns the complete stored message as JSON, within normal ToolScript size limits.
- Ordinary model-facing recall output is unchanged.

### Server memory

- The server now uses .NET's workstation garbage collector instead of the server collector. A long-running server with bursts of activity no longer holds several gigabytes of memory that it is not using.

## Other changes

- The bundled `apply-patch-guide` skill has been removed. The `edit` tool's own description covers patch editing.

## Upgrading

- Back up the data directory first, as usual.
- If you still have an edited `agents/00_SYSTEM.md` from before 0.9.1, it replaces the bundled framework prompt, so you don't get prompt improvements such as the new `ask_user` guidance. Move your additions into `agents/00_SYSTEM.local.md`, then delete the edited copy. The startup log tells you when an edited copy is in use.
- On the first start after updating, Foxwarm rebuilds its history search index and fills in time ranges for existing memory entries. Both run in the background: the server, WebUI and Sessions are available immediately. Until they finish, recall within the current Session uses a simpler history search, and broader recall may report that search is not ready yet. Large histories can take a while.
- If the server is stopped while this repair is running, the repair continues from where it stopped on the next start.
