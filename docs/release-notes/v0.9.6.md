# Foxwarm 0.9.6

Foxwarm 0.9.6 gives agents one command tool, `ctl`, in place of `search_tools`, `call_tool` and most of the rarely used tools they used to see. The same commands run as your `/` commands, from inbound MCP clients and from ToolScript. Tool rules can now name operations, such as reading files or selecting a Node, across every tool that performs them, and one approval covers everything a call needs. This release also adds an Android Node app, a macOS desktop app, native macOS and Windows packages, and a custom window frame for the desktop apps. Several `/` commands are renamed, the deprecated `POST /trigger` endpoint is removed, and scripts that call `search_tools` need a change, so read the upgrade notes before updating.

## Upgrade notes

- Back up the data directory first, as usual.
- **Upgrade check.** `update` and the installer now print a warning, before anything is replaced, for each timer or webhook script that calls `search_tools`, each tool rule that names `search_tools` or `call_tool` or no longer has an effect, and each Agent memory or skill file that mentions `search_tools` or `call_tool`. Each warning names the timer, webhook, rule file, Agent or file to look at. They don't stop the update.
- **macOS and Windows packages.** The native packages replace `foxwarm-osx-arm64-self-contained.tar.gz` and `foxwarm-win-x64-self-contained.zip`. Run `update` as usual: 0.9.6 also publishes the native packages under the old names, and the installation switches to the native package and keeps its data and configuration. Later releases won't publish the old names, so to update a self-contained installation directly to 0.9.7 or later, rerun the installer instead. The Windows desktop app is now compiled to native code too; replace the extracted folder as before. Its data stays where it was.
- **Tools reached through `ctl`.** `search_tools` and `call_tool` are gone. Agents now see `read`, `write`, `edit`, `exec`, `run_script`, `continue_script`, `wait`, `ask_user`, `send_to_session`, `create_child_session`, `task`, `submit_compact_plan` and `ctl`. Every other tool is a `ctl` command, for example `ctl memory read notes.md` for `read_memory` or `ctl tool search <words>` to find commands, MCP tools and Node tools. The tools keep their names in tool rules, activity records and ToolScript. Check the following:
  - **Scripts.** ToolScript's `call_tool` with a tool name works as before, for example `call_tool('read_memory', {...})`. `call_tool('search_tools', ...)` now fails with an `Unknown tool: search_tools` error that names `ctl tool search <words>`. Change such timer, webhook and saved scripts to `ctl('tool search <words>')`, which returns the same rows plus the command for each result. Failed timer runs appear in the timer's recent runs, and failed webhook scripts in **System → Webhooks**.
  - **Tool rules.** Rules match the same tool names as before. A rule naming `search_tools` or `call_tool` still loads but no longer matches anything, and the server log notes it once. Searching is filtered by each tool's own rules, so a rule that denied `search_tools` no longer keeps an agent from finding tools; deny the tools themselves instead.
  - **Memory and skills.** Text that tells agents to use `search_tools` or `call_tool` is out of date. Agents created from the `channel-assistant` template have such a line in `MEMORY.md`; the template now reads files sent to the conversation with `ctl tool call node:master/read --args @args`. The `restricted-worker` and `channel-assistant` rule templates no longer list `search_tools`; existing copies keep working.
  - **Existing Sessions.** Earlier tool calls stay in the history and display as before. A Session keeps its earlier system prompt, which still names the old tools, until the prompt is rebuilt, for example after compaction. Run `/session refresh-snapshot` to rebuild it now. An agent that still calls `search_tools` or `call_tool` gets an error that names the `ctl` command to use instead.
- **Renamed `/` commands.** `/` commands now use the same commands and options as `ctl`, and `/help` lists them. Text that starts with `/` but isn't a command is now sent to the agent as an ordinary message instead of being refused. In 0.9.6 only, these former commands still don't reach the agent: they run nothing and reply with their new spelling. From 0.9.7 they are ordinary messages.

  | Before | Now |
  | --- | --- |
  | `/search` | `/history search` |
  | `/messages` | `/session messages` |
  | `/delete-messages` | `/session delete-messages` |
  | `/verbose` | `/session verbose` |
  | `/attach` | `/channel attach` |

  Other spellings changed within their command and now report an error with the usage: `/compact tools` is `/compact --tools`, `/stop compact` is `/stop --compaction`, `/timer after|at|cron` is `/timer create --after-seconds|--at|--cron`, `/session parent` and `/session unparent` are `/session set-parent` and `/session clear-parent`, `/session move` takes the Session to move and its new ID, `/agent create --no-main` is `--no-create-main-session`, `/node <id>` is `/node select <id>`, `/node create` is `/node token`, `/node move` is `/node rename`, `/node pair-help` is `/node bootstrap-info`, and `/channel weixin status|login|wait` is `/channel weixin-status|weixin-login|weixin-wait`. `/skill show` still works as `/skill load`.
  - `/session list` takes search text instead of a page number. In 0.9.6, `/session list 2` reports an error that points to `--start` and `--count`, which page the list.
- **Inbound MCP.** The five `foxwarm_*` tools are unchanged, and a sixth tool, `ctl`, runs the commands available to external clients. `foxwarm_discover` now matches whole words, so a query such as `pai` no longer finds `node_pair_list`.
- **Rules for an agent's own work.** Calls that act only on the agent's own turn, scripts, transfers or history images are no longer decided by tool rules: `wait`, `continue_script`, inline `run_script`, listing, reading and cancelling its own script runs, `cancel_transfer`, `image_crop`, `submit_compact_plan` and `artifact` `get`. A rule that denied or asked for one of these still loads but has no effect on it, and the server log names the rule. Calls these make on the agent's behalf, such as tool calls and model requests from a script, are still checked.
- **Text redaction.** By default, only values detected as email addresses, phone numbers or postal addresses are now remembered and replaced wherever they appear later. Other detected values are still replaced in the request where they were found. Remembered values with other labels are removed at the first start. To remember every label as before, set `defaults.textRedaction.knownLabels: all` in `models.yaml`.
- **`POST /trigger` removed.** The administrator-only `POST /trigger` endpoint, deprecated in 0.9.4, is gone and now answers 404. Move scripts that used it to a [webhook](https://foxwarm.net/docs/webhooks/): a `bearer` webhook for the same Session accepts the same message text as its body. `bot.enableTrigger` no longer serves a route; it now only keeps the HTTP server running when the WebUI is off and no MCP or webhook identity needs it, so headless installations stay reachable for Nodes and the API.
- **Hosted web search on Anthropic.** `webSearch` on an Anthropic provider or model now enables Anthropic's own web search, which Anthropic bills separately. Remove it there if you don't want that.
- **Code.** Code for server installations is now distributed as `foxwarm-code-<version>.fwassets`. Code installed for an earlier release keeps working; when Code is missing, its page shows the new install command.
- **Source checkouts.** The repository now pins the .NET 10 SDK line with `global.json`. A checkout on a machine with only a newer major SDK needs a .NET 10 SDK installed.
- **Downgrading.** Foxwarm 0.9.5 runs on data used by 0.9.6. Once an Agent's rules contain an operation rule (a rule with `op`), 0.9.5 and earlier refuse to start. Remove those rules before going back.

## Highlights

### One command tool: `ctl`

- Agents run Foxwarm commands with one tool, `ctl`, written as `<noun> <verb> [arguments]`, for example `ctl node list` or `ctl history recall B#12`. Its description lists the nouns, and `--help` on a noun or command shows the usage. Long text and JSON go in `values` and are referenced as `@name`. `ctl` isn't a shell: pipes and other shell operators are refused.
- `ctl tool search` finds commands, MCP tools and Node tools in one list. Built-in tools appear as their commands. MCP and Node tools appear as IDs that `ctl tool call` accepts, and `--schema` adds their argument types.
- A `ctl` call is authorized, asks for approval and is recorded exactly like a direct call of the tool it runs. In the timeline it shows the command it ran.
- Tool output that suggests a next step, such as a history drill-down or the next page of a Session view, writes it as a `ctl` command.
- `/` commands, inbound MCP's `ctl` tool and ToolScript's new `ctl(command, values=None)` use the same commands and grammar. Commands that only people use, such as stopping a run or deleting messages, are available only as `/` commands.
- Pending Node pairing requests are listed by `node pending`, beside `node approve` and `node reject`.
- The `ctl` description lists the most common commands. A command the caller isn't allowed to use is reported as not available, and mistyped commands and options get a suggestion. `node create` and `node ensure` now require `--provider-id`.
- `ctl memory` commands take `--agent <name>` to read or change another Agent's memory, subject to the caller's file rules for that Agent's memory directory.

### Rules for operations

- A tool rule can now name an operation with `op` instead of a tool: `op: node.select` with `action: deny` keeps agents on their Node, whichever tool or spelling would select another. Operations include file reads and writes, commands, Node and Session changes, history reads, Task changes, channel sends, secret use, MCP calls and model requests, with selectors for paths, Nodes, Sessions, Agents, Tasks, channels, secrets, MCP tools and models. Operation rules and existing rules can be mixed in one list; existing rules keep their meaning. The `access-control` skill describes them.
- When a rule needs a fact it can't establish, such as a Session that doesn't exist, the call is refused instead of reaching a default allow.
- Model requests made from a script are checked as `model.request`. An `ask` rule on the script itself asks once per script run, not for each request.
- One approval now covers a call and every other check of that call that asks, and the approval card lists them. A call that changes while it waits for approval is refused.
- `explain_tool_authorization`, now `ctl config explain-auth`, accepts a command, lists each operation of the call with the rule that decided it, and reports the parts it can't plan.
- Denial messages name the deciding rule, its layer and the command that was called.

### Android Node app

- The Android Node is now an app for Android 11 and later that connects a phone to your server as a Node. It replaces the experimental ADB bridge in the source tree.
- In **System → Nodes → New nodes → Android**, create a credential and scan the pairing code with the app. The WebUI also shows a code to download the app from [foxwarm.net/android](https://foxwarm.net/android).
- Through Android's accessibility service, agents can read the screen, take screenshots, tap, type, swipe, open apps, and wake or lock the phone. An optional setting on the phone, off by default, lets agents unlock it with a numeric PIN that never leaves the device.
- Release APKs are signed with the key whose certificate is listed on the installation page, so later releases update the app in place.

### Desktop apps

- A macOS desktop app for Apple Silicon is published as `foxwarm-desktop-osx-arm64.zip`, containing `Foxwarm.app`. It needs macOS 15 or later and isn't notarized.
- Both desktop apps and an installed PWA in window-controls-overlay mode draw their own window frame: the sidebar, tabs and window buttons share one title row, and only the workbench panes are cards.
- Links that open a new window within Foxwarm, such as **Move to new window**, Code in a new window or the Tasks and Logs pop-ups, now open as app windows instead of in the default browser. Other web pages still open in the browser.
- The Windows desktop app is compiled to native code and needs neither .NET nor the Visual C++ runtime.

### Native macOS and Windows packages

- `foxwarm-osx-arm64-native.tar.gz` and `foxwarm-win-x64-native.zip` are compiled to native code and need no .NET runtime. They are the installers' default, as on Linux. The framework-dependent packages remain.
- Server packages and the Windows desktop app now ship a LanceDB library and ToolScript worker built from pinned sources, which are smaller and need no Visual C++ runtime on Windows.
- Each package serves its WebUI and login resources from one compressed resource pack instead of loose files.

## Other changes

### Nodes

- **System → Nodes** can show the command that restarts an existing Node, issue a new token for a Node and disconnect the old one, and delete a Node together with the Nodes below it. Node clients of this version report how they were started, so the restart command matches it.
- Nodes started with the `/node` bootstrap command on Windows x64 and macOS arm64 now download the native Node client, as Linux x64 Nodes already did, instead of using the JavaScript client.
- Code on a Windows host or Windows Node lists every drive at `/`, and Code terminals open in drive folders.

### Tools and models

- `generate_image` in separate mode can use the OpenAI Images API: set `imageGeneration.api: images` and an `imageGeneration.model`. A failed image request is now an ordinary tool error and the turn continues. Usage records name the image model, and `imageGeneration.pricing` (`input`, `imageInput` and `output`, in USD per million tokens) prices these requests.
- Anthropic models with `webSearch` use Anthropic's hosted web search, with sources shown like those of other providers.
- A `run_script` call in `background` mode now waits up to `timeoutSecs` (15 seconds by default, at most 60). A script that finishes in time returns its result directly; otherwise the call returns its run ID, the script continues, and the Session is notified when it ends. `wait` accepts the run ID.
- Text redaction no longer treats placeholder-shaped text as a value to replace, and restores values that span Anthropic text blocks.
- Tool output, saved state and API responses show non-ASCII text as written instead of as `\u` escapes.
- `bot.httpHost` in `config.yaml` sets the address the server listens on, for example `127.0.0.1`. The default stays `0.0.0.0`.

### WebUI

- The sidebar gear opens Setup directly; its chevron opens the color-mode and application menu.
- When the **Needs your answer** section scrolls out of view, a button with the number of waiting Sessions brings it back.
- The Chat status line shows the latest reasoning heading or command summary in every timeline view and keeps it until new input or the end of the turn.
- Setup no longer stops working while you type a YAML alias in Models before its anchor exists.

### Fixes

- On Windows, a command no longer fails as it starts when another program has the exec registry file open.
- A cancelled browser call always reports cancellation.
- ToolScript keeps fractional numbers as ordinary floating-point values, which fixes a failure saving the results of script run tools.
