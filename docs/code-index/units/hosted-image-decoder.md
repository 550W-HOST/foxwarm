# Unit: Hosted native image decoder

Files: `dotnet/Foxwarm.ImageDecoder/`, `dotnet/Foxwarm/Images/DecoderProtocol.cs`, `dotnet/Foxwarm/Images/ImageDecoderProcess.cs`, `dotnet/Foxwarm/Images/DecoderAdmission.cs`, `dotnet/Foxwarm/Images/TenantImageDecoder.cs`, `dotnet/scripts/ImageDecoderQualification/`

The hosted Linux decoder is a one-request NativeAOT process. It links the [ordinary raster and HEIF codecs](./images.md); the replica owns blob and cache I/O, paths and Session identity. No decoder receives a tenant credential, a file name, or another tenant's media. Fixed-size binary headers carry the operation, dimensions and MIME identifiers. Results contain only selected metadata, bounded encoded output or a pass-through marker for the original input. The parent checks fields against the operation, checks the declared payload length before allocation, reads through EOF and requires successful process exit. Error codes select local copy; codec stdout is data and stderr is never forwarded.

`ImageDecoderProcess` starts the installed helper by absolute path with a fresh environment, two dedicated protocol pipes, and `/usr/bin/prlimit` hard ceilings: 1 GiB of virtual address space (before runtime startup), 10 CPU seconds, and no core dumps. Request and reply payloads are limited to 64 MiB. The 15-second wall deadline kills a worker even if it stops consuming the request or never finishes its reply. Parent cancellation also kills the child and reaps it before returning. The worker rejects a direct invocation without its resource ceilings. Size the replica’s memory allocation for Main and both simultaneous workers: per-process address-space limits do not reserve RAM or override a lower pod-wide OOM limit.

Before reading the request, the worker synchronizes NativeAOT finalizer startup, loads Skia, checks the optional pinned HEIF prerequisite for HEIF operations and installs a default-kill libseccomp allowlist on **all** threads. The filter requires no new privileges, permits read on stdin and write on stdout, anonymous private memory, local synchronization and signals within the current process. It forbids filesystem opens, socket operations, new tasks, exec, process inspection and file-backed mappings. HEIF uses the calling thread for tiles and runs the pinned libde265 without its worker pool. Its geometry, coded pixel and other existing native security limits still apply. The child exits directly after sending the response.

The `hosted` and `master-host` Docker targets package the helper beside Main; it uses Main's matching native Skia asset, libseccomp2 and util-linux. Desktop, Windows and file-mode packages require no helper. The optional HEIF libraries must be installed in the immutable application directory or the system loader's normal search path. Generic environment settings and the parent's library paths are not inherited. `ImageDecoderQualification` is a separate test executable; the hosted image CI runs it against the packaged worker with read-only mounts, no added capabilities and default Docker seccomp. Fault cases cover SIGSEGV, denied open/socket, address-space exhaustion, CPU exhaustion and hostile/truncated output, followed by valid decoding through the same parent.

## Routing and admission

The PostgreSQL-backed Session manager and each PostgreSQL Session authority bind their image stores to the database tenant ID. Both hosted profiles use the worker for raster/HEIF probes, HEIF validation/prerequisite checks, provider conversions and cache-hit probes, QQ byte identification and the complete crop operation. This also applies when the blob backend is S3. File stores keep the local codecs. Byte-first visual admission (32 MiB) and managed TIFF/BMP checks do not require the worker; a hosted operation that needs a codec has no local retry, including malformed or legacy inline images when the worker itself fails. Ordinary invalid-raster fallback remains caller-specific. The higher 64 MiB worker ceiling also bounds canonical probes and encoded crops, which bypass ordinary vision admission.

One admission queue per replica runs up to two workers, at most one for any tenant ID. Each eligible tenant appears once in FIFO order regardless of its backlog; when its slot returns, it rejoins at the tail if it has more work. A request waiting 15 seconds gets a busy error. A killed, unavailable or misbehaving worker fails that operation; the server records the reason without media data. Cache conversion coalescing stays per store. Independent authority and manager stores, including those of a retiring and replacement generation of one tenant, use the same tenant key.

`DecoderAdmissionTests` checks fair dispatch, cancellation, expiry and unavailable-worker refusal at canonical storage and legacy provider hydration. `TenantImageRoutesTests` runs on file and PostgreSQL stores, exercising a staged upload, provider variants including a cache hit, Session-owned cropping, QQ byte identification, and the hosted canonical input ceiling through both image owners. The managed hosted CI fixture stages the same NativeAOT executable beside the test host.
