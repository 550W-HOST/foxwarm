## Purpose and boundaries

A separate .NET 10 executable implements a headless CLI Node with file tools, persistent native exec for Session and external owners, and fixed Code filesystem/read-only Git and optional native terminal services, a loopback Session-event trigger and the client Session list/history/send API. It references the [small native primitive library](./dotnet-node-primitives.md), not the Main executable. The existing TypeScript CLI, interactive entry and bootstrap remain unchanged. This is not full CLI parity or a replacement bootstrap/delivery lane.

The implemented model tools are `read`, `write`, `edit`, `apply_patch`, `exec` and `get_default_cwd`. Capability definitions retain the corresponding TypeScript CLI descriptions and schemas. Implemented tools advertise `programmaticToolData`, `execWaitCancellation` and `remoteExecBackgroundRegistration`. Negotiated-v3 connections also advertise `externalToolOwner:1`. Fixed `vscode-fs:1` and `vscode-git:2` services are advertised separately. Code services are not advertised on platforms without the implemented native filesystem backend. Native `vscode-pty:1` is advertised only when its actual backend loads; missing optional PTY leaves file/Git/model/transfer services available. Browser tools and the interactive approval/history/send UI are not implemented or advertised by this executable. The Session client methods are an internal caller API, not a new model tool or HTTP command surface.

## Connection and state contract

- Explicit ID plus per-node auth token overrides an older credential file. Successful authenticated registration persists `{nodeId,authToken,pairedAt}`; Unix files are owner-only. Pairing approval saves credentials and reconnects after 250 ms. Ordinary reconnect waits five seconds.
- Invalid credentials clear the credential file and return to pairing only when a shared pairing token exists. Rejection or incompatible/malformed negotiation suppresses automatic reconnect. No token or credential-bearing WebSocket URL is logged.
- HTTP/HTTPS proxy lookup follows the existing lower-/upper-case and `npm_config_*`/`ALL_PROXY` precedence with `NO_PROXY`, including the WebSocket-to-HTTP scheme mapping. No implicit platform proxy is added. Proxy authentication uses the BCL challenge/response path.
- The receive loop remains active while file operations run. .NET's 30-second keepalive interval and ten-second PONG timeout detect a stale peer; this is the BCL heartbeat, not a claim of TypeScript timer scheduling identity.
- An operation can finish its filesystem effect after a connection is lost. It is not replayed, rolled back or allowed to answer through a newer connection. Main retains authorization, Session selection and response adoption.

## Loopback trigger and Session client API

The default listener binds only `127.0.0.1`, with OS-selected port zero unless `--local-trigger-port` supplies a valid port. `--no-local-trigger` skips both listener and artifacts. A minimal explicitly configured Kestrel host does not load ambient hosting endpoint configuration or own CLI signals. NodePrimitives has no HTTP framework dependency. Managed CLI execution now requires the ASP.NET Core shared framework as well as .NET Core; the Native AOT executable includes its reachable server components.

State lives beside the credential file, or in startup `state`. Existing `node_local_trigger_token` contents are trimmed and reused without chmod; a new random token is owner-read/write. Metadata `node_local_trigger.json` records the actual bound port, host, token/script paths and updated connected Node ID. The owner-executable `trigger-session-event.sh` keeps its original positional shell interface, output and success/failure exit behavior. Its new implementation re-enters the actual managed or native CLI executable before pairing or server startup, reads the existing metadata/token format and needs neither Python nor Node. Shutdown closes the listener but retains artifacts and token, as Source does.

Routing checks the normalized escaped pathname `/trigger` before method, then authentication before JSON. Dot-segment normalization can remove escaped segments; surviving escapes do not match the literal route. POST accepts case-sensitive Bearer authentication with the existing `x-node-trigger-token` fallback. Empty/missing fields return 400; malformed/null JSON and failed or unacknowledged delivery return 500; authorization returns 401. Session IDs use Source whitespace trimming, messages retain their original nonempty whitespace, and only `background`/`onboot` override the default `trigger`. Only Session ID, message and event type cross this HTTP boundary: arbitrary completion IDs, capabilities and timestamps do not.

Kestrel's application body cap and minimum data rates are disabled, and its receipt timeout is disabled once the body arrives. Header limits and timers use bounded Kestrel settings, not identical Source parser/header-collection or timer scheduling behavior. JSON diagnostics remain runtime-specific; valid Unicode is supported, but System.Text.Json rejects escaped lone-surrogate strings that JavaScript accepts.

Ordinary events wait for the existing 15-second correlated request/ACK; success means accepted admission, not completed model work. An empty event Session ID returns without sending. `ListBoundSessions` uses `session_list_request` and returns an empty array for a nonarray result; `GetSessionHistory` sends the supplied binary64 count unchanged, including fractional counts and indices; `SendSessionMessage` sends the existing trigger payload. These three calls retain ten-second deadlines. All pending calls propagate Main errors and reject on their exact connection's disconnect. No fallback, resend, durable outbox, Session creation or completion grant is added. Main retains current-Node/isolated-binding admission and exact durable Session ownership.

## Native file and transfer contract

Agent directories resolve against the captured process startup cwd, with `FOXWARM_AGENT_DIR`, then `FOXWARM_AGENTS_DIR`, then `agents/<agent>`. Relative file calls prefer the supplied Session cwd and otherwise that Agent directory. Canonical resolution removes trailing directory separators except at filesystem roots, matching native Source path resolution for tools and transfers. A leading `$fw_agentdir` or `$fw_tmp` expands only the supported Agent token; other leading names are rejected. `get_default_cwd` returns startup cwd, independently of file defaults.

The shared scanner/excerpt, exact-match and patch algorithms do not bring Main authorization, cached-write references or interpreter budgets into this wrapper. CLI content writes/edit/patch follow native content-write behavior, including final symlinks and partial effects. JS replacement-string tokens remain a CLI edit behavior; Main's exact replacement remains literal. Patch additions do not manufacture a trailing newline. Only complete successful calls return resolved-path sidecars.

Raster reads classify header signatures, not extensions, and return inline image bytes. Size is inspected before opening the raster header; zero-size entries, including a FIFO, follow Source's empty-file text result without opening. Ordinary read does not require a regular file. Programmatic text reads retain full content only within the existing bound and otherwise publish truncation/byte metadata. The directory result remains text, not a fabricated full-content record; nonregular entries are shown as `other`.

Whole-file transfer paths use Agent roots rather than Session cwd, preserve caller restriction flags, classify transfer MIME by extension and retain the existing checksum/receipt fields. Reads follow symlinks and reject nonregular targets before reading, unlike ordinary tool read. Trailing separators do not erase the transfer basename or extension metadata. Same-directory temporary-file publication replaces a final symlink on overwrite; no-overwrite publication does not replace an existing destination. Transfer publication is distinct from ordinary content writes and from Provider chunk operations.

## Fixed Code services

Authenticated Main backend requests use the existing `node_service_request` result/error framing; one-way commands emit the existing error event on failure. They do not enter model-tool approval, Agent path expansion or external-owner execution. Replies stay on the originating connection. Lost/ambiguous replies never retry an effect. Main retains service-version checks, administrator/capability authentication and exact remote namespace selection, without Master fallback.

`vscode-fs:1` implements stat, read-directory, binary read/write, create-directory, delete and rename with native absolute paths, strict Source boolean/base64 semantics and the inclusive 50 MiB boundary. It shares native mechanisms with Main Code, not Session file defaults or transfer publication. `vscode-git:2` implements bounded read-only status/content and immutable commit details, including root/first-parent comparisons, renames, binary/submodule metadata, full content refs and the existing file-count cap. Git remains an optional external executable; absence follows the real Source error/content behavior, never a shell substitute. Code URI/Windows drive adaptation stays in Main's existing `CodeNativePaths` wrapper; no new Windows runtime qualification is implied.

## Optional native PTYs and Code helper

`vscode-pty:1` implements create/list/get/attach/detach/input/resize/close/code-result and output/exit/code-request events through authenticated service transport, never model approval. It retains Source terminal records/IDs, shell override/environment, current-cwd reporting, size coercion and 200,000-character backlog. Radix strings accept only valid unsigned binary/octal/hex digits, retain finite binary64 rounding beyond 64 bits, and use the existing fallback for nonfinite values. Linux kernel dimensions retain node-pty's unsigned-short conversion while the record retains normalized dimensions; Main's separate native-size guards remain unchanged.

Received PTY operations keep wire order. Attachment queues its ready/backlog response under the output lock before live output. Input accepts an ordered native write queue, so a shell that stops reading cannot block later resize/close; close cancels IO before waiting/releasing the exact process. Process records survive disconnect/Main restart, but streaming and pending helper results bind the actual connection generation. Transport loss is not exit; natural exit and explicit close/shutdown clean owned terminal capabilities/files/processes. Independent persistent exec is neither adopted nor killed.

The node-local `code` launcher enters the shared same-executable helper before pairing/startup in managed and native builds. It carries only its random terminal capability, cwd and argument vector. Source path/line/column/open semantics stay local; one authenticated Main control owner handles the existing request/result transport. Missing owners, timeout, detach, disconnect, terminal close and late replies retain their real settlement boundaries. Main/browser authentication and ownership remain in Main, not a new control channel.

## Persistent Session exec

The CLI owns `<Agent>/.temp/exec/running-exec.json` with `execs` and bounded `recentExecIds`; it does not import Main's `LocalExecManager` or Provider registry. Current petnames and historical `exec_...` identities, native records without a backend, original owner/Node/capability, artifact paths and recovery fields remain readable. Recovery scans only CLI Agent roots after compatible authenticated registration. Recovered foreground records become notified/recovered records; commands are never replayed.

Exec prepares the real Agent tmp directory before resolving and validating cwd, including a first call with `$fw_tmp` or `$fw_agentdir`; it does not create arbitrary caller cwd paths. Exec cwd follows the supplied Session cwd, then Node process cwd, independently of file-tool Agent defaults. Launch inherits the process environment, removes the actual reserved Agent variable names (case-insensitive on Windows), then sets current Agent values and native wrapper fields. Date-co-located Bash/PowerShell wrappers own merged output, final cwd and exit status. New Unix wrappers relaunch the actual managed or native CLI executable for launch and JSON sidecars. Existing Source wrappers retain their original Node interpreter dependency until they finish; recovery does not rewrite them.

The final prelaunch fence rejects cancellation before an effect. After the actual start hook, timeout/Stop ends only that call's wait, not the detached command. Native status is inspected before Stop at each observation. Background registration precedes the ordinary tool response; the grant and exact ID persist in the same registry. Launch/registry persistence keep Source's existing uncertain window without replay, rollback or transaction machinery. Normal shutdown drains observers and persistence without killing detached commands.

Completion uses the existing [acknowledged Session-event contract](../threads/node-communication.md#d-node-thread-remote-exec-completion). Rejected, disconnected or missing ACKs retain retryable tracking; removal follows accepted completion. The strict tracking retention boundary remains [shared persistent exec](./shared-persistent-exec.md#d-persistent-exec-completion-event-retention), without command termination or artifact deletion. Foreground logs use bounded display and native process facts; programmatic content is the retained raw byte snapshot within the inclusive 1 MiB limit, not parsed display text. This Session protocol does not add external-owner cwd/result-retention metadata; Main still controls exact-current-Node cwd forwarding.

## External owners

The external receiver accepts only negotiated-v3, exact `{kind:"external",externalId,contextId}` owners and the six available tools. Presence of `sessionId` or `agentName`, including null values, is a mixed owner and fails before effect. There is no synthetic Session, Agent root or filesystem sandbox. Files resolve against the supplied external cwd, then Node startup cwd; leading home expansion and unsupported Agent-variable errors follow Source. Exec inherits ordinary environment values but strips reserved Agent variables without replacing them.

Main supplies the exact reserved petname and nonempty signed completion capability. Node retains the original external identity, context, Node and grant; Main alone validates signatures, policy, selected-context generations and result admission. External background notices, completion request/ACKs and result queries are separate from Session events. Source external receivers do not forward the Session programmatic flag or resolved-path collector; these calls retain native image/structured results and exec ownership/cwd fields, without manufacturing Session-only capture fields. Session programmatic capture remains unchanged.

The actual per-owner namespace is `<Node state>/external-exec/<SHA256(externalId)>/<contextId>`: `running.json` owns tracking and `logs/<date>` owns native artifacts. Node state is the credential file's parent, or startup `state`. Startup Session recovery never scans these directories. Result queries consult only live process-local runtimes and cannot initialize one. A later real exec can initialize its exact retained namespace through Source's on-demand load path; this is not durable Main context reconstruction or automatic recovery authority.

Each runtime keeps twenty completed outputs in insertion order; replacing a retained key does not move its insertion order. This is retention, not an execution quota. Released contexts reject later execs and queries, clear completed results and keep the first release's one-hour tombstone. Ordinary file calls do not acquire a new client-wide release restriction. Release never kills or replays a command. Cleanup waits for in-flight calls and tracked work to settle; tracking expired without a confirmed exit marks the namespace uncertain and retains its artifacts. Rejected, missing or disconnected completion ACKs retain tracking for retry until acceptance or the existing strict 24-hour expiry. External calls do not inherit Session Stop controllers. A connection loss does not cancel their command; direct replies still use their originating .NET connection, while completion requests use the current authenticated connection. External shutdown drains manager observers and persistence without waiting for a foreground timeout or injecting Session Stop.

## Validation and limits

`CliNodeFileTests` and the protocol/file process fixtures cover native paths, replacement/patch ownership, transfer publication, images/programmatic data, credentials/pairing/proxy/heartbeat and exact old-connection effects. Normal Source and C# Main fixtures exercise actual file/model/transfer/image callers and peer restarts.

`CliNodeExecTests` and the Session/external process fixtures cover prelaunch cancellation, uncertain persistence, output/status, current cwd, exact signed reservations, ACK rejection/retry, expiry, release and shutdown. Normal inbound-MCP and Main/model fixtures exercise real external/Session owners rather than a synthetic model service. Existing Source wrappers can finish under their original interpreter; recovery never replays their commands.

Code and PTY fixtures compare real Source/managed/native filesystem/Git/terminal services, errors/limits, actual shells, sizing, blocked input, ordered attachment/output and same-executable Code helper IPC. Normal Main/original-App/official-terminal fixtures cover control ownership, fanout, detach/reattach, same-PID rediscovery after Main restart and list/create races. Optional-backend absence keeps independent file/model/transfer behavior available. Windows-guarded code compiling is not Windows runtime qualification.

`dotnetCliNodeTrigger.e2e.mjs` compares actual Source/managed/native route/method/auth/body handling, whitespace/event mapping, ignored completion metadata, duplicate/nested JSON and a body beyond Kestrel's default cap. It exercises real generated shell helpers, ACK/rejection/timeout/disconnect, selected-port metadata, disabled startup and persisted Source tokens. `CliNodeSessionClientTests` calls the API through an owned WebSocket peer for out-of-order correlation, shapes, deadlines and disconnect. `NodeSessionRequestTests` also calls that client against Main's actual catalog/alias, cold-owner, fractional-history and ordinary ingress paths for current-Node and bound-Agent scope. Headless native trigger/helper execution does not imply that otherwise unreferenced interactive API methods survive AOT trimming.

Both new projects enable trim/AOT analysis; the executable disables reflection-based JSON serialization and enables single-file analysis. Protocol boundaries use explicit JSON values. Analyzer builds alone do not establish native delivery. The actual expanded Linux x64 Native AOT executable, loopback listener and same-executable trigger/Code helpers have run in a masked-.NET Ubuntu 24.04/glibc 2.39 container. The executable is dynamically linked and retains compiler/system-library requirements, including floating-point remainder; it does not promise the earlier file-only graph's older glibc compatibility. Windows has an implemented but unqualified PowerShell path; exec is not advertised on other platforms. Complete CLI parity, browser/UI work, packaging and bootstrap replacement remain separate work.
