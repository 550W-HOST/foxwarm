## Purpose and contracts

The plain-module Chrome and Firefox MV3 extensions supply the cooperative shared-browser product defined by the [Browser Node module](../modules/browser-node.md). Short tool names are self-advertised on the existing Node connection; there is no compatibility alias. Runtime packaging selects a small browser-specific page driver; transport, sharing, DOM helpers and popup remain shared.

## File responsibilities

- `manifest.json`: Chrome 120+ manifest minimum, qualified with Chrome 145 on Linux; tabs/debugger/webNavigation/storage/notifications/alarms, module worker and popup. No host grants, activeTab or scripting driver.
- `manifest.firefox.json`: Firefox 153+ module background scripts, scripting/webNavigation/storage/tabs/alarms, broad `<all_urls>` host access and optional-only userScripts. It has neither debugger nor notifications permission.
- `pageDriver.js`: Chrome source/default entry; Firefox runtime packaging replaces its re-export with `firefox.js`.
- `firefox.js`: document-ID-targeted isolated DOM injection and MAIN user-script execution, explicit-tab capture, page identities, cancellation fencing and navigation commit observation. Rejects editing keys and supplies browser-specific DOM-input descriptions.
- `storage.js`: serialized connection/site writes in local storage and live tab/window sharing in session storage. Main normalization preserves deployment paths. Credential installation checks current target and enabled intent.
- `permissions.js`: one synchronous observation-based tab/site/window/Off resolver, with an async current-tab wrapper, transient Ask requests, full action previews, expiry/cancellation and async validation on Allow. Chrome notifications draw attention to the popup; closing one denies the pending request. Firefox uses a pending-count action badge and never interprets presentation failure as denial.
- `main.js`: local popup dispatch, reconnect wakeups and tab/window lifecycle invalidation. Rule changes cancel all in-flight targetless tab listings as well as affected targeted calls/confirmations; losing sharing detaches its page.
- `websocket.js`: exact-socket pairing/authentication, persisted-enabled admission, bounded heartbeat/reconnect, up to 32 active calls, per-call deadlines/abort signals and correlated `tool_call_cancel`. Stop aborts pending work, closes the socket and detaches. Late replies never move to a new socket or changed Main.
- `tools.js`: exact approved schemas/copy, metadata authorized from the same final tab-query observation without later asynchronous per-ID policy lookups, tab/window admission, document capture before the per-tab ordering lane, Ask and execution/result checks. `open_tab` requires a shared destination window and creates inactive; closing a last tab can close its window.
- `cdp.js`: one tab-targeted Page/Runtime/Input adapter, retained attachments, isolated-world DOM helpers, page identities, screenshots and supported input. It never activates windows, retries actions or exposes arbitrary CDP commands. Unexpected detach stops connection intent.
- `pageFunctions.js`: bounded DOM snapshot/text/HTML extraction with password omission, current-snapshot element maps, unique selector checks, focus/select/scroll helpers and fixed wait conditions. Old refs are not reconstructed.
- `toolResults.js`: current structured PNG `inlineData` envelope consumed by the established Main image path.
- `popup/*`: Main setup, Stop/Forget, tabs grouped by window, explicit Off/Ask/Auto and Clear-to-inherit, persistent site editing and actual Agent/Session/page/action approval cards. Fill previews mask entered text.

## Page operations

Snapshots return at most 400 visible semantic/interactive elements with opaque references from the latest snapshot; text/HTML and explicit JS results are bounded. Reference and selector operations target the top document. Selectors must match exactly one element. Coordinate clicks bind to a screenshot page identity and use viewport CSS pixels. Chrome native CDP mouse/text/editing-key input is tab-targeted. Firefox uses coordinate-bearing synthetic DOM click activation and DOM value setters and synthetic input/change events, without trusted input or editing-key emulation. Fill accepts text/search/email/url/tel/password/number inputs, textarea and contenteditable; other input types fail before focus/selection. Select and scroll use fixed DOM helpers. `wait_for` exposes element visible/hidden/attached, visible text and exact URL conditions within the remaining call deadline. JavaScript uses page context and awaits Promises under CSP; it remains privileged page access. Firefox requires the current optional userScripts permission, injects source directly in MAIN without eval/Function and targets the admitted document ID. It does not relax CSP or expose extension APIs.

An exact active call marks its accepted navigation/close effect immediately at the browser command boundary. URL events preserve only that dispatched effect, while canceling pending Ask/queued work and invalidating refs. Completed mouse/key input returns its boolean outcome without old-document data, including when it follows a link. A move, revocation, Stop, deadline or command failure remains an interruption. When accepted navigation ends sharing, detach is deferred only until that exact call settles; the unshared destination's metadata is not returned. No action is replayed.

Navigation waits for the requested document commit, then resolves sharing before reporting the resulting identity. Navigation can intentionally end sharing; no destination content is released in that case. Ordinary calls keep identity checks internal; stale targets fail and require a fresh snapshot/screenshot.

## Connection and packaging integration

Pairing and authenticated registration retain the shared core Node protocol range 1–2 and omitted-protocol legacy response reader; this is shared transport compatibility, not old Browser configuration migration. Approved pairing discards the bootstrap token. JSON ping every 25 seconds is answered by current C# Main; reconnect alarms respect disabled intent. No self-port keepalive exists. Main transport uses only a WebSocket, without cross-origin fetch/XHR. Browser-specific page drivers remain separate from that transport. The Chrome package needs no broad host grants. Firefox requires `<all_urls>` for capture/injection; extension sharing remains independent and enforced.

The C# publish carries extension assets through `Delivery.targets`; `NodeBootstrap` assembles credential-free browser-specific ZIPs from those runtime files: the existing Chrome URL remains default, while `/node/browser-extension-firefox.zip` selects the Firefox manifest/driver and excludes CDP. Each archive excludes the other browser’s implementation. Authenticated `NodeRoutes` Browser setup returns the normalized Main address and private pairing token. Production `NodeOnboardingModal` exposes browser selection/download, Chrome load-unpacked/debugger guidance or Firefox temporary-install/permission/DOM-input/badge guidance, then common pair/approve/share steps. Deployment-relative URLs preserve non-root mounts. These C# and UI files remain owned by their existing units.
