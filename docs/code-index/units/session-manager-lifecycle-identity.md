# Unit: Session manager lifecycle, deletion, and identity moves

## Purpose

Coordinates create/fork/clear/delete, deletion claims, canonical identity moves, artifact journals, recovery evidence, and lifecycle gate ownership.

## Stable methods and callers

Lifecycle methods claim exact identity/deletion gates before changing owner/store/catalog. Identity move validates Archive reservation/ledger evidence, renames bound artifacts, rebinds save-lane/store identity, and publishes aliases only after committed evidence. Identity move and deletion invalidate the owner-scoped [outbound MCP bindings](./mcp.md#connection-and-cancellation-contract). Delete drains/cancels runtime work, removes active authority/catalog artifacts in declared order, and reports partial cleanup without rewriting immutable Archive history.

## Contract and side effects

Concurrent create/delete/move/queue/busy races resolve through manager claims, not catalog guesses. A registered runner carries a transient exact-entry execution scope through settlement. During host closure, that scope permits its own committed tool/cwd settlement on the ordinary mutation/save lane without reopening processing admission. It is not a long-held mutation lease: normal deletion can still claim a busy target and send Stop before waiting for its owner, and unrelated/new callers remain rejected. Pending/ambiguous identity evidence fails startup or operation closed; historical aliases remain read-only. A post-rename/post-authority failure is reported as committed/partial, never silently compensated by deleting pre-existing Archive rows.

`RetireDeletionOwnerAsync` shares the ordered owner/save-lane retirement primitives with failed channel-candidate compensation. The latter has its own unused-candidate policy and does not enter general exec-tracking cleanup; see [external channels](./dotnet-external-channels.md#admission-commands-and-persistence). Post-retirement candidate-cleanup failures retain the same exact-owner partial-delete receipt and completed stages used by explicit deletion, permitting the existing null-source same-host manual continuation. That continuation uses ordinary retained-Archive deletion, not creation rollback. Explicit `DeleteAsync` retains its existing captured-queue removal, busy Stop/retry, partial deletion and retained-Archive behavior.

Completed deletion removes every resident identity-slot key for the exact deleted lifetime, including historical keys retained by real identity moves. While retirement or cleanup is still pending, those keys keep the same unavailable fence; a partial cleanup failure does not become not-found. After completion, ordinary live history/state and Session-message tools return not-found immediately through old, intermediate and current IDs. Archive records, alias reservations and the historical write/reuse prohibition remain intact.

`MoveIdentityAsync` retains ordinary cross-Agent isolation restrictions. Authorized `create_agent(convertSession=true)` instead enters the same private `RenameIdentityAsync` owner with Agent-conversion purpose: the caller must remain nonisolated, but an explicitly selected isolated source is permitted, matching Source's direct identity-rename caller. This purpose is not a tool argument. Both callers retain identity authority, Agent admission, target reservation, save-lane/journal ordering, aliases, child and channel rewrites, settings preservation, and existing committed/rollback failure fences. Optional target isolation runs afterward through the existing Agent settings owner; conversion alone preserves the source's raw current Node, not its old Agent's isolation metadata.

Bare `/fork` uses the ordinary local-date/base-36 generator as its child-style suffix; `/session fork` and the WebUI fork API keep the literal default `fork` and append-style allocation. Explicit suffixes retain their existing numeric collision rules. New derived leaf names are validated without restricting reads of persisted legacy identities.

Manual `ForkAsync` and `/fork` share inherited context and exact parent lineage, but do not create a delegated completion duty. The command retains child-style name allocation and sends its initial instruction through ordinary `QueueItem.UserText` ingress before the existing passive parent notice. `CreateChildAsync` retains delegated/task completion contracts. Fork suffixes no longer append a synthetic assistant acknowledgment; copied historical rows, including old acknowledgments, remain unchanged. Fork capture, Archive caps, publication and partial-create receipts still use their original owner/save-lane paths.

## Agent deletion callers

`DeleteAgentFromCommandAsync` snapshots canonical catalog keys with the requested Agent's literal ID prefix, not metadata ownership, aliases or hydrated owners. It permits attached/current targets and retains incoming inheritance and raw surviving-child parents. Each selected lifetime uses the existing deletion claims, retirement/storage stages and exact same-host partial receipt. Busy command targets receive Stop and captured-queue removal, then settle in the same request before retirement; no independent process is killed. The captured turn scope can finish its own mutations while this command claim is settling, but new callers remain fenced and retirement closes that scope's authority. Ordinary `DeleteAsync` source/self, attachment, busy Stop/retry, child detach and typed partial policies are unchanged; retries cannot switch caller policy.

`DeleteAgentAsync` serves the original WebUI Agent DELETE route. It protects main, checks incoming inheritance from all metadata (including orphan entries), and preflights metadata-owned catalog members for busy state and exact non-WebUI bindings without hydrating cold owners. It sequentially calls coordinated nonrecursive `DeleteAsync` with no source owner, retains the final metadata-membership check and returns the actual canonical deleted IDs. Other-Agent descendants are not expanded into either caller's selection.

Canonical WebUI folder cleanup writes Agent metadata only when its own row was removed; an absent row is a no-op even if the metadata path is unwritable. Retained-layout cleanup still persists its membership envelope without an own metadata row. Genuine metadata-write failures retain the existing post-directory partial effects. Independently scheduled [timer clocks](./tasks-timers.md) do not inherit the originating turn's command-settlement authority.

Removal owns only the named Agent's process-local membership admission. Create/child/fork and identity-move paths join their affected Agents before changing membership; removal closes new admission and awaits accepted relevant work before selection. It does not await foreground under the lifecycle monitor or serialize unrelated Agents. New members are not silently added to the selection. A non-main metadata-owned survivor outside the command prefix keeps its folder with a truthful failure after any earlier deletions. Canonical main's unprefixed survivors remain intentional. Folder cleanup retains Archive, branches and ID reservations, and neither caller promises rollback, cross-process exclusion or durable Agent deletion jobs.
