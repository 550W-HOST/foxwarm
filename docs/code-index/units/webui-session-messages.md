## Purpose and symbols

- `receivedSessionCommunication` reads the single first-party `foxwarm-message` system part of an input, beside other system parts such as a first input's Session tag. It recognizes inter-agent and Task envelopes, retains the decoded source ID (or `origin: 'user'` for a user-sourced Task notice), removes only the outer wrapper and, for Task envelopes, takes the recipient role from `recipient` or, on older envelopes, from the event and trusted hint. Notices to a previous owner return nothing and stay in Activity.
- `projectSessionCommunications` derives ordered outgoing deliveries from paired successful send calls, UI-only delivery lists on responses, subcall lists (or the older single record of a completed subcall) and a background finish event's message-level list (`origin: 'background'`). Task records carry `task`; previous-owner records are kept as evidence but not shown. It never parses stdout, rewrites history or sends messages.
- `SessionMessageCard` renders direction, peer identity and the shared sanitized Markdown body in a distinct semantic card. A Task card adds a Task icon, `taskEventLabel` and, when App supplies `TaskLinkContext`, a Task ID control that opens Tasks with that Task selected (`TasksView` `focus`); the scoped identity root supplies none. User-sourced notices read From you; background finish records add From a background run. `taskMessageLayout` reads the Task title for the header and the text after the generated lead lines; the card renders that text through `renderPreview` while collapsed, always offers expansion then, and renders the full body when expanded or revealed by Search. `SessionMessageNamesContext` receives only already-loaded names from App. Unresolved legacy boundary aliases are not navigable destinations.

Conversation defaults to cards outside Activity and indexes their rendered body once. Disabling Show inter-agent messages renders both directions inside expanded Activity, retaining native call/result evidence and metadata-backed delivery bodies without Search hits. Cards share tool-result three-line clamping, actual-overflow fades and native thread-card height transitions; expansion and transient Search reveal show the full available body without altering history. Technical source records remain available in process details. Canonical behavior: [Session communication presentation](../threads/session-communication-presentation.md).

`sessionCommunications.test.mjs` covers Task envelopes in any attribute order, recipient roles with the older hint fallback, user-sourced notices, the first input beside the Session tag and every delivery-list source. `conversationActivity.test.mjs` counts recorded deliveries. `mainHostTaskCards.e2e.mjs` runs a real Main with the coordinator workflow and checks Task cards in Conversation, Search, the switch, the Task link and a first-message From card. `conversationDisplaySettings.e2e.mjs` covers the actual Chat menu, browser preference synchronization, standalone/folded bodies and full-body disclosure. Its detached-reading probe starts inside an expanded delivery and awaits completed native wheel movement before streaming/resizing: the follow button confirms intent, not movement. It checks native position through resize correction frames and explicit bottom rejoin.
