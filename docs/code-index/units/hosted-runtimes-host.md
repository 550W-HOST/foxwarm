## Purpose

A P2 replica serves many tenants behind one front. This unit owns where a tenant may run (placement and eligibility at acquisition) and the replica process that hosts tenant runtimes as generations of the activation coordinator. Leases, renewal, fences and generations are [hosted runtime](./hosted-runtime.md); the tenant server the front dispatches to is [D-hosted-tenant-server](./hosted-runtime.md#d-hosted-tenant-server).

## D-hosted-placement

**Plan §3.3 (P2), coordinator-confirmed.** Placement ranks; the lease decides.

- **Rank.** `Placement.Score(slug, name)` is the first 8 bytes of SHA-256 over the slug, a zero byte and the replica's logical name, as an unsigned big-endian integer; `Rank` orders names by descending score, ties by name. `Candidates` takes the live boots (`ReplicaRegistry.LiveAsync`), counts two boots of one logical name as the older one, drops draining replicas and those whose role may not serve the tenant, then applies the capacity filter, which only ever concerns new placement.
- **Eligibility at acquisition.** `TenantLease` carries the acquiring replica's role. Both eligibility reads (before and under the row lock) check `ReplicaRoles.MayServe(role, profile, pinned_role)`: a general replica takes only unpinned `hosted` tenants, the master host only `operator`-profile tenants (Q8: a pin alone isn't enough), the operator surface none. A refusal is `TenantNotEligibleException`, a definite decline that leaves the lease untouched; another replica may take the tenant.
- **The checked profile.** The acquisition returns the profile it read under the row lock in `LeaseGrant.Profile`, and the runtime is built for that profile (`ActivationContext.Grant`, then `BuildRuntimeAsync(profile)`): capabilities are `RuntimeCapabilities.For(profile, deployment.Egress)`. Production builders never re-read the tenant row.
- **Role source.** A replica's role is the bootstrap variable `FOXWARM_ROLE` (`general` by default, `master-host` or `operator`; anything else is a bootstrap error). The single-tenant replica and the runtimes host both acquire and register with it; a single-tenant replica whose one tenant its role may not serve exits with `HostedExit.Configuration`.
- **Edits are ordered against grants (migration 0004).** A `BEFORE UPDATE OF profile, pinned_role` trigger on `tenants` (SECURITY DEFINER) locks the tenant's lease row `FOR NO KEY UPDATE`, the row an acquisition locks before its eligibility read. An edit waits for a grant in flight, and an acquisition that starts during an edit waits and reads the edit's result; every writer is covered, direct operator SQL included.
- **A committed change retires the generation.** The replica's `foxwarm_tenants` handler (and every resubscription) compares its published grants with the stored profile and pin; a mismatch, or a placement its role may no longer serve, retires that generation and releases its grant once the stop is confirmed (`TenantActivations.RetireForPlacementAsync`), so the next activation acquires under the new eligibility.

## D-hosted-runtimes-host

**Plan §2.1 (P2), coordinator-confirmed; transitional selection.** `TenantReplica` is the multi-tenant replica: one front, many tenant runtimes, each a generation of `TenantActivations`.

- **Selection.** `FOXWARM_HOSTED_TOPOLOGY=tenants`, read only in `HostedEntry.RunAsync`. Without it a process runs P1's single-tenant `HostedReplica`. The variable is transitional: no chart, Compose file or user doc sets it, and it is removed when forwarding replaces the single-tenant replica (plan §12.1).
- **Start and settlement.** A tenant runtime's start is awaited whole (`IGenerationRuntime.StartAsync` never cancels only the wait): a fence or shutdown during the start disposes the runtime only after the start ended, and the pre-armed supervisor bounds it.
- **Shutdown accounting.** Shutdown is clean only when every activation it snapshotted ended, every generation known then or later recorded a confirmed stop, and no acquisition's outcome is unknown (`UncertainUntil`, a TTL after an acquisition failed other than by a definite decline). Acquisitions aren't cancelled by shutdown; a grant acknowledged after shutdown began is handed back with a bounded release. A failed stop stays in the slot's `Retiring` before the generation leaves `Building`.
- **Composition.** After the schema check the replica opens the control and renewal data sources, the `GrantRenewer`, the `FenceSupervisor` (exit through `Environment.Exit`) and `TenantActivations` with the replica's role and one shutdown bound, then registers its boot. Each generation gets a `TenantDb` with the statement cap, attached to the generation's fence, and a `TenantServer` with the tenant's public origin (the deployment `url` with `{slug}`). `HostedEntry.CreateTenantRuntimeAsync` builds the production runtime through `BuildRuntimeAsync` with its scratch directory (and the host's Agents directory inside it) under `t/<tenant id>`: the numeric ID, never the stored name. Persisted layouts keyed by name (blob prefixes) are unchanged. A stored name that fails the slug rule (`TenantSlugs`, grandfathered names) is refused before anything is built, with a log line naming the tenant ID.
- **Public URL.** The deployment `url` may be a template with `{slug}`; bootstrap validates its expansion. `DeploymentConfiguration.ForTenant(slug)` gives each tenant one expanded configuration, which the host, Node routes and model configuration read, and `TenantOrigin(slug)` is the same origin for its `TenantServer`. A literal `url` (single-tenant replicas) is unchanged.
- **Shutdown route.** A tenant runtime behind the front can't stop the process: `POST /admin/shutdown` answers 403 "Shutting down isn't available in this deployment." (`HttpServerSettings.ShutdownAvailable`). The single-tenant replica keeps the route.
- **Dispatch.** The front resolves `Host` through `tenant_hostnames` (`HostnameDirectory`) and admits the request into the tenant's published generation; the admission is held until dispatch completes. A host with no tenant gets a bare 404. Every activation failure (acquisition, build, start; held elsewhere, not eligible, fenced) is a bare 503 with no tenant data and its cause in the replica's log; dispatch failures and client aborts are the tenant pipeline's. Forwarding replaces the 503 for tenants held elsewhere.
- **Hostname cache.** Entries live 30 s. `NOTIFY foxwarm_tenants` and every resubscription start a new generation; a lookup that began in an older one is repeated, never cached or trusted. Expired entries are evicted, and at most 1,024 unknown hosts are remembered.
- **Operator documents.** One `LISTEN` connection (`foxwarm-listen`) subscribes to `foxwarm_operator` and `foxwarm_tenants`. Every subscription and resubscription invalidates as a notification does, since a change made while the connection was down notified nobody. Invalidation applies the injected callback to every started runtime, one callback at a time per runtime and coalesced; a change during the build or start is recorded and applied when the start ends. Retirement stops further callbacks and waits for a running one before the runtime is disposed; no callback runs under a replica or lease lock.
- **Health.** `/livez`, `/readyz` (serving) and `/status` (role, state, replica, published tenant count), with no tenant names.
- **Stop.** A graceful stop runs `ShutdownAsync` (parallel retirement under one bound), then stops the front. The exit is `Stopped` when every stop was confirmed and `Fenced` otherwise; the boot row is removed only after a confirmed stop.
- **Not yet.** Tenant runtimes report themselves never idle, so idle release releases nothing until runtimes report busy work and wake-ups. There is no forwarding or mesh, no placement-driven acquisition (a replica activates whatever it is asked for, subject to eligibility), and the operator-document callback is a seam: production passes none until the ceiling entry point lands.

## Tests

  `TenantReplicaTests` runs the runtimes host in process over real lease rows with small runtimes: activation on the first request and routing by `Host`, a tenant held elsewhere refused without data, a takeover fencing only its tenant, operator-document invalidation on notification and on resubscription after the listener's backend is terminated, and a graceful stop that releases every tenant.

  4b adds: a fence and a SIGTERM during a gated start (disposal only after the start ended), a profile change retiring and releasing the tenant, a legacy name refused before any build, an arbitrary factory failure answered 503 and logged, a change during a gated start applied once, retirement waiting for a running callback, and a change committed while this database's listener backend was terminated reaching the runtime after reconnect. `TenantActivationsTests` adds shutdown with an acquisition waiting on its row lock (not clean; the late grant handed back) and with a build whose cleanup fails. `TenantRuntimeConstructionTests` builds production runtimes: two tenants' expanded URLs, numeric directories, and the profile refusal. `HostnameDirectoryTests`, `HostedSetupCleanupTests`, the URL-template parse test and the shutdown-route test behind the front cover the rest.

  `ReplicaProcessTests` runs real replica processes through `ReplicaProcessHarness` (`dotnet Foxwarm.dll`, a `PgTcpProxy` per replica, `DOTNET_GCHeapHardLimit`, kill and SIGTERM, `/status`): a killed replica's tenant moves only after expiry at the next epoch, SIGTERM releases every tenant (raw rows `released`) for an immediate takeover, and a partitioned owner retires the tenant (its `/status` count or its fenced exit) before the expiry and refuses it across it. The successor is probed throughout, and its `acquired_at` is compared with the old `expires_at` on the database clock.

  `PlacementTests` covers the rank's stability and order, candidate filtering (role, drain, duplicate logical name, capacity), Q8's master-host rule, acquisition by role and profile with the profile carried in the grant, the placement edit serialized against an in-flight grant in both orders, and the registry's live boots.
