## Purpose

Discovers concrete tools, projects model definitions, applies output/control policies, and executes Session-local tools for memory/knowledge, observation, waits, settings, timers, compaction, and ToolScript.

The [external Session runtime](./session-claude-runtime.md) adds an exact-run pre-effect support guard to the ordinary attributed executor. Runtime discovery projects handoff enums/copy without changing canonical definitions; resolved aliases and `argsJson` remain subject to execution checks. Independent unattended work keeps its existing executor lifetime.

## Stable methods and callers

- `ToolRegistry` combines builtins, MCP, provider-hosted definitions, and permitted Node capabilities into one discovered set with stable names/schemas.
- `UnifiedToolDefinitions`/`UnifiedTools.Schema` publish model-facing JSON; `UnifiedTools` resolves calls and carries Session/agent/request scope into execution.
- `SessionToolExecutor` dispatches definitions, commits observation/memory/wait/settings/timer/compact changes through SessionManager/save-lane APIs, and returns source JSON values with separately typed trusted receipts; the `session` tool resolves targeted status through the real Main owner and applies parent changes through catalog presentation mutation; its ToolScript partial bridges to MainToolScript. The default-hidden `set_agent_isolated` binds/clears existing Agent Node metadata and updates legacy exact rules through the established Agent tool executor. Advertised external tools use current or explicit Node capability snapshots from the [external Node unit](./external-nodes.md); builtin name collisions stay source-qualified, and external exec uses the [remote exec authority unit](./remote-exec.md). Executable provider exec instead joins the existing [persistent local/provider owner](./tools-local-io.md#provider-exec), carrying exact-Node cwd through normal and deferred Session save-lane updates. Copy, image export/delivery and remote source use the [file consumers unit](./external-node-files.md), preserving their distinct builtin and path identities.
- `ToolCallControls`, `ToolOutputGuard`, `BoundedTextExcerpt`, and `ToolResponseFormatting` enforce call ordering, size/truncation, status/error envelopes, and provider-visible output boundaries.

## Contract and side effects

Definition discovery is not authorization: execution calls `ToolAuthorizationEvaluation` before local/MCP/Node effects. Tools that change Session state use owner/save-lane boundaries; a model-visible success is not emitted before the underlying operation reports its committed/accepted outcome. Ordinary foreground dispatch also rechecks the exact runner's closure after awaited authorization. An independently accepted [scheduled script slice](./tasks-timers.md#owner-bound-toolscript-timers) has its own dispatcher and no foreground projection, cancellation or batch post-action consumer; it still uses the normal authorization and tool effects. Unstarted calls receive an explicit not-executed shutdown result; launched calls retain real successful results or an after-dispatch cancellation uncertainty, and complete batches pair before terminal control is adopted. Provider-hosted tools remain provider-scoped. JSON source values and model/history projection follow [the cross-module tool contract](../threads/tools-permissions-and-exec.md#outbound-mcp-values-and-trusted-control).

The [Main browser registrations](./browser-host.md#hosting) return the host's structured results, including to native ToolScript; they stay discoverable but default-hidden, are registered only when the host reports itself available, and are filtered from discovery otherwise. The registry retains existing object-only registration callers through a value adapter, without general output unwrapping. `ToolRegistry.ExecuteAsync` returns the natural directory listing string only for a programmatic Main-local `node`/`master`/`read` result with its directory-only output shape. Ordinary model display remains wrapped; file data/metadata, images, remote Node values and unrelated builtin/MCP JSON are not unwrapped.

Creation tool inputs and prospective model/effort selection are owned by [Session creation operations](./session-manager-operations.md). `create_session` advertises parent, Node and prompt-file selection; `create_child_session` advertises its child Node override without turning it into tool execution placement. These inputs reach the ordinary creation owner rather than being schema-only options. `create_agent` likewise connects its memory-copy/source/conversion/isolation/rule options to the existing lifecycle and metadata owners, and `refresh_session_snapshot` accepts an explicit target; their defaults, precedence and failure effects are governed by the same operations unit.

The discoverable hidden `mcp_notifications` and default-injected `send_to_channel` use the real Session owner, concrete authorization and the existing direct/unified/native ToolScript execution paths; their reception and text delivery lifetimes are owned by [Session notifications and text channels](./dotnet-mcp-notifications.md). Successful channel sends use ordinary tool/subcall presentation, not Session handoff receipts.

The discoverable hidden `node_remove` builtin shares the existing credential revocation/disconnection owner without Provider or environment effects; the [external Node unit](./external-nodes.md) owns its commit/failure contract. ToolScript starter resolution uses its root `node` only as file-source/authorization selection, not VM placement or nested execution placement. `view_session` live-context boundaries and archived `msg#N` sequences remain distinct in observation/recall tool guidance; live projection/counting is owned by [conversation and history](../behaviors/conversation-and-history.md#search-recall-and-statistics).

The discoverable hidden `node_create_auth_token` builtin always resolves to Main and returns only Node ID/file path. Its file/registry ordering and private-path boundary are owned by [the external Node unit](./external-nodes.md).

Local callable declarations carry `type: function`; the channel, notification, artifact and Main browser declarations follow the same function schema contract as other builtins and Node capabilities. `ToolRegistry` and `ToolCallControls.ForModel` preserve that discriminator when projecting definitions. This is separate from MCP discovery's `inputSchema` objects and from provider-native tools added by the [Responses request plan](./model-responses.md). Discovery-only declarations remain hidden by default. Ordinary description rendering and schema selection follow [unified discovery](../modules/tools-and-permissions.md#d-tools-unified-discovery); `UnifiedTools` keeps comment escaping without the former per-description clipping or displayed injection marker.

### D-tools-node-independent-default-declarations

**Directly selected for request-prefix stability (2026-11-04).** Default model requests use the canonical framework `DefaultInject` declarations in stable order. Selecting master, a Provider Node, or a compatible external Node never replaces their names, descriptions or schemas with advertised capabilities, or removes them when connectivity changes. Default Node builtins remain declared even when no selected-Node capability or permission allows the call, including for isolated Agents. No enumeration of all Nodes or permission union is required. Hidden Node tools, including browsers, remain discovery-only. Other builtin visibility and external-runtime support restrictions retain their existing filtering; explicit schema overrides remain caller-owned. Configuration, non-Node policy, and provider-native tool changes are separate from execution placement.

`SessionManager.ModelDefinitions` is the shared projection for chat, compaction, BTW and the external runtime. Direct, unified and ToolScript calls still resolve their actual execution Node and enforce capability admission, authorization and isolation before effects. `search_tools` keeps target-specific advertised descriptions, schemas and visibility, and remote-only capabilities remain accessible through explicit discovery and `call_tool`. A declaration is not an invocation grant. The retained TypeScript resolver's current-Node visibility and Shell exec substitution are reference behavior, not the maintained declaration contract.

Inputs of the default declaration list, in `SessionManager.ModelDefinitions`:

- Process-fixed: the framework definitions registered once at construction. `HandoffConfirmationEnabled` (app config at startup) selects the handoff parameter shape; `MontyWorker.IsSupported` and `LocalExecManager.IsSupported` (host capability) include or omit the ToolScript and local exec families.
- Session-fixed or rule-driven, intentional: the external runtime (`ClaudeRuntimeToolSupport`/`Project`, fixed by the Session's authority envelope), Agent isolation (`IsolatedToolCompatibility.Visible`, structural limits plus legacy exact rules), and the global and Agent rule layers evaluated by `ToolAuthorizationEvaluation.Visible`. A tool denied by identity alone (no Node, argument or path selector) is not declared; editing rules or isolation is an explicit configuration change, separate from execution placement. An unreadable Agent rule chain declares only the Node builtins.
- Provider-native declarations (web search, image generation) come from the selected model's configuration and are appended by the request plan; secret masking and text redaction rewrite the serialized list per their own configuration.
- Never an input: the current Node, Node capabilities, connection state, registry ancestry, channel attachments and Session cwd.

`send_file` and `image_write_to_file` choose their Node per call (`node`, defaulting to the current Node). Their declaration visibility evaluates with unknown target Node and unknown Node targets, so Node selectors, `node: {current: true}` and argument matchers keep the tool declared, and the current Node does not influence the result. The Node-dependent checks run when the tool is called: `RequireFileNodeBoundary` (isolated Agents only transfer between master and the bound/current Node) and the concrete Node authorization of the resolved target, both of which fail with `tool_authorization_denied` before any file effect.

Session/Agent management tools that Source marks nondefault remain discovery-only by default, including child-model/compact-threshold settings, snapshot refresh, compaction, Agent/Session creation and Agent inheritance changes. Hiding their default model schemas does not unregister them or grant/deny invocation authority: explicit discovery and calls still use the same concrete policy owner.

For remote `exec`, `SessionToolExecutor.RemoteResultMetadata` and `SettleRemoteExec` capture the [placement record](../threads/tools-permissions-and-exec.md#d-exec-placement-record); local starts report it through `LocalExecManager`, and `TurnToolExecution.ExecPlacement` carries it to history. For concrete remote `read`, `write`, `edit`, `RemoteResultMetadata` binds the documented first-party path sidecar to the captured execution Node. It records bounded display-only absolute POSIX targets for the original WebUI's Code actions and strips the private carrier from model/ToolScript output. This metadata is not Main filesystem, cwd or model-control authority; ambiguous relative tool paths remain inert.

`ToolResponseFormatting.FormatToolScriptExecution` formats only cleaned outer execution presentation into literal print/return sections followed by block-YAML metadata. The runtime's `ProjectSlice` emits trusted subcall metadata even for an empty slice; the registry measures that presentation with the existing guard. Neither a tool name nor a result object's metadata key grants this classification. Native Monty values, persisted run/history values, nested tools, typed completion receipts and image carriers retain their existing paths. Request/journal projection is owned by [provider-neutral history](./model-common-wire.md).

The [two-stage guard](../threads/tools-permissions-and-exec.md#structured-output-guard) retains all ordinary siblings when shortening `output` is sufficient. Its whole-response summaries use ordinary response formatting, including the existing .NET `outputTruncated: true` envelope whose error branch carries an `error` excerpt without `output`. Only a non-null top-level `error` selects that branch; an explicit `error: null` remains null and uses the successful output excerpt. Guarding must not manufacture a batch error and thereby clear an otherwise valid same-batch wait. This preserves both current and persisted summaries without wrapping the excerpt in a new execution metadata section.

When the persisted verbose flag is enabled, resolved and authorized top-level dispatch broadcasts the original invocation name and existing argument preview through the normal transient non-WebUI delivery owner. A malformed top-level attempt also broadcasts before returning `invalid_tool_arguments`, without generic effect authorization or dispatch; its raw string arguments use the same 200-character preview bound, with the ordinary preview fallback when raw text is absent. Cancellation, closing, preset results and unavailable policy still short-circuit before malformed display, while well-formed denied calls do not reach the dispatch hook. Programmatic subcalls keep their existing outer presentation. The broadcast adds no canonical history, ordinary progress duplicate or platform-ACK dependency, and does not move structured runtime/progress boundaries.

Resolved, authorized top-level dispatch supplies runtime name/source/server/Node, optional wrapper invocation, short resolved-argument preview and zero-based batch position. Programmatic subcalls preserve the outer script runtime and use its existing subcall progress. Successful builtin `send_to_session` delivery supplies separate display-only canonical destination/body evidence, bounded to 32,768 UTF-16 units. `TurnToolExecution.SessionMessages` flows to function-response `__meta.sessionMessages`, while ToolScript captures only its current completed host subcall's `sessionMessage`. These values do not broaden child-to-parent handoff receipts, alter returned values or delivery count, or trust arbitrary MCP/result JSON. Existing provider projection removes the metadata.

`SessionToolExecutor.CompleteBatchAsync` reads errors from the complete committed tool row and settles explicit waits, handoff waits and finish requests under the [batch-error contract](../behaviors/execution-and-waiting.md#explicit-wait-ends-an-otherwise-finished-turn). Direct, unified and trusted ToolScript effects share this settlement; pending controls are consumed even when an error suppresses their terminal action.

### Tool activity summaries

Model-facing `exec` and `run_script` schemas require `summary` describing the action/purpose. It stays in ordinary call arguments; the execution handlers do not require it, preserving existing Node, MCP and ToolScript automation. `LocalExecManager` accepts this additional display argument without changing its command/cwd/timeout semantics. Discovery and direct model definitions expose the same parameter, including current CLI Node capabilities. Older Node schemas and persisted calls remain readable.

`ToolActivity` resolves `call_tool` descriptors for display (including `argsJson`), takes the supplied exec/script purpose and uses a short literal command prefix for older exec calls. Existing action/path/title fields summarize other tools without new generic parameters. Resolved runtime `argsPreview` uses the same purpose for exec/script calls. No shell interpretation, result inference, new exec registry field or additional history read is involved. See [context previews](./session-compaction.md#recall-and-lineage-contract) for source pairing and [tool timeline](./webui-tool-timeline.md) for browser display.
