# Unit: Session manager Agent, setup, files, knowledge, waits, and compaction

Files: `dotnet/Foxwarm/Sessions/SessionManager.AgentOps.cs`, `dotnet/Foxwarm/Sessions/SessionManager.AgentTools.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Authorization.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Compact.cs`, `dotnet/Foxwarm/Sessions/SessionManager.FileDelivery.cs`, `dotnet/Foxwarm/Sessions/FileDeliveryArtifact.cs`, `dotnet/Foxwarm/Sessions/SessionManager.InboundFiles.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Knowledge.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Settings.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Setup.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Wait.cs`

## Purpose

Delegates authenticated Main operations for Agent setup/knowledge/memory, Session settings, file delivery/inbound files, waits, compaction, and authorization to exact owners and feature services.

## Stable methods and callers

Agent/setup methods load/validate Agent metadata and provider forms; knowledge/memory methods select/update Agent resources; file methods validate ownership/path and create delivery refs; settings methods stage model/display/cwd changes through save-lane operations; wait/compact methods call owner safe points and return explicit committed/accepted outcomes.

## Contract and side effects

This unit is an orchestration boundary. It does not write active JSON/Archive outside `SessionSaveLane`, does not make catalog rows semantic history, and leaves optional Vector work to the [derived owner](./vector-owner.md) after committed authority publication. File export/delivery and bound-Agent ingress use the [external Node file consumers](./external-node-files.md) without moving Session/image authority off Main. File delivery is authenticated/deployment-relative; memory/knowledge selection affects future prompt input, not past history.

`create_agent` takes the caller's raw model and current Node as supplied defaults, then falls back to the selected source's raw model and Node. The source supplies raw effort and future-child model/effort defaults; child policy is not substituted for the new main's own model. Agent-main creation retains a nonempty raw model key after normal configuration removal, while the current configured fallback determines allowed inherited effort and concrete snapshot selection. Incompatible inherited effort clears; a virtual fallback defers snapshot construction. Restoring the key restores its effective selection without rewriting the saved raw setting. This does not relax explicit force-model validation or ordinary Session creation. An explicit source ID resolves aliases and cold owners through normal admission. A valid missing source in an existing Agent enters the established new-lifetime creation owner, with master placement rather than the Agent-main Node fallback; archived/deleting identities retain their ordinary rejection. Target-main reservation is checked before this source-creation side effect and again under the target's existing creation key before Agent publication.

One-time `inheritMemory` uses the existing memory-directory copier and does not install an inheritance link. Ongoing inheritance rejects an isolated source in the shared Agent metadata validator, covering tools, HTTP and direct manager calls without adding caller-principal restrictions. `convertSession` uses the existing [identity-rename owner](./session-manager-lifecycle-identity.md#contract-and-side-effects), preserving history, aliases, children, channel bindings and settings; it requires main creation. Its admission differs deliberately from ordinary `move_session`, as defined by that owner. Optional isolation and legacy exact-rule replacement use the existing metadata/Node owners after creation or conversion, followed by requested inheritance and main refresh. Failures in these later steps retain the already created/moved effects; they do not introduce a conversion transaction or rollback layer. Empty rules remain an explicit replacement.

`refresh_session_snapshot` defaults to the calling owner or admits the explicit target through normal exact-owner lookup, regardless of inactivity. Refresh retains a recorded concrete generation identity. Without one, it resolves only a concrete configured model; a virtual model remains deferred without choosing a leaf or saving a fabricated snapshot. Existing generic authorization still precedes tool execution.

Inherited channel guests use the Source base-36 random fraction (up to six characters), skip existing directories, and retry archived-main/already-existing allocation collisions. They reuse ordinary Agent-main preflight and creation rather than leaving a new Agent on a reserved-main collision; failures after creation are not retried as allocation collisions.

`CreateNamedLockedAsync` chooses the target Agent's isolation binding, an explicit caller/timer selection, a non-master Node from that Agent's existing main Session, then master. The main fallback applies only when the caller omitted selection, excludes the main Agent, follows catalog aliases, and uses non-allocating owner lookup. It does not inherit cwd or require an online Node. Child/fork source placement and explicit master remain explicit. WebUI named and automatic non-main creation use this same path. Main-Agent exclusion and alias following retain the current Source behavior rather than resolving its open product questions.

Fresh named creation writes a hyphenated UUID prompt-cache key, matching the lazy, fork-capture and clear-history writers and the retained Source reader's accepted form. Existing saved keys remain unchanged, including previously issued 32-character values; creation does not normalize unrelated Sessions or split their existing cache identity. The original-App Completions fixture checks fresh authority, provider substitution and restart continuity, while the Agent workflow retains an issued-key compatibility case.

`create_session` consumes the source's prospective model/effort pair (explicit force, child defaults, raw current pair), without copying future-child defaults. Its optional parent records only a relation: Node inheritance still follows the caller, not the recorded parent. An explicit Node overrides caller selection unless the target Agent is bound; cwd is not copied. Optional prompt-file selection is normalized through the existing memory owner, including an empty selection. Parent existence, Agent membership, authorization and strict persistence remain creation boundaries. `create_child_session` carries its explicit Node through both fresh and fork paths; fresh cross-Agent children retain target memory and binding rules, while same-Agent forks retain copied context/cache/Archive lineage. Display names remain independent of allocated IDs and accept strings verbatim.

Custom prompt-file selection follows [creator-scoped admission](../behaviors/conversation-and-history.md#custom-prompt-files-and-legacy-isolation). `create_session` resolves each source through `AgentMemory.ResolveSelectedPath` and checks the caller's existing Main-host `read` authorization before creating a lifetime, even for virtual models. Operator command/direct-manager creation remains administrator-owned. `AgentMemory.Selected` reads the admitted selection without consulting destination isolation; normalized Agent-relative paths, ordinary-file symlinks, missing/non-file errors and virtual deferral retain their existing semantics. Snapshot ownership stays on Main regardless of execution Node placement.

`InstallConfigAsync` resolves/captures one regular candidate through the existing read/path boundary, checks both `set_config` and Main read authority, then reauthorizes inside the configuration installation lane. Native validation errors do not expose candidate content. `ValidateWait` shares argument/source validation between deferred ToolScript intent and `DeclareWaitAsync`; only declaration calls the existing save lane. The [ToolScript unit](./toolscript.md) owns terminal deferral/checkpoint behavior. `wait` with exact owned `waitExecIds` defaults to one 600-second fallback unless input waiting or an explicit null disables that fallback; explicit positive fallback values remain unchanged.

`SendFileAsync` preserves the existing destination/path/Node authorization and staging owners. It dispatches external files through the shared channel registry, preserving direct error propagation and partial Session-fanout results; [external channels](./dotnet-external-channels.md) owns adapter and automatic-delivery behavior. It returns a bounded version-1 `fileDelivery` value only after at least one actual delivery succeeds. `FileDeliveryArtifact.Create` prepares original basename/MIME/size, exact canonical Session or direct channel target, unique delivery ID, source Node and actual Main staging path under the [shared receipt contract](./shared-file-delivery.md). Remote receipts retain the transfer payload MIME, using the ordinary extension fallback only when no MIME was supplied; receipt metadata does not change download/preview authorization. The structured receipt survives direct tool values and nested ToolScript return values; failed sends and unrelated image exports do not gain receipts. No extra queue row, target history message or notification accompanies delivery.
