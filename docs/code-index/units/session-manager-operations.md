# Unit: Session manager Agent, setup, files, knowledge, waits, and compaction

Files: `dotnet/Foxwarm/Sessions/SessionManager.AgentOps.cs`, `dotnet/Foxwarm/Sessions/SessionManager.AgentTools.cs`, `dotnet/Foxwarm/Sessions/SessionDelivery.cs`, `dotnet/Foxwarm/Sessions/SessionManager.CreationModel.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Authorization.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Compact.cs`, `dotnet/Foxwarm/Sessions/SessionManager.FileDelivery.cs`, `dotnet/Foxwarm/Sessions/FileDeliveryArtifact.cs`, `dotnet/Foxwarm/Sessions/SessionManager.InboundFiles.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Knowledge.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Settings.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Setup.cs`, `dotnet/Foxwarm/Sessions/FirstRunWelcome.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Wait.cs`

## Purpose

Delegates authenticated Main operations for Agent setup/knowledge/memory, Session settings, file delivery/inbound files, waits, compaction, and authorization to exact owners and feature services.

## Stable methods and callers

Agent/setup methods load/validate Agent metadata and provider forms; knowledge/memory methods select/update Agent resources; file methods validate ownership/path and create delivery refs; settings methods stage model/display/cwd changes through save-lane operations; wait/compact methods call owner safe points and return explicit committed/accepted outcomes.

## Contract and side effects

This unit is an orchestration boundary. It does not write active JSON/Archive outside `SessionSaveLane`, does not make catalog rows semantic history, and leaves optional Vector work to the [derived owner](./vector-owner.md) after committed authority publication. File export/delivery and bound-Agent ingress use the [external Node file consumers](./external-node-files.md) without moving Session/image authority off Main. File delivery is authenticated/deployment-relative; memory/knowledge selection affects future prompt input, not past history.

`create_agent` takes the caller's raw model as supplied default, then falls back to the selected source's raw model. The new main's Node is its binding, `defaultNode`, installation default, then master; neither the caller's nor the source's Node applies. The source supplies raw effort and future-child model/effort defaults; child policy is not substituted for the new main's own model. Agent-main creation retains a nonempty raw model key after normal configuration removal, while the current configured fallback determines allowed inherited effort and concrete snapshot selection. Incompatible inherited effort clears; a virtual fallback defers snapshot construction. Restoring the key restores its effective selection without rewriting the saved raw setting. This does not relax explicit force-model validation or ordinary Session creation. An explicit source ID resolves aliases and cold owners through normal admission. An existing defaults-only source transfers no content; [creator-scoped management](./session-manager-lifecycle-identity.md#creator-scoped-model-management) owns the separate conversion/copy checks. A valid missing source in an existing Agent enters the established new-lifetime creation owner, with its Agent default Node or master rather than the existing Agent-main Node fallback; archived/deleting identities retain their ordinary rejection. Target-main reservation is checked before this source-creation side effect and again under the target's existing creation key before Agent publication.

One-time `inheritMemory` uses the existing memory-directory copier and does not install an inheritance link. Ongoing inheritance rejects non-`inheritable` sources and applies the [creator-ancestor constraint](./session-domain.md#agent-creator-metadata-and-admission) through the shared Agent metadata validator for tools, HTTP and direct manager calls. `convertSession` uses the existing [identity-rename owner](./session-manager-lifecycle-identity.md#contract-and-side-effects), preserving history, aliases, children, channel bindings and settings; it requires main creation. Its admission differs deliberately from ordinary `move_session`, as defined by that owner. Requested inheritance and main refresh follow creation or conversion. Failures in these later steps retain the already created/moved effects; they do not introduce a conversion transaction or rollback layer. Empty rules remain an explicit replacement.

The `session` tool's `archive`/`unarchive` actions (2026-11-23; `ctl session archive|unarchive [--session-id]`, which also serve the user's `/session archive`) resolve the target, defaulting to the caller, and apply `SessionCatalog.Archive` for that Session alone through `ChangePresentation`: Main catalog presentation only, no owner hydration, history or runtime change. Repeating an action reports the existing state. Authorization is `session.control` with `change: archive` on the target ([operation catalog](./tool-operation-catalog.md)).

`refresh_session_snapshot` defaults to the calling owner or admits the explicit target through normal exact-owner lookup, regardless of inactivity. Refresh retains a recorded concrete generation identity. Without one, it resolves only a concrete configured model; a virtual model remains deferred without choosing a leaf or saving a fabricated snapshot. Existing generic authorization still precedes tool execution.

Inherited channel guests use the Source base-36 random fraction (up to six characters), skip existing directories, and retry archived-main/already-existing allocation collisions. They reuse ordinary Agent-main preflight and creation rather than leaving a new Agent on a reserved-main collision; failures after creation are not retried as allocation collisions.

`CreateNamedLockedAsync` chooses the supplied `initialNode` (an explicit Node or a same-Agent parent's current Node, resolved by the caller) or for timers the stored owner Node, then the effective default (own `defaultNode`, else installation `agentDefaultNode`), then master ([user decision 2026-11-06](../behaviors/sessions-and-agents.md#omitted-creation-settings-do-not-have-one-universal-source)). Fresh children and WebUI user children pass the parent's current Node only when the target is the parent's Agent; forks use binding, explicit Node, then the parent's current Node. Timer firing keeps the stored Node only when the target Agent is the owner's Agent. A `create_session` parent is recorded as a relationship only and does not supply placement (user decision 2026-11-08). There is no main-Session or caller fallback. It does not inherit cwd or require an online Node. WebUI named and automatic non-main creation use this same path. After Node selection it writes the Agent `defaultCwd` into the first authority image when `DefaultCwdFor` matches that Node; fork creation applies the same check to its copied or selected Node.

Fresh named creation writes a hyphenated UUID prompt-cache key, matching the lazy, fork-capture and clear-history writers and the form legacy readers accept. Existing saved keys remain unchanged, including previously issued 32-character values; creation does not normalize unrelated Sessions or split their existing cache identity. The original-App Completions fixture checks fresh authority, provider substitution and restart continuity, while the Agent workflow retains an issued-key compatibility case.

`create_session` consumes the source's prospective model/effort pair (explicit force, child defaults, raw current pair), without copying future-child defaults. Its optional parent records only a relation; neither it nor the caller supplies a Node, so placement is binding, explicit Node, target defaults, then master. cwd is not copied. Optional prompt-file selection is normalized through the existing memory owner, including an empty selection. Parent existence, Agent membership, authorization and strict persistence remain creation boundaries. `create_child_session` carries its explicit Node through both fresh and fork paths; fresh cross-Agent children retain target memory and binding rules, while same-Agent forks retain copied context/cache/Archive lineage. Display names remain independent of allocated IDs and accept strings verbatim.

Custom prompt-file selection follows [creator-scoped admission](../behaviors/conversation-and-history.md#custom-prompt-files-and-creator-authority). `create_session` resolves each source through `AgentMemory.ResolveSelectedPath` and checks the caller's existing Main-host `read` authorization before creating a lifetime, even for virtual models. Operator command/direct-manager creation remains administrator-owned. `AgentMemory.Selected` reads the admitted selection without consulting the destination Agent's rules; normalized Agent-relative paths, ordinary-file symlinks, missing/non-file errors and virtual deferral retain their existing semantics. Snapshot ownership stays on Main regardless of execution Node placement.

`InstallConfigAsync` resolves/captures one regular candidate through the existing read/path boundary, checks both `set_config` and Main read authority, then reauthorizes inside the configuration installation lane. Native validation errors do not expose candidate content. `ValidateWait` shares argument/source validation between deferred ToolScript intent and `DeclareWaitAsync`; only declaration calls the existing save lane. Empty optional source lists normalize to omission under the [explicit-wait contract](../behaviors/execution-and-waiting.md#explicit-wait-ends-an-otherwise-finished-turn), before mutual exclusion, real-source validation and exec fallback selection. The [ToolScript unit](./toolscript.md) owns terminal deferral/checkpoint behavior. `wait` with a nonempty list of exact owned `waitExecIds` defaults to one 600-second fallback unless input waiting or an explicit null disables that fallback; explicit positive fallback values remain unchanged.

`SendFileAsync` preserves the existing destination/path/Node authorization and staging owners. It dispatches external files through the shared channel registry, preserving direct error propagation and partial Session-fanout results; [external channels](./dotnet-external-channels.md) owns adapter and automatic-delivery behavior. It returns a bounded version-1 `fileDelivery` value only after at least one actual delivery succeeds. `FileDeliveryArtifact.Create` prepares original basename/MIME/size, exact canonical Session or direct channel target, unique delivery ID, source Node and actual Main staging path under the [shared receipt contract](./shared-file-delivery.md). Remote receipts retain the transfer payload MIME, using the ordinary extension fallback only when no MIME was supplied; receipt metadata does not change download/preview authorization. The structured receipt survives direct tool values and nested ToolScript return values; failed sends and unrelated image exports do not gain receipts. No extra queue row, target history message or notification accompanies delivery.

`RestoreRetainedAgentAsync` joins the existing Agent admission/creation key and catalog publication owner without creating a main Session. Its trusted route and cleanup counterpart follow [retained Agent administration](./session-manager-lifecycle-identity.md#retained-agent-administration).

`EnsureFirstRunSessionAsync` creates the first-run default Session with its opening and prepared welcome through `CreateNamedAsync` and the existing owned-row append; its admission and caller contract are owned by [First-run default Session](./dotnet-webui-agents-setup.md#first-run-default-session).

## Design decisions

- [2026-08-01] Every successful `get_session_messages` response must include the target session's execution state via the shared `SessionRuntimeState` path, including empty and fully filtered pages. Keep the four-state runtime taxonomy canonical rather than defining retrieval-specific labels; append only a nonzero queue count when the compact summary would otherwise omit pending work.
- [2026-07-22] Rename the shared literal result filter on `recall` and `get_session_messages` from ambiguous `query` to `contentFilter`. It is explicitly a case-insensitive post-filter after target/page/vector retrieval; `target` owns exact CTX-BLOCK/range selection and `vector_query` owns semantic search. Do not preserve old `query` compatibility: reject it clearly. Report staged literal/include/exclude exclusion counts, and preserve the count/omit-filter hint even for zero-result or truncated previews.

### D-message-preview-timestamps

Message previews use persisted `Message.__meta.timestamp`, with a valid authoritative Archive row timestamp taking precedence and the persisted Message timestamp as fallback for raw Archive rows. Only finite numeric values representable by `Date` are timed. Each displayed message shows local time to seconds and the numeric UTC offset. The first displayed message/page shows its full local date; only the immediately preceding displayed message on the same local day permits date elision. Missing/invalid message times remain untimed, reset comparison, and never use wall-clock time or body/wrapper parsing.

The shared renderer applies this comparison after filters, result selection and clipping. Grouped raw vector windows retain generated heading spans so the first surviving row keeps its date even when match-centered snippets omit earlier rows. Date removal only shortens the bounded output and never modifies matching body text. `/messages` uses the same time state with a fresh state per page. Archived CTX-BLOCK ranges, canonical messages, Archive storage, provider serialization and WebUI Timeline timing are unchanged.

### D-session-tool-list-scope

[2026-07-02, updated 2026-09-28] The old model-facing `list_sessions` builtin is removed rather than compatibility-wrapped. The replacement is the default model-facing `session` tool: `session()` / `session({action:"status"})` for current status, and `session({action:"list", start, count, scope?, query?})` for catalog listing. List defaults to the calling Session's Agent; only explicit `scope:"all"` retains the previous global view. Filter before pagination to keep offsets and totals consistent. The existing list permission and isolation checks remain unchanged; the scope option is not a grant and does not alter WebUI lists.
- [2026-11-08] `session({action:"list", query})` adds keyword selection with the same matcher as WebUI metadata search (`SessionListQueries.MetadataMatcher`): a trimmed 1-256 character query matched as one case-insensitive literal substring against ID, aliases, display name, Agent, current Node, cwd and model keys. Whitespace does not split terms. It applies after scope and before `start`/`count`; totals and range messages count matches, and ordering stays most recent activity first. It is a metadata candidate scan, not message-content search (`recall` owns that). Omitting `query` keeps the indexed catalog page path.
- [2026-11-11, user decision] The model-facing list, `session` status "Recent child sessions" and `list_agents` show only the caller's own Session and Agent plus the Sessions and Agents its policy might let it address. Filtering happens before `start`/`count`/`query`, so totals and ranges count listed Sessions; `scope` keeps its meaning over the listed set, `list_agents` counts listed Sessions only, and no hidden count is shown. An unavailable policy fails the list. Administrator surfaces (including channel `/status`), inbound MCP Session lists and scoped WebUI identities are unchanged, and tool descriptions are unchanged. Admission rules, probe semantics and the per-class cost model are in [Session and Agent list visibility](./session-list-visibility.md).
- [2026-07-02] `/status` and `session({action:"status"})` must share the same status information source/formatter (`dotnet/Foxwarm/Sessions/SessionObservation.cs`) and expose the union of old `/status` fields plus the new tool fields: agent id/name, agent dir, session id, parent id, model, message/token/image status, last usage, last message time, effective auto-compact threshold, current node/connection, current cwd/default cwd, busy/queue state, and recent child sessions.
- [2026-08-26] Session status/list distinguishes all-session, any-session, exec, input, and fallback waits. Current model calls must declare a real source/fallback; legacy persisted source-less waits remain readable without acquiring current quiescence semantics.

`SendAsync` reports each committed delivery (`SessionDelivery`: canonical target, body, `deliverySeq`) to an optional explicit callback passed by the calling tool, after the real send. `send_to_session`, a child's initial message and the Task service's notifications use it. Callback failures do not turn a delivered message into a failed send. Task envelopes carry the recipient's role in `recipient`. Existing plain/structured return and afterSend behavior remain unchanged. See [Session communication presentation](../threads/session-communication-presentation.md).

Script self-delivery uses the existing send API and its ordinary checks; provenance and framing are canonical in [script self-notification](./toolscript.md#d-script-self-notification).
