# Unit: Vector search, Archive source selection and previews

Files: `dotnet/Foxwarm/Vector/VectorSearch.cs`, `dotnet/Foxwarm/Vector/VectorRecall.cs`, `dotnet/Foxwarm/Vector/VectorRawWindow.cs`, `dotnet/Foxwarm/Vector/ArchiveLexicalRecall.cs`, `dotnet/Foxwarm/Sessions/SessionManager.VectorHistory.cs`

## Purpose

Turns derived dense/lexical candidates into scoped source families, then reloads authoritative Archive context for model recall and administrator History. Stored dense text is only a compatibility fallback, not the preferred source of truth.

## Search and caller contract

`VectorRuntime.SearchAsync` applies escaped Agent/Session/cumulative-lineage predicates, clips crossing raw ranges from Archive, rejects crossing legacy fact spans, filters patterns, adapts candidate count up to 1024, and groups deterministic raw/block/fact sources. Ranking retains semantic distance buckets, block/fact/recency preference, matched fact metadata and overlap diversity. Hybrid fusion uses identifier/prose lane weights and shared-source boosts rather than vector-distance substitution.

`ArchiveRecallTool.ExecuteAsync` selects nonempty `vector_query` before exact-target parsing or owner admission. It uses existing current-Session/current-Agent model scope. [2026-11-12] The model-facing definition no longer declares `agentName` or `scope: all`, and both are rejected: only the caller's own Agent was ever searchable, so neither carried a capability. An owner still initializing (`VECTOR_UNAVAILABLE`), including pending source-time repair, uses the existing bounded canonical Archive identifier search for an exact Session. That fallback obeys the same source-date, scope and selected-context filters; it never reads unrepaired dense metadata and its text label reports Vector unavailability. Structured results remain bounded and incomplete. Broader scopes and completed initialization failures retain the retryable unavailable error, and explicit `VECTOR_DISABLED` never enables the fallback. Other Vector operation failures retain their error codes. Exact overview/block/message selectors retain their existing behavior. `limit` counts unique sources after selected-context filtering; preview text, headers, notices and drill-down advice share the existing bounded renderer budget.

`VectorRecall.SearchAsync` reloads raw ranges and blocks from immutable Archive. Modern facts resolve their block, never silently widen into raw text when that block is absent. Raw selection respects tool-call/response atomicity, meaningful/fallback anchors, normal seven-message windows, a hard sixteen-message cap and positive-filter omission notices attached to their source item. Only groups surviving final filters and the requested result limit contribute those notices; query-level notices remain separate. The renderer collects priority notices before warnings/filter/selection notices and the title, following the Source limits. Administrator source reload scans bounded pages with bounded neighbors; it does not transfer a whole raw source range merely to choose a display window.

`VectorRawScore` is a small readonly value record used in generic score arrays and nullable anchor tuples. It has no identity or resource lifetime; selection retains the existing score, substantive/text-length and index tie-breaks. Programmatic recall projects source locators and raw dense distance, lexical score/rank, and the actual same-query fusion score without claiming cross-query normalization. Dense-family merging preserves the lexical rank. `VectorRecall.Reload` shares authoritative source loading between initial search and retained-window continuation; `ContextPreviewRenderer.FilterItems` owns the literal/include/exclude stages for both structured and ordinary callers. Structured selection applies them before its source limit; ordinary text keeps its renderer notices and preview budget. Raw expansion applies time bounds to canonical records before window selection, and projected timestamps come from the Archive row.

Semantic continuation and completeness semantics are canonical in [archive and recall](../threads/archive-and-recall.md#recall-and-preview). `RecallWindowStore` retains at most four windows per live Session owner for fifteen minutes, each containing at most 128 ranked source locators and scoring/window-anchor metadata, not message bodies. Initial retrieval uses a fixed candidate budget; cursor pages do not call Vector or change ordering. Each page rechecks canonical source authorization. Previously available sources reload Archive content and fail if no longer available; initially unavailable compatibility sources retain only their selected bounded fallback projection. The initial source filters stay fixed for continuation, including when an original compatibility match lies beyond its stored excerpt. No source is silently substituted or reranked. Cursor binding includes time bounds, source filters, block preference, tool detail and page size. The cache is transient, with no persistence or background cleanup service.

`SearchVectorHistoryAsync` serves the real authenticated administrator `/api/history/search` route with source ranges, bounded messages/blocks, earlier/later metadata and image externalization. Omitted or empty Session filters select global or Agent scope and reload each hit from its own Archive identity. Only a nonempty exact Session filter supplies a resolved read identity, preserving canonical aliases and captured fork lineage/caps. Scoped WebUI identities remain forbidden from that global endpoint. Disabled Vector and unavailable broad-scope Vector are 503; an exact-Session search during initialization can use the same bounded Archive fallback. Actual search failures are not an empty-success response.

## Canonical scope after alias resolution

Current-Agent model semantic search rechecks each resolved canonical source against the same target boundary as explicit semantic targeting, before Archive text or old stored-text fallback can return. Historical Agent/Session metadata in a dense or lexical row does not grant access after cross-Agent move. The existing durable canonical Session identity determines Agent scope even after deletion removes the active catalog row: never-moved retained history remains searchable, and moved-then-deleted history does not regain its original Agent scope. Captured allowed fork lineage and cumulative caps remain valid; exact Archive lookup and administrator global scope retain their existing authority.

This deliberately closes a reproduced pre-move-content exposure. It does not migrate dense rows or promise destination-Agent dense retrieval of old content.

## Fallback and failure limits

When exact current-Session persistent lexical search is unconfigured/unready/backfilling or query failed, `ArchiveLexicalRecall` can supplement identifier search from bounded Archive reads. Limits are 16 lineage entries, 2000 substantive visible messages and 1000 blocks per branch, 64 branch candidates and 256 total candidates. Role/visibility and canonical time filters apply before the message limit; block time overlap is also applied before its scan limit, resolving missing endpoint timestamps through effective lineage. late parent messages/blocks remain clipped by captured caps. Literal ranking/deduplication preserves Source behavior without scanning arbitrary Sessions.

If authoritative source is absent, legacy stored text can supply a bounded compatibility preview only after the same caller scope boundary. Warnings contain bounded source metadata and reason, never query or text. Logging failure does not break recall. Exact missing targets still do not create owners, databases, branch reservations or active history from Archive.

## Design decisions

### D-vector-source-family-ranking

[2026-08-28] Semantic retrieval ranks canonical archive source families rather than individual embedding rows. Exact raw-range chunks collapse together; a block and its modern block-identified facts form one family with bounded matched-fact metadata; strongly overlapping raw families are deferred while distinct ranked ranges remain. Semantic distance is the primary ordering. Source-time recency and block/fact preferences may break only effectively equal-distance ties, so metadata cannot promote a clearly worse semantic match. The hardcoded Qwen3 model receives one stable query-only retrieval instruction, while all document/index embedding input remains unchanged. Candidate retrieval starts with the bounded normal row window and, only when that window is saturated and the pre-backfill diverse-family count remains below the request, doubles deterministically up to a hard 1,024-row cap; the same query vector, scope, lineage, filters, and owner-local maintenance gate are reused throughout. An unsaturated window or the hard cap returns the final selection with overlap-deferred families backfilled, so genuinely overlap-only corpora still fill available slots.

### D-vector-persistent-hybrid-read-rollout

**Selected derived retrieval design under [optional Vector](../threads/archive-and-recall.md#d-context-optional-vector) and [source-backed recall](../threads/archive-and-recall.md#d-context-source-backed-recall).** Opt-in hybrid reads improve identifiers without making the derivative authoritative. Safe partial coverage and bounded bootstrap fallback were chosen; completeness diagnostics are not a requirement to reject every lagging query.

The disabled-by-default `vector.hybridSearch` flag is normalized on only with enabled Vector plus lexical indexing. Dense embedding/search remains mandatory and keeps the Phase 1 query instruction; only after dense success may the exact Vector owner query FTS with the raw user query. RPC descriptor version 3 adds a detailed search result carrying bounded lexical readiness/coverage/use/error metadata while legacy `vector.search()` remains array-compatible. Shared family fusion gives identifier hits stronger bounded rescue weight, prose/CJK weaker weight, collapses block/fact and contained raw families, and preserves dense-only order when no lexical family contributes. Pre/post-query fork-capped snapshots compute coverage diagnostics; an append during FTS keeps `coverageComplete:false` even if lexical catches up before the post-check. This reports completeness without rejecting safe partial hits or itself activating the Archive side-channel. Current-agent persistent search may be partial but never performs the Archive-wide fallback. All presentation still reloads Archive authority; FTS text is never returned as preview authority.

Exact-session hybrid lookup may consume safe partial persistent FTS hits while ordinary coverage is incomplete; `coverageComplete` remains internal diagnostic/rebuild evidence rather than a normal recall correctness gate. Recall invokes bounded Phase 2A only when persistent lexical is disabled/unconfigured, unready/rebuilding, globally startup-backfilling, or query-errored—not solely for checkpoint lag or an exact pre/post authority change. Current-agent scope still performs no Archive fallback. Model-facing recall makes no status call solely for checkpoint lag and emits no `[vector lag]` notice. Titles distinguish persistent-only, bootstrap/error fallback-only, combined persistent-plus-fallback, and vector-only results.
