## Purpose

Provides friendly, explicitly invoked Node setup and pending approval inside System Architecture's Nodes surface. The canonical onboarding contract is [D-node-thread-onboarding-options](../threads/node-communication.md#d-node-thread-onboarding-options).

## Exports and function index

- `useNodePendingApprovals(enabled)` — owns one visibility-aware five-second pending refresh, cancellation/publication fencing, exact total, and bounded page navigation. Explicit refresh replaces an in-flight request; ordinary timer ticks do not overlap. Empty out-of-range pages return to the last available page.
- `NodeOnboardingModal` — mounted-only setup method/address/name controls, shared generated commands, explicit Shell creation, copy action and pending approval. Escape/backdrop/close unmount it; focus is confined and restored.
- `post(path, body)` — modal-owned authenticated request with no-store caching and abort on unmount.
- `updateCommands()` — explicit address/name/directory regeneration; default address gives config precedence, later user input is an override.
- `createShell()` — explicit, non-retried creation returning a one-time direct-auth command; selecting a method never creates trust.
- `approve(request)` — explicit pending approval, inline errors and Node/pending refresh after acceptance or stale state.

## Behavior and integration

- Linux CLI, interactive CLI, Shell, Docker and Windows are ordinary method choices. Systemd and manual Compose are optional method-specific controls.
- The modal requests setup credentials only on open or explicit command update. Pending polling and ordinary Node status responses contain no credentials. All setup state remains within this mounted component; close aborts requests and discards it, without browser storage or token-bearing URLs/logs.
- An unset configured address uses browser origin plus the deployment prefix derived from the existing API base. The server validates but never fetches that address. Created Shell credentials cannot be regenerated by refresh; their original address/name remain visible with the command until close.
- The Nodes surface owns the hook only while visible or the modal is open. Hidden documents pause dispatch and abort current requests; unmount/mode exit cancels timers and rejects late publication. No global poll or realtime topic is added.
- The ordinary Architecture Node refresh is reused after actions. Session topology, cached bounded catalog and Agent management remain separate.

## Tests

The browser fixture uses React 18, production theme/CSS, actual Chromium, real authenticated HTTP routes and a fresh temporary Main registry/catalog. It covers Nodes-only rendering and return to Topology, deployment-prefix fallback, explicit literal address override/copy, true pending total refresh without credential reload, hidden-page pause, stale approval recovery, explicit Shell creation and reopening without retained credentials. It verifies no setup token enters storage or request URLs. Screenshots use only synthetic fixture data. No deployed Node, credential or shared runtime is used.
