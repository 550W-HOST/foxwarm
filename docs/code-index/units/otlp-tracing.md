## Runtime and delivery

`MainHost` owns the exporter in console and Desktop builds, including headless Main. `OtlpConfiguration.Capture` validates the same app settings on startup and supported config saves. `FoxwarmTraces.Open` resolves only the OTLP header references when Main starts. An unavailable header secret or unsupported retry policy disables export. SDK disablement and the memory-only retry policy are checked before SDK construction. The host passes an optional observer to the Session runtime. Settings and credentials are recaptured on restart. The exporter listens to the Foxwarm activity source and filters by the owning source instance before enqueueing. The OpenTelemetry .NET batch processor owns the bounded queue and sends completed spans over HTTP protobuf. Main drains accepted work before a bounded exporter shutdown.

`SessionTurnRunner` starts a root after selecting a foreground input batch or a validated Continue. Session identifiers group independent traces. A Stop accepted before turn settlement records cancellation even when the committed assistant result returns normally. Same-owner model and tool spans choose the closest Foxwarm ancestor in the current execution context. Independent work starts its own trace. `ModelRequestOwner` creates an attempt span after the provider adapter prepares its semantic payload and the journal admission settles. Preparation failures before this point produce no call span. Setup connection tests use their separate journal path and do not emit Session model spans. Retry and failover use the same attempt boundary. `SessionToolExecutor` owns attributed local, Node and MCP spans, including operations which fail before dispatch. MCP result envelopes with `isError: true` record failure before tool output is abbreviated. `LocalSessionTurnHost.ExecuteToolBatchAsync` forwards calls that settle without reaching the executor to the same instrumentation.

`FoxwarmTraces.GenAi` projects OpenTelemetry 1.41.1 GenAI fields. Metadata includes the provider’s normalized finish reason and, when available, local journal request ID and attempt. Model/tool-use metadata does not require content capture. The local journal remains authoritative for request diagnostics.

Each content class is opt-in. Project provider input after preparation and provider output before `TextRedactionChatService` restores it. Proposed and historical calls carry names/IDs only. Tool execution projects resolved arguments after authorization, masking known secrets and omitting sensitive fields. For text-redacted batches only a direct call with matching provider-form arguments can export them; local results are omitted. Reasoning requires its own switch as well as the corresponding message class. `TraceField` bounds the visited source, string lengths, depth and UTF-8 output per field. A content projection failure is diagnostic only. No telemetry state enters persisted messages or model input.

`OtlpTraceTests` exercises the headless host, synthetic providers and an OTLP/HTTP protobuf receiver. `OtlpEnvironmentTests` covers disabled and unsupported exporter policies under isolated process settings.
