## Purpose

The independent workbench Search tab shows authenticated Archive search groups and exact Session message references using the existing ChatTimeline without mounting Chat, its composer or its realtime subscription. Global search defaults to every Agent and Session; optional Agent and Session inputs narrow the source. A copied `sessionId=... msg#N-M` reference selects its Session directly; a bare `msg#N` requires a selected Session.

## Functions and behavior

- The shared [Workbench content host](./webui-workbench-content.md#d-workbench-stable-content) retains one HistorySearchView per open search tab while tab/pane/mobile surfaces are hidden, including temporary slot replacement during layout changes. App supplies draft metadata callbacks and the host supplies current-pane headers and tab error isolation. The retained DOM owns scroll position; closing the tab unmounts the view and aborts only that instance's requests.
- `HistorySearchView` owns separate draft inputs and one submitted search/result state. Editing query, Agent, or Session drafts does not change the tab title, clear results, or abort the submitted request/metadata lookup; an explicit Search/Enter captures the draft scope, then invalidates the prior request and starts the replacement. Every result contains independent earlier/later loading state, errors, sequence anchors and one Timeline. Its header shows the current first message's valid local time, using a structured CTX block's raw range start instead of its creation time; unavailable or invalid timestamps show no time. Full-width context rows above/below the timeline load earlier/later messages with a directional arrow and the visible message range on that row; when neither direction can load, a static range row remains. A copied range retains its requested and currently shown bounds while its first 20-row page continues within the requested range, then returns to ordinary later browsing. Block/fact hits display an actual expandable CTX-BLOCK; a missing source shows a labeled cached excerpt rather than a fabricated message or fake range.
- `readHistory` calls deployment-relative authenticated GET routes. `mergeMessages` deduplicates sequence IDs when appending/prepending archive pages.
- Result headers append a nonblank Session display name in parentheses, using deduplicated `/session-list/by-id` batches of at most 100 IDs rather than the current Sidebar page. Lookup failures leave the archived messages visible; query changes and unmount abort and invalidate stale name lookups. `Open session` delegates to normal App Chat navigation without keeping previews or removing History; standalone viewers use the existing deployment-relative Chat popup URL in a new page, with native modified-click behavior.
- Unmount and new submissions invalidate/abort old requests; draft changes alone do not invalidate the submitted generation, so its success/error and session-name lookup remain visible until a replacement submission. Late responses cannot replace current results. No browser-global search state is required.
- `App` opens or reuses a blank History tab from the history-clock icon in the desktop/mobile/collapsed footer. If every existing History tab has a draft, submitted search, zero-result response, or error, the entry point creates a new independent tab. Legacy `system:search` remains readable; new instances have independent route/move/close IDs. A tab title is the trimmed last submitted query or `History`; unsubmitted draft edits do not retitle it. Draft query/scope, submitted query/scope, archive results, per-result paging/errors/disclosures, and scroll remain owned by that tab for the current page lifetime; closing it aborts and releases only its own requests/state. Archive results are not persisted to localStorage. Footer icons keep the `Search history` action label and their existing size and placement; the mobile footer Settings menu opens upward within the viewport. Popout uses the existing leaf route and window title `History`, while the viewer heading remains `Search history`. The ChatTimeline/ToolTimelineItems rendering and Chat-local search mechanics remain unchanged.
- Result timelines consume the shared `timelineView` preference without changing archive queries, result scope, or permissions. Conversation changes only the presentation of the messages already returned; CTX expansion remains explicit. See [D-webui-timeline-view](../modules/webui.md#d-webui-timeline-view).
- Browser fixtures verify Timeline grouping, independent paging, tool/CTX/image behavior, reference paste and deployment subpath. Backend HTTP fixtures and the shared source contract are described in [context compaction and recall](../threads/archive-and-recall.md#d-context-history-search-viewer).

The search form and result sections share the centered reading-column cap and outer gutter with non-full-width Chat and Tasks, without reserving minimap space. Individual result cards retain their internal padding. Geometry is canonical in [D-webui-shared-content-width](../modules/webui.md#d-webui-shared-content-width).

## Workbench header integration

The normal sole-tab header controls and empty-header pane movement use [Single-tab headers](./webui-workbench.md#single-tab-headers). Standalone and embedded leaf roots retain their existing navigation and do not own Workbench tabs.
