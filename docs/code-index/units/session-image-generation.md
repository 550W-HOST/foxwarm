# Unit: Separate image generation

Files: `dotnet/Foxwarm/Sessions/SessionManager.ImageGeneration.cs`, `dotnet/Foxwarm/Models/ImageGenerationRequests.cs`
Secondary files: `dotnet/Foxwarm/Models/SessionChatService.cs`, `dotnet/Foxwarm/Sessions/SessionOwner.cs`, `dotnet/Foxwarm/Tools/MainLocalToolDefinitions.cs`, `dotnet/Foxwarm/Tools/SessionToolExecutor.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Authorization.cs`, `dotnet/Foxwarm.Tests/Models/SeparateImageGenerationTests.cs`

`imageGeneration.mode: separate` exposes `generate_image` instead of the native conversation image tool. Omitted mode and `hosted` keep native hosted generation. The earlier `isolated` spelling remains accepted as a compatibility alias; new configurations should use `separate`, avoiding confusion with legacy Agent isolation metadata. No file rewrite is required to keep existing configurations working.

`SessionChatService` captures the concrete model and catalog before each attempt's declarations. During its tool loop, declarations, discovery and dispatch use that captured leaf, including failover and session-hash routes. The separate request retains that leaf rather than rerouting with a fresh image cache key. A changed explicit model selection invalidates the previous selection. Outside an active model turn, only a directly selected concrete model can supply this capability; a virtual route has no adopted tool-producing leaf yet. Hosted and disabled models neither declare nor discover this builtin, and guessed direct/unified calls are rejected before dispatch. Normal tool authorization still applies to an enabled capability.

The Session boundary validates a bounded visual prompt and at most eight same-Session image IDs. IDs resolve against current and archived caller history before any provider request; credentials and filesystem paths are not accepted. Successful images return through the existing `imageParts` reference carrier and normal tool-image persistence/delivery. Missing images become a normal tool error.

`ImageGenerationRequests` owns the dedicated request policy: prompt/reference-only history, fixed image instructions, no functions or search, a single forced native image tool, one attempt, cancellation propagation and no reasoning. Its wire builder is selected before ordinary Responses planning; reserved `extraFields` cannot restore reasoning, ordinary conversation state, functions or cache continuation. Image options use the same native image-tool builder as hosted generation. Other provider extensions retain their established behavior. The separate request never changes Session reasoning effort or appends a detached assistant message into canonical history. HTTP and WebSocket use the same policy through `ModelRequestOwner`, retaining secret masking, text redaction, diagnostics and request journal handling.

`SeparateImageGenerationTests` exercises HTTP/WS tool loops for concrete, failover and session-hash selections, including a failed primary, exact image-leaf affinity, mixed-mode failover rejecting a guessed separate call, normal high-effort preservation, ownership and journal references, one-attempt failures and cancellation. Declaration/discovery/direct/unified authorization tests cover hosted, disabled, separate and legacy modes. Wire policy tests reject reasoning and ordinary-history overrides from `extraFields`.
