## Purpose

Owns the pure timeline row model. `buildTimelineRows` derives groups, tool-run membership, per-row layout and visibility fields, Conversation Activity slices, reasoning runs, and data-only Search projections, and reuses unchanged row objects. Reasoning recognition and Activity summaries live beside it.

## Key Exports

- `buildTimelineRows(input, previousCache)` — pure derivation of the render model; returns the row list plus the identity-reuse cache
- `isReasoningPart` / `getReasoningText` / `getReasoningRuns` — known-reasoning recognition and original-index, message-local contiguous display runs; only visible summaries become body text.

## Behavior

- The browser-local `timelineView` selects Detailed, Grouped, or Conversation. Detailed/Grouped retain the established tool grouping and manual/tail disclosure behavior below. Conversation derives visible original-index body slices and continuous technical activity rows in the same row owner, with CTX cards as hard visible boundaries. Full mode and Search contracts are canonical in [D-webui-timeline-view](../modules/webui.md#d-webui-timeline-view).
- Activity rows start collapsed, including the live tail. Explicit disclosure mounts only their technical fragments in a Detailed nested timeline; ordinary text and independent model images are not repeated. The summary uses supported nonzero statistics, with no Error aggregate. Only the complete committed history tail retry is an independent original card; Chat supplies full history separately from its viewport, while nested and queue timelines supply no tail authority. The existing height-transition/viewport mechanism owns disclosure movement; nested details add no top-level anchors. Activity details omit the CTX nesting margin without changing real nested CTX or ordinary user layout. The statistics and error contracts have one canonical owner in D-webui-timeline-view.
- Tool call and tool response messages are grouped: consecutive model (with functionCall) + tool pairs collapse into a summary card that can be expanded. The summary counts each visible tag instead of repeating it and keeps failed calls in their own counted entry. A model text/system part or independent visible model image splits the group that contains it: thinking before that output stays with the group that ends there (counted in its `REASONING ×N` and hidden until that group is expanded), while the output and everything after it belong to the next group, so that group's summary counts only the parts from that output on. A metadata-classified display-only LLM retry notice is the exception: it is a system-like group member, contributes one `LLM error` tag item per prefix-free body line, and stays paired across continuous call/result rows. An ordinary-output-only model message with no tool call of its own never owns the tool run that follows it, so every run renders its summary exactly once even when a text-bearing row such as a CTX-BLOCK row or an LLM retry notice precedes it. A group without tool calls renders no summary row, so thinking with no group to fold into (a plain reply, or the final tool group that is kept expanded) keeps its ordinary Reasoning card. An image-only model message without a tool call stays an ordinary row between adjacent tool groups rather than joining either group; a mixed image-plus-call row begins the next run after its ordinary image. Inline image, blob reference, and unavailable-image displays follow the same boundary; tool-response images identified by tool association stay with their call/result and never split a run.
- A whole `foxwarm-system` wrapper of kind `event` or `goal-reminder` joins an existing tool run. Historical groups count each kind under its own system-tone icon/tag; other input and system-message boundaries remain unchanged. The timeline derivation decision below owns the full membership contract.
- `Chat` passes the current runtime's `running-tool` state only to the committed timeline. `timelineRows` combines it with the existing final standalone call/result-run index and includes the derived `runningTool` field in row identity reuse, so runtime-only changes reach tool cards. Whole Event/Goal reminder rows retain their existing transparent tail/pairing semantics; nested archive and queued timelines receive no live execution flag. Each card independently checks its paired response and streaming state; result-label rendering belongs to [webui-tool-timeline](./webui-tool-timeline.md).
- Model reasoning runs are built before visible/surface filtering. The first original-index run owns any actual message reasoning-token display, while grouped summaries count every actual reasoning part, including empty ones. Per-part body markers keep Search offsets local. Canonical contract: [D-webui-contiguous-reasoning-cards](../modules/webui.md#d-webui-contiguous-reasoning-cards).
- Pane-local Search reuses `getPartDisplayText`, `findAttachmentCorrelations`, and `stripGeneratedDescriptorLines` from ordinary user rendering, so generated attachment metadata do not become false matches. It parses pasted blocks before removing ordinary wrapper metadata: metadata-shaped characters inside pasted content remain literal. Display-math/Mermaid, commit controls, citations, and inline pasted controls are excluded from the parent text surface when locating an ordinary match.
- A data-only second `buildTimelineRows` pass expands discovered historical group keys for the Search projection so Event/Goal reminder members omitted by the normally collapsed row model keep their own row and group identities; the mounted Timeline does not expand all groups.
- Optional Search selection opens only its owning historical group and card through transient reveal props, independent of manual disclosure; CTX selection removes the summary clamp but never invokes archive expansion. Ordinary/nested/read-only Timeline callers need no search controller. Chat highlights the current word in mounted rendered text without mutating React DOM nodes. Scope: [D-webui-chat-session-search](../modules/webui.md#d-webui-chat-session-search).
- Timeline rendering is driven by an explicit row model: one pure temporal prepass compares the next request start (timestamp fallback) with the preceding persisted timestamp for optional separators, retaining strict CTX range starts; `buildTimelineRows` scans the message list for group membership, safe time boundaries, summary tags, aggregate usage, folded thinking, the kept-expanded tail group, and each row’s layout/visibility/anchor fields. `ChatTimeline` only maps resulting rows and independent divider siblings; `MessageRow` reads one row object, so the renderer never reconciles parallel per-index arrays. Groups and rows are rebuilt on message-list identity change, but equal values reuse previous objects so a stream update leaves unaffected rows mounted.

## Design Decisions

- [2026-09-18] Timeline derivation is owned by `timelineRows.ts` and exposes one `row` object per rendered surface; `MessageRow`'s memo compares `row` by identity. The builder is the only place allowed to decide group membership, summary tags, aggregate usage, folded thinking, kept-expanded groups, and row layout/anchor classes — keep those decisions out of the render bodies so an incremental change cannot desynchronize them. Identity reuse is a value-equality decision made inside the builder (equal derived values reuse the previous object); it is what keeps a streaming delta from re-rendering every row (measured on a 1200-message fixture with long tool results: one streaming increment committed ~22 ms and touched exactly one DOM node, versus ~324 ms and ~3290 DOM nodes when the previous per-index prop plumbing re-rendered rows). Do not reintroduce per-index side arrays or identity-unstable derived objects for the row props; extend `TimelineRowView`/`sameRowView` instead. A row outside any callable run has `group: null` — group state is only consumed by the model/tool render branch, so non-groupable rows deliberately do not carry an enclosing group.

A user-role message containing one whole `<foxwarm-system>` wrapper of kind `event` or `goal-reminder` (structured `system` part or standalone text-backed history wrapper) belongs to an existing tool run, not a new run of its own. Collapsing a tool-containing run hides the original system cards and counts `Event ×N` and `Goal reminder ×N` separately using their existing system-tone icons; expanding restores complete cards in source order. Calls and results remain paired by tool-use ID across either intervening kind, and a trailing event or reminder does not collapse the final tool run. A wrapper outside a tool-containing run remains visible and cannot claim a later run. Direct-user quoted/inline text, mixed compact-completion-plus-reminder parts, external-input metadata, and other system kinds still bound separate messages; selecting Detailed keeps their system cards and paired tool cards visible.
