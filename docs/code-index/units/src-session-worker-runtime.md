## Purpose

Provides durable ownership/mailbox coordination, save-before-ack authoritative state persistence, a pure bounded projection DTO, supervised process lifecycle, and the activated child caller of the canonical SessionTurnRunner. With `sessionWorkers:true`, production SessionRuntime and ordinary channel ingress use the exact Worker owner; the child uses fixed Main reverse services for supported tool, history, intermediate/final delivery, and presentation paths.

## Key exports

- `SessionWorkerStore` — SQLite-backed generation/incarnation ownership, durable mailbox intents, acknowledgement cursor, activity, exit, cleanup, and fail-closed cursor reconciliation.
- `SessionWorkerStore.findOwnership()` — non-creating exact ownership lookup used by presentation readers so checking a later local owner never creates or revives a Worker fence.
- `SessionWorkerSupervisor` — one-child-per-session candidate activation, exact-process startup reconciliation, idle release, bounded drain/TERM/KILL, exit confirmation, and optional post-exit restart.
- `SessionWorkerPersistence` — versioned authoritative JSON replace/legacy upgrade plus canonical pending-prefix apply/save-before-ack recovery; callers choose only a bounded count and cannot supply intent payload rows.
- `SessionWorkerPersistence.persistActivated()` / `reloadActivated()` — generation/incarnation-verified complete turn-state save without advancing the mailbox cursor, plus exact-owner resync from authoritative JSON after a failed run.
- `buildSessionWorkerProjection()` — pure cloned bounded DTO builder with no catalog writer or ownership protocol.
- `sessionWorkerControlServiceDescriptor` — minimal versioned candidate identity/activation/status control service used while the real session service is still being implemented.
- `SessionWorkerHost` / `sessionWorkerRuntimeServiceDescriptor` — one process-lifetime exact owner, canonical runner, worker-local effects/ExecRuntime, version-5 activated `loadProjection`, `runPending({limit})`, exact settings/history/index/snapshot/fork-notification operations, exact idle `compactAwaited`, persisted safe-point mailbox ingestion during an active turn, and post-append typed intermediate/final delivery through Main.
- `SessionWorkerIngressCoordinator.ensureWorkerOwner()` / `SessionWorkerSupervisor.loadProjectionActivated()` — ensure/spawn the exact durable owner and, when the generation has no committed projection, force one authoritative load/legacy upgrade/full projection publication even without mailbox work; an already-loaded generation reuses its projection so busy-owner reads do not queue behind the turn, and mere process activation is not treated as semantic readiness.
- `SessionWorkerIngressCoordinator.submitEnsuringWorker()` — the closed Main ingress operation that ensures or spawns an inactive exact Worker generation through the supervisor, then appends one durable mailbox intent and invokes that Worker's `runPending`; `submitQueuedInput()` remains the ready-only variant.
- `SessionWorkerIngressCoordinator.enqueueEnsuringWorker()` — the event-producer variant with local queue-and-trigger parity: resolve/ensure and the durable intent append are awaited, then processing is triggered detached. Producers must never await the target's turn (an awaited send whose target replies to a busy-mid-turn source deadlocks); a post-append processing failure leaves the durable intent retryable.
- `SessionWorkerStore.listSessionsWithPendingIntents()` / `resumeSessionWorkerPendingIntents()` — startup discovery of sessions holding durable unapplied mailbox intents and their non-fatal ensure/run resume; per-session failures keep the work retryable. With a candidate provider it also eagerly resumes sessions whose authoritative JSON still says busy (crash-after-ack with no pending intent); the fresh worker clears the stale flag and re-triggers the canonical runner inside its own ownership on load.
- `SessionWorkerStore.reconcileDrainedMailboxCursor()` / `performSessionWorkerHandback()` / the worker runtime `idleStatus` method — the release boundary: exec/busy/queue-aware idle postponement, mailbox-cursor reconciliation against the authority while the fence is draining, and read-only Main catalog-stub refresh before fence release (including clearing hydrated stub history and refreshing Worker-owned settings such as `verbose`).
- the worker runtime `interrupt` method / `SessionWorkerSupervisor.interruptActivated()` — the closed fenced stop: immediate in-memory stop signal plus provider abort, detached serialized transactional `stopping=true` persist.
- `SessionWorkerStore.deleteSessionRows()` / `teardownSessionWorkerForDelete()` — the worker-fenced half of closed delete: interrupt, graceful stop with handback, durable fence/mailbox removal requiring an inactive fence; lifecycle failures propagate so callers fail closed.
- `readSessionWorkerProcessIdentity()` — Linux boot-ID plus proc start-tick identity used to distinguish an exact old process from PID reuse.
- `sessionWorker.ts` — child bootstrap for the shared-gate control and runtime services.

## Durable records

`state/session-runtime.sqlite` contains:

- `session_worker_ownership`: one row per session with process generation, random incarnation, candidate/ready/draining lifecycle, PID plus process identity, activation time, acknowledged mailbox cursor, activity timestamp, and last exit reason;
- `session_worker_mailbox`: immutable idempotent input intents with per-session intent identity and optional applied generation/incarnation/time audit fields.

`state/sessions/<id>.json` is the sole full semantic authority and carries `sessionStateVersion:1` plus `lastAppliedMailboxId`. Unversioned files are seeded once from historically catalog-only stats/meta/vector fields and rewritten; current v1 files exactly replace semantic state and cannot inherit stale stub values. The worker applies only the exact ordered pending prefix for that session, and only store-read canonical intent rows reach the callback. It durably replaces the complete JSON, then marks rows applied and advances SQLite's cursor in one transaction. Numeric gaps for globally allocated IDs belonging to other sessions are valid. Recovery acknowledges `JSON > SQLite` without reapplying and rejects `SQLite > JSON`; applied-row deletion is a later bounded operation limited by the acknowledged cursor. Mailbox payloads accept only strict JSON values and use stable object-key ordering; descriptor-only traversal prevents getters from executing, and invalid/cyclic/non-finite/sparse/accessor/non-plain values fail before a database write. Exact duplicate intent insertion is one database-level idempotent transaction across concurrent connections.

Schema open sets the busy timeout before lock-taking pragmas, migrates known version zero/one state inside `BEGIN IMMEDIATE`, records `user_version=2`, validates exact columns, state-dependent ownership and mailbox-application constraints, uniqueness/partial-index semantics, canonical strict-JSON payload rows, and cursor/application row ordering, and rejects unknown newer versions. Version zero/one payloads are strictly canonicalized inside the rollback-safe migration; version one head columns are intentionally removed because semantic state remains in per-session JSON. A legacy inactive ownership row remains inactive, while any legacy noninactive row without provable process identity becomes an unproven retained fence.

## Lifecycle

- A new random incarnation starts as a durable inert `candidate` only from `inactive` state. The child exposes only activation control and cannot run active methods yet.
- Main verifies session ID, generation, incarnation, PID, boot identity, and proc start ticks; it durably registers the candidate and marks it activated before asking the child to verify that exact row and open its activation gate.
- Main establishes provisional ownership and exit/error/disconnect tracking immediately after `fork()`, before process-identity reads or RPC transport construction. Any post-fork startup failure must confirm that exact `ChildProcess` exit before an unregistered candidate can be cleared; unconfirmed exit retains the candidate fence and a supervisor lifecycle failure. A main crash before registration leaves an inert candidate that cannot activate, while registered candidates and activated owners retain exact process identity for startup reconciliation.
- IPC disconnect removes readiness but retains ownership until process exit is observed.
- Idle or explicit release records `draining`, attempts RPC drain, then escalates through SIGTERM and SIGKILL within a bound. Idle release first queries the worker's exact `idleStatus` and postpones while the owner is busy, has queued work, or has running background exec processes; a worker that never loaded has nothing to hand back.
- After accepted RPC work drains, graceful Worker cleanup awaits the process-owned ToolScript/Monty pool close before reverse-service teardown, IPC disconnect, process exit, handback, and fence release. Startup cleanup uses the same close without creating an unused runtime; persisted ToolScript run/snapshot files remain untouched.
- Exit observation runs the supervisor's single injected handback step before the fence is released: Main reconciles the mailbox cursor against the authoritative JSON (`reconcileDrainedMailboxCursor`: JSON-ahead acknowledges without reapply, SQLite-ahead fails closed) and refreshes the Main presentation stub strictly read-only from that authority (never from the projection); catalog-only `meta.lastChannel` is preserved across the mirror, and Main remains the sole catalog writer. A failing handback retains the fence and fails closed on both stop and crash paths. A candidate that exits inside the activation window skips the handback entirely (it never touched the authority) so its fence releases and the session stays retryable.
- Replacement/restart is scheduled only after exit observation and handback successfully return ownership to `inactive`.
- Startup reconciliation compares boot/start identity before signaling an old PID, never signals a reused PID, and clears the fence only after the exact incarnation is proven gone. Unreadable/unprovable identity or unconfirmed exit retains the fence and fails startup placement.
- Drain/exit database failures never skip process termination. Stop reports lifecycle persistence failure after real exit; shutdown terminates every tracked PID concurrently, aggregates errors, and leaves any unrecorded fence intact.

## Invariants

- At most one activated generation/incarnation is recorded for one session.
- Candidates cannot hydrate, process, touch activity, or acknowledge mailbox inputs before durable activation. Stale generations/incarnations cannot advance the mailbox cursor or replace a current owner.
- SQLite acknowledgement can never advance before the authoritative JSON cursor.
- There is no session-worker catalog writer, generic main-mutation claim, or standalone release/handoff API. Main catalog projection and lifecycle handback use the closed supervisor-owned SessionRuntime flow described in the integration section.
- Invalid/reused mailbox intent identities fail closed; exact idempotent repeats return the original record.
- Draining generations may publish one final revision before confirmed exit.
- The supervisor never treats IPC disconnect alone as permission to replace a worker.
- This process boundary provides fault containment and throughput placement, not security isolation.

## Integration status

The real child registers control plus runtime services behind one activation gate. `loadProjection` hydrates/upgrades authoritative JSON and publishes a complete projection without mailbox work; `runPending` applies the shared wait/drop/defer/enqueue transition to each validated QueueItem, acknowledges that bounded prefix, and runs the shared SessionTurnRunner against the same exact owner. That runner now keeps one Worker busy claim across its iterative compact/source-turn action loop; separate source turns receive fresh turn identities without recursively re-entering Worker queue processing. Ordinary release belongs to that outer loop, while Stop/fenced turn cleanup owns its exact release call and prevents a second outer attempt if restored-busy persistence fails; the Worker effect's existing `SESSION_WORKER_RESYNCED_RETRY` branch remains the only authorized retry inside that one call. Every ingress path performs a nonhydrating loaded-catalog existence preflight before ownership/mailbox/spawn effects. Exact typed owner operations cover normal settings, history delete/clear/index, snapshot refresh, and committed-idle manual-fork notification; a busy manual-fork notification instead uses the existing durable background mailbox input so the active runner can ingest it at a canonical safe point. Display name, parent relation, pin/archive/sidebar order, session list, and other catalog/presentation fields remain Main-owned; a Worker display-name request crosses the fixed Main Management boundary. Session identity move/rename and agent-wide snapshot-affecting inheritance/isolation changes fail before effects while Worker placement is enabled rather than opportunistically hydrating authority in Main. The remaining delivery, tool-placement, compaction, publication, startup-resume, and lifecycle behavior follows the fixed-service boundaries described above and the canonical stable-ownership decision.

Model-text delivery is separate from that subscription-gated presentation channel. After each Worker canonical model append and full publication, mailbox ingest plus a compatible-input peek determines whether that iteration uses fixed `session-turn-delivery@2` intermediate or committed-final delivery. Intermediate delivery leaves `turnFinal` unset, excludes WebUI and active WeWork aggregation, carries QQ source metadata for the live/latest passive message ID and sequence, and logs failures without retry, rollback, or mutation poison. Tool terminal paths use empty-final only to close active WeWork and never resend model text; no tail duplicate-suppression state remains.

Transient presentation channel (subscription-gated): Main tracks per-session SSE subscribers (webuiChannel `sseClients`); 0↔1 transitions push `setPresentationSubscription` (current runtime descriptor v5; originally introduced in v3) to the exact ready worker, and activation re-pushes when subscribers exist. While subscribed, the worker forwards two transient, droppable, never-persisted presentation event kinds over the reverse transport (`session-worker-presentation` service, exact-worker fenced): appended-message copies (after each transactional append) and model-stream events (500ms per-streamId coalesce for cumulative-snapshot updates — WebUI replaces the draft wholesale — with a turn-end flush; structural resets forward immediately). **Core invariant: Main handlers are pure pass-throughs into the existing WebUI SSE fan-out (`broadcastMessage`) and stream-event bus (`notifySessionEvent`) — they never update semantic state, the catalog, or the stub.** Forwards are fire-and-forget on a dedicated tail, time-bounded, log-only on failure; no subscription means zero worker→Main calls; committed projection and detached history reads remain the only correction path.
