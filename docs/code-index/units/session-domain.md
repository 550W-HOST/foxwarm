## Purpose

Defines stable Session/Agent identity and message shapes used by owner/runtime, JSON authority, catalog authority, model request construction, tools, and WebUI.

## Stable symbols and callers

- `SessionIdentity` is the canonical `(sessionId, agent)` lifetime key; `SessionBoundary`/`SessionContinuation` carry fork/continuation relationships.
- `CanonicalMessage`, `FunctionCallArguments`, and `ModelRetryNotice` define validated history/tool/retry records; `SessionObservation.cs` supplies message-page and targeted status observation helpers plus the `session` parent-update dispatch. Targeted status resolves aliases to the real hot owner, accounts for that owner's persistent memory snapshot, and does not admit unknown IDs.
- `SessionBoundary.ChannelInput` creates the existing WebUI source wrapper at ingress, with source time and hint. Plain text uses one wrapper; structured input retains its parts between opening/closing parts. Deferred consumption decorates that source wrapper rather than manufacturing one later.
- `SessionNotices.Create` constructs version-1 bounded typed operational metadata and preserves original diagnostics in display-only model parts. `SessionOwner.PresentFailureAsync` deduplicates exact errors per owner, recognizes existing terminal retry tails, appends safely through the canonical save lane or publishes a temporary message when authority is unsafe or its caller requests temporary presentation. The turn runner requests temporary fallback for model-request errors not represented by a terminal retry, including failed best-effort retry-notice saves; ordinary and owner-applied compact failures retain their safe durable path. Existing visibility filtering excludes both forms from provider replay.
- `SessionWait`, `SessionWaitTimeouts`, and `WaitLiveness` distinguish declared durable waits from transient in-flight states.
- `AgentCatalog`/`AgentMemory` load Agent metadata, selected/conditional memory, manifests, and knowledge references; `SessionListQueries` builds query DTOs but does not own catalog rows.
- `SessionPresentation`, `SessionGoal`, counters, and source normalization provide stable fields for manager/save-lane/UI operations.

## Contract and side effects

These are value/domain boundaries, not persistence writers. JSON authority owns active history/queue/wait semantic instances; catalog owns Main identity/topology/presentation summaries. Agent memory selection can affect a prompt but does not mutate Session history until a turn save commits its canonical result.

## Tool argument parsing

`FunctionCallArguments.Parse` is the shared canonical boundary for Responses HTTP/WS, Chat Completions conversion, and Anthropic Messages. Null, direct objects, empty strings and JSON object strings retain their established meanings. Malformed strings, JSON strings containing nonobjects, and raw numeric/boolean/array values produce empty `args` plus `rawArgsText` and `argsParseError`; they do not reject valid siblings or enter whole-response provider retry. Direct malformed values use Source's diagnostic string projection, including array joining, without making those values executable arguments. Ordinary strings retain their exact text.

The normal turn host returns a paired `invalid_tool_arguments` response without invoking the malformed call; valid same-batch calls proceed normally. Serializers replay parse errors as safe JSON objects containing the error and nonempty raw text, rather than forwarding invalid provider arguments. Canonical Session and Archive rows retain the original per-call error fields. `FunctionArgumentErrorTests` covers real normal-owner HTTP/WS/Messages batches, one valid sibling effect, canonical/Archive pairing and the next physical request; converter controls cover Chat Completions without adding another transport mode. The existing argument parity corpus compares the actual Source helper, retaining native JSON diagnostic wording as a compatibility category rather than an editorial contract.

## Wait-liveness observation identity

`WaitLiveness.Diagnose` traverses the current owner/catalog dependency graph and keeps the existing progress/candidate rules, grace window and four-wake admission bound. Its persisted identity matches Source `waitLiveness.ts`: compact `JSON.stringify` field order and spelling, absent `timeoutSeconds` omitted, `state` omitted for a missing Session, current runtime state for an existing owner, ordinal sorting of dependencies and serialized observations, newline join, and the first 24 lowercase hexadecimal SHA-256 digits. The existing `EcmaJson` projection is used only at this observation boundary; ordinary JSON serialization is unchanged.

The same traversal also reconstructs the original C# observation spelling as a read-only receipt alias. A matching Source or original C# fingerprint suppresses the unchanged observation without changing its wait, history or recorded fingerprints. Only newly delivered diagnostics write Source identities through the existing strict owner admission and bounded 16-entry `waitLivenessFingerprints` list. No metadata version, migration, eager normalization or background recovery pass is added. Original C# admission recorded a receipt before persisting its queued diagnostic; restart consumes that already-admitted queue normally rather than applying wait admission again.

`WaitLivenessSourceTests.cs` uses `dotnet/wait-liveness-fixture-ts.mjs` to create actual Source observations through the normal liveness/turn/persistence APIs, then exercises mandatory C# startup, strict save, reopen, repeated declarations, changed-graph delivery, input-backed progress and independent busy recovery with a localhost provider. The historical synthetic C# records in `dotnet/Foxwarm.Tests/Sessions/Fixtures/wait-liveness-csharp-v1.json` cover the old-writer/new-reader boundary; their provenance is documented alongside them. Catalog-backed idle dependencies, dependency cycles and a deleted dependency are covered without changing owner admission or startup diagnostics.

## Agent directories and retained layouts

Canonical Source-style installs store every Agent, including main, at `<Agents root>/<name>`. `state/agents.json` is the plain Source name-to-metadata map, not a membership registry. Existing non-dot, valid real directories participate in membership even without a metadata row; orphan metadata does not invent an Agent directory. Unknown metadata fields survive supported mutations. Inheritance, isolated Node and exact tool rules retain the existing metadata/evaluation owners. Framework and missing-only main-memory bootstrap use these resolved directories and packaged templates; an existing main `memory/00_SYSTEM.md` remains the framework fallback. No default Session is created at application startup.

The identified C# v1 list and v2 list-plus-metadata envelopes retain their original main-at-workspace layout through the existing explicit embedded workspace caller. They continue writing v2 metadata in that same single file. Main files/memory, non-main `workspace/agents/<name>`, stored Session cwd and the old policy workspace are not rebased or relocated. Normal entry encountering an old envelope without its original workspace rejects with guidance before creating another main-memory tree. Main-only retained callers without an Agent envelope keep their explicit original workspace. Version-1 Session authority is also written by Source and is not layout provenance; startup does not scan Session files to identify a C# layout. Without an identified legacy envelope or explicit retained caller, ordinary entry uses canonical Source paths and missing-only bootstrap, including after an explicit Agents-root change. It cannot discover an unrecorded old workspace. Desktop retains its known workspace caller. Selecting a new physical layout for old data requires a separately authorized migration, not automatic startup conversion.

Directory membership is not Session identity recovery evidence. The existing identity journal still proves its exact owned destination, unique lifetime and recovery direction before removing owned files. Unrelated directories remain ordinary Agent members, not recovered Session lifetimes. The historical unindexed-directory startup rejection is not a Source authority boundary.

## History ownership

`HistoryMessage` owns an immutable `JsonElement`: mutable JSON is serialized at admission, and externally supplied elements are cloned out of their document lifetime. Its `Data`, scalar properties, and history indexing/enumeration are read-only; `ToJson` and `SessionHistory.Materialize` explicitly create detached mutable projections. `SessionHistory` wraps a persistent immutable list. Snapshot capture shares its root, append path-copies the list with newly owned records, and retry replaces only its changed record. `SessionHistoryBuffer` changes the owner's root under the existing state gate. Registry restore and fork can share roots without sharing mutable JSON.

Compaction builds a new root while retaining unchanged immutable records; preserved-record metadata and pruned responses produce replacement records. Clear installs the empty root. Old snapshots retain their prior roots across these operations and across queue, Stop, task, and settings changes. Queue and envelope snapshots still use meaningful isolation copies. The ordinary chat path carries the captured root to its request projection so the [journal can reuse immutable record preparation](./model-journal.md#immutable-record-preparation), without looking up provenance in fresh live state. Mutable request repair, authority/Archive publication, and tool/UI JSON output use explicit projections; durable formats and Archive ownership do not change.

`CanonicalMessage` owns one private JSON tree; its part views borrow children of that tree and expose only detached JSON values. Validation/visibility inspection does not require creating a canonical copy. This is distinct from history structural sharing: caller-owned request JSON still needs an ownership boundary.

Agent removal has two catalog outcomes after exact Session cleanup: operator command deletion retains the metadata row, while WebUI deletion removes it. Retained non-main membership is removed in either case using the existing v2 writer. Directory removal precedes the metadata write, and a later writer failure remains a real partial effect. Canonical main has its exclusive directory; command deletion of main in the retained shared-workspace layout refuses before any Session/file effects. Identity recovery's owned-destination cleanup remains a separate authority.
