# Unit: Desktop packages and qualification

Files: `dotnet/scripts/desktop-window.ps1`

Secondary files: `dotnet/scripts/validate-desktop-package.mjs`, `dotnet/scripts/qualify-desktop-package.mjs`, `dotnet/scripts/qualify-desktop-mac-package.mjs`, `dotnet/scripts/desktop-cleanup.mjs`, `scripts/release/package.mjs`, `scripts/release/package.test.mjs`, `.github/workflows/release.yml`, `dotnet/Foxwarm.Desktop/Foxwarm.Desktop.csproj`, `dotnet/Foxwarm.Desktop/README.md`, `dotnet/Foxwarm.Desktop.Mac/Foxwarm.Desktop.Mac.csproj`

The Desktop editions of the [release packages](./release-packages.md): their packaging decisions and the producers and acceptance lanes that qualify them. The hosts themselves are the [Windows Desktop boundary](./host-runtime.md#desktop-boundary) and the [macOS Desktop host](./desktop-macos.md).

## macOS Desktop app

<a id="d-release-macos-desktop"></a>
**Decision: the macOS Desktop ships as a NativeAOT app in a zip without Developer ID signing** (user, 2026-11-12, Foxwarm 0.9.6). Apple Silicon trials favored NativeAOT for memory (about 70 MB against 160 MB or more for managed Debug), helper start-up (0.02 s against 0.10 s) and size (224 MB bundle). The `desktop-osx-arm64` target publishes the [AppKit host](./desktop-macos.md) with `-p:PublishAot=true`. It archives `Foxwarm.app` as `foxwarm-desktop-osx-arm64.zip` with `ditto -c -k --keepParent`. The Apple SDK ad-hoc signs the bundle; no files may be changed after signing, so it carries no `release.json` and uses `CFBundleShortVersionString` instead. It has no notarization, dmg, installer or updater. A dmg would still need the same Gatekeeper override; the install guide gives per-archive quarantine removal.

### Bundled Code on macOS Desktop

**Decision: bundle Code with the macOS Desktop** (user, 2026-11-18), revising the 0.9.6 choice to keep it optional. As on Windows Desktop, Code opens without a separate download, at the cost of a larger ZIP. The complete pinned Code OSS and YAML resources, built-in language extensions and notices enter the shared asset pack before signing. Server packages keep Code separate.

The Apple SDK writes the bundle to `bin/Release/net10.0-macos/osx-arm64/` and leaves the publish directory empty. `package.mjs` removes the stale bundle before publishing and copies the new bundle whole. The arm64 `macos-desktop` job selects Xcode 26.3 through `DEVELOPER_DIR` without changing the image default, and pins workload manifest 26.2.10233 for its macOS 26.2 SDK. See [Desktop producer and qualification](#desktop-producer-and-qualification).

## Desktop producer and qualification

### Windows Desktop app

<a id="d-release-windows-desktop-native"></a>
**Decision: the Windows Desktop ships as a NativeAOT app** (user, 2026-11-13, Foxwarm 0.9.6), as the [macOS Desktop](#macos-desktop-app) does, revising the earlier managed decision. The `desktop-win-x64` target (`kind: 'desktop'`, `native: true`) publishes the [WinUI host](./host-runtime.md#desktop-boundary) with `-p:PublishAot=true`, keeps the Code workbench and ships no Visual C++ runtime ([static C runtime](./release-packages.md#visual-c-runtime-in-windows-packages)); it needs no .NET installation or redistributable. The asset name, layout (one `foxwarm-desktop-<version>-win-x64/` directory, `release.json` with `native: true`) and data location are unchanged, so an existing user replaces the extracted folder as before. Windows App SDK API metadata minimum is 17763; the supported Windows versions follow the .NET 10 policy.

Desktop uses the Windows App SDK WinUI component 2.6.5. Its manifest/XAML/PRI generation requires Windows tools, so the Windows job produces `desktop-win-x64` with `scripts/release/package.mjs` and the same `--native-libraries` directory as the server packages. The Ubuntu producer builds the Linux server targets and forwards the shared `code-resources` archive. Windows extracts that same pinned pack, builds the shared assets, produces Desktop, checks the Desktop's imports with `windows-imports.mjs`, fails when the NativeAOT compiler reports a warning in the Desktop's own code (`Foxwarm.Desktop.*`; Main's warnings are gated by the Tests native lane, and release publications carry no symbols, so warnings name only the caller), and runs the extracted-ZIP acceptance. The `foxwarm-desktop-win-x64.zip` artifact feeds checksums and tag publication after Windows qualification.

`validate-desktop-package.mjs` requires the NativeAOT layout: `release.json` with `native: true`, the native x64 executable, WinUI/Windows App SDK/WebView2 natives and resources, the shared resources and the Code workbench, and no .NET runtime, `*.runtimeconfig.json`, `*.deps.json` or managed assembly (any `.dll`/`.exe` outside `node_modules` with a CLR header). `qualify-desktop-package.mjs EXTRACTED_DIRECTORY REPORT` then launches the extracted app with a temporary data directory, configured Agent root, unrelated cwd and a local model and embedding peer. It attaches to WebView2 for native cookie sign-in, the authenticated WebSocket and Setup, executes the packaged esbuild/sharp, runs a native ToolScript turn with the exec helper, and indexes and searches through exactly one packaged Vector child (`Foxwarm.Desktop.exe --foxwarm-vector-child`), which loads `lancedb_ffi.dll` while Main does not. The process must not load `coreclr.dll`, `hostfxr.dll`, `hostpolicy.dll` or `clrjit.dll`. Window and notification-icon checks use `dotnet/scripts/desktop-window.ps1`, which touches only the Desktop process's own windows: Explorer must hold the icon (a no-op `NIM_MODIFY` succeeds only for an existing icon); closing the window (`WM_CLOSE`) hides it while Main stays ready and the icon stays; the icon's double-click notification shows it again; the icon's right-click opens the native menu (`Open`, `Exit`), whose **Exit** item is clicked with the mouse. Exit must end the process with status 0, log `Main stopped.` and end its child processes. A restart keeps origin, token, models and history, and `/admin/shutdown` ends the app with status 0. A `--tray` start must register the icon without a visible window or a WebView2 process; a second `--tray` start must exit by itself; opening from the icon must sign in the WebView2; `--exit` must end the app with status 0, one more `Main stopped.` and no remaining child process, and `--exit` with nothing running must succeed. Interactive file dialogs, Windows sign-out, real-keyboard and HiDPI behavior are outside this lane.

The [macOS Desktop](#macos-desktop-app) producer extracts `code-resources` into the existing preparation paths, publishes with [Code bundled](#bundled-code-on-macos-desktop), and logs the ZIP size. `qualify-desktop-mac-package.mjs EXTRACTED_APP REPORT` runs on Apple Silicon against the extracted bundle with a temporary data directory, configured Agent root, unrelated cwd and `TMPDIR`, and a local model and embedding peer. It checks identity/version, required resources and notices, no managed assemblies, debug symbols, installers or instance data, and `codesign --verify --deep --strict`. `otool -L` must show only system and bundled .NET runtime libraries for the executable, and no Homebrew dependencies for any bundled native. It runs the bundle's esbuild and sharp. WKWebView has no remote debugging protocol, so the window is read through the Accessibility API (System Events, which the hosted runner allows for `osascript`): the signed-in application ("Open setup") must render, without "Sign in again" or the startup label. Unauthenticated `/api/auth/session` is refused. The check requires Code OSS, built-in language and YAML resources and notices in `Contents/MonoBundle/foxwarm.assets` and fetches the authenticated `/vscode-web` bootstrap and workbench JavaScript. The test then exercises PTY input/output/resize/cancel, Setup save, a native ToolScript turn with the exec helper, and Vector indexing and search through exactly one packaged Vector child, which maps LanceDB, while Main maps neither LanceDB nor libvips (`lsof`). Quit Foxwarm through the menu must end the process with status 0, log `Main stopped.` and leave no child process. A restart keeps origin, token, models and history, and a second launch while the window is closed must exit 0 and reopen the window. `/admin/shutdown` must also end the app with status 0. Interactive file dialogs, quarantine handling, the WebKit profile and real-keyboard or VoiceOver behavior are outside this lane; WebKit's profile under the runner's Library is left to the disposable runner.
