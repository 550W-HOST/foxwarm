## Callers and metadata

`ExternalCommands` reads one embedded command metadata resource. Help, Telegram registration and administrator `GET /api/commands` project the same completed set. WebUI rows retain leading-slash names, description, nullable usage, `requiresSession`, `showInTelegram` and autocomplete trees. `/messages` and `/delete-messages` are executable and WebUI-visible but absent from Telegram registration and ordinary help. `/btw`, `/verbose` and `/compact tools` have owner-backed effects and metadata. `/agent delete` is available through the same authorized, Session-optional family and requires explicit confirmation. Existing `/session delete` retains its separate lifecycle safeguards.

`HandleExternalCommandAsync` is the shared text command entry; selected-Session WebUI calls supply their actual owner and command-reply closure. Replies are source-facing text, not serialized route/tool result envelopes. Correlated WebUI controls stay in `HandleControlAsync` and retain one bounded feedback event plus fresh state, without a command-history row. Catalog-only presentation commands remain before owner lookup. Existing WebUI move/delete calls retain their typed result/error envelopes as well as source-facing replies. Restricted WebUI identities reject recognized catalog commands before reaching this dispatcher; slash-prefixed ordinary text remains eligible for normal message admission.

The generic external Router checks direct/wildcard authorization before administrative command dispatch, so override-only senders continue through ordinary chat. Telegram's existing earlier direct command hook remains distinct and can use the authorized conversation override. This is not a new common authorization middleware. `/whoami` still runs before authorization, binding or guest work.

## Owner-backed behavior

- `/session` resolves an existing external binding explicitly; non-current commands such as list, new/create, explicit snapshot refresh, parent/unparent, archive/unarchive and explicit delete do not require an attached current Session. List pages use Main catalog/projections, include archived rows and non-WebUI attachment targets, and do not enumerate semantic owners. Create flags are strict, repeatable selected-memory files stay selected, and current/child model-effort plus Node inputs use existing creation and validation owners. A configured target Agent default Node takes precedence over the implicit current-owner fallback, following [Agent placement](./session-domain.md#agent-creator-metadata-and-admission).
- Model and child-model commands submit the model/effort pair in one settings commit. Exact matches precede case-insensitive unique displayed-key substrings; ambiguous/missing input does not mutate settings. `/model` retains the valid selected/default catalog key for its displayed selection and current marker, while the resolved leaf supplies effort capabilities. Explicit incompatible effort fails the pair, while a model-only switch retains the existing normalization that clears incompatible old effort. Threshold, display name, refresh, clear, fork, identity move and presentation operations reuse their existing save/catalog/lifecycle owners.
- `/fork` preserves its raw multiline initial message and leaves the parent attachment in place; `/session fork` rebinds to its created fork. An omitted `/session fork` suffix uses the existing owner's `fork` default and numbered collision allocation; `/fork` retains its distinct generated suffix. The direct fork refuses an already-existing requested child ID. Identity move keeps target-first option grammar and reports the committed target, aliases, child-reference updates and separate requested-parent failure without adding a transaction or rollback guarantee.
- Agent deletion confirms the literal canonical ID-prefix selection and retained Archive boundary. It retires attached/current members sequentially, sends Stop and settles busy work in the same request, removes the Agent folder and retains metadata. It keeps raw surviving-child links, unlike coordinated WebUI deletion. The retained shared-main layout refuses before effects, and a non-main metadata-owned survivor outside that prefix keeps its folder with a partial-effects diagnostic. [Session lifecycle](./session-manager-lifecycle-identity.md#agent-deletion-callers) owns admission, exact retirement and partial cleanup.
- Agent commands use canonical directory membership and existing metadata, isolation, inheritance and creation operations. Command-created Agent memory receives the standard generated `SOUL.md` through a narrow existing-owner input. Inheritance rejects an isolated parent at the Source command boundary; it does not silently refresh unrelated Session snapshots.
- `/skill` reuses `Skills`. Generic `requiresSession:false` entry receives no implicit attached owner and therefore falls back to main; actual explicitly selected WebUI entry uses its selected Agent. Show returns the entry document and resource names, not eagerly loaded resource contents. Attach/detach report their removal.
- Timer commands use existing timer CRUD, timer-specific isolation checks, scheduler and captured placement. They are not automatically calls through the generic model-tool policy gate. `/timer list` retains message details and distinguishes inline ToolScript from file-backed ToolScript with its source Node (or current) and path. No new timer store, scheduler or Session allocator exists. `/search` deliberately calls `ArchiveRecallTool.ExecuteAsync`, retaining recall authorization, Agent scope and optional Vector availability rather than bypassing them.
- `/messages` reads active history offsets, not Archive seqs. Its bounded per-message preview includes role, timestamp, non-context marker and the existing text/tool/image forms without creating history. `/status` uses the actual owner's model/effort, memory/context, usage, Node/cwd, compact threshold, child policy, wait/runtime and recent-child projections; it does not hydrate unrelated children. Its Node display uses the existing effective DTO projection, including an offline Agent binding when retained authority has no explicit selection, without saving or changing placement.
- Native `/node` operator commands reuse the approved registry, live connection hub, bootstrap and selection owner. List, pairing help, initial credential creation, approve/reject, revocation and rename return human-readable summaries and explicit credential-bearing administrator replies. Existing C# `/node inspect` presents the full public Node summary as indented JSON, retaining services, protocol and tools rather than a list row. Bootstrap commands preserve deployment prefixes and explicit IDs; omitted IDs use `my-shell` for shell credentials and `my-node` for generic CLI examples. Chat selection refuses changes for an isolated Agent even when selecting its bound Node; valid lower-level bound-Node selection remains supported. These commands manage client trust, not Provider environments.

## Detached BTW requests and active-history controls

`SessionManager.RunBtwAsync` ensures the real cache key before capturing the immutable history root and detached authority settings. It uses the existing model request owner, detached memory preparation, copied tool schema and captured execution environment with journal purpose `btw`. The side question is a separate text part after the trusted BTW system wrapper. Provider retry/routing stays ordinary, without canonical retry notices, task-reminder mutation, normal streaming callbacks or foreground cancellation registration. The WebSocket scope retains its separate BTW cache partition; other providers reuse the captured lineage. Returned function calls are never dispatched. One canonical display-only model notice carries the actual concrete/virtual attribution on success, empty output or denied tools, or the formatted request error. The append occurs outside provider retry, followed by transient non-WebUI delivery.

The side operation joins the existing accepted-operation drain. A completed identity move resolves through retained aliases; deletion is never undone by implicit Session creation. If its target has been deleted or shutdown has closed admission, result publication fails through the existing owner boundary. Shutdown cancels provider work before closing its dependencies. Neither this lifetime nor ordinary main Stop claims foreground/busy/queue ownership for BTW.

`/delete-messages` parses a signed integer prefix, clamps to the available active rows and removes oldest rows for positive counts or newest rows for negative counts. The ordered save lane replaces the immutable active root, advances `historyVersion`, clears legacy indexing state and adjusts any legacy vector position while retaining Archive rows, branch/block identities and the next message sequence. It adds no idle-only gate or forced Stop. Concurrent canonical appends stay ordered; an incompatible pending compaction cannot restore the deleted prefix.

`/verbose` inspects or persists the boolean through the existing settings lane. Its actual authorized top-level tool-start consumer is described by [Session tool execution](./tools-registry.md); command inspection and disabling do not emit tool broadcasts.

## Parser and failure boundaries

The text callers retain Source whitespace tokenization without shell quote processing. Timer options stop at message text, and the optional `--` separator is consumed only there. Single-token cron presets such as `@hourly` work. Multi-field expressions cannot reach this text caller intact: an unquoted first token can itself be a valid shortened cron expression, with remaining fields treated as message text; quoted input retains the quote in the first token and can fail schedule validation. API/scheduler multi-field support is unchanged.

`/session compact-threshold` floors the parsed token count after applying the optional `k` multiplier, then submits that result to the [settings lane](./session-save-lane-state-ops.md). A positive spelling that normalizes to zero, such as `0.9`, fails there without changing the saved override or effective policy. Valid fractional/unit inputs retain their normalized integer values; `clear|unset` explicitly removes the override. This is distinct from the threshold tool's unfloored numeric input and inspection behavior.

`MessageRouter.TryReadCommand` classifies complete, case-sensitive `ExternalCommands` catalog heads using the existing Source `CommandSpace` grammar: optional leading whitespace, the command name, and whitespace or end-of-input. Unknown slash text and absolute paths (including `/session/file` or `/stop.txt`) are ordinary input; their original text and attachments are preserved. Recognized heads retain argument validation and command replies/errors rather than falling back to chat. Raw arguments retain multiline content and trailing whitespace. U+0085 is not Source command whitespace, so it does not expose a hidden command through a later .NET-only whitespace pass: presentation, identity-move and correlated-control dispatch are also gated by shared classification.

WebUI upload validation and restricted-identity checks reuse this classifier. Restricted checks inspect both the effective text and joined text parts, including the existing optional mention prefix; known commands cannot be hidden behind whitespace, mentions or an independent `text` field. Uploads accompanying known commands remain rejected, while path-prefixed messages can carry attachments. The generic external Router uses the same catalog classification before its existing authorization/override-only gate, and unknown slash text follows ordinary authorization-gated media materialization and queue admission. Telegram's direct command hook retains its separate authorization semantics.

Manual `/compact [keep%]` forwards a valid positive percentage up to 100; malformed/absent input uses the configured fallback. `/compact tools [keep%]` uses the same percentage fallback and the existing response-only pruning/save-lane owner without the automatic relative-reduction gate or a provider call. Its text reply reports actual response/message counts, inspected/recent rows and token estimates; correlated WebUI controls emit the existing single feedback event. Ordinary text replies and correlated feedback remain separate presentations of existing owner outcomes. Creation/binding, Agent files, timer scheduling and identity moves retain their existing partial-commit and failure semantics; command presentation does not add cross-owner atomicity.

An uncorrelated selected-WebUI `/compact` command returns HTTP 200 with `success:true` after delivering its text reply, including when awaited compaction could not claim the foreground processor. Busy release precedes processor finalization; HTTP callers waiting to start awaited compaction must also observe foreground `runtimeState.processing` settlement. A correlated `/compact` request reports actual new admission as HTTP 202 with `accepted:true`; a no-op reports HTTP 200 with `accepted:false`.
