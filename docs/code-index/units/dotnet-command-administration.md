## Callers and metadata

[2026-11-14] User decision (phase B of [D-ctl-command-registry](./ctl-command-registry.md#d-ctl-command-registry)): `/X …` and `ctl X …` are the same command as far as possible; only authority and presentation differ. User commands are the [ctl registry](./ctl-command-registry.md)'s `user` ingress, parsed with the ctl grammar. People are the only users of `/` commands, so their spellings follow the registry rather than earlier forms.

`UserCommands` generates the catalog from the registry: heads are `/help`, the registry shortcuts (`/stop`, `/continue`, `/dequeue`, `/btw`, `/model`, `/fork`, `/compact`, `/status`, `/whoami`) and every noun with a user command. Help, Telegram registration (every head) and administrator `GET /api/commands` project the same set. WebUI rows keep the leading-slash name, description, nullable usage, `requiresSession`, `showInTelegram` and an autocomplete tree built from each command's options and positional words, with enumerated values as literals. There is no hand-maintained catalog file. The former `/search`, `/messages`, `/delete-messages`, `/verbose` and `/attach` heads are now `history search`, `session messages`, `session delete-messages`, `session verbose` and `channel attach`; their old text is ordinary input.

`HandleExternalCommandAsync` is the shared text command entry; selected-Session WebUI calls supply their actual owner and command-reply closure. It parses with `CtlParser.ParseUser` and runs the command's registry `user.handler`. Handlers call the owner operations the model's commands also reach (Session manager, catalog presentation, lifecycle, settings lane, Skills, timers, Node registry, channel bindings) with the user's authority, not the model tool wrapper and its calling-Session policy, and reply with human text rather than the tool result envelope. Parse errors and `/help [noun] [verb]` use the shared ctl help with the `/` prefix. Model-only commands and parameters are unknown to users, and user-only commands and parameters (Session controls, BTW, verbose, message previews and deletion, Agent deletion, Node pairing reject/rename, channel administration and Weixin login) are absent from the model and external views.

`HandleWebCommandAsync` keeps the WebUI-specific outcomes: catalog presentation commands (archive, parent changes) still run before owner lookup, move and delete keep their typed result/error envelopes, and correlated controls (`/stop [--compaction]`, `/continue`, `/dequeue`, `/compact`) stay in `HandleControlAsync` with one bounded feedback event plus fresh state and no command-history row; a malformed control is a 422 control error. Restricted WebUI identities reject recognized command heads before reaching this dispatcher; slash-prefixed ordinary text remains eligible for normal message admission.

The generic external Router checks direct/wildcard authorization before administrative command dispatch, so override-only senders continue through ordinary chat. Telegram's existing earlier direct command hook remains distinct and can use the authorized conversation override. This is not a new common authorization middleware. `/whoami` (and `/channel whoami`) still runs before authorization, binding or guest work, whatever text follows it.

## Owner-backed behavior

- `/session` commands resolve the conversation's Session (the selected WebUI Session or the channel's attached Session) only when they need it; explicit `--session-id` or positional targets work without an attachment. `/session list [query] [--start] [--count] [--scope all|current-agent]` uses Main catalog projections (the WebUI metadata matcher for a query), includes archived rows and non-WebUI attachment targets, defaults to every Agent and does not enumerate semantic owners. Create options are strict, repeatable `--system-prompt-files` stay selected, and model/effort/Node/parent inputs use existing creation and validation owners. A configured target Agent default Node takes precedence over the implicit current-owner fallback, following [Agent placement](./session-domain.md#agent-creator-metadata-and-admission). `session new`, `session create` and `channel attach` attach the conversation.
- `/model` and `/session child-model` submit the model/effort pair in one settings commit. Exact matches precede case-insensitive unique displayed-key substrings; ambiguous/missing input does not mutate settings. `/model` retains the valid selected/default catalog key for its displayed selection and current marker, while the resolved leaf supplies effort capabilities. Explicit incompatible effort fails the pair, while a model-only switch retains the existing normalization that clears incompatible old effort. Threshold, display name, refresh, clear, fork, identity move and presentation operations reuse their existing save/catalog/lifecycle owners.
- `/session fork [suffix] [message…] [--attach]` (shortcut `/fork`) is one command: a child-mode fork with the parent notice, the raw multiline message delivered as its first input, and the conversation left on the parent unless `--attach`. An omitted name is `fork` with numbered collision allocation; an explicit name that already exists is refused. `/session move` uses the model's grammar (`[session-id] --new-session-id … [--new-agent-name …] [--create-agent] [--parent-session-id …]`) and reports the committed target, aliases, child-reference updates and separate requested-parent failure without adding a transaction or rollback guarantee.
- Agent deletion confirms the literal canonical ID-prefix selection and retained Archive boundary. It retires attached/current members sequentially, sends Stop and settles busy work in the same request, removes the Agent folder and retains metadata. It keeps raw surviving-child links, unlike coordinated WebUI deletion. The retained shared-main layout refuses before effects, and a non-main metadata-owned survivor outside that prefix keeps its folder with a partial-effects diagnostic. [Session lifecycle](./session-manager-lifecycle-identity.md#agent-deletion-callers) owns admission, exact retirement and partial cleanup.
- Agent commands use canonical directory membership and existing metadata, inheritance and creation operations. Command-created Agent memory receives the standard generated `SOUL.md` through a narrow existing-owner input. `/agent inherit <agent>` without a parent clears inheritance; it does not silently refresh unrelated Session snapshots.
- `/skill list|load` reuses `Skills` for `--agent-name`, else the conversation Session's Agent, else main. Load (alias `show`) returns the entry document and resource names, not eagerly loaded resource contents.
- Timer commands use existing timer CRUD, scheduler and captured placement for the conversation's Session. They are not calls through the generic model-tool policy gate. [2026-11-10] Like `/channel attach` and `/session`, human `/timer` commands follow the human-command authority of the channel or WebUI administrator; the timer-specific legacy isolation checks retired in R2, and the generated layer of a migrated Agent limits only its model tool calls. `/timer create` takes one of `--after-seconds`, `--at` or `--cron` and the message as rest text; `/timer pause|resume` update `paused`. `/timer list` retains message details and distinguishes inline ToolScript from file-backed ToolScript with its source Node (or current) and path. `/history search` deliberately calls `ArchiveRecallTool.ExecuteAsync`, retaining recall authorization, Agent scope and optional Vector availability rather than bypassing them.
- `/session messages` reads active history offsets, not Archive seqs. Its bounded per-message preview includes role, timestamp, non-context marker and the existing text/tool/image forms without creating history. `/status` uses the actual owner's model/effort, memory/context, usage, Node/cwd, compact threshold, child policy, wait/runtime and recent-child projections; it does not hydrate unrelated children. Its Node display uses the existing effective DTO projection, including an offline Agent binding when retained authority has no explicit selection, without saving or changing placement.
- `/node` operator commands reuse the approved registry, live connection hub, bootstrap and selection owner: `list`, `inspect`, `select`, `token` (initial credential), `bootstrap-info`, `pair-list`, `pair-approve` (alias `approve`, which deployed Node clients print), `pair-reject`, `remove` and `rename`. They return human-readable summaries and explicit credential-bearing administrator replies. `/node inspect` presents the full public Node summary as indented JSON. Bootstrap commands preserve deployment prefixes and explicit IDs; omitted IDs use `my-shell` for shell credentials and `my-node` for generic CLI examples. These commands manage client trust, not Provider environments.

## Detached BTW requests and active-history controls

`SessionManager.RunBtwAsync` ensures the real cache key before capturing the immutable history root and detached authority settings. It uses the existing model request owner, detached memory preparation, copied tool schema and captured execution environment with journal purpose `btw`. The side question is a separate text part after the trusted BTW system wrapper. Provider retry/routing stays ordinary, without canonical retry notices, task-reminder mutation, normal streaming callbacks or foreground cancellation registration. The WebSocket scope retains its separate BTW cache partition; other providers reuse the captured lineage. Returned function calls are never dispatched. One canonical display-only model notice carries the actual concrete/virtual attribution on success, empty output or denied tools, or the formatted request error. The append occurs outside provider retry, followed by transient non-WebUI delivery.

The side operation joins the existing accepted-operation drain. A completed identity move resolves through retained aliases; deletion is never undone by implicit Session creation. If its target has been deleted or shutdown has closed admission, result publication fails through the existing owner boundary. Shutdown cancels provider work before closing its dependencies. Neither this lifetime nor ordinary main Stop claims foreground/busy/queue ownership for BTW.

`/session delete-messages` takes a signed integer, clamps to the available active rows and removes oldest rows for positive counts or newest rows for negative counts. The ordered save lane replaces the immutable active root, advances `historyVersion`, clears legacy indexing state and adjusts any legacy vector position while retaining Archive rows, branch/block identities and the next message sequence. It adds no idle-only gate or forced Stop. Concurrent canonical appends stay ordered; an incompatible pending compaction cannot restore the deleted prefix.

`/session verbose` inspects or persists the boolean through the existing settings lane. Its actual authorized top-level tool-start consumer is described by [Session tool execution](./tools-registry.md); command inspection and disabling do not emit tool broadcasts.

## Parser and failure boundaries

### D-slash-catalog-classification

[2026-11-12] Only a complete, case-sensitive catalog command head selects command dispatch. Unknown slash text, including `/stpo` and `/Stop`, is ordinary model input rather than an unknown-command error. This supports paths and other slash-prefixed messages without reserving every slash word. Ordinary authorization, guest provisioning, uploads and queue admission still apply; malformed arguments to a recognized command stay in that command's validation path.

Arguments use the ctl lexer in user mode: POSIX-style quotes and backslash escapes, the `CommandSpace` whitespace set, no `@name` values (such words are literal text) and no shell-operator rejection. Options are `--kebab-case` with the camelCase spelling accepted, `--` ends options, and a rest parameter (`/btw`, `/fork`, `/timer create` messages) takes the remaining raw text exactly as typed, including newlines. A quoted cron expression keeps all its fields; an unquoted `--cron` value is one word, the rest being message text.

`/session compact-threshold` floors the parsed token count after applying the optional `k` multiplier, then submits that result to the [settings lane](./session-save-lane-state-ops.md). A positive spelling that normalizes to zero, such as `0.9`, fails there without changing the saved override or effective policy. Valid fractional/unit inputs retain their normalized integer values; `clear|unset` explicitly removes the override. This is distinct from the threshold tool's unfloored numeric input and inspection behavior.

`MessageRouter.TryReadCommand` classifies complete, case-sensitive `UserCommands` heads using the existing Source `CommandSpace` grammar: optional leading whitespace, the command name, and whitespace or end-of-input. Unknown slash text and absolute paths (including `/session/file` or `/stop.txt`) are ordinary input; their original text and attachments are preserved. Recognized heads retain argument validation and command replies/errors rather than falling back to chat. Raw arguments retain multiline content and trailing whitespace. U+0085 is not Source command whitespace, so it does not expose a hidden command through a later .NET-only whitespace pass: presentation, identity-move and correlated-control dispatch are also gated by shared classification.

WebUI upload validation and restricted-identity checks reuse this classifier. Restricted checks inspect both the effective text and joined text parts, including the existing optional mention prefix; known commands cannot be hidden behind whitespace, mentions or an independent `text` field. Uploads accompanying known commands remain rejected, while path-prefixed messages can carry attachments. The generic external Router uses the same catalog classification before its existing authorization/override-only gate, and unknown slash text follows ordinary authorization-gated media materialization and queue admission. Telegram's direct command hook classifies against the same catalog before command authorization; an unknown head falls through to ordinary ingress, including configured guest provisioning. Its known-command authorization/override semantics remain separate and unchanged. Own-bot suffix normalization applies only to recognized Telegram commands; unknown text retains its suffix and whitespace.

Manual `/compact [keep%]` forwards a positive percentage up to 100; an absent or out-of-range value uses the configured fallback, and a non-number is a usage error. `/compact [keep%] --tools` uses the same percentage fallback and the existing response-only pruning/save-lane owner without the automatic relative-reduction gate or a provider call. Its text reply reports actual response/message counts, inspected/recent rows and token estimates; correlated WebUI controls emit the existing single feedback event. Ordinary text replies and correlated feedback remain separate presentations of existing owner outcomes. Creation/binding, Agent files, timer scheduling and identity moves retain their existing partial-commit and failure semantics; command presentation does not add cross-owner atomicity.

An uncorrelated selected-WebUI `/compact` command returns HTTP 200 with `success:true` after delivering its text reply, including when awaited compaction could not claim the foreground processor. Busy release precedes processor finalization; HTTP callers waiting to start awaited compaction must also observe foreground `runtimeState.processing` settlement. A correlated `/compact` request reports actual new admission as HTTP 202 with `accepted:true`; a no-op reports HTTP 200 with `accepted:false`.
