## Callers and metadata

`ExternalCommands` reads one embedded command metadata resource. Help, Telegram registration and administrator `GET /api/commands` project the same completed set. WebUI rows retain leading-slash names, description, nullable usage, `requiresSession`, `showInTelegram` and autocomplete trees. `/messages` is executable and WebUI-visible but absent from Telegram registration and ordinary help. The unimplemented `/btw`, `/delete-messages`, `/verbose`, `/compact tools` and `/agent delete` effects are not advertised. Existing `/session delete` retains its separate lifecycle safeguards.

`HandleExternalCommandAsync` is the shared text command entry; selected-Session WebUI calls supply their actual owner and command-reply closure. Replies are source-facing text, not serialized route/tool result envelopes. Correlated WebUI controls stay in `HandleControlAsync` and retain one bounded feedback event plus fresh state, without a command-history row. Catalog-only presentation commands remain before owner lookup. Existing WebUI move/delete calls retain their typed result/error envelopes as well as source-facing replies. Restricted WebUI identities still reject slash commands before reaching this dispatcher.

The generic external Router checks direct/wildcard authorization before administrative command dispatch, so override-only senders continue through ordinary chat. Telegram's existing earlier direct command hook remains distinct and can use the authorized conversation override. This is not a new common authorization middleware. `/whoami` still runs before authorization, binding or guest work.

## Owner-backed behavior

- `/session` resolves an existing external binding explicitly; non-current commands such as list, new/create, explicit snapshot refresh, parent/unparent, archive/unarchive and explicit delete do not require an attached current Session. List pages use Main catalog/projections, include archived rows and non-WebUI attachment targets, and do not enumerate semantic owners. Create flags are strict, repeatable selected-memory files stay selected, and current/child model-effort plus Node inputs use existing creation and validation owners.
- Model and child-model commands submit the model/effort pair in one settings commit. Exact matches precede case-insensitive unique displayed-key substrings; ambiguous/missing input does not mutate settings. Explicit incompatible effort fails the pair, while a model-only switch retains the existing normalization that clears incompatible old effort. Threshold, display name, refresh, clear, fork, identity move and presentation operations reuse their existing save/catalog/lifecycle owners.
- `/fork` preserves its raw multiline initial message and leaves the parent attachment in place; `/session fork` rebinds to its created fork. The direct fork refuses an already-existing requested child ID. Identity move keeps target-first option grammar and reports the committed target, aliases, child-reference updates and separate requested-parent failure without adding a transaction or rollback guarantee.
- Agent commands use canonical directory membership and existing metadata, isolation, inheritance and creation operations. Command-created Agent memory receives the standard generated `SOUL.md` through a narrow existing-owner input. Inheritance rejects an isolated parent at the Source command boundary; it does not silently refresh unrelated Session snapshots.
- `/skill` reuses `Skills`. Generic `requiresSession:false` entry receives no implicit attached owner and therefore falls back to main; actual explicitly selected WebUI entry uses its selected Agent. Show returns the entry document and resource names, not eagerly loaded resource contents. Attach/detach report their removal.
- Timer commands use existing timer CRUD, timer-specific isolation checks, scheduler and captured placement. They are not automatically calls through the generic model-tool policy gate. No new timer store, scheduler or Session allocator exists. `/search` deliberately calls `ArchiveRecallTool.ExecuteAsync`, retaining recall authorization, Agent scope and optional Vector availability rather than bypassing them.
- `/messages` reads active history offsets, not Archive seqs. Its bounded per-message preview includes role, timestamp, non-context marker and the existing text/tool/image forms without creating history. `/status` uses the actual owner's model/effort, memory/context, usage, Node/cwd, compact threshold, child policy, wait/runtime and recent-child projections; it does not hydrate unrelated children.
- Native `/node` operator commands reuse the approved registry, live connection hub, bootstrap and selection owner. List, pairing help, initial credential creation, approve/reject, revocation and rename return human-readable summaries and explicit credential-bearing administrator replies. Bootstrap commands preserve deployment prefixes. Chat selection refuses changes for an isolated Agent even when selecting its bound Node; valid lower-level bound-Node selection remains supported. These commands manage client trust, not Provider environments.

## Parser and failure boundaries

The text callers retain Source whitespace tokenization without shell quote processing. Timer options stop at message text, and the optional `--` separator is consumed only there. Single-token cron presets such as `@hourly` work. Multi-field expressions cannot reach this text caller intact: an unquoted first token can itself be a valid shortened cron expression, with remaining fields treated as message text; quoted input retains the quote in the first token and can fail schedule validation. API/scheduler multi-field support is unchanged.

Manual `/compact [keep%]` forwards a valid positive percentage up to 100; malformed/absent input uses the configured fallback. `/compact tools` is rejected rather than starting model compaction. Ordinary text replies and correlated feedback remain separate presentations of existing owner outcomes. Creation/binding, Agent files, timer scheduling and identity moves retain their existing partial-commit and failure semantics; command presentation does not add cross-owner atomicity.
