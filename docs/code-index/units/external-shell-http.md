## Purpose and contract owner

Connects the exec-only POSIX sh/curl and Windows PowerShell 5.1 clients to the .NET host using its real HTTP protocol. This is an external Node transport, not environment provisioning. The canonical transport/output decision is [D-node-thread-shell-http](../threads/node-communication.md#d-node-thread-shell-http); current .NET integration is mapped in [Remote Node compatibility](../threads/remote-node-compatibility.md#net-external-node-integration).

## Stable symbols and callers

| Symbol | Responsibility |
| --- | --- |
| `NodeConnectionHub.RegisterShellRoutes` | Installs independently credential-authenticated register, long-poll and report routes; starts process-local expiry collection. |
| `PublishShell` | Revalidates and durably touches the approved credential inside the existing identity publication/revocation lock, then replaces the exact predecessor transport. |
| `ShellRuntime.Dispatch` / `Poll` / `Cancel` / `Disconnect` | Captures the actual Main invocation/claim, resolves POSIX cwd or emits literal Windows startup/target cwd changes, queues one bounded command, removes it before handoff, and removes only unclaimed commands on cancellation/disconnect. |
| `CollectShell` | Retires only the exact expired published connection and removes expired transient task contexts. |
| `ReportShell` | Serializes task transitions, activates the exact reservation, settles foreground results, or calls existing strict Session completion admission before ACK. |
| `ShellFullText` / `ShellOutput` | Projects bounded text/binary samples, client-reported duration and total byte counts; provides exact programmatic text only when the sample is the complete valid text. |
| `ShellDefaultCwd` | Supplies startup cwd to real Node selection without executing a synthetic tool. |

The shared hub connection record contains either a real WebSocket or a Shell HTTP runtime. Ordinary Node discovery/selection/replacement/removal use that same identity map. Shell advertises only its dialect-specific `exec` capability and background-registration feature. File transfer, Code, PTY and external-owner capabilities are absent and fail at their existing capability boundaries without Main fallback. Main/CLI exec definitions remain separate and unchanged.

`NodeBootstrap` packages and serves `run-shell.sh` and `run-shell.ps1` through the actual public bootstrap route. Administrator `create-shell` uses the ordinary direct approved credential and returns its setup command only to that operation. Deployment-prefix addresses are preserved. Registration defaults to POSIX for existing clients; explicit `X-Foxwarm-Shell-Dialect: powershell` selects Windows capabilities and absolute drive/UNC startup validation without using Main-host path APIs. PowerShell executes relative paths after selecting its startup directory, so Linux Main does not reinterpret Windows paths. Windows reports accept signed 32-bit process exit codes; POSIX retains 0–255. Shell requests carry the credential in Authorization and Node identity in a header; administrator authentication cannot substitute for Node authentication.

## Implementation limits

Polling waits at most 25 seconds; polling activity controls the 90-second online boundary. Main limits each Node to 32 unfinished tasks and 32 finished transient report receipts, with a 24-hour dispatch-context retention limit. The signed completion grant and bounded durable receipt field remain owned by the existing remote-exec authority and exact Session save lane, not a second ledger. Reports cannot supply a Session or grant. Report retry never redispatches a command.

The optional official `X-Foxwarm-Elapsed-Seconds` metadata is measured by the client from process start to finish (or foreground handoff), independent of dispatch/report latency. Integer zero renders `<1s`, positive safe integer seconds render approximate duration with `~`, and absent/invalid legacy metadata renders `unknown`. Reports retain their measured value across retries; Main adds no estimator or programmatic timing field.

The original source Session/Agent, exec identity and grant are captured before dispatch. Background activation and completion retain that owner across Node selection and Session moves. A delivered command stays uncertain after disconnect; no transport expiry or host shutdown kills it. Restart does not reconstruct dispatch context or replay commands. Both clients own independent jobs, bounded 4 KiB head/tail collection and continuous output draining. The PowerShell client uses inbox .NET Framework HTTP/process APIs compiled in memory, private bounded per-job scripts and independently drained stdout/stderr pipes; it adds no installed client dependency or service. Each child reads its bounded command file into a ScriptBlock through a short encoded file-reader expression, retaining in-memory execution under stock Windows file policy without changing that policy. The HTTP worker sets the origin ServicePoint limit directly, including the existing point created by bootstrap download, so long-poll and concurrent report requests do not inherit the desktop two-connection default. Polling and report workers remain separate, and process duration freezes before report retries.

## Qualification

`ShellHttpTests` uses owned real HTTP/WebSocket hosts, actual Main-issued claims and owner save lanes. Its system `/bin/sh` case executes the actual generated curl-to-`sh -s --` command and tests missing-utility startup refusal without installation. Its unclaimed-command test observes the real 62-second call deadline without shortening the protocol. It covers independent credentials, publication/revocation serialization, precommit/committed persistence failures, HTTP/WS successor fencing, report transition concurrency, strict-save retry, task/receipt bounds, body/metadata validation, incomplete native data and absent file/service capabilities.

`ShellHttpTests.PowerShell.cs` covers Windows drive/UNC registration and literal cwd/command dispatch on any Main OS, signed Windows exit codes, served PowerShell assets, and generated CLI ScriptBlock argument binding and saved-versus-memory source/state ownership with bracket, apostrophe and Unicode roots. Portable PowerShell controls do not qualify native Windows execution. `dotnet/Foxwarm.Tests/scripts/qualify-shell-onboarding.mjs` uses production WebUI and current C# routes for explicit Windows Shell creation, direct-only authentication, method switching with one identity, streamed commands and credential discard on close.

`ShellHttpTests.Duration.cs` covers legacy/invalid/zero/positive metadata and exact background owner/receipt behavior. `experimentHostNodeConsumers.e2e.mjs` downloads the unchanged official client and qualifies short, seconds-long and background timing against the real host.

`experimentHostShellHttp.e2e.mjs` downloads the actual bootstrap script, uses real sh/curl with a restricted BusyBox utility PATH when available, and schema-checks both ordinary model requests and the actual effectful native Monty exec arguments. It checks prefixed routes, rejected error/HTML/unmarked responses, cwd/exit/empty/no-newline/overlapping/binary samples, fractional timeout rounding, 4 MiB continuous output with observed bounded intermediate files, exact background waits across selection/move, strict-save and lost-response retries with one effect/receipt, delivered tasks across HTTP replacement, restart uncertainty and credential revocation. Four 95-second jobs run alongside two concurrent 35-second foreground calls while polling stays alive across the real 90-second boundary; a separately idle HTTP registration expires. It does not qualify physical routers, every BusyBox/curl build or a 24-hour wall-clock run.
