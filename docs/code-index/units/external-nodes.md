# Unit: External Node trust and ordinary tools

Files: `dotnet/Foxwarm/Nodes/ApprovedNodeRegistry.cs`, `dotnet/Foxwarm/Nodes/NodeConnectionHub.cs`, `dotnet/Foxwarm/Nodes/NodeRoutes.cs`, `dotnet/Foxwarm/Nodes/NodeBootstrap.cs`, `dotnet/Foxwarm/Nodes/NodeToolDefinitions.cs`, `dotnet/Foxwarm/Nodes/RemoteNodeResult.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Nodes.cs`, `dotnet/Foxwarm/Sessions/SessionManager.NodeCredentials.cs`, `dotnet/Foxwarm/Sessions/Turns/SessionSaveLane.Node.cs`, `dotnet/Foxwarm/MessageRouter.Nodes.cs`

## Purpose

Records administrator-approved trust in already-running Node environments, publishes their authenticated WebSocket or exec-only Shell HTTP connections, and dispatches advertised ordinary tools. This is not a Node Provider or environment-creation service.

## Stable symbols and consumers

- `ApprovedNodeRegistry` reads Source-compatible `state/nodes.json` and `state/node_token`, with numbered/legacy registry backup readers. Atomic updates persist credential hashes, pending requests and unclaimed pairing credentials. `Create`, `Request`, `Approve`, `Claim`, `Reject`, `Rename`, `Remove`, `Touch` and `Cleanup` implement the trust lifecycle. Credentials are rechecked at registration, so removing and recreating an identity cannot revive a socket authenticated with the old credential.
- `NodeConnectionHub.HandleAsync` owns `/node_ws` authentication, registration, protocol negotiation, heartbeat, quarantine and connection replacement. `ExecuteAsync` correlates calls to the exact authenticated connection and delegates exec authority to the [remote exec unit](./remote-exec.md); `DiscoveredDefinitions` provides an atomic compatible-capability snapshot without turning an offline Node into a model-preparation failure.
- `NodeRoutes.Register` supplies administrator list/inspect, onboarding/pending/commands/create/approve/reject, rename and removal APIs. `NodeBootstrap` serves the packaged official setup templates and source archive with deployment-prefixed addresses. `MessageRouter.HandleNodeCommandAsync` serves the existing `/node` administrator command family.
- `SessionManager.SelectNodeAsync` validates the actual owner/placement and commits through `SessionSaveLane.CommitNodeAsync`. Explicit tool/command selection clears cwd; the composer passes `clearCwd:false` and retains it. Both publish only through the existing authority lane. `SetAgentIsolationAsync` uses the same lane with cwd retention only for a nonempty binding. `ExecutionPlacement` captures Node/cwd together; `ExecutionEnvironment` renders the request-time connection context without rewriting persistent Agent memory.
- `NodeToolDefinitions` provides list/select/inspect, approved pairing helpers and the hidden Main-private `node_create_auth_token` builtin. `CreateNodeAuthTokenAsync` creates an exclusive absolute Main file with mode 0600 before calling the existing registry reservation, writes the token plus newline, and returns only Node ID/path. Existing IDs, files and symlinks are never replaced; missing parents are not created. Reservation failures clean the new file and report committed registry truth, while post-reservation write failures retain the Node and report whether cleanup succeeded. Ordinary discovery, neutral calls and native ToolScript use the same handler and Main authorization/path facts even with remote execution placement. `ToolRegistry` and `UnifiedTools` consume advertised capabilities for current or explicit targets, while Main-local capabilities retain their existing implementation and authorization.
- `RemoteNodeResult.Normalize` removes the private documented path sidecar and translates documented legacy Node image carriers at ingress. For the four concrete remote file tools, a separately captured callback records bounded display-only paths with the authenticated execution Node before removing the sidecar. Arbitrary peer fields remain data and do not become Main paths, cwd mutations or control receipts.

## Current contracts

The canonical integration boundary is [Remote Node compatibility](../threads/remote-node-compatibility.md#net-external-node-integration). Pairing/approved credentials are independent of administrator cookies/tokens. Credential-bearing URLs are excluded from ordinary ASP.NET request logging. Ordinary listings never expose credential hashes or unclaimed auth tokens; approved credential/setup responses are explicitly secret-bearing administrator operations.

The negotiated protocol range is 1–3, with absent offers treated as legacy version 1. Incompatible Nodes stay connected for diagnostics and ping/pong but have no executable capabilities. Replacement rejects predecessor calls and fences its late replies/close. Capability changes take effect on the new registered connection; duplicate registration follows the official Source behavior and is ignored.

The optional advertised `get_default_cwd` is a real call, not a synthetic shell effect. Without it, selection reports an unknown default. Remote cwd strings are forwarded in the Node namespace; Main-owned memory, configuration, Archive and observation paths do not pass them through Main path resolution. Existing Main exec semantics retain a declared captured cwd and use invocation-time live cwd when the captured local value was unset.

Agent Node binding uses existing Agent metadata and owner admission/creation. Administrator Agent creation accepts `isolatedNode`; updates use the existing PUT route. The default-hidden `set_agent_isolated` model consumer sets/clears isolation and replaces the existing exact legacy rule array, with the existing isolated-caller restriction. Omitting `nodeId` preserves binding. [Remote Node integration](../threads/remote-node-compatibility.md#net-external-node-integration) defines the distinct binding, clearing and explicit-selection placement effects and active self-Agent caller contract. It is a tool-authorization boundary, not an OS/network sandbox. Offline Nodes do not block Main-owned Session history, status or deletion; remote effects fail without Main fallback. The model batch skips every remaining unstarted call after failed or canceled Node selection, including wrapped selection and a later selection call.

## Phase boundary

Advertised external exec and authenticated Node Session events are connected through the [remote exec unit](./remote-exec.md), including transient start-time authority, durable completion ACK, waits and truthful Stop. Whole-file transfer/copy, remote ToolScript source, image export/delivery and bound-Agent attachments are connected through the [file consumers unit](./external-node-files.md). Code/PTY Node consumers connect through the [fixed service transport](./external-node-services.md); The [Shell HTTP transport](./external-shell-http.md) connects the unchanged exec-only sh/curl client. Inline native ToolScript can dispatch ordinary Node tools through the same concrete registry. Protocol 3 negotiation alone does not grant external-owner or Worker behavior; Session events use authenticated placement or the exact exec completion grant. Official CLI/browser/Android client code is unchanged.

## Tests

`dotnet/Foxwarm.Tests/Tools/ExternalNodeRegistryTests.cs` covers persisted credentials/claims, expiry, backup compatibility, rename/removal, protocol negotiation and legacy result normalization. `ExternalNodeRevocationTests.cs` pauses the actual registry persistence primitive during real HTTP/WebSocket registration to establish publication/revocation serialization, then exercises removal/rename, selection refusal and normal successor registration. It also covers precommit versus committed revocation failures. `dotnet/Foxwarm.Tests/Sessions/SessionNodeCommitTests.cs` covers real pre/post-rename placement publication with explicit-selection cwd clearing and Agent-binding cwd retention, plus remote cwd exclusion from Main paths. `NodePrivateCredentialTests.cs` covers Main policy/isolation, exclusive files/symlinks, private permissions, registry pre/postcommit faults and canceled writes after real reservation. `experimentHostNodeConsumers.e2e.mjs` proves private credential authentication with owned official clients, native Monty, original composer selection/binding/busy/restart and process duration. `packages/webui/test/experimentHostExternalNodes.e2e.mjs` starts owned real host/client processes and exercises the official CLI, official Chrome MV3 extension, model/native ToolScript dispatch, authorization, selection batching, restart, identity correlation, fencing and browser image/heartbeat paths. Its binding cases include the active self-Agent model caller, HTTP/model clears, bind/rebind/rule-only retention, literal remote namespace dispatch and follow-on official-client file effects without Main fallback. Physical Android hardware is not qualified by these tests.
