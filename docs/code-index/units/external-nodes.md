# Unit: External Node trust and ordinary tools

Files: `dotnet/Foxwarm/Nodes/ApprovedNodeRegistry.cs`, `dotnet/Foxwarm/Nodes/NodeConnectionHub.cs`, `dotnet/Foxwarm/Nodes/NodeConnectionHub.Sessions.cs`, `dotnet/Foxwarm/Nodes/NodeRoutes.cs`, `dotnet/Foxwarm/Nodes/NodeBootstrap.cs`, `dotnet/Foxwarm/Nodes/NodeToolDefinitions.cs`, `dotnet/Foxwarm/Nodes/RemoteNodeResult.cs`, `dotnet/Foxwarm/Sessions/SessionManager.Nodes.cs`, `dotnet/Foxwarm/Sessions/SessionManager.NodeRequests.cs`, `dotnet/Foxwarm/Sessions/SessionManager.NodeCredentials.cs`, `dotnet/Foxwarm/Sessions/Turns/SessionSaveLane.Node.cs`, `dotnet/Foxwarm/MessageRouter.Nodes.cs`

## Purpose

Records administrator-approved trust in already-running Node environments, publishes their authenticated WebSocket or exec-only Shell HTTP connections, and dispatches advertised ordinary tools. This is not a Node Provider or environment-creation service.

## Stable symbols and consumers

- `ApprovedNodeRegistry` reads Source-compatible `state/nodes.json` and `state/node_token`, with numbered/legacy registry backup readers. Atomic updates persist credential hashes, pending requests and unclaimed pairing credentials. `Create`, `Request`, `Approve`, `Claim`, `Reject`, `Rename`, `Remove`, `Touch` and `Cleanup` implement the trust lifecycle. Credentials are rechecked at registration, so removing and recreating an identity cannot revive a socket authenticated with the old credential.
- `NodeConnectionHub.HandleAsync` owns `/node_ws` authentication, registration, protocol negotiation, heartbeat, quarantine and connection replacement. `ExecuteAsync` correlates calls to the exact authenticated connection and delegates exec authority to the [remote exec unit](./remote-exec.md); `DiscoveredDefinitions` provides an atomic compatible-capability snapshot without turning an offline Node into a model-preparation failure.
- `NodeConnectionHub.HandleSessionRequestAsync` routes the existing CLI list/history/send frames to `SessionManager.HandleNodeSessionRequestAsync` and replies on that exact connection. `NodeHistoryMessage` preserves the CLI's text/system/image/tool history rendering, message indexes and optional timestamp without changing canonical history.
- `NodeRoutes.Register` supplies administrator list/inspect, onboarding/pending/commands/create/approve/reject, rename and removal APIs. `NodeBootstrap` serves the packaged official setup templates and source archive with deployment-prefixed addresses. `MessageRouter.HandleNodeCommandAsync` serves the human-readable native client trust/selection command family, including secret-bearing initial credentials and live approval; [command administration](./dotnet-command-administration.md) owns its actual chat-caller distinctions.
- `SessionManager.SelectNodeAsync` validates the actual owner/placement and commits through `SessionSaveLane.CommitNodeAsync`. Explicit tool/command selection clears cwd; the composer passes `clearCwd:false` and retains it. Both publish only through the existing authority lane. `SetAgentIsolationAsync` uses the same lane with cwd retention only for a nonempty binding. `ExecutionPlacement` captures Node/cwd together; its shared `ResolveExecutionNode` chooses trimmed stored selection, then recorded Agent binding, then `master`. Owner/history DTOs and admitted-owner list projections use that resolution without saving a default into retained authority. `ExecutionEnvironment` renders the request-time connection context without rewriting persistent Agent memory.
- The discoverable, non-default `node_remove` builtin calls `SessionManager.RemoveNode` and the existing `NodeConnectionHub.Remove` revocation owner. It returns `{nodeId, disconnected}` with disconnect presence captured under the same registry/publication lock. Precommit failures retain the active connection; committed registry failures still disconnect and surface the durability error. Removal does not terminate clients, remove files or alter Agent/Session placement. Normal authorization precedes this operation, and removed credentials cannot republish a connection.
- `NodeToolDefinitions` provides list/select/inspect, approved pairing helpers and the hidden Main-private `node_create_auth_token` builtin. `CreateNodeAuthTokenAsync` creates an exclusive absolute Main file with mode 0600 before calling the existing registry reservation, writes the token plus newline, and returns only Node ID/path. Existing IDs, files and symlinks are never replaced; missing parents are not created. Registry failures attempt to clean the new file and report the cleanup outcome. A committed registry error leaves the requested reservation unconfirmed: `Create` may have committed expired-pairing cleanup before attempting that reservation, so the caller must inspect the registry before retrying. Post-reservation token-write failures retain the known reserved Node and report whether file cleanup succeeded. Ordinary discovery, neutral calls and native ToolScript use the same handler and Main authorization/path facts even with remote execution placement. `ToolRegistry` and `UnifiedTools` consume advertised capabilities for current or explicit targets, while Main-local capabilities retain their existing implementation and authorization.
- `RemoteNodeResult.Normalize` removes the private documented path sidecar and translates documented legacy Node image carriers at ingress. For the four concrete remote file tools, a separately captured callback records bounded display-only paths with the authenticated execution Node before removing the sidecar. Arbitrary peer fields remain data and do not become Main paths, cwd mutations or control receipts.

## Current contracts

The canonical integration boundary is [Remote Node compatibility](../threads/remote-node-compatibility.md#net-external-node-integration). Pairing/approved credentials are independent of administrator cookies/tokens. Credential-bearing URLs are excluded from ordinary ASP.NET request logging. Ordinary listings never expose credential hashes or unclaimed auth tokens; approved credential/setup responses are explicitly secret-bearing administrator operations.

The negotiated protocol range is 1–3, with absent offers treated as legacy version 1. Incompatible Nodes stay connected for diagnostics and ping/pong but have no executable capabilities. Replacement rejects predecessor calls and fences its late replies/close. Capability changes take effect on the new registered connection; duplicate registration follows the official Source behavior and is ignored.

The optional advertised `get_default_cwd` is a real call, not a synthetic shell effect. Without it, selection reports an unknown default. Remote cwd strings are forwarded in the Node namespace; Main-owned memory, configuration, Archive and observation paths do not pass them through Main path resolution. Existing Main exec semantics retain a declared captured cwd and use invocation-time live cwd when the captured local value was unset.

Agent Node binding uses existing Agent metadata and owner admission/creation. Administrator Agent creation accepts `isolatedNode`; updates use the existing PUT route. Clearing binding recaptures the affected already-admitted owners' bounded list projections before announcing topology, without admitting cold Sessions or saving placement/cwd. The default-hidden `set_agent_isolated` model consumer sets/clears isolation and replaces the existing exact legacy rule array, with the existing isolated-caller restriction. Omitting `nodeId` preserves binding. [Remote Node integration](../threads/remote-node-compatibility.md#net-external-node-integration) defines the distinct binding, clearing and explicit-selection placement effects and active self-Agent caller contract. It is a tool-authorization boundary, not an OS/network sandbox. Offline Nodes do not block Main-owned Session history, status or deletion; remote effects fail without Main fallback. The model batch skips every remaining unstarted call after failed or canceled Node selection, including wrapped selection and a later selection call.

The unchanged CLI's `session_list_request`, `session_history_request` and `session_send_message` receive correlated `cli_response` objects with `ok` plus `result` or `error`. List uses catalog/live projections without admitting cold owners. History and send resolve canonical IDs/aliases through existing membership and admit only existing owners. Access requires current effective Node placement or an isolated Agent bound to the authenticated Node, not an administrator principal. History rechecks assignment after admission, returns the established eight-field summary and indexed text messages, and retains the default 30 and 1–100 count bounds. As in Source, fractional counts truncate the start only for row selection; emitted index labels retain the fractional start. Send wraps the selected trigger/background/onboot event through normal Session ingress, rechecking placement and connection after awaits before queue admission. Replacement, revocation and shutdown fence unsent work and late responses; responses never move to a successor connection. Pairing and incompatible-protocol quarantine remain unchanged.

## Phase boundary

Advertised external exec and authenticated Node Session events are connected through the [remote exec unit](./remote-exec.md), including transient start-time authority, durable completion ACK, waits and truthful Stop. Whole-file transfer/copy, remote ToolScript source, image export/delivery and bound-Agent attachments are connected through the [file consumers unit](./external-node-files.md). Code/PTY Node consumers connect through the [fixed service transport](./external-node-services.md); The [Shell HTTP transport](./external-shell-http.md) connects the unchanged exec-only sh/curl client. Inline native ToolScript can dispatch ordinary Node tools through the same concrete registry. Protocol 3 negotiation alone does not grant external-owner or Worker behavior; Session events use authenticated placement or the exact exec completion grant. Official CLI/browser/Android client code is unchanged.

## Bootstrap address ownership

Authenticated Nodes-modal command generation selects an explicit `baseUrl`, otherwise the startup configured public URL, otherwise the browser's `fallbackUrl`. An empty `FOXWARM_PUBLIC_BASE_URL` override suppresses the configured URL and leaves the public address undeclared, matching normal startup; onboarding then uses the browser fallback. Invalid explicit values, including an empty `baseUrl`, fail rather than falling back; generated commands preserve the deployment path and contextual shell/PowerShell quoting. Shell creation validates this selection before issuing its one-time credential. CLI bootstrap information retains its existing address owner.

Public template GETs instead substitute the validated first forwarded-host/Host and HTTP(S) forwarded/actual request protocol, as in the original bootstrap renderer. Invalid hosts produce an empty script default; configured public URLs and mount paths are not silently substituted into a downloaded script. Path-prefixed instructions supply an explicit host argument. All templates use this renderer, including the interactive alias; templates without a placeholder remain unchanged. These request-derived defaults are confined to bootstrap text and do not affect listening, authentication, cookies or global public-address capture.

`dotnet/scripts/qualify-bootstrap-default-tools.mjs` checks real browser-shaped commands, explicit/configured/browser precedence, public templates and forwarded/prefix inputs through owned authenticated/public HTTP requests. `dotnet/scripts/qualify-onboarding-empty-override.mjs` exercises normal startup with absent/empty overrides, including suppression of a configured public address, and checks command/Shell selection plus explicit validation before credential creation.
