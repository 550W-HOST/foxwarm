## Purpose and current boundary

Provides the shared external-channel authorization, routing, persisted attachment, delivery, transient progress and managed-lifecycle path, with Telegram Bot API polling, the [Matrix/Weixin transports](./dotnet-matrix-weixin.md) and [WeWork callback/WebSocket/stream/media transport](./dotnet-wework.md). The [official QQ Bot gateway and media adapter](./dotnet-qqbot.md) shares these owners. Main TUI and the final entry/service cutover are separate work. Public administration is mapped in [command administration](./dotnet-command-administration.md). The TypeScript [channel module](../modules/channels.md) remains a compatibility/reference map, not a claim that those adapters run in .NET.

## Stable symbols and callers

- `ExternalChannelContext` keeps channel type, configured instance, conversation, sender and reply closure separate. A target splits at its first colon; the conversation remainder is not split again.
- `ChannelRegistry.Register`/`Get`/`SendAsync` own the single transport registry shared by WebUI, managed adapters and temporary MCP reply contexts. Registration does not create a persisted attachment. Text-only registrations adapt to the richer text/file/typing/lifecycle contract. Native progress and lifecycle-active hooks are optional parts of that same registration, not another transport registry.
- `ChannelAuthorizationOwner.Inspect` combines the captured startup allowlist with the current configured allowlist, type/instance wildcard rules and the persisted per-conversation override. Telegram uses the actual sender ID before conversation fallback.
- `MessageRouter.HandleExternalMessageAsync` performs discovery, authorization/guest provisioning, shared command detection, exact binding resolution, optional authorization-gated current-message materialization and ordinary User queue admission. Original ingress authorization is captured before guest creation; first guests do not gain media-fetch permission from the resulting attachment override. Slash detection uses original text before ingress metadata is placed inside the direct-channel User wrapper. Callbacks and turn-presentation IDs are transient, not Session/tool/history fields. `HandleExternalCommandAsync` is also Telegram's direct pre-Router command hook. The completed shared command set is available through the actual selected-Session Main-local WebUI entry; see [command administration](./dotnet-command-administration.md).
- `SessionManager.ResolveChannelAsync` serializes creation for an unbound conversation, durably binds the new owner and compensates a failed creation/bind. An existing binding to a missing owner is an error, not permission to allocate a replacement. `AttachChannel`, `SetChannelBinding` and `DetachChannel` reuse the existing attachment store and identity admission.
- `RecordLastChannel` writes catalog metadata, not Session JSON authority. `BestChannel` retains narrow current-wrapper and legacy `FROM:`/backtick source readers before the attachment-order fallback.
- `SaveInboundChannelFileAsync` uses the existing Agent/Node file and image owners. `SaveInboundChannelFileFromPathAsync` saves a bounded spool to the already resolved Session through the shared atomic path copier on Main, or the existing whole-buffer Node path under its fixed 10 MiB QQ cap. Raster bytes cross the canonical image-blob owner before queue persistence. `ChannelFileNames` shares the naming/XML descriptor grammar with WebUI ingress without merging external media admission with WebUI upload staging.
- `ChannelAssistantCommittedAsync` presents committed intermediate/final model text and generated image refs. All ordinary automatic text and terminal lifecycle sends are fire-and-forget; they do not hold processor ownership, busy release, next input, Stop or owner drain on platform acknowledgement. Generated image delivery retains its separate awaited contract. Explicit tools continue to await actual transport success or failure.
- `ChannelProgress.Report`/`Decorate`/`Finish`/`Reset` provide bounded target-local ordinary fallback presentation with injectable time for tests. Top-level provider tool calls feed neutral names/counts; exact `wait` is silent in ordinary fallback. Provider-neutral `ChannelTurnProgress` carries top-level LLM/batch-tool facts with stable IDs, original names, statuses and optional model text to native channel hooks; active native targets bypass fallback decoration and sends. Progress never becomes canonical text, another model input or a delivery ledger.
- `ManagedChannels.ReloadAsync`/`ChangeAsync`/`Statuses` start, stop, restart and describe managed Telegram, Matrix, Weixin, WeWork and QQ Bot instances through the small `IManagedChannel` contract. There is no universal async lifecycle lock across joined adapter handlers; the Source-aligned ordering and retained Weixin self-join limitation are documented in [Matrix/Weixin](./dotnet-matrix-weixin.md). Main starts them with its normal host lifetime. The managed owner retains initializing adapters as well as running transports: ingress stop closes admission under the same gate as transport registration, stops both sets and joins original initializers through their cleanup. A stopped initializer cannot register or create its configured attachment later. This is not a universal async lifecycle lock or a change to adapter network timeouts. Configuration/Setup/`set_config` share the existing installation lane and reload all managed instances, including unchanged entries. Reload does not unregister WebUI or temporary MCP transports.

## Admission, commands and persistence

Unauthorized `/whoami` reports only the current sender/target, without attachment resolution, guest creation or model admission. Ordinary admitted content is `QueueItemType.User` with external `QueueSource`, never inter-Session or task authority. Source-time/hint wrappers preserve body whitespace, structured image parts and escaped attributes; send-only remains inbound-enabled and carries its explicit-reply notice.

The generic Router command gate protects override-only conversations from administrative slash commands. Telegram's Source direct command hook is a distinct earlier entry path and is preserved as such; it is not described as a stronger common command middleware. Single/inherited guest allocation uses the existing Agent and Session creation owners, with their isolation/Node validation and partial-effect semantics.

The existing `channels.json` owner accepts supported legacy string/object bindings, `push-only` and the old group-wide flag. Normal writes use current names. Ordinary mutations retain live state if persistence fails; a critical bind restores its prior live map and surfaces its error. This is not a transaction across channel, Agent and Session files. Identity rewrite and deletion retain their existing claims and representation-sensitive behavior; see [coordination storage](./session-deletion-storage.md).

The shared [command administration owner](./dotnet-command-administration.md) defines catalog/help/autocomplete, source-facing replies, actual caller distinctions and completed effects. Channel runtime/auth/mode/override and attach commands continue using these same channel owners, including actual `/channel weixin status|login|wait` through the [configuration/Setup owner](./dotnet-matrix-weixin.md#configuration-setup-and-lifecycle-ordering).

## Delivery and lifecycle

Automatic text, generated images, typing and progress use normal persisted attachments and skip send-only targets. Automatic text excludes WebUI, whose committed-event path already presents the message. Temporary MCP reply contexts are unattached and therefore receive no automatic fanout. Empty terminal turns schedule a lifecycle hook without sending empty Telegram text. Successful finish-after-send handoffs remain terminal; explicit waits and handoff waits carry a separate suspended lifecycle, with neither terminal text nor `TurnFinal`. Passive WeWork presentation stays open across that ending. The runner finalization hook closes transient presentation before releasing/retriggering its processor without awaiting automatic text or lifecycle delivery. Escaped failures can produce terminal presentation only before a final has been handled; a later strict idle-release or post-final maintenance failure retains its existing persistence/error/busy rollback behavior without a second external semantic final. Interrupted shutdown does not fabricate a terminal response. Display-only `llm-stop` notices remain canonical history/WebUI records, not additional channel finals. Automatic transport failures remain diagnostic-only, without a replacement model failure or replay.

`send_to_channel` keeps caller authorization, exact-owner admission and isolated own-attachment restrictions. `send_file` keeps existing Node staging/path authorization and receipts while dispatching supported external transports. Session fanout reports successful deliveries, send-only/no-file skips and unavailable/failed destinations; explicit direct failures remain failures. Neither operation creates destination history or queue rows. A successful API response is a transport outcome, not proof that a person received or read it.

Retry presentation sends the initial/final Source channel snippets rather than cumulative stored notice text; a terminal retry attempt suppresses a second generic request-failure response. Generic terminal failures send the existing plain error form, not the stored notice markup.

Progress is disabled without a valid configured interval from 30,000 to 1,800,000 milliseconds. It has fixed cadence, running heartbeats, per-target counters/baselines, bounded retained state and one-hour idle expiry. Normal automatic text consumes its own target's pending counts; direct tools are not decorated. Completion does not wait for an in-flight standalone progress send, and reload resets/fences future progress work.

## Telegram wire contract and deliberate media order

The adapter follows the used Telegraf 4.16.3 path: register commands, resolve bot identity, delete the webhook without dropping pending updates, then poll from offset zero. Batch offsets advance to the last update plus one; polling makes its final offset-sync attempt after abort/handler settlement. Stop aborts polling without joining handlers or final offset sync, including installer reload and Main shutdown. Main retains ownership of adapter startup, ingress abort and dependency teardown, while accepted Session owners retain their own drain boundary. HTTP status 500 and above is classified as a server error before parsing the body, including non-JSON gateway bodies. Network/429/server polling failures retry with the existing Source delay rules; 401/409 terminate polling without offset sync.

Text and photos ignore bot senders; the document path intentionally retains Source's missing bot guard. Own-bot command suffix handling and multiline raw arguments use the pinned adapter behavior. Photos choose the final supplied size; documents retain caption/name/MIME. Both download through `getFile` and the file endpoint, store escaped descriptors and canonical image refs, then schedule Router ingress.

**Telegram media storage remains eager and precedes Router authorization.** The adapter also intentionally passes its type (`telegram`), rather than a named instance ID, to the retained storage helper. Thus unauthorized media can leave stored bytes, and a named instance does not gain attachment-aware placement from a different instance binding. This is the preserved contract, not authorization-first deferred media admission. An effectively isolated bound Session stores on its existing current non-master Node or bound Node; a non-isolated selected remote execution Node does not redirect storage. Image blobs remain Main-owned.

Outbound text/photo/document sends use Markdown with one plain fallback for the Source payload/parse error condition. Other sends retain at most four attempts with 5/10/10-second delays. Upload streams reopen for each actual attempt. Request-context replies schedule observed sends; explicit tools await the transport. No new chunking, outbox, ack ledger or vendor delivery guarantee is introduced.
