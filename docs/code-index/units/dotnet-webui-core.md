# Unit: WebUI channel registration and shared DTO contract

Files: `dotnet/Foxwarm/Channels/WebUi/WebUIChannel.cs`, `dotnet/Foxwarm/Channels/WebUi/WebUIChannel.Nodes.cs`, `dotnet/Foxwarm/Channels/WebUi/WebUiContract.cs`

## Purpose

Registers the .NET WebUI route surface and defines shared request/response/event DTOs, route limits, deployment-relative identifiers, and host-to-client compatibility shapes.

## Stable methods and callers

`WebUIChannel.Register` composes route groups and injects `SessionManager`, `SessionRuntime`, `TaskService`, `ImageBlobStore`, `TerminalRegistry`, `CodeWorkbench`, and realtime publisher dependencies. `WebUiContract` owns parsing/serialization helpers and bounded pagination/operation results consumed by all partial route units and React WebUI units.

## Contract and side effects

Ordinary Session creation and Agent-main creation place the newly committed root first in the sidebar. Session IDs supplied to the HTTP creation route are not trimmed into a different identity; invalid new leaves fail before allocation. Explicit reserved-ID creation reports a conflict rather than creating a replacement lifetime. Agent creation checks an archived main identity before creating its directory, and the WebUI does not allow an isolated Agent as an inheritance source.

The authenticated model-settings HTTP boundary normalizes trimmed model selections and case-insensitive trimmed effort selections before entering the existing strict settings owner. Empty/default/unset effort clears the raw setting; model selections also recognize clear. Child settings accept `childModelDefault`/`model` and `childEffortDefault`/`effort`, with canonical child fields taking precedence even when null. An explicit model takes precedence over `clear=true`. Unknown fields and invalid values retain validation errors; this does not loosen internal settings DTOs or model/runtime effort validation. `AgentSettingsParityHttpTests` covers actual HTTP bodies, persistence, alias precedence, invalid controls, strict internal callers and shared isolated-source inheritance rejection through Agent PUT.

Canonical message content is projected through [WebUI message transport](./webui-message-transport.md) before browser delivery, independently of the shared image converter. Internal Session and provider consumers retain full canonical messages.

Routes are registered behind `HttpServer` normal auth. DTO validation precedes manager/runtime calls; this file does not write Session JSON, Archive, or catalog directly. Accepted/committed/partial failures retain explicit status fields for browser state reconciliation.

Authenticated `GET /api/sessions/{id}/nodes` reads catalog identity and real Node topology without admitting a Session owner, returning `nodes[{id,label,selectable,reason}]` and `lockedReason`. Approved offline and incompatible choices retain useful reasons; Agent-bound choices are locked and scoped to that binding. `POST /api/sessions/{id}/node` admits the actual owner and delegates selection with cwd retention, returning `{session}` after durable publication. The original composer permits busy selection; no new busy/Worker restriction is added. Its semantics are governed by [the original composer decision](./webui-chat-composer.md#d-composer-session-node-picker), with explicit .NET tool/command cwd clearing kept separate in [remote compatibility](../threads/remote-node-compatibility.md#net-external-node-integration).

`WebUiContract.Session` and owner `BuildDto` project effective execution placement into history, composer responses and realtime snapshots, so the original picker survives refresh and reconnect. History resolves the Node from its captured authority snapshot through the owner's Agent binding. Both use the same resolver as `SessionManager.ExecutionPlacement`: trimmed stored selection, otherwise the isolated Agent's recorded binding, otherwise `master`. Retained authority with absent or null `currentNode` therefore presents its actual execution Node without writing a selection or changing cwd, history, settings or usage. Main catalog listings remain bounded projections; rendering does not admit other catalog members or change identity/alias ownership.

For administrators, `WebUiContract.History` returns `persistentMemorySnapshot` verbatim from the same captured `SessionSnapshot.AuthorityEnvelope` used for messages and history boundaries, with an empty string for absent/null values. Full, tail, prefix and after-sequence responses share this projection; reads do not rebuild memory or consult a later owner snapshot. Session state and catalog/list projections remain prompt-free. The original Chat synchronization owner consumes this history metadata; active-history Detailed/Grouped views show its synthetic top snapshot, while continuous history retains its existing suppression. Memory-only refresh does not alter history version/count, so an unchanged reconnect may skip history I/O; a normal history reread or App reload observes the newly persisted prompt.

History projects supported queued user, intersession, background, trigger and onboot inputs separately from committed rows. Compact wakes and unsupported control kinds are excluded. Existing system wrappers remain intact; unwrapped non-user text/thinking becomes a queued-event system wrapper with its source Session. Prebuilt messages retain their role and metadata. `SanitizeQueuedPreviewParts` clones parts, bounds only top-level text/system/thinking to 4,000 UTF-16 units plus the truncation marker, and replaces inline attachments with an omission label. Nested application values remain intact. At most 20 preview rows retain their original queue indices and the existing omitted count. Preview construction never rewrites queued input or canonical history. `WebUiQueuePreviewTests.cs` and `WebUiAdjacentProjectionTests.cs` cover real peer/task/trigger/Node event producers, passive admission, wrapper/prebuilt handling, controls, limits and unchanged authority. Canonical queue consumption publishes one `history-append` WebSocket envelope with the exact appended rows, remaining queue preview and captured history boundaries. Session state precedes this batch, following the original producer contract; the unchanged client can move both timeline sides atomically. Legacy per-Session SSE expands the same batch into its existing individual `message` envelopes.

Optional `controlRequestId` is a nonempty string of at most 128 UTF-16 units, validated separately from composer `clientMessageId` before command dispatch. Correlated controls use the router's existing message route and revisioned Session-event transport; admission is not completion. History uses the exact owner's current runtime projection with the same builder as live/reconnect and list/Architecture overlays, including durable wait details; the history messages/frontier retain their ordinary captured-snapshot semantics.

Scoped responses omit the prompt snapshot and use role-safe Session/list DTOs. The shared live identity, default-administrator routes, text-only ingress and post-await/admission boundaries are canonical in [shared access](./dotnet-access-identities.md).

Administrator `GET /api/sessions/{id}/state` and per-Session SSE use the same owner `BuildDto` and `WebUiContract.Event` projections as WebUI, not the internal diagnostic `State()` shape. SSE registers before `connected` and its initial state; live commits retain `type: message` so the unchanged shipped Multica bin receives model text, tool results and terminal channel errors. Diagnostic-only request-progress is not a public event; ordinary model-stream events remain unchanged. Keepalives recheck scoped authority; disconnect, deletion and host stop release the owner subscription. Administrator access remains full, while scoped identities retain the existing per-Session stream allowlist and cannot read the administrator state/debug routes. No second bridge protocol or durable replay is introduced.

## Conversation request metadata

The original Conversation projection is merged from the retained frontend rather than reimplemented in this host. Normal model commits preserve `llmRequestId` from the actual request journal; live drafts use the same owner request identity, and Responses parts retain recognized explicit phases. Thus the frontend can infer unmarked commentary only from actual tools in the same loaded CTX-local request, without borrowing adjacent-request tools. Explicit phase remains authoritative and tool-free live text stays visible. The frontend contract is owned by [timeline rows](./webui-timeline-rows.md).
