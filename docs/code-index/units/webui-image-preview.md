# Unit: WebUI image preview

## Purpose

Shared full-viewport image viewer for draft images, user/history/tool images and delivered reply images. Interaction is governed by [D-fullscreen-image-preview](../threads/webui-attachment-presentation.md#d-fullscreen-image-preview); URL/MIME authority remains with the original source.

## Symbols

- `ImagePreviewDialog` — client-only portal into a native modal dialog that owns the dialog, scroll lock, focus return, the ←/→ keys and the position in the surrounding image sequence. The shown image's view is keyed by entry, MIME type and URL, so switching or a changed image resets it without resetting an unchanged live preview.
- `ImageGalleryContext`, `useImageGalleryStore` (`imageGallery.ts`) — the ordered images a viewer opened in this scope switches between, as a stable store that only open viewers subscribe to. `galleryItem` names the opener's entry (a message part object or a string key); an opener that isn't found keeps a single-image viewer.
- `buildTimelineImageGallery` (`ChatTimeline.tsx`) — the Session's sequence from the top-level timeline's row model; `replyFileGalleryEntry` (`ReplyFileGrid.tsx`) — a delivered image with its own signed path download.
- `isSafeImagePreviewMime` — shared PNG/JPEG/GIF/WebP allowlist used by the viewer and its callers.
- `Preview` — one image: fitted/intrinsic sizing, bounded zoom by touch pinch, ctrl/⌘ + wheel and WebKit gesture events, touch and mouse pan, touch swipe, image load/error feedback and source-preserving download actions.
- `requestImageDownloadUrl` — resource-specific authenticated signature issuance for global/Session blobs, with local `blob:`/`data:` passthrough.
- `lockPageScroll` — reference-counted document scroll lock, restoring the previous root/body overflow after the last shared viewer closes.

## Integration

`ImageItem` retains scoped authenticated blob URLs and legacy inline-data handling. The composer borrows its existing editor-owned object URL and never owns another File or edits the draft. Missing draft files retain the existing reattachment dialog. `ReplyFileTile` supplies its download callback, pending/error state and Main-cache URL; it requests an action-local path-download signature while retaining server-side file validation and remote provenance. Remote image-blob download actions request a fresh signature using the original global or Session blob route; local `blob:`/`data:` downloads stay local. Unsafe-format attachment download buttons also obtain a signature before native download and keep errors inline. Ordinary displayed image URLs remain unsigned and credential-protected. Authority and lifetime are canonical in [D-webui-download-capabilities](../modules/webui.md#d-webui-download-capabilities). All use the same viewer rather than opening image URLs in another tab.

The native top layer escapes pane clipping and provides keyboard focus containment. Close/Escape restores the connected opener with preventScroll. Images fit without cropping; actual size uses intrinsic image pixels and enables native scrolling for mouse/keyboard inspection. Touch pointers captured on the original image/stage target support midpoint-anchored pinch zoom and one-finger scrolling when enlarged, including a remaining finger after pinch. Zoom is bounded between fit and the larger of intrinsic size or eight times fit. Only the image surface handles gestures; page touch zoom/scroll is disabled there. Moved, multi-touch and cancelled gestures suppress their trailing click without disabling the next deliberate tap or toolbar action. Resize observation updates fitted geometry without changing an enlarged image's pixel scale. Closing aborts viewer-owned requests, while the reply tile remains responsible for its own download request. Active formats are not rendered inline.

Wheel and gesture zoom render synchronously, so each event of a gesture measures the image the previous one produced; successive wheel events at one pointer position keep the image point they started with instead of re-measuring it from rounded scroll offsets. Gesture events are ignored while touch pointers are active (iOS sends both for a touch pinch). The mouse pans only an enlarged image, from the primary button, after the same movement threshold as touch, and captures the pointer on the original target. A touch swipe switches only from fit, with one finger, at least 48 px and mostly horizontal. Ctrl + wheel and gesture events anywhere in the viewer are cancelled so the page never zooms.

The timeline sequence walks the grouped rows in order: activity rows contribute their source messages, Conversation rows their own part, other rows their message (a user message's attachment grid first, cached per message object) and the paired tool response, and each reply-file grid follows the row it is placed after. Entries are keyed by stable message key and part index, so a live message object replacement keeps the current image. Only the top-level timeline provides the sequence; nested timelines open into it. The composer provides its own draft-only sequence around its viewer.

Pan retains a floating-point intended scroll position for the gesture. Pointer movement and intended scrolling share CSS-pixel coordinates, without multiplying by image scale, device-pixel ratio or browser viewport zoom. The threshold admits the full movement since pointer-down; subsequent movement clamps the retained intent at the image's scroll bounds. This avoids losing repeated subpixel deltas by adding them to browser-rounded scroll offsets. Switching between pinch and a single remaining pointer rebases that intent from the current view. The viewer and its descendants explicitly disable WebKit selection and touch callouts; the image stage cancels touch-origin long-press context menus only. Mouse and keyboard menus remain native, with the real image as the target, preserving browser Copy/Save actions without changing zoom. `touch-action: none` alone does not suppress text selection.

## Verification

`imageParts.e2e.mjs` runs the component against managed Main behind a recording proxy, with an Archive-referenced image from the continuous-history snapshot for the scoped identity, and uses real built CSS and authenticated nested-path URLs to check full viewport geometry, image containment, focus, Escape/backdrop, scroll-lock cleanup, no popup/navigation, native cookie-less signed image download, safe filename/MIME/disposition, and unsafe-format signed attachment fallback. Chromium native touch input waits for the fitted rendered image and enabled size control, not only decoded natural dimensions, then checks off-center pinch anchoring, pinch-in to fit, pinch-to-one-finger continuation, independent pan/cancellation, trailing-click suppression, deliberate subsequent taps, unchanged source/page viewport and intrinsic sizing through rotation. Pan assertions compare exact image displacement against CSS-pixel pointer displacement, including quarter-pixel steps at multiple image scales and device-pixel ratios, unpaced input and hold-then-drag. Computed WebKit selection policy, empty selection after a Chromium touch hold, and native context-menu cancellation are checked separately. The empty-space swipe before the deliberate tap uses a native touch gesture with fling disabled: Chromium can consume a tap that stops an active fling before emitting a DOM click. These checks are mobile browser emulation, not physical iOS selection/callout evidence. A second `imageParts.e2e.mjs` case serves a static gallery of local images: ←/→ and the buttons through the sequence and its ends, focus on the pressed control, a decode error inside the viewer, reset on switch, ctrl + wheel and small pinch-like deltas keeping the image point under the pointer within 1.5 px up to eight times fit and back to fit, plain-wheel scrolling, one-to-one mouse panning without a size toggle, ←/→ scrolling an enlarged image, swipes (horizontal, vertical, at both ends and on an enlarged image) and focus return to the opener. WebKit gesture events cannot be produced in Chromium; synthetic events carrying WebKit's `scale`/`clientX`/`clientY` fields check their cancellation, cumulative scale and anchor. `messageAttachmentDrafts.e2e.mjs` covers composer entry points, retained File/ref/undo semantics and the draft-only sequence. `replyFiles.e2e.mjs` retains live-grid/modal identity, download errors and focus restoration, and walks a Session of attachment, collapsed tool image, generated image, skipped SVG and delivered image in the Detailed, Grouped and Conversation views. The framed viewer is covered with the [window frame](./webui-window-frame.md#tests).
