## Purpose and callers

Implements the used legacy group-webhook, intelligent-bot HTTP callback and optional AIBot WebSocket adapter through [shared external channels](./dotnet-external-channels.md). `ManagedChannels` constructs it from the canonical configuration object under one configured instance ID. Ingress uses the existing Router, sender authorization, commands, Session attachments and queue; files and images use the existing Main/isolated Node owners. This adapter adds no Session engine, registry, persisted receipts or replay layer.

Conversation-latest passive context and proactive priorities are governed by [channel decisions](../modules/channels.md#d-channel-conversation-latest-passive-context) and [WeWork proactive delivery](../modules/channels.md#d-channel-wework-aibot-proactive-delivery).

## Stable symbols and transport

- `StartAsync` starts the separately configured `listenPort`/`listenPath` Kestrel callback listener and/or the optional WebSocket connection. Readiness accepts a nonempty legacy `webhookUrl`, complete callback listener/token/AES-key configuration, or enabled WebSocket bot ID/secret. Callback operation is independent of administrator HTTP, WebUI, Trigger and administrator-token initialization; it does not add administrator-authenticated routes. The internal transport dependency can restrict synthetic callback fixtures to loopback.
- `VerifyCallback` requires GET timestamp, nonce, echo and matching signature. `HandleCallbackAsync` preserves JSON/XML parsing, casing/wrappers, the 100 KiB JSON/XML body limit, passive response forms and errors. **POST is not universally authenticated:** plain legacy input is accepted, and encrypted signatures are checked only when timestamp, nonce and signature are all present. Query and `x-tif-*` headers retain their actual fallback roles. Encrypted passive replies require timestamp and nonce; otherwise the passive object is plain. Missing crypto for an encrypted POST returns the existing success response without admitting the body.
- `WeWorkCrypto` implements sorted ordinal SHA1 signatures, Base64 AES-256-CBC with key-prefix IV, random 16-byte prefix, big-endian message byte length, trailing receive-ID handling and manual 32-byte padding. Resource decryption takes a per-resource key before the callback-key fallback. It does not replace this protocol with ordinary 16-byte PKCS7 or add receive-ID authentication absent from the reference.
- `ProcessInboundAsync` distinguishes sender, username, conversation/chat type and instance, strips configured self mentions through the existing Router and keeps 15-minute msgid/result deduplication. Eager text/image/file/mixed/voice/quote normalization precedes Router authorization; event input is ignored and other types retain the reference placeholders. Direct URLs and legacy `media_id` retrieval reuse the existing type-keyed `wework` file helper, not the configured instance ID. Unauthorized media can therefore leave stored bytes. Effectively isolated bindings still materialize through their current/bound Node; image blobs remain Main-owned.
- `ConnectionLoopAsync` subscribes, runs configured/default heartbeat and reconnect intervals, reassembles complete UTF-8 messages across fragments and routes message/event callbacks. It retains the reference client's 100 MiB decoded-message limit. `disconnected_event` closes the socket. Callback work is observed independently of the receive loop so an awaited command ACK cannot block that same receiver.
- `SendCommandAsync` chains commands sharing a `req_id`; different request IDs may await ACKs concurrently. `RunAfterAsync` serializes actual .NET socket writes, correlates same-ID ACKs, rejects nonzero error codes, times out after ten seconds and rejects pending work on close/stop. This is a transient protocol ACK, not exactly-once delivery, an offline outbox or a cross-connection receipt guarantee.
- `StopAsync` closes timers, socket and callback admission, clears terminal response contexts and rejects pending ACKs without joining Router/send handlers. Pending ACKs receive their stopped outcome before receive cancellation can race the close path. Newly entering requests on a draining old Kestrel keep-alive connection are aborted, matching the reference listener's idle-connection closure; already-entered callback handlers are not joined or cancelled. Already-started effects keep their actual outcomes; this adapter introduces no universal lifecycle semaphore or handler-drain framework.

## Cards, structured progress and text routes

`WeWorkStreamAggregator.Begin` supersedes the conversation's previous active card before installing the latest card, including busy/queued input. Supersession retains substantive text, removes transient thinking/tool groups and finishes with the reference nonempty fallback when necessary. HTTP callbacks return initial snapshots and pull refreshes; WebSocket callbacks push initial/progress/final snapshots and best-effort old finals on their saved request IDs. Duplicate callback results reuse the original initial response rather than allocating another card.

`Apply` resolves explicit request stream binding before explicit webhook/latest-card selection. Ongoing Session output always resolves the latest unfinished card independently for each eligible attachment, not a queued turn's old stream ID. `ApplyProgress` retains call IDs, original tool names, per-status first-occurrence grouping, same-batch counts and text-delimited groups. The provider-neutral top-level producer supplies model-start and tool-batch start/finish facts; model text and running tools enter one native snapshot. Native `wait` is retained even though exact `wait` is silent in ordinary fallback. Unchanged snapshots are not pushed again. Finalization removes thinking but retains substantive text and completed tool status.

Stream state expires after fifteen minutes. Default content budget is 20,000 bytes, configured budgets clamp to 20,480 and truncation does not split Unicode scalars. The reference's fixed truncation-marker behavior for exceptionally tiny requested budgets is retained. Progress, stream IDs and response URLs never enter history, queues, catalog, tool context or Worker metadata.

`SendTextAsync` priorities are explicit stream binding; explicit nonempty webhook override; latest unfinished card; one terminal latest `response_url`; enabled WebSocket proactive Markdown; legacy webhook. A request reply carrying both explicit stream and webhook retains stream priority. Terminal context is removed before awaiting its attempt, so a newer callback survives; failure does not reuse or cross-route it. Ordinary proactive/direct sends do not consume terminal context. Finished/expired cards use the existing proactive route without recovery. Native-active targets skip ordinary progress decoration/fallback; other conversations retain their configured ordinary progress.

## Media and partial effects

`SendFileAsync` selects explicit legacy override, otherwise enabled WebSocket, otherwise legacy-only delivery. WebSocket upload validates a regular file and the 50 MiB protocol cap, hashes sequential bytes, sends init with filename/type/size/chunk count/MD5, then zero-based sequential 512 KiB chunks and finish. Required `upload_id`/`media_id` ACK fields are validated. Zero-length files retain one empty chunk. An optional caption is a separate same-route Markdown message after upload and before proactive image/file send. There is no chunk retry/resume/cache or WebSocket-to-webhook fallback after an ambiguous failure.

Legacy image delivery sends Base64/MD5. Generic files use the legacy multipart upload and returned media ID. Captions retain their existing before-media order. Legacy webhook posts preserve up to three conditional attempts with one/two-second backoffs for network, server or API-error outcomes, but not ordinary HTTP client failures; upload and terminal `response_url` do not gain those retries. Explicit tools await actual errors through the shared direct/unified/native send owners; ordinary automatic text remains fire-and-forget and generated images retain their separate awaited contract.

## Verification and limits

`WeWorkCallbackTests`, `WeWorkSocketTests`, `WeWorkDeliveryTests`, `WeWorkTurnTests`, `WeWorkLifecycleTests`, the WeWork ingress extension in `ExternalChannelNodeTests` and mixed `McpNotificationTests.ChannelReload` use owned local crypto/HTTP/WS/model peers. They cover actual configured callbacks, conditional signatures, passive encryption and refresh, dedup/expiry, busy latest-card supersession, native and fallback progress, final/empty/wait/error/stop, multi-instance attachments, direct/unified file/text effects, chunk/hash/ACK failures, partial reloads, headless normal Main and actual CLI Node materialization. Shared post-final/llm-stop and delivery-lifetime tests retain the existing truth boundaries.

`dotnet/wework-fixture-ts.mjs` executes the retained reference adapter against a loopback-only callback fixture to compare crypto, GET/POST signatures, XML/JSON normalization, dedup, supersession and native progress. `packages/webui/test/experimentHostWeWork.e2e.mjs` exercises the original prefixed WebUI, Setup reload/status and normal Main/provider/Router with local AIBot peers, busy no-tool followup, direct/unified/native text and multi-chunk file tools, generated images and canonical browser final output. These fixtures do not qualify real WeWork accounts, vendor permissions/entitlements, external callback reachability or live delivery. QQ, Main TUI and the final default Main/service cutover remain outside this adapter.
