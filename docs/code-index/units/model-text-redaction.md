## D-model-text-redaction

[2026-11-03] Model-selected redaction is disabled by default. It replaces detected private ordinary input text on request copies, then restores only known placeholders in ordinary output and structured tool arguments. Local history is unchanged by input preparation. All thinking, reasoning summaries, signatures and encrypted blocks pass through unchanged in both directions. Request `extraFields`, headers, credentials, protocol identifiers and schema structure are outside detection. Citation offsets are not adjusted; restored text may no longer match a citation span.

[2026-11-09] Placeholders are keyed and short: `[[PRIVATE_` followed by the first 16 lowercase hex characters (64 bits) of HMAC-SHA256 over the detected original UTF-8 bytes, then `]]`. The HMAC key is derived from the shared instance key (`<data root>/keys/secrets.key`) with the HKDF purpose `text-redaction-placeholder`; there is no separate key file. Placeholders are therefore stable across Sessions and restarts of one installation, differ between installations, and a provider cannot confirm a guessed low-entropy value by hashing it. The shape is deliberately distinct from irreversible `[[FW_SECRET:<label>]]` markers and uses a fixed hex alphabet that models copy verbatim. One redactor per installation owns a bounded reverse map and a bounded detection cache. Unknown or modified placeholders remain unchanged. This is reversible substitution, not encryption. [2026-11-10, user decision] Successful detection results and the reverse map persist across restarts in an encrypted store under the data root, so history is sent byte-identically after a restart; a settings change re-processes everything ([persistence](./model-text-redaction-persistence.md#d-model-text-redaction-persistence)). This replaces the 2026-11-03 memory-only rule. Output never invokes the detector.

[2026-11-09, independent review] Three rules close gaps between detection and restoration:

- **Restoration is request-scoped.** `TextRedactionScope` records every pair one provider attempt introduces, by detection or literal masking. Only those placeholders are restored in that attempt's progress, commentary, results and tool arguments. Placeholder text that merely appears in input, for example copied from another Session through provider state, thinking or diagnostics, is passed through and never restored. Keys stay global and stable; the reverse map alone is not a restoration authority.
- **Known originals stay masked.** After every slot of a request has been detected, exact occurrences of originals retained in the reverse map are replaced in all slots as well, leftmost and longest first, whatever the detector reports for the new context. This keeps values the feature restored into history (assistant text, tool arguments and anything derived from them) protected on later requests. Literal masking skips placeholders and secret markers, needs at least two UTF-16 code units, and does not match where an original's ASCII letter or digit edge touches another ASCII letter or digit (so a short name does not replace part of a longer word; scripts without word separators match anywhere). An original detected only under labels the current settings exclude is left unchanged.
- **Literal masking is a backstop, once per slot.** [2026-11-09, delta review] The literal pass backs up detection; it is not a second detector. Its result is memoized with the slot's detection cache entry: once a slot has been through both passes, later requests reuse that result while the entry stays cached, even if more originals are registered meanwhile, so an unchanged slot keeps its form and the provider prompt-cache and WS suffix reuse are not disturbed by other Sessions. Masking a slot that was already sent would add no privacy. A memoized slot still registers every pair it uses in the attempt's scope, so its placeholders restore. Slots processed for the first time are scanned against the reverse map as it stands after the whole request was detected. The scan is one Aho-Corasick pass over an immutable automaton of the retained originals, linear in the slot length plus the occurrences found; the automaton is rebuilt outside the redactor's lock only when a scan is needed after originals were added or evicted, and scans never hold that lock. Known misses of the word-boundary rule, left to detection: an original next to further ASCII letters or digits (a phone number after a country code such as `+86`, or followed by a suffix such as `alice2024`); case variants (`Alice` for a registered `alice`); and partial matches, where a longer CJK name keeps its extra characters (a three-character name that starts with a registered two-character name keeps its third character) or overlapping originals keep the remainder of the shorter one (`Ann Lee Smith` with `Ann Lee` and `Lee Smith` known keeps `Smith`).
- **Failover keeps redaction.** A request that started on a redacting leaf never moves to a failover target without redaction. [2026-11-09, delta review] Because route health is shared by every Session, a failover route whose first configured target redacts applies this rule to every request from its first attempt, whatever the shared health state, so a cooling primary never makes a later request start on a plain target. `ModelRouting.Select` passes over such targets like cooling ones, and its all-cooling fallback counts only redacting targets: when none is ready, the last redacting target in route order is retried, cooling or not, within the normal retry budget, so transient failures do not block the route for a whole cooldown. A configuration or authentication cause (missing key, rejected key, unknown model ID) on a redacting target whose only alternatives are ineligible ends the request at once with that cause's ordinary explanation, as for a single model. Only a route without any redacting target (for example after a configuration change during retries) ends the request before contact, with a terminal error naming the refused target. On a route whose first target does not redact, the rule still holds within each request that started on a redacting target. `session-hash` routes keep their hashed target and ignore the filter; a request that started on a redacting hashed target is refused rather than sent if it would re-hash to a plain one. An explicit selection change during retries starts a new decision.

Registering a placeholder that already maps to a different original is a collision. The request fails with a terminal (non-retryable) text-redaction failure before any provider contact; the existing mapping is kept, and the colliding text is not cached. Deterministic termination was chosen over longer digests or suffixes because a 64-bit truncated HMAC collision is not expected in practice and must never restore a wrong value.

If the instance key cannot be read (missing key beside an existing store, unreadable or malformed key file) or the request owner has no key source, an enabled request fails with a terminal text-redaction failure before detection; the original is never sent. A store file that is locked for other reasons does not block redaction while the key itself is readable.

Secret masking (stage S in `ModelRequestOwner`) runs before the journal manifest and `PrepareRequest`; this wrapper runs later in `CreatePreparedService`, so detection only sees already masked text. `[[FW_SECRET:<label>]]` markers pass through unchanged: a detected range keeps only its parts outside markers (whitespace-only remainders are not replaced), and restoration only matches this feature's placeholders.

The detector contract signals that a text is too large with HTTP 413. A slot the detection service rejects that way fails ordinary requests with a terminal error that names the cause and the remedies (shorten or delete the long message, or turn off redaction for the model). Compaction planning (`compact-plan`) replaces that slot in its request copy with a fixed omission notice instead, so one long message cannot block the compaction that would remove it. Tool output is capped by the tool output guard (40,000 characters) before it reaches history, but user messages, model-written tool arguments and instructions have no comparable cap, and service limits are deployment-defined, so the case is reachable. [2026-11-09, accepted] Compaction keeps the newest part of history outside its candidate range, and the typical oversized slot (the latest user message or a recent tool argument) sits in that kept tail, so it stays in active history and later requests keep failing until the user shortens or deletes it, as the error says. Automatic compaction is not triggered by this error. Other detector rejections (for example 400 or 422) are ordinary terminal detection failures.

Enabled detection fails closed. Transient detection errors consume the existing request retry budget without provider-health failures, failover, provider attempt-start publication or a claim that an LLM request was sent. Configuration/authentication/invalid-response errors are terminal; Stop does not retry. Other preparation failures keep their existing behavior.

Statistics and the sent-version view: [observability](./model-text-redaction-observability.md). Restart persistence: [persistence](./model-text-redaction-persistence.md).

## Configuration and external service

`textRedaction` accepts a boolean or an options object. Fields inherit independently from models `defaults`, concrete provider, then model. Booleans set only `enabled`; an object does not implicitly enable redaction. Explicit lower-level `false` overrides an inherited enablement. Virtual providers cannot configure it; the selected concrete leaf supplies the captured settings. All supplied scopes validate even when masked. Raw YAML editing uses the shared Models schema; structured saves retain existing provider/model overrides and remove the concrete-only setting on virtual conversion.

```yaml
defaults:
  textRedaction:
    enabled: true
    endpoint: https://detector.example/v1/classify
    threshold: 0.5
    timeoutMs: 30000
    maxConcurrency: 1
    batchBytes: 0
    keepValues: []
    excludeLabels: [private_date, private_url]
providers:
  example:
    providerType: openai-responses
    models:
      - id: protected
      - id: unfiltered
        textRedaction: false
```

`endpoint` is the full `http://` or `https://` classification URL (lowercase scheme, as in the shared schema) and is required when enabled. Optional `apiKey` supplies a Bearer credential to that service. It is a secret sink at defaults, provider and model level (`SecretSinks.Models`): a `${secret:NAME}` reference resolves with the catalog, the value is used only for the detection request's `Authorization` header, and literal or stored values are known values for the secret redactor. A missing referenced name fails providers whose enabled redaction would send it (for a defaults reference, only providers with a leaf that inherits that key), before detection or provider contact. Like every field, an inherited `apiKey` is sent to whichever endpoint the leaf resolves, including an endpoint an administrator sets at a lower level; `apiKey: ""` there stops inheriting it. Because an endpoint at one level can redirect a key from another, model-initiated `set_config` compares each concrete leaf's effective settings, enumerated and resolved by the catalog itself (`HostModels.Parse` over the raw current and candidate documents, including the singular `model` list and every catalog key), and refuses the edit when an existing leaf whose `apiKey` is a reference before or after would change its endpoint, `apiKey` source text or enablement. A new or renamed leaf may resolve a referenced key only together with an endpoint that key is already paired with (in an existing leaf or in `defaults`), so adding, splitting or renaming models that inherit the detector settings stays possible; a new leaf that would newly pair the key with an endpoint is refused, enabled or not. A removed leaf sends nothing. A candidate the catalog rejects is refused with the catalog's own error, so no leaf escapes the comparison. Other settings of such leaves (threshold, timeout, labels) remain editable. `excludeLabels` lists detection labels left unchanged (default `private_date` and `private_url`), trimmed and matched case-insensitively; a lower-level list replaces the inherited list, and an empty list redacts every label. `keepValues` lists values never replaced (default none): a detected range whose text equals one, ignoring case and surrounding whitespace, is dropped before registration, and a retained known original on the list is not literal-masked. Configured values add to Foxwarm's own vocabulary, which is always kept: its name, the channel platform identifiers it writes into message envelopes and `foxwarm-*` envelope tag names. [2026-11-09, user] The detector flagged a platform identifier in an envelope attribute as a person, and literal masking then replaced that word in every Session. The list is part of cache identity, so a changed list applies to the next request without a restart; a lower-level list replaces the inherited list. A positive integer `timeoutMs` bounds each detection call (default 30000); `maxConcurrency` limits concurrent detection calls per endpoint (see below); `threshold` is finite and between zero and one (default 0.5). An existing explicit model-attempt hard deadline also includes detection; the configured value still reaches the provider adapter unchanged, so Anthropic per-phase timeouts (including `0`, no limit) behave as without redaction. No model runtime, service management or dedicated administration surface is provided.

`TextRedactor.RedactAsync` posts one Content-Length-delimited JSON object `{text, threshold}`. A successful response must contain `entities: [{start, end, score, label}]`, `offset_unit: "utf8_bytes"`, matching `input_bytes` and nonnegative integer `input_tokens`. Offsets are half-open UTF-8 byte ranges with strict scalar boundaries. Scores are finite within zero and one; every entity is validated, then entities whose label is excluded are dropped. Every other nonempty category, including an unknown future category, is redacted. Overlapping ranges are merged; adjacent independent ranges keep separate keys. The service owns whole-text classification and any sliding windows. A size/token-limit rejection is not partial success, and the client does not silently truncate or split input.

HTTP 408, 429, 5xx, connection failures and timeouts are retryable. HTTP 413 is terminal (see above). Other HTTP failures and malformed/invalid success responses fail directly. Service bodies and credential values are not copied into public detection errors. The client has no additional retry loop. A detection service may accept only a few requests at a time and answer 429 beyond that instead of queueing, so the process limits detection calls per endpoint to `maxConcurrency` (an integer from 1 to 64, default 1): calls from every request and Session wait in one per-endpoint queue. The wait is bounded by the request's own deadline and Stop, not by `timeoutMs`, which applies to each call once it is sent. Changing the limit starts a new queue; calls already admitted finish. The limit is not part of detection cache identity. With a limit above one, the wrapper first collects the attempt's slot texts from a throwaway copy of the projection, detects the uncached distinct texts concurrently up to the limit, then runs the ordered pass, which registers, caches and literal-masks in slot order exactly as with a limit of one; any detection failure fails the request the same way, and a slot rejected as too large is left to the ordered pass. Per-call cost against a remote service is dominated by network round trips, so a limit matching the service's in-flight capacity mainly hides latency even when it runs one inference at a time. A 429 can still occur when another client uses the service or a cancelled call is still running there; it then takes the normal retry path.

`batchBytes` (0 to 262144, default 0) combines uncached slot texts, in order, into one detection call of up to that many UTF-8 bytes, joined by a blank line (`TextRedactor.BatchSeparator`, ASCII, so slot boundaries stay character boundaries). [2026-11-09, user] The detection contract classifies one text per call, and against a remote service the per-call round trip dominates a first-turn detection of a long history. Each returned range is clipped to every slot it overlaps and shifted to that slot's offsets; a clipped part that is only whitespace is dropped, so a range across a separator is replaced in each slot. Combined texts give the detector neighbouring slots as context, so a result can differ slightly from single-slot detection; the first result is cached either way, and the size is not part of cache identity. Combined calls run in the same ahead-of-order phase as concurrent calls (also at a concurrency of one) and share the per-endpoint queue; a text at or above the limit is a call of its own. A combined call rejected as too large leaves its texts to the ordered pass, which detects them one by one under the usual 413 rule.

The detection cache holds one entry per distinct slot text and settings, keyed by the resolved detector settings and a SHA-256 of the text. An entry stores only the replaced ranges (offset, length, placeholder, original, labels) of detection and, once the slot has been through it, of the literal pass, not the text, and the cache is an LRU bounded by an estimated 32 MiB (a memory miss falls back to the [persisted record](./model-text-redaction-persistence.md)), so unchanged history of long Sessions is not detected again on each turn and any slot size is cacheable. A cache hit re-registers its pairs. The reverse map is a separate LRU bounded by an estimated 16 MiB. An evicted pair is no longer literally masked or collision-checked; its original is protected again only when detection flags it, and through literal masking once it is registered again. Restoration never depends on the reverse map, so eviction cannot break an attempt in progress.

## Request, progress and replay integration

`ConfiguredModelRequests.CreatePreparedService` installs the semantic wrapper only for an enabled concrete model. It runs after concrete history projection/hydration and before serializer/transport preparation, covering configured Responses HTTP/SSE/WebSocket, Chat Completions and Anthropic requests. The shared request owner reaches normal turns, compact planning, detached BTW, automatic titles, ToolScript and CLI calls without changing their budgets. Setup's ad-hoc connection test retains its transient, single-attempt connection-test configuration; it does not adopt installed model redaction settings.

`TextRedactionChatService` runs `TextRedactionProjection` twice over the same slots: first detection, then literal masking with the reverse map as it stands after the whole request was detected. `TextRedactionProjection.RedactHistoryAsync` edits text slots in the request-owned history already produced by concrete preparation and image hydration. It does not clone hydrated message/part trees again: unsupported-image, deduplication and transmitted-dimension side tables depend on those part identities. Canonical history remains outside this mutable ownership. The projection selects instructions, ordinary `text`/`system` and supported legacy text content, historical function-argument string values, formatted tool output text and tool/schema descriptions. JSON object keys, function names, call IDs, enums, schema example/default values and schema keywords are not substituted. Only description fields reached through schema keywords are scanned. Raw historical argument text has serializer precedence: valid JSON is parsed and its string values transformed. Raw text is rewritten only when a substitution happened, and then serialized without escaping non-ASCII or HTML characters, as tool output is; otherwise the provider's raw text is sent unchanged. Malformed historical raw argument text remains on its existing error/replay path, with its text detected. Tool outputs are formatted through the existing text formatter before detection; canonical business results are not rewritten.

Cumulative streaming snapshots restore ordinary text while holding a trailing incomplete placeholder. Thinking snapshots remain untouched. Tool-argument progress is published as restored JSON once a complete JSON value is available; incomplete argument JSON is withheld. Completed commentary callbacks and final results use the same canonical restoration before persistence, display and local tool execution. When a placeholder was restored, valid raw argument JSON is re-serialized from the restored object with the same encoder, so escaping quotes, backslashes and line breaks does not corrupt JSON; arguments without placeholders keep the provider's raw text. Invalid argument errors retain their existing non-executable status.

The wrapper returns restored committed rows to canonical consumers but keeps provider-form rows in the Responses attempt. Its append finalizer substitutes the corresponding provider-form assistant parts before WS fingerprint extension; a call whose placeholders were restored uses the same serialized representation the next request produces, and other calls keep the provider's raw text on both sides. It never detects or guesses text during synchronous finalization. A changed canonical append discards the chain rather than caching an unrecognized replay. The next request detects its own request copy before WS suffix selection. Existing reconnect, hosted-search discard, prefix persistence and Stop semantics remain owned by Responses and the turn host.

The neutral journal manifest still contains local original input; successful journal results contain restored canonical output. Attempt digests and raw transport diagnostics observe provider-form requests/output. This feature does not redact local storage or change raw diagnostic retention.

## Not covered

These paths do not pass through this wrapper; enabling `textRedaction` does not protect them:

- Embedding requests (Vector) receive only stage-S secret masking.
- The Claude runtime sends its prompt file and stdin through stage S only; Claude Code's own model requests and the tool results it receives are not redacted.
- Thinking replay: by decision, thinking is never detected or restored. Thinking produced before redaction was enabled, or by an unredacted history-compatible leaf, is replayed verbatim and may contain originals.
