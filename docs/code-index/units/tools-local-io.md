## Purpose

Implements shared canonical file reads/writes/patches over native or target primitives, native path/cwd rules, persistent native/provider and parallel exec, file delivery, and explicit handoff confirmation.

## Stable methods and callers

- `MainNativePaths` resolves native file/exec defaults from the actual Agent directory and explicit Session cwd; the separate generic policy and isolated-Agent checks authorize physical destinations; `FileToolCore` scans/reads/writes with byte/line/output limits and `PendingWriteRefs` tracks retryable write artifacts.
- `ITargetFileOperations` supplies opaque target primitives. `WorkspaceTools.Target` connects the existing workflow to those primitives without a second parser; `FileToolCore.ReadContent` and `FormatDirectory` share the scanner/formatting with native files. `TargetFileContent` composes bounded full reads and chunked transfer writes; [.NET providers](./dotnet-node-providers.md) maps actual generic consumers and target authority.
- `ExactReplacement.Apply` owns the pure ordinal, nonoverlapping unique-match calculation and literal text replacement shared by ordinary edit and operation-owned compact repair; each caller retains its own paths, authorization, effects and errors.
- `WorkspaceTools.Target.ReadHeaderAsync` reads at most twelve bytes through the native stream or existing target primitive. `WorkspaceTools` chooses image versus text from the shared raster signature classifier, never the filename extension; directories bypass image reads. Full image reads, text budgets, provider snapshots and canonical authorization retain their existing owners.
- `WorkspaceTools` exposes repository-aware list/read/write/edit/patch operations; `WorkspacePatch` parses/apply-checks bounded patches, accepts Unicode punctuation/space-equivalent context after strict matching, and reports only the original failing hunk (anchor and context/deletion/insertion prefixes) on a context mismatch, including EOF cases. `FormatContextErrorPath`, `FormatBoundedFailedHunk`, and `FormatContextMismatch` bound the diagnostic to 1,600 characters with head/tail retention for long hunks; no guessed candidate or file preview is included. The same update engine serves ordinary patches and operation-owned compact repair.
- `LocalExecManager` defines persistent/parallel process records, cwd/env/petname, foreground wait and output lifecycle. `IsSupported` admits Linux and Windows local execution; other hosts retain an inactive manager for Session lifecycle, omit its local definitions, and return explicit unavailability if invoked internally. Linux uses the existing Bash wrapper; Windows uses the Source PowerShell 5.1 shell/flags, a separate UTF-8-BOM user script, and shell-owned transcript/cwd/status files. The finite Main environment retains its existing POSIX variables plus required Windows system/user/temp/module paths and reserved Agent values. Windows process identity is PID plus native process creation time; it has no foreign-process live-cwd reader, so only the actual finished shell location updates cwd on Windows. Connected Nodes still expose their own definitions. Process start comes from the launched process rather than artifact allocation; the wrapper captures millisecond finish time before sidecar publication. Foreground/completion output includes `Duration`, and background handoff includes `Elapsed`, using `ExecDuration.Format`. Detection-only recovered finishes and legacy fallback errors remain `unknown`; remote WS duration stays peer-provided. These are process clocks, not invocation `executionTiming`; `ExecPetnames` provides stable process labels.
- `FileDeliveryDefinitions` turns approved paths into authenticated delivery metadata; `HandoffConfirmation` requires ordered `handoffRecall` and final `handoffConfirmation` fields before enabled inter-agent handoffs.

Callers: `SessionToolExecutor`, `WebUIChannel.Files/Images`, Code services, and Node-compatible local tooling. All effects pass the unified authorization boundary first.

## Contract and side effects

Path/cwd checks are security and data-loss boundaries, not convenience validation. Reads/writes are bounded; patch/write retries retain artifact lifetime and do not assume a failed transport erased a successful filesystem change. Exec output is truncation-aware and process termination is explicit. Lifecycle cancellation ends a launched local exec's foreground wait with a process-shutdown receipt; explicit Stop/Run queued retain their own cause. Neither cancellation kills the independent process, reverses its effects, or replaces its actual finished result. The executor stays available until foreground turn owners settle. File delivery exposes deployment-relative/authenticated references, not local absolute paths.

## Provider exec

`LocalExecManager.Provider` adapts target start/poll/log observations inside the existing owner; it is not a second manager or registry. Provider records extend `meta.json` with `ProviderId`, exact `NodeId`, `Reference`, `LogPath`, target-only `ProviderPid` and persisted `KnownCwd`. Native records without those fields retain their readers and artifacts. `tracking.json` remains the notification authority; terminal metadata uses the existing `status.json` sidecar. The resolver is composed by `SessionManager` from startup configuration. Source `state/running-exec.json` is neither adopted nor rewritten.

One in-flight metadata query is shared by foreground, read_exec and reconciliation observers of a pending record. Foreground timeout/Stop races independently of that query. Reconciliation starts independent per-record observations each tick and holds the existing exact-owner completion gate only for receipt/removal, not external polling. Metadata transport retains its five-second cap. Transient query errors or missing provider configuration retain tracking; explicit loss records unknown exit and an estimated finish, never success. Strict callback failure retries; acknowledged completion, retirement and strictly older-than-24-hour expiry remove only tracking. Ordinary shutdown neither restarts nor kills the target command or deletes adapter artifacts.

Provider output is read from target primitives with no Main log cache. One per-result observation budget covers display and programmatic capture: remaining foreground budget for a finished result, 500 ms after an ordinary timeout, and immediate unavailability after Stop/hard cancellation. A stat-time snapshot at or below 1 MiB retains raw content; larger logs read bounded 5,000-byte head/tail samples and omit full content. Foreground display also checks the rendered character budget before choosing the existing bounded excerpt, without truncating captured programmatic content. Short/unreadable output is unavailable, not an empty log or a fabricated exit. Boundary whitespace is retained and missing trailing LF is stated. Durations use supplied measured intervals or real finish timestamps; estimated finishes remain unknown. Native output/pagination is unchanged.

`read_exec` retains byte offsets and owner-local historical lookup for both backends. Provider reads share the pending poll and a single five-second cancellable observation budget, report unavailable output independently of known completion, and distinguish unavailable metadata with `status:unknown`. The provider target PID is never passed to native process/cwd inspection. Known target cwd crosses the exact Session save lane without native whitespace trimming, and deferred replay checks the current exact Node and owner before mutation.
