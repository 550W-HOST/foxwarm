## Purpose

Implements shared canonical file reads/writes/patches over native or target primitives, native path/cwd rules, persistent native/provider and parallel exec, file delivery, and explicit handoff confirmation.

## Stable methods and callers

- `MainNativePaths` resolves native file/exec defaults from the actual Agent directory and explicit Session cwd; the separate generic policy and isolated-Agent checks authorize physical destinations; `FileToolCore` scans/reads through the [shared native primitives](./dotnet-node-primitives.md); Main-owned `FileToolWrite` publishes authorized atomic writes and `PendingWriteRefs` tracks retryable write artifacts.
- `ITargetFileOperations` supplies opaque target primitives. `WorkspaceTools.Target` connects the existing workflow to those primitives without a second parser; `FileToolCore.ReadContent` and `FormatDirectory` share the scanner/formatting with native files. `TargetFileContent` composes bounded full reads and chunked transfer writes; [.NET providers](./dotnet-node-providers.md) maps actual generic consumers and target authority.
- `ExactReplacement.Apply` owns the pure ordinal, nonoverlapping unique-match calculation and literal text replacement shared by ordinary edit and operation-owned compact repair; each caller retains its own paths, authorization, effects and errors.
- `WorkspaceTools.Target.ReadHeaderAsync` reads at most twelve bytes through the native stream or existing target primitive. `WorkspaceTools` chooses image versus text from the shared raster signature classifier, never the filename extension; directories bypass image reads. Full image reads, text budgets, provider snapshots and canonical authorization retain their existing owners. Main regular-file, policy and opened-handle admission use the shared Linux type primitive with their original flags/error handling; native directory formatting distinguishes nonregular entries from files without following symlinks. Provider stat kinds remain target-owned.
- `WorkspaceTools` exposes repository-aware list/read/write/edit/patch operations; `WorkspacePatch` parses/apply-checks bounded patches, accepts Unicode punctuation/space-equivalent context after strict matching, and reports only the original failing hunk (anchor and context/deletion/insertion prefixes) on a context mismatch, including EOF cases. `FormatContextErrorPath`, `FormatBoundedFailedHunk`, and `FormatContextMismatch` bound the diagnostic to 1,600 characters with head/tail retention for long hunks; no guessed candidate or file preview is included. The same update engine serves ordinary patches and operation-owned compact repair.
- `LocalExecManager` owns Main's single Source-shaped active registry, native/provider starts, foreground waiting, exact-owner notification and tracking retirement. It supports Linux and Windows; other hosts keep the existing unavailable local-exec boundary. Native shell launch, scripts, bounded capture and output formatting are shared with CLI through [NodePrimitives](./dotnet-node-primitives.md), not a second manager. Main retains authorization, exact Session persistence, Agent cwd defaults, provider adaptation and completion authority.
- `FileDeliveryDefinitions` turns approved paths into authenticated delivery metadata; `HandoffConfirmation` requires ordered `handoffRecall` and final `handoffConfirmation` fields before enabled inter-agent handoffs.

Callers: `SessionToolExecutor`, `WebUIChannel.Files/Images`, Code services, and Node-compatible local tooling. All effects pass the unified authorization boundary first.

## Contract and side effects

Path/cwd checks are security and data-loss boundaries, not convenience validation. Reads/writes are bounded; patch/write retries retain artifact lifetime and do not assume a failed transport erased a successful filesystem change. Exec output is truncation-aware and process termination is explicit. Lifecycle cancellation ends a launched local exec's foreground wait with a process-shutdown receipt; explicit Stop/Run queued retain their own cause. Neither cancellation kills the independent process, reverses its effects, or replaces its actual finished result. The executor stays available until foreground turn owners settle. File delivery exposes deployment-relative/authenticated references, not local absolute paths.

## Persistent exec storage and lifecycle

`state/running-exec.json` is the one active tracking authority: Source-shaped `execs` plus at most 1,024 `recentExecIds`. IDs are reserved against active/in-flight/recent executions and existing remote claims, not all historical artifacts. Native records without `backend` and supported historical `exec_...` IDs remain readable. Recovery opens only this registry, marks recovered foreground entries notified/recovered and observes only active entries. It does not enumerate retained exec trees or discover another runtime's live authority. No reader, importer, migration or normal-startup scan is provided for the superseded experimental C# per-exec hierarchy.

New native runs put scripts, transient paths handshake, log, cwd and exit JSON together under the actual Agent's `.temp/exec/YYYY-MM-DD`. Shell-selected log names include local time and shell PID; records retain their original absolute artifact paths. Linux uses a detached same-executable launch helper, Bash and same-executable JSON helpers rather than Node/TypeScript. Console and Desktop dispatch these private helpers before configuration/startup. Windows uses PowerShell 5.1 flags, separate BOM-encoded user source and shell-owned transcript/cwd/status publication. It has no foreign-process live-cwd reader. Existing native process identity facts prevent inspecting an unrelated reused PID; provider PIDs remain target metadata only.

Native commands inherit ordinary host environment, strip reserved Agent variable names (case-insensitively on Windows), then set the actual `fw_agentdir`, `fw_tmp` and wrapper fields. POSIX unrelated uppercase names remain inherited. Agent tmp preparation and actual cwd validation precede launch. `SessionToolExecutor` preserves the native pre-exec exact-owner save and retains concrete authorization and final launch fences. Cwd synchronization and ordered direct-segment replay keep their original exact-owner/Node boundaries.

Default foreground wait is 15 seconds, minimum 1, clamped above 60 with warning; native polling is 250 ms with status-before-Stop precedence. Reconciliation is every five seconds and observes executions independently. Source launch-before-registry and mutation-before-save failure ordering remains uncertain without replay, rollback or exactly-once claims. Acknowledged exact-owner completion is followed by tracking removal; delivery failure retries. Expiry is strictly older than 24 hours from `startedAt`, before queries or notification. Foreground finalization follows output/cwd work. Removal/retirement/expiry retain artifacts and never kill commands. Shutdown drains observers/persistence after foreground owners settle.

Output names the actual original log path; normal same-Node `read` consumes it. There is no `read_exec` model surface or permanent historical-ID lookup. Native and provider output use the shared Source display: 4,000-character partial and 20,000-character completed previews, token fallback, exact boundary whitespace and missing-trailing-LF information. Programmatic capture is independent raw UTF-8 within the inclusive 1 MiB bound; larger logs use 5,000-byte head/tail samples only for display. Native timeout receipts include best-effort bounded process trees; provider receipts never inspect Main processes. Process duration uses actual timestamps or measured intervals, not wait/dispatch budgets; missing-status detection and estimated finishes remain unknown.

Artifact archival is separate from active tracking and uses the actual [date-directory rotation policy](./dotnet-log-rotation.md#d-main-date-log-rotation); it does not protect long-running commands or extend notification retention.

## Provider exec

`LocalExecManager.Provider` is the bridge inside the existing lifecycle owner. Records use `backend:{providerId,ref}`, actual Node, original target log path, initial/known cwd and optional target PID in the same registry. There are no provider metadata/status sidecars or Main log cache. Missing configuration never falls back to native. A shared in-flight query serves foreground/reconciliation observers; transient errors retain tracking, while explicit loss yields unknown exit and estimated finish. Transport metadata queries retain their five-second cap.

The ephemeral foreground file view carries the original selected-Node Session cwd, not an inferred receipt cwd. One per-result observation budget covers target display and programmatic capture: remaining foreground budget after a finish, 500 ms after ordinary timeout and immediate unavailability after Stop/hard cancellation. Unavailable or short capture remains distinct from a known exit and never invents empty content. Known target cwd crosses the exact Session save lane without native whitespace trimming; deferred replay rechecks current Node and owner.

`LocalExecRegistryTests` covers synthetic Source records, acknowledged delivery, strict expiry, original paths, concurrent native effects and Linux directory-open observation proving that recovery does not traverse 20,000 retained artifacts. `MainExecLifetimeTests` covers real native effects across identity moves and retirement. `experimentHostNativeExec.e2e.mjs` covers actual Main exit/restart, native Stop, original-path reads and startup rotation. Provider process restart/uncertainty coverage is mapped in [Node providers](./dotnet-node-providers.md). Synthetic record interoperability is not production Source takeover or permission to rewrite/replay existing wrappers. Windows runtime qualification remains separate from Linux tests/builds.
