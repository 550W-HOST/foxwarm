## Purpose

Implementation of the [secret references and redaction](../threads/secret-references-and-redaction.md) thread, which owns the cross-module contract, sinks, failure rules, redaction points, model-facing restrictions and the decision `D-secrets-store-references-redaction`. This unit owns the store and key formats, the matcher, exposure records, the secret destination comparison, the Agent store tools, the Setup surface and tests.

## Store and key

`InstanceKeys` owns `<data root>/keys/secrets.key`: a versioned JSON document with a key ID and 32 random bytes, created once at Main start in an owner-only directory (0700) and file (0600) through a temporary file and a no-overwrite move. Purpose keys are derived with HKDF-SHA256 (`foxwarm/<purpose>/v1`); `secret-store` encrypts the store and `text-redaction-placeholder` keys reversible [text-redaction placeholders](./model-text-redaction.md) through `InstanceSecrets.TextRedactionPlaceholderKey`, which throws (so enabled redaction fails closed) while the key is unavailable; `text-redaction-store` (64 bytes) encrypts and keys the [text-redaction store](./model-text-redaction-persistence.md) opened by `InstanceSecrets.TextRedactor`. The key directory is outside `state/` so state backups and Git-backed copies do not carry it; restores must carry the key separately. When `state/secrets.json` exists and the key file does not, Main never creates a replacement key.

`SecretStore` keeps `state/secrets.json` (owner-only, atomic writes). Each name has a description, an `owner` (`{kind: agent, agent}` or `{kind: instance}`; absent or unrecognized reads as the instance, so older files need no migration) and versions; `Set` (Setup) keeps an existing owner and gives a new name to the instance, `Create` refuses a name with a current value and records the given owner, and `TransferToInstance` reassigns an Agent's names; each version is AES-256-GCM sealed with AAD `name\0version\0keyId`. Names are 1-64 lowercase letters, digits, `.`, `_` or `-`. Values are at most 64 KiB without NUL. Replacing or deleting a value retires the current version; retired values are pruned after 90 days. Values shorter than 12 characters are accepted and resolved but are not redactable, and Setup says so. A file that cannot be read, is malformed or has a newer `version` raises `SecretStoreLockedException`, the same as a missing or foreign key; the read is retried on next use and the file is never rewritten while unreadable. `InstanceSecrets.LockError` reports the reason. `Generation` changes on every mutation; the model catalog cache, MCP pooled-connection comparison and the redactor rebuild from it, and a catalog resolved while locked is rebuilt once the store is usable.

## Matcher and sources

`InstanceSecrets` builds one `SecretRedactor` from the store's current and retained values plus literal sources registered with `AddSource` (models, app configuration, access and instance tokens, Node secrets, MCP static credentials and OAuth tokens). `InstanceSecrets.Literals` applies the per-sink literal rules from the thread (`SecretSinkKind` `Credential`, `Url`, `Environment`, `Header`, `Argument`). Sources are re-read at most every five seconds, immediately after configuration installation, or when the store generation changes; a change also schedules a background rebuild, because log writes use the last built matcher and never rebuild it themselves. Other readers wait for an in-progress rebuild instead of masking with an older matcher.

The matcher covers raw text, JSON string escapes, upper/lower percent-encoding, upper/lower hex and the stable core of base64/base64url at every byte alignment, using leftmost-longest matching. Values below the minimum length produce no patterns and are not known values. `SecretMessageRedaction` applies it to canonical messages, skipping `__meta` except `questionAnswer`, `providerMeta`, inline data and reasoning parts, which are reported instead. `SessionSaveLane.RedactStagedHistory` (`SessionSaveLane.Redaction.cs`) is the single history point described in the thread.

`SecretExposures` records label, count, first/last time, last redaction point and last Session ID in `state/secret-exposures.json` (debounced, at most 512 labels). Writes are serialized and an older snapshot never replaces a newer one. Content is never recorded. The count is the number of times a value was masked at a redaction point, not the number of distinct occurrences: a value in instructions is counted on every request. Setup shows these as rotation hints and can dismiss them.

## Secret destination comparison

`SecretConfigurationChanges` computes the thread's [secret destination facts](../threads/secret-references-and-redaction.md#secret-destination-facts). A route is `(destination, field, name)`; facts are the sorted names of routes in the result that are absent from the current routes. `ForConfiguration` parses a `set_config` candidate and builds model routes with `HostModels.Parse`, so leaves, inheritance (`llm.<family>BaseUrl`/`ApiKey`, merged `extraHeaders`, field-by-field `textRedaction`) and virtual providers follow the catalog exactly; `ReadCurrentModelsRaw` supplies the installed models file or its template. App routes cover `asrService` and each channel's `SecretSinks.App` fields with the channel destination. Current routes are the union under the captured app settings and the saved app file. `ForMcpServer` merges an `mcp_config` patch the way `McpConfiguration.UpdateAsync` does and normalizes it; `ForMcp` compares two server maps, and `McpConfiguration.UpdateAsync` calls it through its `admit` hook with the exact maps it is about to persist. Header names compare case-insensitively; destination strings compare exactly, so even a case-only URL change is a fact. A document the catalog or normalizer cannot accept makes every reference in it a fact. `DeniedMessage` is the refusal text used when the secret part of a decision denies without a rule reason.

## Agent store tools

`SecretToolDefinitions` declares `add_secret` and `list_secrets`; they are registered builtins outside default injection, found through `search_tools`. `SessionManager.AddSecretAsync` validates the name and exactly one source, refuses an existing name, and authorizes the sources' internal steps as the caller: the `read` of a `filePath` on the current Node (then read like `CompactPlanInput`: master file, Provider primitives or a resident Node `read` with a size bound), the `edit` deletion for `deleteFile`, or a master `read` of each source configuration file for `fromConfig`. It then authorizes `add_secret` again with the facts of the moment (`AddSecretFacts`: the name, when `SecretUsages` lists it and the store has no value) before `SecretStore.Create`. A value given in the call records a `tool-call` exposure. `SecretLiteralMove` parses `fromConfig` locations, reads the common literal through `ConfigurationYaml.Parse` (sink fields only), and rewrites YAML scalars by their parser marks: it refuses anchors and aliases along the path, merge-only paths and block scalars, writes a double-quoted reference over each scalar's range and verifies that the parsed result differs from the original exactly at the listed fields. The models or app file is rewritten through `ModelConfiguration.InstallAsync` (the app file with the webhook lock), re-reading the installed bytes (`ReadInstalledRaw`, which preserves a byte order mark) inside the lane; MCP fields go through `McpClient.ReplaceLiteralAsync`, whose `admit` hook requires the server to equal the snapshot the patch was built from. `ListSecretsAsync` joins store metadata with `SecretUsages` and computes `usable` from the secret part of an `exec` assessment at the caller's Node.

`SessionManager.ApprovalArgs` replaces `add_secret`'s `value` with `(hidden)` in the approval record, summary and live waiter arguments; `ToolArgsPreview` summarizes `add_secret` by name. `DeleteAgentCoreAsync` checks that the store is readable before deleting Sessions and calls `TransferToInstance` before removing the Agent directory.

## Setup

`/api/setup/secrets` (administrator-only like all Setup routes) lists metadata (including the owner), usages by provider/channel/setting/MCP server, referenced-but-missing names, exposures, the lock state and the key file path. `InstanceSecrets.LockError` is always a `SecretStoreLockedException` whose message is one of the fixed user-facing locked-store sentences (other key-loading or store-read failures are wrapped as "the instance key is unavailable" or "its file cannot be read"), and `lockMessage` is that message alone, without the exception type. `PUT /api/setup/secrets/{name}` sets a value and/or description, `DELETE` retires the current value, `POST .../forget-retired` drops retained values and `POST /api/setup/secrets/exposures/clear` dismisses one exposure label. Responses never contain values. The WebUI Secrets tab offers add/replace/describe/delete, prefill for missing names and exposure dismissal; value inputs are password fields cleared after save.
