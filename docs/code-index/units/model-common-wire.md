# Unit: Provider-neutral history and OpenAI wire helpers

Files: `dotnet/Foxwarm/Models/ConcreteRequestHistory.cs`, `dotnet/Foxwarm/Models/OpenAIHttp.cs`, `dotnet/Foxwarm/Models/OpenAIRequestText.cs`, `dotnet/Foxwarm/Models/OpenAISseReader.cs`, `dotnet/Foxwarm/Models/ProviderHttpRequest.cs`, `dotnet/Foxwarm/Models/ProviderResponseDecodingHandler.cs`, `dotnet/Foxwarm/Models/StreamActivityWatchdog.cs`, `dotnet/Foxwarm/Models/ProviderImageParts.cs`, `dotnet/Foxwarm/Models/RequestHistory.cs`, `dotnet/Foxwarm/Models/RequestHistoryRepair.cs`, `dotnet/Foxwarm/Models/SessionChatService.cs`

## Purpose

Builds provider-neutral request history, handles HTTP/SSE primitives, repairs retry inputs, adapts canonical image parts, and presents one chat-service contract to the Session turn host.

Ordinary and detached BTW instruction composition follows the [stable request-prefix contract](../threads/conditional-memory-snapshots.md#d-memory-request-prefix-stability).

## Stable methods and callers

- `ConcreteRequestHistory` selects canonical history/prompt-visible parts for a concrete request without changing active Session JSON.
- `ConcreteRequestHistory.ProjectDisplayMetadata` removes top-level message `compaction` diagnostics and function-response display metadata from request copies. Trusted `toolScriptSubCalls` presence projects the outer native response into `{ output: formattedExecutionText }`, including empty subcall arrays. `LlmRequestJournalStore.CanonicalMessage` applies the same projection before canonical journaling; concrete preparation applies it before image hydration and provider serialization. Ordinary MCP values and result-owned metadata are not classifiers. Session/Archive/run history stays native; pruned historical outputs and guard summaries retain their existing formatter fallback.
- `RequestHistory.FromSnapshot` materializes the exact captured immutable history with per-record provenance; `FromMutable` and request-only context deliberately carry none. Repair transfers that provenance only for unchanged selected rows; synthetic responses have none. `Messages` remains a request-owned projection, never active Session JSON.
- `RequestHistoryRepair` repairs provider retry inputs at the supported safe point; it does not rebuild a missing Session authority.
- `OpenAIHttp`, `ProviderHttpRequest`, and `OpenAISseReader` own request headers/body/status/SSE parsing and preserve provider error/stream boundaries. HTTP errors are consumed to EOF under the existing cancellation and deadline owners before retry/health classification, so a trailing structured error code is not lost to diagnostic truncation. Public exception bodies and diagnostic/error-message projections retain their 64 KiB bound; the complete body stays internal to classification. The reader optionally accepts a terminal predicate and final-event EOF flush for Messages; existing Completions EOF behavior is unchanged. Provider-specific accumulation remains in the adapters.
- `ProviderHttpRequest.CreateClient` gives ordinary model/Setup/CLI requests a cookie-free shared transport. `ProviderResponseDecodingHandler` decodes successful and failed gzip/zlib/raw-deflate/Brotli responses once, before collectors, while preserving explicit Accept-Encoding and intentional configured Cookie headers. Request compression remains independent; existing Anthropic decoding is not applied twice.
- `StreamActivityWatchdog` owns only attempt-local output inactivity: initial allowance, ordinary progress, and the latched ten-minute hosted-image/safety-buffering floor without reducing larger configuration. Responses SSE keeps this bound until collection settles at EOF, not merely until `response.completed`; that event still guards reasoning recovery. Caller cancellation and the independent hard deadline remain outside that allowance.
- `OpenAIRequestText` extracts model-visible request text and recognizes only supported historical compatibility strings; it is not a child-handoff receipt consumer.
- `ProviderImageParts` adapts canonical image refs/inline data; `SessionChatService.ChatAsync`/`ChatCoreAsync` supplies prompt/cache/model request orchestration behind `IChatService`, while `LocalSessionTurnHost` owns the tool loop. Its normal-owned callbacks recapture explicitly changed raw model/effort pairs at retry safe points and commit actual concrete model/Node adoption before request serialization; [model routing](./model-configuration.md) owns the attempt/budget contract. New notices and recaptures obtain a fresh immutable root, retaining request-owned JSON and provenance rather than reconstructing from mutable projections.

Callers: `LocalSessionTurnHost`, model-specific services, retry preparation, image pipeline, and `LlmRequestJournalStore` qualification.

## Contract and side effects

The ordinary `ISessionChatService` retry-capable path carries a captured `SessionHistory` and the turn host's zero-based loop iteration through `RequestChatService` to `SessionChatService`; a successful committed-context retry captures a new root. The same loop index feeds the normal journal manifest and raw interaction diagnostics. Completed tool batches and provider-time follow-up advance the host loop; a new turn starts at zero. Physical retries, including a new logical request after changed input, keep that iteration while retaining their separate request/attempt identity. Normal-owned Responses requests additionally carry the turn host's completed-segment callback through this same chain; retained prefixes force retry recapture even without newly queued input. It does not recover provenance by looking up live Session state. History-to-request conversion is still an explicit mutable JSON projection, not an alias of Session history. The [journal](./model-journal.md#immutable-record-preparation) alone memoizes neutral record encoding; concrete preparation always applies current repair, model filtering and hydration. Visibility validation reads existing records without cloning them. Retry repair owns its output; concrete preparation can mutate that owned output directly while the standalone preparation API still copies caller input. Cross-model part filtering reuses the already-owned request parts rather than cloning them a second time. Canonical part views share only their private canonical tree, as documented in [history ownership](./session-domain.md#history-ownership).

Detached BTW preparation uses the same immutable-root request projection and model request owner, with its own purpose/cache scope and no foreground callbacks. Its command, result and lifetime contracts belong to [public command administration](./dotnet-command-administration.md#detached-btw-requests-and-active-history-controls).

Provider input is derived from Session state and request scope. The neutral repaired/visibility-filtered manifest precedes concrete leaf filtering and image hydration. History-compatible missing-generated-blob and other local preparation/persistence failures happen before provider send and do not enter provider retry/health. The `all-images-fail` condition is produced while processing provider output/generated-image results; it is non-retryable/non-countable but is not a send-preparation failure. Provider transport failures alone enter normal backoff/retry/health handling. Retry repair preserves the safe point, logical request identity, and attempt attribution; canonical Session messages remain owned by Session persistence.

Concrete native-history filtering uses the request-captured catalog [compatibility projection](./model-configuration.md#native-history-compatibility). It preserves original source IDs for downstream serializers and generated-image admission; canonical/Archive records are never rewritten. Low-level configured wrappers and ordinary/compact/BTW/one-shot request owners use the same comparison.

Before stripping message `__meta`, concrete preparation projects a positive canonical tool-row seq onto the request-owned function-response envelope as `contextSeq`. The shared `OpenAIRequestText.PreviousRequest` prefix exposes it beside existing timing (or as seq-only tool metadata), covering Responses, Completions and Anthropic tool groups. Multiple results in one row share its seq; synthetic repaired responses without canonical seq receive none. Tool business payloads, canonical Session/Archive records and neutral journal history are unchanged. These cues locate a record, not a complete exchange; active source validation stays in the compactor.
