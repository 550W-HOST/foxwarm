## Purpose

Contains a bounded .NET 10 host and compatibility probes outside the production Node.js runtime and normal test graph. One solution owns three projects; source folders do not represent separate assemblies.

## Scope

- `Foxwarm` is one Web executable: root `Foxwarm` memory helpers; `Foxwarm.Sessions` Message JSON, ordered Session turns, persistence/Archive, and layered compaction; `Foxwarm.Models` Responses SSE/client and concrete model configuration; `Foxwarm.Tools` fixed workspace, trusted local exec and Session-tool dispatch; `Foxwarm.Channels.WebUi` authenticated localhost HTTP/realtime channel. Root `Foxwarm` also owns startup, HTTP infrastructure and the message router. Its persisted JSON/SQLite and provider-facing contracts remain limited to the supported ordinary subset.
- `Foxwarm.Tests` groups the existing memory, model/streaming, Session, and storage test files in one project without deleting their cases.
- `Foxwarm.DevTools` selects one existing development entry by `conditional-memory`, `responses-request`, `responses-stream`, or `session-restart`. The original corpus and process-restart outputs remain unchanged.

The host serves the original App, Sidebar and Workbench with the supported Chat/Agent/Session paths. It is not the complete Agent/Setup backend. Authenticated same-origin Cookie or CLI Bearer owns API and WebSocket routes; a small local login gate wraps the ordinary frontend entry. Unsupported App entries remain visible and may return 404/501 rather than requiring a temporary feature-discovery system. The original frontend uses genuine revisioned list-plus-Chat WebSocket subscriptions, v2 draft deltas, canonical messages, queue previews and range/historyVersion snapshots. The experiment-only composer preserves the existing model selector for current concrete model and effort while hiding child defaults/Setup and unsupported attachments; normal frontend builds are unchanged. `/compact` durably claims an idle Session processor and runs synchronous planning, `/stop compact` cancels only that planner and preserves ordinary queued ingress; auto compaction runs under the current turn claim when cached+input+output usage exceeds 85% of selected context limit. Runtime status uses the existing requesting-model/compaction phase. The planner accepts only `submit_compact_plan`; normal turns execute fixed relative-workspace `read`/`write`/`edit`/`apply_patch`, local `exec`/`read_exec`, declared activity `wait`, and exact current-Session `recall({target:"msg#N",offset?})`. The recall tool returns at most 12,000 Unicode code points of immutable stored message JSON per call and has no search, range, cross-Session or Vector scope; the authenticated exact-seq HTTP endpoint exposes the complete original row. These application-level path/auth limits are not an OS sandbox or production authentication. No ordinary tool call may execute `submit_compact_plan`. Shutdown cancels active planner/provider requests and waits for save/processor completion; it does not kill already-started local exec commands. Persisted busy/stopping states fail closed.

The experimental Agent layer retains existing flat `s_<GUID>` authorities as Agent `main` with the original configured workspace, JSON, Archive and exec receipts. The main Agent has no invented canonical `main` Session: it can be created explicitly. New Agent names use the TypeScript alphanumeric/hyphen/underscore grammar; new Session names are nonempty slash-free components. New IDs are canonical `agent/session` (or flat names for Agent `main`), and fresh children can be named under the same or another Agent, including a legacy flat parent. A separate atomically written Agent catalog records created Agents while per-Session JSON remains the sole active authority for Agent, parent ID, model/effort and snapshot. Metadata/Agent directories exist before Session publication; partial creation returns the committed ID when one exists. Startup validates every bound Agent and acyclic existing parent relationship, recursively loads namespaced authorities, and still refuses corrupt/missing active JSON despite complete Archive. HTTP resolves exactly one encoded path layer from the literal request target, including `%2F` for a slash while retaining a literal `%2F` in a flat Session name. Agent workspace/memory is `<tool-root>/agents/<name>/memory` for new Agents; legacy main keeps `<tool-root>/memory`. The framework 00_SYSTEM.md comes from the common Agent root, with the main-memory 00_SYSTEM.md as fallback. The legacy main workspace contains the new Agent subdirectories, and all shell effects run with the host UID; Agent ownership and workspace-root-relative file tools are not OS isolation.

One selected concrete model identity governs the stored memory snapshot. Ordered framework and owning-Agent Markdown sources use the existing `<memory_file ...>` wrapper and `foxwarm-if` filtering; recognized YAML `include-session`/`exclude-session` front matter controls per-Session inclusion, and ordinary unknown keys do not suppress the text body. Explicit host instructions remain before the stored snapshot. Same-identity requests reuse its exact persisted bytes even when files change; switching concrete leaf or explicitly refreshing writes the new snapshot strictly through the owning Session save lane before a request can be sent. A precommit failure leaves its previous hot/persisted snapshot and sends no provider request; postrename failure retains the published committed snapshot and also prevents that request. Detached compaction planning can construct a per-model captured snapshot without replacing the live one. No inheritance chain, custom prompt-file selection, skills scan, virtual routing or automatic idle refresh is claimed.

Five fixed ordinary-turn Agent tools create an Agent, create a Session, create a fresh child, deliver to another existing Session, or refresh the caller's snapshot. Agent creation normally includes an `agent/main` Session and may intentionally omit it. Fresh children bind their real parent and owning Agent, preserve an independent history/cache lineage and inherit only one raw model/effort pair (explicit override, existing parent child defaults, or parent current); they do not recursively copy future child defaults. Their genuine new-child boundary and initial message are strict persisted operations; a child that was committed before initial delivery failed remains visible with its actual ID rather than being rolled back fictitiously. Source-bearing inter-Session messages, including between non-parent/non-isolated Agents, use a narrow strict target save-lane enqueue. Only after commit does the existing single processor start if idle; busy targets merely queue. `send_to_session` self/missing targets fail and `<parent>`/`<main>` resolve only when an actual Session exists. `afterSend=finish` ends the caller's turn only after every sibling tool in the same assistant batch has a paired persisted response; it does not stop or kill another Session and does not implement managed handoffs or confirmation rules. Ordinary declared activity waits and waiting handoffs are supported below.

The original App/Sidebar/Workbench and their existing bounded list/realtime hooks are used directly. `ExperimentChatApp` and its build entry have been removed. `VITE_FOXWARM_DOTNET=1` adds only the cookie login gate and passes the existing text-only Chat option; it does not create a capabilities matrix, probe missing features, clean stored layouts or hide all unimplemented menus. Agent/Session creation uses the original browser DTO (`agentId`, optional `sessionId`; Agent creation responds with `sessionId`), while model tools retain their separate approved `agentName` schema. Bare legacy Session creation remains supported. The channel translates the existing strict display-name update and real local branding settings; pin, inheritance, destructive Session/Agent operations, Setup, Code, Terminal and global history search remain unimplemented and may fail explicitly through their normal frontend entry points.

## Continue and collaboration waits

`/continue` uses the original Chat availability/control path and the ported `SessionContinuation.IsIncomplete` history classifier. Temporary/optimistic/display-only and generated compact-boundary rows are transparent; request retry notices, incomplete segments, empty/text/tool tails, and exact complete call/response pairing retain the source semantics. Successful terminal handoff exchanges are complete. The backend independently rejects busy/processor-owned, waiting, and complete Sessions, claims the existing processor, and sends committed history without another user/trigger row. Continue does not reexecute old tools, synthesize missing outputs, or add an effect receipt/retry journal. A provider rejection of an unmatched historical call remains an ordinary request failure. Stop during a continuation uses the existing cancellation and passive queue-finalization path. Automatic busy/crash recovery remains unsupported.

`wait` accepts the closed declared-source argument shape: positive finite `wakeIfNoActivityAfterSeconds`, mutually exclusive `waitAllSessions` (at least two distinct other existing Sessions) / `waitAnySessions` (at least one), exact current-Session owned active or queued-completion `waitExecIds`, `waitForInput:true`, and optional reason. A reason alone is insufficient. Any/exec/input expectations are advisory and do not filter legitimate incoming activity. `afterSend:wait` requires an initial message for a fresh child and coalesces only successful resolved delivery targets after the complete paired tool-result batch; ordinary queued fast replies pass the same wake transition immediately. A successful waiting or finish handoff remains terminal despite a sibling error. An explicit wait with a sibling error clears only its own created wait token and continues the ordinary provider loop.

Active JSON owns `meta.wait` (ID/start/reason/source declarations, timeout duration, and waitAll sessions/satisfiedSessions/deferredQueue). Listed inter-Session messages advance a waitAll barrier and stay durably deferred without a provider/processor claim until all sources have responded. Unrelated user/system/inter-Session input releases deferred items in order, appends the input and a source-derived pending reminder, and clears the wait. Deferred messages are not Archive/active-history rows until their normal canonical append. Admission, wait start/clear, receipts and defer/wake updates share the existing per-Session save lane. Strict inter-Session/exec/internal-event operations stage and publish only their owned queue/wait/receipt changes; pre-rename failures do not publish, postrename failures retain/publish and report. Ordinary user ingress remains best-effort: its owned hot admission is published when its ordered operation starts, before its save attempt; failure does not erase acknowledged content. Stop's synchronous state/CTS updates are not replaced by an older staged envelope.

`SessionWaitTimeouts` is an internal one-shot controller, not the TypeScript general timer/cron table. It derives the deadline from committed wait.startedAt + timeoutSeconds, rearms from clean-idle JSON before ordinary admission, and queues an overdue current-token fallback once. Stale timeout/liveness tokens are discarded without claiming a processor. Source-only declarations use the ported `WaitLiveness` reverse dependency graph, 300ms grace, active/queued/timed/exec/input/transitive progress observation, persisted newest16 fingerprint dedup and at most four diagnostic wake slots. `wait-sources-quiescent` reports an observed lack of progress, not proof of deadlock or task completion. Shutdown stops admission, cancels/drains controller jobs and preserves idle waits; busy/stopping authorities still fail closed. Idle-wait Stop remains the active-control no-op; input wakes the wait.

Runtime/list/Chat derive `waiting` and bounded source/deadline/satisfied/pending details from wait metadata. Their metadata capture copies only that declaration, never deferred message bodies or full history. Original Chat Continue is enabled independently of the remaining text-only attachment/ASR/unsupported-action restrictions. No managed state, Worker/RPC, general timer tools, wait cancellation command or frontend capability system is added.

They do not clone or serialize active history to read metadata. `LocalSessionTurnHost` consumes the complete leading ordinary prefix without source/platform/conversation splitting while retaining one canonical history row and `clientMessageId` per logical input. The bounded inter-Session delivery now uses an owned source/reply target on ordinary Session queues; no other external Channel adapter or arbitrary Channel reply routing is implemented. The lane lock only links a new tail to its predecessor; an asynchronous launch signal starts previous-wait and operation execution after lock release, so synchronous SQL/fsync is never run while holding `laneGate`. Precommit failure publishes no staged hot mutation and rolls back only newly inserted rows; byte-exact preexisting replays are retained. Postrename `AuthorityCommittedException` keeps Archive and JSON, publishes only that operation's queue/history/seq/meta delta, and reports the durability problem without rollback or provider/tool retry. `IChatService` returns an optional owned canonical assistant Message rather than a text shortcut. The fake chat builds the same narrow result shape. Assistant-save failure prevents the effect; tool-row-save failure stops after any already-completed external effect and never reexecutes it or sends another request. The experiment has no effect receipt ledger.

The Responses request serializer filters exact `modelVisible:false`, preserves open JSON by cloning, and implements the current bounded TypeScript input projection for canonical system/text content, assistant phase grouping, reasoning replay, compatible annotations, function calls, and paired tool outputs. Multi-field parts preserve TypeScript's `system` → reasoning → `text` → function-call order, with commentary fallback for model messages containing calls. Stable call IDs, exact raw arguments, parse-error metadata, safe malformed-argument replay, and current shared tool-result formatting are retained. System formatting uses explicit ECMAScript whitespace and ASCII-boundary behavior rather than .NET `Trim`/Unicode `\b`, covering whitespace-only self-closing output, FEFF, NEL, and non-ASCII suffixes on Foxwarm tag names. Semantic inputs outside this slice fail explicitly: missing stable call IDs, images, native output-item replay, and legacy system normalization. The HTTP client uses explicit options only, streams through the existing collector, captures at most 64 KiB of non-success bodies, and propagates cancellation through send, read, and disposal. Empty completion creates no assistant.

The older bounded Slice B effect implementation is an injected `write_fixture` executor rooted in a test-owned temporary directory; the later interactive host separately advertises and executes its fixed `read`/`write` workspace tools. It validates the exact bounded object shape and plain filename, performs a UTF-8 atomic create-new write, and rejects existing files and symlinks. A create collision returns `file_exists`; another open/write/flush `IOException` returns `tool_io_error` without retry or deletion of a possibly partial file. Unknown tools, invalid paths/schema, and malformed parsed arguments produce paired errors with the original call ID and no effect. The directory boundary is not an OS sandbox. The default loop cap is 500 and tests can inject a smaller explicit cap; no recursive processor is created. Bounded error response serialization matches the actual shared `js-yaml` formatter for supported fixed errors and dynamic unknown/parse messages, including quote, comma, newline, tab, NUL, NEL, and other C0/C1 scalar escaping.

Workspace `edit` replaces exactly one UTF-8 text occurrence. `apply_patch` uses the existing action-envelope, contextual/anchored line diff and ordered Add/Update/Delete semantics: it validates all paths before effects, then validates and performs each filesystem operation in order, returning already-applied operations on a later failure rather than implying a transaction or rollback. Relative file paths are always rooted at the configured tool workspace; existing regular files and resulting content stay within 1 MiB, symlinks are rejected, and Add can create missing workspace-parent directories. This path check is not race-proof OS confinement.

Local Linux `exec` uses the configured workspace root as its default initial working directory; an explicit cwd must be an existing relative workspace directory without symlinks. A shell's `cd` does not update subsequent exec/file defaults. Exec spawns a standalone bash wrapper with a narrowly selected PATH/HOME/locale/user environment and no automatically inherited host API/provider secrets. Its command, full raw stdout/stderr log, atomic exit status, and active tracking live under the separate authority root `state/exec/<Session key>/<petname exec ID>/`; logs and metadata persist after tracking is removed. A fixed bounded foreground preview or partial timeout preview points to `read_exec`, which checks the exact current Session owner and returns status plus at most 16 KiB of original bytes per page, an actual consumed-byte `nextOffset`, byte size, and explicit escaped bytes when a UTF-8 boundary is broken. The Responses tool-output formatter admits only this bounded shape. Timeout defaults to 15s, clamps values above 60s with a warning, and does not kill the process. Stop during the wait cancels the Session's wait but leaves the shell tracked in background and strictly persists the paired tool row; the cancellation handle retains its token after the Stop owner disposes the source. There is no process-list/kill tool, session-cwd mutation, OS sandbox, or assurance that an arbitrary same-UID shell cannot inspect paths outside the workspace.

The completion reconciler reads only owned tracked artifacts after loading valid idle Session authorities. It strictly persists one background system queue item and the newest 32 exact `exec-completion:<id>` receipts on that Session's ordered save lane, publishes only its own queue/meta delta, then triggers the existing single Session processor if idle. A precommit failure keeps tracking for retry; postrename publication is retained, so retry sees the receipt rather than duplicating the event. If the wrapper cannot write status, a three-second grace plus exact `/proc/<pid>/stat` start-time observation writes an unknown-exit fallback without operating on that PID; background tracking older than 24 hours is discarded without killing the process or deleting artifacts. No child-process kill or arbitrary PID-based control occurs during Stop or host shutdown; the independent wrapper can write status after the host exits. A clean-idle restart reloads pending tracking and delivers its event once. Historical flat `s_<GUID>` IDs keep their existing exec directory names; new namespaced/nonlegacy IDs encode one canonical ID into one filesystem segment so slashes never produce nested exec ownership. A crash during a busy Session and the launch-to-tracking-write failure window are not recovered, nor does this create a general tool-effect ledger or generic durable event platform.

This remains bounded Message/persistence compatibility rather than a complete Session implementation. Slice D proves explicit-ID clean-idle two-process continuation. The interactive host additionally supports multiple concrete localhost Responses models with persisted effort, current-v1 synchronous layered compaction, trusted local development tools, and a bounded Agent/fresh-child loop. Crash/power-loss and committed-busy recovery, full catalog/Agent lifecycle, move/alias/fork, inheritance, skill scanning, automatic memory refresh, custom systemPromptFiles, request journals, provider retry/routing, general registry/MCP/Node tools, image/hosted input, virtual/WS/failover models, async/background compact, full recall/vector search, process kill, managed state, other external channels, Worker placement and production runtime integration remain excluded. Active history never reconstructs from Archive.

Active JSON remains the sole active-history authority. The supported subset preserves ordinary queue shapes, CTX-BLOCK metadata, `preservedFromBlockId`, monotonic `nextBlockId`, and declared wait metadata/deferred inputs, while rejecting unsupported lineage/managed/Worker state and images. Layered candidates/plans come solely from one active snapshot, respecting 30% newest rendered-history keep (without splitting existing call+tool pairs), 2,000-token raw eligibility and 20% raw replacement, source-block 3,000/5,000-token eligibility/force quotas, oldest 40% candidate window, and at most 15 planner rounds. Ranges follow display order rather than numeric block-ID order. Archive blocks preserve source block IDs, original seq/time ranges and optional memory facts; no Vector indexing or automatic Archive reconstruction follows. Only historical tool-output pruning reads and rechecks exact immutable Archive provenance; it publishes a pruned active row only if estimated context falls to at most 50% of the selected model limit, leaving the original reachable by exact paginated recall and HTTP. Staged Archive blocks/completion row are written before atomic JSON authority replacement; precommit rolls back only new rows, postrename retains/publishes committed state and throws. Hot publication changes only compaction-owned history/version/seq/block metadata, preserving concurrent queued ingress, Stop and model settings. Missing/corrupt JSON still fails closed, and busy/crash recovery remains unsupported.
