## Purpose

Contains a bounded .NET 10 host and compatibility probes outside the production Node.js runtime and normal test graph. One solution owns three projects; source folders do not represent separate assemblies.

## Scope

- `Foxwarm` is one Web executable: root `Foxwarm` memory helpers; `Foxwarm.Sessions` Message JSON, ordered Session turns, persistence/Archive, and layered compaction; `Foxwarm.Models` Responses SSE/client, concrete model configuration, fixed workspace tools, and trusted local exec; `Foxwarm.Web` authenticated localhost HTTP/realtime Session adapter. Its persisted JSON/SQLite and provider-facing contracts remain limited to the supported ordinary subset.
- `Foxwarm.Tests` groups the existing memory, model/streaming, Session, and storage test files in one project without deleting their cases.
- `Foxwarm.DevTools` selects one existing development entry by `conditional-memory`, `responses-request`, `responses-stream`, or `session-restart`. The original corpus and process-restart outputs remain unchanged.

The host exposes a bounded CLI and original-Chat-leaf adapter, not the complete WebUI App/Agent/Setup API. Authenticated same-origin Cookie or CLI Bearer owns API and WebSocket routes; static assets load the local login shell. The original Chat uses genuine revisioned Session-only WebSocket subscriptions, v2 draft deltas, canonical messages, queue previews and range/historyVersion snapshots. The experiment-only composer preserves the existing model selector for current concrete model and effort while hiding child defaults/Setup and unsupported attachments; normal frontend builds are unchanged. `/compact` durably claims an idle Session processor and runs synchronous planning, `/stop compact` cancels only that planner and preserves ordinary queued ingress; auto compaction runs under the current turn claim when cached+input+output usage exceeds 85% of selected context limit. Runtime status uses the existing requesting-model/compaction phase. The planner accepts only `submit_compact_plan`; normal turns execute fixed relative-workspace `read`/`write`/`edit`/`apply_patch`, local `exec`/`read_exec`, and exact current-Session `recall({target:"msg#N",offset?})`. The recall tool returns at most 12,000 Unicode code points of immutable stored message JSON per call and has no search, range, cross-Session or Vector scope; the authenticated exact-seq HTTP endpoint exposes the complete original row. These application-level path/auth limits are not an OS sandbox or production authentication. No ordinary tool call may execute `submit_compact_plan`. Shutdown cancels active planner/provider requests and waits for save/processor completion; it does not kill already-started local exec commands. Persisted busy/stopping states fail closed.

The experimental Agent layer retains existing flat `s_<GUID>` authorities as Agent `main` with the original configured workspace, JSON, Archive and exec receipts. The main Agent has no invented canonical `main` Session: it can be created explicitly. New Agent names use the TypeScript alphanumeric/hyphen/underscore grammar; new Session names are nonempty slash-free components. New IDs are canonical `agent/session` (or flat names for Agent `main`), and fresh children can be named under the same or another Agent, including a legacy flat parent. A separate atomically written Agent catalog records created Agents while per-Session JSON remains the sole active authority for Agent, parent ID, model/effort and snapshot. Metadata/Agent directories exist before Session publication; partial creation returns the committed ID when one exists. Startup validates every bound Agent and acyclic existing parent relationship, recursively loads namespaced authorities, and still refuses corrupt/missing active JSON despite complete Archive. HTTP resolves exactly one encoded path layer from the literal request target, including `%2F` for a slash while retaining a literal `%2F` in a flat Session name. Agent workspace/memory is `<tool-root>/agents/<name>/memory` for new Agents; legacy main keeps `<tool-root>/memory`. The framework 00_SYSTEM.md comes from the common Agent root, with the main-memory 00_SYSTEM.md as fallback. The legacy main workspace contains the new Agent subdirectories, and all shell effects run with the host UID; Agent ownership and workspace-root-relative file tools are not OS isolation.

One selected concrete model identity governs the stored memory snapshot. Ordered framework and owning-Agent Markdown sources use the existing `<memory_file ...>` wrapper and `foxwarm-if` filtering; recognized YAML `include-session`/`exclude-session` front matter controls per-Session inclusion, and ordinary unknown keys do not suppress the text body. Explicit host instructions remain before the stored snapshot. Same-identity requests reuse its exact persisted bytes even when files change; switching concrete leaf or explicitly refreshing writes the new snapshot strictly through the owning Session save lane before a request can be sent. A precommit failure leaves its previous hot/persisted snapshot and sends no provider request; postrename failure retains the published committed snapshot and also prevents that request. Detached compaction planning can construct a per-model captured snapshot without replacing the live one. No inheritance chain, custom prompt-file selection, skills scan, virtual routing or automatic idle refresh is claimed.

Five fixed ordinary-turn Agent tools create an Agent, create a Session, create a fresh child, deliver to another existing Session, or refresh the caller's snapshot. Agent creation normally includes an `agent/main` Session and may intentionally omit it. Fresh children bind their real parent and owning Agent, preserve an independent history/cache lineage and inherit only one raw model/effort pair (explicit override, existing parent child defaults, or parent current); they do not recursively copy future child defaults. Their genuine new-child boundary and initial message are strict persisted operations; a child that was committed before initial delivery failed remains visible with its actual ID rather than being rolled back fictitiously. Source-bearing inter-Session messages, including between non-parent/non-isolated Agents, use a narrow strict target save-lane enqueue. Only after commit does the existing single processor start if idle; busy targets merely queue. `send_to_session` self/missing targets fail and `<parent>`/`<main>` resolve only when an actual Session exists. `afterSend=finish` ends the caller's turn only after every sibling tool in the same assistant batch has a paired persisted response; it does not stop or kill another Session and does not implement wait/managed/handoff confirmations.

The original Chat frontend is reused behind a small experimental Agent/Session shell with real HTTP creation, Agent grouping, parent/child navigation and current-Session memory refresh. It does not implement the full Setup/Code/Terminal/Agent-management API.

`SessionTurns` consumes the complete leading ordinary prefix without source/platform/conversation splitting while retaining one canonical history row and `clientMessageId` per logical input. Queue source fields remain provenance. The bounded inter-Session delivery now uses an owned source/reply target on ordinary Session queues; no Channel adapter or arbitrary Channel reply routing is implemented. The lane lock only links a new tail to its predecessor; an asynchronous launch signal starts previous-wait and operation execution after lock release, so synchronous SQL/fsync is never run while holding `laneGate`. Canonical append takes selected queue object identities and an owned staged snapshot under the state gate, allocates contiguous sequence/timestamp metadata, then performs Archive insertion and JSON commit outside both gates. Timestamp `0`/`-0` follows TypeScript's falsy timestamp rule; ordinary appends preserve `historyVersion` rather than treating it as a process generation. Precommit failure publishes no staged hot mutation and rolls back only newly inserted rows; byte-exact preexisting replays are retained. Postrename `AuthorityCommittedException` keeps Archive and JSON, publishes only that operation's queue/history/seq/meta delta, and reports the durability problem without rollback or provider/tool retry. Later ingress and Stop/meta changes stay hot and their queued saves run afterward. Queue-prefix and Stop-finalization notifications remain non-poisoning; other callback semantics are unchanged. Stop cancellation still happens outside the gate before its save wait.

`IChatService` returns an optional owned canonical assistant Message rather than a text shortcut. The fake chat builds the same narrow result shape. The Responses client converts supported reasoning, output text, refusal, function calls, phase, annotations, usage, concrete model identity, and request timing, then returns without persistence; persisted timing derives fractional `startedAt` from completion wall time minus monotonic duration. `LocalSessionTurnHost` alone strictly commits assistant and paired tool rows, executes a committed call through the injected executor, consumes newly queued ordinary input only after the tool row, and performs the next request under the same processor claim. Assistant-save failure prevents the effect; tool-row-save failure stops after any already-completed external effect and never reexecutes it or sends another request. The experiment has no effect receipt ledger.

The Responses request serializer filters exact `modelVisible:false`, preserves open JSON by cloning, and implements the current bounded TypeScript input projection for canonical system/text content, assistant phase grouping, reasoning replay, compatible annotations, function calls, and paired tool outputs. Multi-field parts preserve TypeScript's `system` → reasoning → `text` → function-call order, with commentary fallback for model messages containing calls. Stable call IDs, exact raw arguments, parse-error metadata, safe malformed-argument replay, and current shared tool-result formatting are retained. System formatting uses explicit ECMAScript whitespace and ASCII-boundary behavior rather than .NET `Trim`/Unicode `\b`, covering whitespace-only self-closing output, FEFF, NEL, and non-ASCII suffixes on Foxwarm tag names. Semantic inputs outside this slice fail explicitly: missing stable call IDs, images, native output-item replay, and legacy system normalization. The HTTP client uses explicit options only, streams through the existing collector, captures at most 64 KiB of non-success bodies, and propagates cancellation through send, read, and disposal. Empty completion creates no assistant.

The older bounded Slice B effect implementation is an injected `write_fixture` executor rooted in a test-owned temporary directory; the later interactive host separately advertises and executes its fixed `read`/`write` workspace tools. It validates the exact bounded object shape and plain filename, performs a UTF-8 atomic create-new write, and rejects existing files and symlinks. A create collision returns `file_exists`; another open/write/flush `IOException` returns `tool_io_error` without retry or deletion of a possibly partial file. Unknown tools, invalid paths/schema, and malformed parsed arguments produce paired errors with the original call ID and no effect. The directory boundary is not an OS sandbox. The default loop cap is 500 and tests can inject a smaller explicit cap; no recursive processor is created. Bounded error response serialization matches the actual shared `js-yaml` formatter for supported fixed errors and dynamic unknown/parse messages, including quote, comma, newline, tab, NUL, NEL, and other C0/C1 scalar escaping.

Workspace `edit` replaces exactly one UTF-8 text occurrence. `apply_patch` uses the existing action-envelope, contextual/anchored line diff and ordered Add/Update/Delete semantics: it validates all paths before effects, then validates and performs each filesystem operation in order, returning already-applied operations on a later failure rather than implying a transaction or rollback. Relative file paths are always rooted at the configured tool workspace; existing regular files and resulting content stay within 1 MiB, symlinks are rejected, and Add can create missing workspace-parent directories. This path check is not race-proof OS confinement.

Local Linux `exec` uses the configured workspace root as its default initial working directory; an explicit cwd must be an existing relative workspace directory without symlinks. A shell's `cd` does not update subsequent exec/file defaults. Exec spawns a standalone bash wrapper with a narrowly selected PATH/HOME/locale/user environment and no automatically inherited host API/provider secrets. Its command, full raw stdout/stderr log, atomic exit status, and active tracking live under the separate authority root `state/exec/<Session key>/<petname exec ID>/`; logs and metadata persist after tracking is removed. A fixed bounded foreground preview or partial timeout preview points to `read_exec`, which checks the exact current Session owner and returns status plus at most 16 KiB of original bytes per page, an actual consumed-byte `nextOffset`, byte size, and explicit escaped bytes when a UTF-8 boundary is broken. The Responses tool-output formatter admits only this bounded shape. Timeout defaults to 15s, clamps values above 60s with a warning, and does not kill the process. Stop during the wait cancels the Session's wait but leaves the shell tracked in background and strictly persists the paired tool row; the cancellation handle retains its token after the Stop owner disposes the source. There is no model wait/list/kill tool, session-cwd mutation, OS sandbox, or assurance that an arbitrary same-UID shell cannot inspect paths outside the workspace.

The completion reconciler reads only owned tracked artifacts after loading valid idle Session authorities. It strictly persists one background system queue item and the newest 32 exact `exec-completion:<id>` receipts on that Session's ordered save lane, publishes only its own queue/meta delta, then triggers the existing single Session processor if idle. A precommit failure keeps tracking for retry; postrename publication is retained, so retry sees the receipt rather than duplicating the event. If the wrapper cannot write status, a three-second grace plus exact `/proc/<pid>/stat` start-time observation writes an unknown-exit fallback without operating on that PID; background tracking older than 24 hours is discarded without killing the process or deleting artifacts. No child-process kill or arbitrary PID-based control occurs during Stop or host shutdown; the independent wrapper can write status after the host exits. A clean-idle restart reloads pending tracking and delivers its event once. Historical flat `s_<GUID>` IDs keep their existing exec directory names; new namespaced/nonlegacy IDs encode one canonical ID into one filesystem segment so slashes never produce nested exec ownership. A crash during a busy Session and the launch-to-tracking-write failure window are not recovered, nor does this create a general tool-effect ledger or generic durable event platform.

This remains bounded Message/persistence compatibility rather than a complete Session implementation. Slice D proves explicit-ID clean-idle two-process continuation. The interactive host additionally supports multiple concrete localhost Responses models with persisted effort, current-v1 synchronous layered compaction, trusted local development tools, and a bounded Agent/fresh-child loop. Crash/power-loss and committed-busy recovery, full catalog/Agent lifecycle, move/alias/fork, inheritance, skill scanning, automatic memory refresh, custom systemPromptFiles, request journals, provider retry/routing, general registry/MCP/Node tools, image/hosted input, virtual/WS/failover models, async/background compact, full recall/vector search, model wait/kill, managed state, channels, Worker placement and production runtime integration remain excluded. Active history never reconstructs from Archive.

Active JSON remains the sole active-history authority. The supported subset preserves ordinary queue shapes, CTX-BLOCK metadata, `preservedFromBlockId`, and monotonic `nextBlockId`, while rejecting unsupported lineage/wait/managed/Worker state and images. Layered candidates/plans come solely from one active snapshot, respecting 30% newest rendered-history keep (without splitting existing call+tool pairs), 2,000-token raw eligibility and 20% raw replacement, source-block 3,000/5,000-token eligibility/force quotas, oldest 40% candidate window, and at most 15 planner rounds. Ranges follow display order rather than numeric block-ID order. Archive blocks preserve source block IDs, original seq/time ranges and optional memory facts; no Vector indexing or automatic Archive reconstruction follows. Only historical tool-output pruning reads and rechecks exact immutable Archive provenance; it publishes a pruned active row only if estimated context falls to at most 50% of the selected model limit, leaving the original reachable by exact paginated recall and HTTP. Staged Archive blocks/completion row are written before atomic JSON authority replacement; precommit rolls back only new rows, postrename retains/publishes committed state and throws. Hot publication changes only compaction-owned history/version/seq/block metadata, preserving concurrent queued ingress, Stop and model settings. Missing/corrupt JSON still fails closed, and busy/crash recovery remains unsupported.

## Tests and integration

Added regressions load nonzero `historyVersion`, inject a deterministic clock for missing/null/0/-0 timestamps, prove synchronous BeforeRename I/O does not hold `laneGate` while another thread performs Stop/Cancel/enqueue, and observe a default-trigger failure before one explicit recovery trigger. The Responses-client files in `Foxwarm.Tests` run the real two-POST UTF-8 fixture effect through JSON/SQLite authority, require rows 1..4/next 5 and actual TypeScript zero-insert exact replay, checks the actual TypeScript ordinary sequence/timestamp/historyVersion builder, and injects persistent assistant/tool-row precommit failures to prove no HTTP resend or effect replay. Its Slice D test runs two distinct child PIDs serially under one bounded test process tree, verifies A exit before B launch, three total localhost requests, persisted rows 1..6/next 7, no repeated file effect, final actual-TypeScript read/zero-insert replay, and missing/corrupt JSON fail-closed child loads with complete Archive and no extra HTTP. The new `host-e2e.py` is one local scripted-Responses integration driver (not a new unit-test suite): two concurrent Sessions and one same-Session queued turn, real incremental SSE, read/write and overwrite/escape outcomes, held-provider Stop, clean host restart with continued JSON/Archive sequences, and fail-closed missing/corrupt authority without a provider request. The new one-shot scripted localhost/browser acceptance in this branch’s WebUI tests exercises two configured concrete models/effort with in-flight switch and clean restart, automatic and manual L1→L2 compaction with a real invalid-plan correction, immutable raw and nested CTX expansion, prune-only recovery with middle-page recall, and held-planner cancellation followed by queued input. The experiment is run manually from the solution or focused project. No Foxwarm service restart is required because the .NET host is not the production runtime.
