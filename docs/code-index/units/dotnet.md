## Purpose

Contains a bounded .NET 10 host and compatibility probes outside the production Node.js runtime and normal test graph. One solution owns three projects; source folders do not represent separate assemblies.

## Scope

- `Foxwarm` is one Web executable: root `Foxwarm` memory helpers; `Foxwarm.Sessions` Message JSON, ordered Session turns, persistence/Archive, and layered compaction; `Foxwarm.Models` Responses SSE/client and concrete model configuration; `Foxwarm.Tools` fixed workspace, trusted local exec and Session-tool dispatch; `Foxwarm.Channels.WebUi` authenticated localhost HTTP/realtime channel. Root `Foxwarm` also owns startup, HTTP infrastructure and the message router. Its persisted JSON/SQLite and provider-facing contracts remain limited to the supported ordinary subset.
- `Foxwarm.Tests` groups the existing memory, model/streaming, Session, and storage test files in one project without deleting their cases.
- `Foxwarm.DevTools` selects one existing development entry by `conditional-memory`, `responses-request`, `responses-stream`, or `session-restart`. The original corpus and process-restart outputs remain unchanged.

The host serves the original App, Sidebar and Workbench with the supported Chat/Agent/Session paths. It is not the complete Agent/Setup backend. Authenticated same-origin Cookie or CLI Bearer owns API and WebSocket routes; a small local login gate wraps the ordinary frontend entry. Unsupported App entries remain visible and may return 404/501 rather than requiring a temporary feature-discovery system. The original frontend uses genuine revisioned list-plus-Chat WebSocket subscriptions, v2 draft deltas, canonical messages, queue previews and range/historyVersion snapshots. The experiment-only composer preserves the existing model selector for current and future-child concrete model/effort while hiding unsupported Setup and attachments; normal frontend builds are unchanged. `/compact` durably claims an idle Session processor and runs synchronous planning, `/stop compact` cancels only that planner and preserves ordinary queued ingress; auto compaction runs under the current turn claim when cached+input+output usage exceeds the effective Session threshold (model-derived 85% by default). Runtime status uses the existing requesting-model/compaction phase. The planner accepts only `submit_compact_plan`; normal turns execute workspace file tools (`read` also accepts accessible absolute paths), local `exec`/`read_exec`, declared activity `wait`, and exact archived-context `recall` selectors with current/selected hosted-Session scope. Recall uses bounded preview rendering and no Vector search; the authenticated exact-seq HTTP endpoint exposes the complete original row. These application-level path/auth limits are not an OS sandbox or production authentication. No ordinary tool call may execute `submit_compact_plan`. Shutdown cancels active planner/provider requests and waits for save/processor completion; it does not kill already-started local exec commands. Persisted busy/stopping states fail closed.

The experimental Agent layer retains existing flat `s_<GUID>` authorities as Agent `main` with the original configured workspace, JSON, Archive and exec receipts. The main Agent has no invented canonical `main` Session: it can be created explicitly. New Agent names use the TypeScript alphanumeric/hyphen/underscore grammar; new Session names are nonempty slash-free components. New IDs are canonical `agent/session` (or flat names for Agent `main`), and fresh children can be named under the same or another Agent, including a legacy flat parent. A separate atomically written Agent catalog records created Agents while per-Session JSON remains the sole active authority for Agent, parent ID, model/effort and snapshot. Metadata/Agent directories exist before Session publication; partial creation returns the committed ID when one exists. Startup validates every bound Agent and acyclic existing parent relationship, recursively loads namespaced authorities, and still refuses corrupt/missing active JSON despite complete Archive. HTTP resolves exactly one encoded path layer from the literal request target, including `%2F` for a slash while retaining a literal `%2F` in a flat Session name. Agent workspace/memory is `<tool-root>/agents/<name>/memory` for new Agents; legacy main keeps `<tool-root>/memory`. The framework 00_SYSTEM.md comes from the common Agent root, with the main-memory 00_SYSTEM.md as fallback. The legacy main workspace contains the new Agent subdirectories, and all shell effects run with the host UID; Agent ownership and workspace-root-relative file tools are not OS isolation.

One selected concrete model identity governs the stored memory snapshot. Ordered framework and owning-Agent Markdown sources use the existing `<memory_file ...>` wrapper and `foxwarm-if` filtering; recognized YAML `include-session`/`exclude-session` front matter controls per-Session inclusion, and ordinary unknown keys do not suppress the text body. Explicit host instructions remain before the stored snapshot. Same-identity requests reuse its exact persisted bytes even when files change; switching concrete leaf or explicitly refreshing writes the new snapshot strictly through the owning Session save lane before a request can be sent. A precommit failure leaves its previous hot/persisted snapshot and sends no provider request; postrename failure retains the published committed snapshot and also prevents that request. Detached compaction planning can construct a per-model captured snapshot without replacing the live one. Inheritance and skill knowledge sources are supported below. Custom prompt-file selection and virtual routing remain outside this concrete-model host.

The fixed ordinary-turn Agent tools create an Agent, create a Session, create a fresh child, deliver to another existing Session, or refresh the caller's snapshot. Agent creation normally includes an `agent/main` Session and may intentionally omit it. Fresh children bind their real parent and owning Agent, preserve an independent history/cache lineage and inherit only one raw model/effort pair (explicit override, existing parent child defaults, or parent current); they do not recursively copy future child defaults. Their genuine new-child boundary and initial message are strict persisted operations; a child that was committed before initial delivery failed remains visible with its actual ID rather than being rolled back fictitiously. Source-bearing inter-Session messages, including between non-parent/non-isolated Agents, use a narrow strict target save-lane enqueue. Only after commit does the existing single processor start if idle; busy targets merely queue. `send_to_session` self/missing targets fail and `<parent>`/`<main>` resolve only when an actual Session exists. `afterSend=finish` ends the caller's turn only after every sibling tool in the same assistant batch has a paired persisted response; it does not stop or kill another Session and does not implement managed handoffs or confirmation rules. Ordinary declared activity waits and waiting handoffs are supported below.

The original App/Sidebar/Workbench and their existing bounded list/realtime hooks are used directly. `ExperimentChatApp` and its build entry have been removed. `VITE_FOXWARM_DOTNET=1` adds only the cookie login gate and passes the existing text-only Chat option; it does not create a capabilities matrix, probe missing features, clean stored layouts or hide all unimplemented menus. Agent/Session creation uses the original browser DTO (`agentId`, optional `sessionId`; Agent creation responds with `sessionId`), while model tools retain their separate approved `agentName` schema. Bare legacy Session creation remains supported. The channel translates the existing strict display-name update and real local branding settings; pin, destructive Session/Agent operations, Setup, Code, Terminal and global history search remain unimplemented and may fail explicitly through their normal frontend entry points.

Same-marker snapshots reuse exact persisted bytes even after metadata or skill changes. A live skill list/load sees current sources; loading does not refresh the prompt. Real changed-leaf rebuilding still requires strict save before send, including retained postrename/error semantics. Fresh host-created lifetimes start with source-equivalent current lastMessageTime. Explicit per-Session refresh retains its recorded identity; detached compaction never replaces a live prompt.

## Local file usability

`Tools/FileToolCore` owns physical byte-line scanning, bounded text rendering, directory listing and atomic write mechanics; `WorkspaceTools` retains caller validation/path authorization, parent/cache handling and approved definitions. Reads accept relative workspace paths (including `.` for the root listing) or absolute host paths. Writes remain relative to the owning workspace. No symbolic-link traversal, FIFO/device reads, tilde/environment expansion, image dispatch, Node adapter or OS sandbox is added. Existing edit/patch limits and exec/cwd behavior remain unchanged.

Source-style physical lines recognize LF, CRLF and bare CR, including chunk-split CRLF; exact selected terminators remain intact. Empty files have zero lines, trailing terminators create no virtual EOF line, and a final unterminated segment receives a single tool LF before the metadata footer plus an explicit no-trailing-newline notice. Omitted/null/zero line bounds are absent; finite bounds floor, start clamps to 1 and end to 0. Small files up to 1 MiB are read fully and report exact totals. Large default reads sample only 5000 bytes from each end; finite large ranges scan 64 KiB chunks only through their endpoint and report total lines only if EOF was reached. A selected range crossing 1 MiB drops full retention and keeps bounded head/tail plus exact selected-byte counts, including giant single lines. Small complete UTF-8 uses replacement decoding; bounded samples preserve source partial/invalid-byte escaping and 10% binary classification with 64-byte hex previews. Source file bytes are never rewritten by read.

Directories are nonrecursive, name-collated using the host's explicit English collation adapter, with source numbering/type/size/ISO-time and next-page hints; default 50 entries, explicit inclusive bounds. Symlink entries may be identified without traversing them. The collation adapter is not a claim of every ICU/locale version being byte-identical to JavaScript localeCompare.

Write requires explicit createDirs to create missing parents; parent-is-file is distinct. Existing files remain protected without overwrite. Supplied text no longer has the previous 1 MiB cap; existing atomic temp→move publication remains. Host-owned PendingWriteRefs caches only refused existing-file/missing-parent attempts, with exact Session ID plus Agent scope, 15-minute original TTL, 32 entries, 2 MiB single payload and 8 MiB aggregate budget. Expired/oldest entries are pruned under a short lock that never spans filesystem I/O. Retry requires overwrite:true and no content alongside contentRef, may select another authorized target, retains the reference on failure and consumes on success. Path validation precedes cache lookup and effects. No persisted cache, timer service or durable receipt is created; after restart an old ref is honestly missing/expired, while prior canonical error/result history and successful file bytes remain intact.

The concentrated Files workflow covers actual large/mixed/giant/chunk-boundary reads, directory pagination, newline/zero/negative/range metadata, Unicode/binary display, denied symlink/FIFO, cached retries/scope/consumption/entry and aggregate eviction, uncached oversized supplied writes and clean-process restart. A single integrated clock-injected file retry fixture validates original TTL despite failed retries and no createDirs effect after expiry; no public clock/fault endpoint exists. Developer-tool, Knowledge and ModelCompact regressions verify affected original UI and source-retrieval paths with the new read footers.

## Continue and collaboration waits

`/continue` uses the original Chat availability/control path and the ported `SessionContinuation.IsIncomplete` history classifier. Temporary/optimistic/display-only and generated compact-boundary rows are transparent; request retry notices, incomplete segments, empty/text/tool tails, and exact complete call/response pairing retain the source semantics. Successful terminal handoff exchanges are complete. The backend independently rejects busy/processor-owned, waiting, and complete Sessions, claims the existing processor, and sends committed history without another user/trigger row. Continue does not reexecute old tools, synthesize missing outputs, or add an effect receipt/retry journal. A provider rejection of an unmatched historical call remains an ordinary request failure. Stop during a continuation uses the existing cancellation and passive queue-finalization path. Automatic busy/crash recovery remains unsupported.

`wait` accepts the closed declared-source argument shape: positive finite `wakeIfNoActivityAfterSeconds`, mutually exclusive `waitAllSessions` (at least two distinct other existing Sessions) / `waitAnySessions` (at least one), exact current-Session owned active or queued-completion `waitExecIds`, `waitForInput:true`, and optional reason. A reason alone is insufficient. Any/exec/input expectations are advisory and do not filter legitimate incoming activity. `afterSend:wait` requires an initial message for a fresh child and coalesces only successful resolved delivery targets after the complete paired tool-result batch; ordinary queued fast replies pass the same wake transition immediately. A successful waiting or finish handoff remains terminal despite a sibling error. An explicit wait with a sibling error clears only its own created wait token and continues the ordinary provider loop.

Active JSON owns `meta.wait` (ID/start/reason/source declarations, timeout duration, and waitAll sessions/satisfiedSessions/deferredQueue). Listed inter-Session messages advance a waitAll barrier and stay durably deferred without a provider/processor claim until all sources have responded. Unrelated user/system/inter-Session input releases deferred items in order, appends the input and a source-derived pending reminder, and clears the wait. Deferred messages are not Archive/active-history rows until their normal canonical append. Admission, wait start/clear, receipts and defer/wake updates share the existing per-Session save lane. Strict inter-Session/exec/internal-event operations stage and publish only their owned queue/wait/receipt changes; pre-rename failures do not publish, postrename failures retain/publish and report. Ordinary user ingress remains best-effort: its owned hot admission is published when its ordered operation starts, before its save attempt; failure does not erase acknowledged content. Stop's synchronous state/CTS updates are not replaced by an older staged envelope.

`SessionWaitTimeouts` is an internal one-shot controller, not the TypeScript general timer/cron table. It derives the deadline from committed wait.startedAt + timeoutSeconds, rearms from clean-idle JSON before ordinary admission, and queues an overdue current-token fallback once. Stale timeout/liveness tokens are discarded without claiming a processor. Source-only declarations use the ported `WaitLiveness` reverse dependency graph, 300ms grace, active/queued/timed/exec/input/transitive progress observation, persisted newest16 fingerprint dedup and at most four diagnostic wake slots. `wait-sources-quiescent` reports an observed lack of progress, not proof of deadlock or task completion. Shutdown stops admission, cancels/drains controller jobs and preserves idle waits; busy/stopping authorities still fail closed. Idle-wait Stop remains the active-control no-op; input wakes the wait.

Runtime/list/Chat derive `waiting` and bounded source/deadline/satisfied/pending details from wait metadata. Their metadata capture copies only that declaration, never deferred message bodies or full history. Original Chat Continue is enabled independently of the remaining text-only attachment/ASR/unsupported-action restrictions. No managed state, Worker/RPC, general timer tools, wait cancellation command or frontend capability system is added.
