## Continue and collaboration waits

`/continue` uses the original Chat availability/control path and the ported `SessionContinuation.IsIncomplete` history classifier. Temporary/optimistic/display-only and generated compact-boundary rows are transparent; request retry notices, incomplete segments, empty/text/tool tails, and exact complete call/response pairing retain the source semantics. Successful terminal handoff exchanges are complete. The backend independently rejects busy/processor-owned, waiting, and complete Sessions, claims the existing processor, and sends committed history without another user/trigger row. Continue does not reexecute old tools, synthesize missing outputs, or add an effect receipt/retry journal. A provider rejection of an unmatched historical call remains an ordinary request failure. Stop during a continuation uses the existing cancellation and passive queue-finalization path. Automatic busy/crash recovery remains unsupported.

`wait` accepts the closed declared-source argument shape: positive finite `wakeIfNoActivityAfterSeconds`, mutually exclusive `waitAllSessions` (at least two distinct other existing Sessions) / `waitAnySessions` (at least one), exact current-Session owned active or queued-completion `waitExecIds`, `waitForInput:true`, and optional reason. A reason alone is insufficient. Any/exec/input expectations are advisory and do not filter legitimate incoming activity. `afterSend:wait` requires an initial message for a fresh child and coalesces only successful resolved delivery targets after the complete paired tool-result batch; ordinary queued fast replies pass the same wake transition immediately. A successful waiting or finish handoff remains terminal despite a sibling error. An explicit wait with a sibling error clears only its own created wait token and continues the ordinary provider loop.

Active JSON owns `meta.wait` (ID/start/reason/source declarations, timeout duration, and waitAll sessions/satisfiedSessions/deferredQueue). Listed inter-Session messages advance a waitAll barrier and stay durably deferred without a provider/processor claim until all sources have responded. Unrelated user/system/inter-Session input releases deferred items in order, appends the input and a source-derived pending reminder, and clears the wait. Deferred messages are not Archive/active-history rows until their normal canonical append. Admission, wait start/clear, receipts and defer/wake updates share the existing per-Session save lane. Strict inter-Session/exec/internal-event operations stage and publish only their owned queue/wait/receipt changes; pre-rename failures do not publish, postrename failures retain/publish and report. Ordinary user ingress remains best-effort: its owned hot admission is published when its ordered operation starts, before its save attempt; failure does not erase acknowledged content. Stop's synchronous state/CTS updates are not replaced by an older staged envelope.

`SessionWaitTimeouts` is an internal one-shot controller, not the TypeScript general timer/cron table. It derives the deadline from committed wait.startedAt + timeoutSeconds, rearms from clean-idle JSON before ordinary admission, and queues an overdue current-token fallback once. ### Decision: Main unmanaged ToolScript runtime and safety boundary

Confirmed 2026-10-04. The implementation uses the exact pinned upstream standalone native protocol, not a new interpreter/ABI or a fourth product project. Native interpreter memory remains 64 MiB, framed protocol remains 256 MiB and the qualification-supported legal 48-level value boundary is preserved. Before generated protobuf parsing, `MontyFrameBudget` scans the fixed protocol with distinct protocol/value depth and charges fields, repeated values, decoded strings, bytes and materialization coexistence; unknown fields are discarded. Normal script results and host input/value conversions share the current conservative data accounting.

The independently fixed parent activity data budget is 1 GiB, not a process RSS, sandbox or precise heap guarantee. It includes retained stdout/snapshots/run metadata together with current frame/value/conversion/host result/JSON projection/record materialization, using the same activity budget through the normal host bridge. Run loads preflight token/text/container costs before copying decoded JSON. They use standard `Utf8JsonReader` materialization rather than `JsonDocument`'s payload-proportional metadata allocation for a large escaped string. Atomic record writes use .NET 10 `Utf8JsonWriter.WriteStringValueSegment` and bounded flushes for stdout and other string values; merely choosing a stream-backed writer does not make whole-string encoding bounded. Old over-budget records and malformed snapshot encodings are reported before mutation, without rewriting them, deleting snapshots or pretending they are empty successes.

Cumulative accepted stdout is independently limited to 64 MiB UTF-8 across all slices. Overflow kills/closes that owned interpreter, commits a failed run when the write boundary permits it, retains the complete accepted Unicode-safe prefix and already-completed tool effects, removes unusable continuation data, and prevents subsequent host calls. It does not silently truncate/claim successful completion. `ask_agent` and actual safe-boundary timeout checkpoints retain official Source-compatible opaque snapshots, continuation IDs and settled pending returns/exceptions. Continuation emits only new stdout and never rereads source or repeats a settled pending host effect. Loading a snapshot preserves native CPU consumption rather than granting a new interpreter lifetime by assumption.

Run records remain individual atomic JSON files in `state/toolscript-runs`, with existing Source IDs and `@pydantic/monty`/0.0.19/`monty-pool-snapshot-v0.0.19` identity. A running checkpoint commits before native effects. Active cancellation is request-first and reports the actual committed/current status until the execution owner drains already-started host work and saves `cancelled`; management does not independently overwrite a live mutable run. Self/ancestor cancellation does not wait for its own settlement. Initial/waiting/terminal write failures preserve truthful pre-rename or post-rename state, never invent an actionable uncommitted continuation or replay effects, and drain the owned native child. Shutdown closes admission, cancels active work and awaits every accepted execution/management activity. Persisted managed waiting/controller/lease records remain inspectable but reject continuation/cancellation without modifying their snapshot or references. Historical literal owners are not rebound through current Session aliases; idle/deleted/moved-owner histories remain separate records, not repaired or auto-replayed runs. New runs capture the same mutable owner's current Session ID at creation, including nested starts after a self-move; this does not change the inherited literal caller context used by management. Active cancellation snapshots the actual record owner, so its fast path and persisted ownership checks agree. Run lists sort parsed numeric updated timestamps newest first and apply numeric limits through the existing number conversion, without depending on directory enumeration order.

### Decision: Main timer persistence and scheduling

Confirmed scope: Main-local ordinary once/cron timers and compatibility with existing timer records. The active Session JSON still owns canonical wait declarations and deadlines; the general timer document is not a second wait authority.

A genuinely absent store starts fresh. An unreadable/malformed whole store or unrecognized root/container makes only timer management unavailable, reports a diagnostic and leaves existing bytes unchanged. This is an ordinary tool error, not the trusted authorization-unavailable condition. Valid documents preserve root extensions, unknown JSON values and extra record fields on later writes; whitespace and escape spelling are not a persisted contract. Duplicate ID groups are retained unarmed and are ambiguous for mutation. Unknown records and unsupported schedules/placements remain retained and unarmed while healthy unique ordinary records continue. No repair, quarantine, enabled flag or new persisted receipt/epoch schema is introduced.

The async timer save lane stages a candidate, serializes and atomically replaces the file outside short synchronous gates. Pre-rename failure publishes nothing. After an actual rename, the committed document and its future registration are published even if a later durability step fails; the caller gets a truthful partial result. Publication never rolls back an already admitted delivery. A callback may finish only its captured record, so completing an older once delivery cannot remove a subsequently updated replacement. Cancel/update/delete affect future registrations, not a queue admission or Session creation already started. Cron deliveries may overlap. Once records are consumed after successful delivery or ordinary delivery failure; successful cron delivery records its callback-start time, while failure retains the previous `lastTriggeredAt`.

Loading does not arm ordinary jobs until real Main and every mandatory C2 owner have passed startup validation. Future targets remain metadata-only; due delivery performs exact semantic admission. Unsupported effective Node placement stays unarmed rather than falling back to Main. Overdue once records fire on restart; cron starts from restart-now without replaying downtime from `lastTriggeredAt`. Shutdown stops future clocks and drains already accepted creation/queue work and completion saves before owner shutdown. Ordinary best-effort queue durability and Stop/Continue behavior are unchanged.

New-session timers capture the owning Session's raw logical model/effort, Agent and Node settings internally. Firing revalidates them against the current catalog, then uses the real atomic allocator, skipping live and permanently reserved identities. The created Session is fresh, has no parent and does not clone the former owner's history/cache/snapshot. Removing the owner does not by itself revoke that captured creation. Management remains scoped to the stored literal owner ID; due delivery may resolve an active alias. Move and deletion do not rewrite timer rows. Isolated callers independently remain limited to their exact current Session and own Agent even when policy explicitly allows the capability.

Recognized old internal wait records never become clocks. Only a genuinely admitted, validated current owner can prove matching, absent or different canonical wait ID and consume the redundant/stale record. Missing/unknown/unsupported relationships remain untouched; no cold-history scan or synthetic empty owner is used. `SessionWaitTimeouts` still derives the sole deadline from committed `startedAt + timeoutSeconds`.
