## Purpose

Contains limited, manual .NET migration experiments. The projects are outside the Node.js runtime and normal test dependency graph; source and tests remain the authoritative contract for each probe.

## Scope

- `Foxwarm.ConditionalMemory` ports pure conditional-memory helpers.
- `Foxwarm.MessageJson` is an owned `JsonObject` compatibility leaf for supported canonical messages and tool arguments.
- `Foxwarm.OpenAIResponses.Streaming` ports a transport-neutral Responses event accumulator and asynchronous SSE collector. It stops before HTTP request construction, authentication, retries/routing, timeout policy, WebSocket pooling, request journaling, Session ownership, and final canonical `Message` conversion.
- `Foxwarm.OpenAIResponses.Client` is the bounded localhost-capable HTTP slice over the collector. It owns supported Responses request serialization, `ResponseHeadersRead` POSTs within one host-owned tool loop, bounded non-success capture, completed-output conversion, the concrete `IChatService` adapter, and one injected test-root `write_fixture` executor. It has no retry, routing, journal, general tool registry, or runtime-configuration layer and never persists independently of its Session host.
- `Foxwarm.SessionTurns` is the bounded translation of the Main-local `sessionWorkers:false` Session-turn seams. It keeps owned authority-envelope, queue, history, `nextMessageSeq`, and `historyVersion` state; uses a short per-Session state gate plus one ordered asynchronous save lane; claims one processor atomically; owns one active cancellation handle; and binds an in-process chat/tool host to one exact Session entry. The in-memory authority substitute and the C2 persistent adapter use the same staged canonical-append path.
- `Foxwarm.SessionPersistence` owns bounded current-v1 JSON validation, the pinned `Microsoft.Data.Sqlite` 10.0.12 exact TypeScript message and block Archive layouts, immutable replay/conflict/inserted-only rollback, exact stored `message_json`, per-Session read-only indexed seq lookup and Linux temp-fsync→rename→directory-fsync with postrename classification. `PersistentSessionAuthorityStore` stages canonical and compact rewrites for one explicit Session ID without a cross-store transaction or recovery framework.
- `Foxwarm.SessionRestartHarness` is a test-only CLI for the bounded Slice D process-A, process-B, and fail-closed load-check modes; it is not a Foxwarm runtime entry point.
- `Foxwarm.ExperimentHost` is an independent loopback HTTP host for multiple ordinary Sessions. Its explicit JSON-only `FOXWARM_EXPERIMENT_MODELS_FILE` accepts concrete local HTTP Responses providers, context limits and effort allow-lists/defaults; `apiKeyEnv` reads startup credentials without serializing them to browsers or Sessions. The original single-model environment remains a fallback. Per-Session model/effort changes persist on the ordered save lane, and each provider request captures its own model/credential/effort. Every Session retains its own processor and JSON authority; short-lived SQLite WAL connections share the Archive. Startup scans only owned idle JSON and uses Archive IDs only to fail closed if JSON disappears.

The host exposes a bounded CLI and original-Chat-leaf adapter, not the complete WebUI App/Agent/Setup API. Authenticated same-origin Cookie or CLI Bearer owns API and WebSocket routes; static assets load the local login shell. The original Chat uses genuine revisioned Session-only WebSocket subscriptions, v2 draft deltas, canonical messages, queue previews and range/historyVersion snapshots. The experiment-only composer preserves the existing model selector for current concrete model and effort while hiding child defaults/Setup and unsupported attachments; normal frontend builds are unchanged. `/compact` durably claims an idle Session processor and runs synchronous planning, `/stop compact` cancels only that planner and preserves ordinary queued ingress; auto compaction runs under the current turn claim when cached+input+output usage exceeds 85% of selected context limit. Runtime status uses the existing requesting-model/compaction phase. The planner accepts only `submit_compact_plan`; normal turns execute fixed relative-workspace `read`/`write` and exact current-Session `recall({target:"msg#N",offset?})`. The recall tool returns at most 12,000 Unicode code points of immutable stored message JSON per call and has no search, range, cross-Session or Vector scope; the authenticated exact-seq HTTP endpoint exposes the complete original row. These application-level path/auth limits are not an OS sandbox or production authentication. No ordinary tool call may execute `submit_compact_plan`. Shutdown cancels active planner/provider requests and waits for save/processor completion. Persisted busy/stopping states fail closed.

`SessionTurns` consumes the complete leading ordinary prefix without source/platform/conversation splitting while retaining one canonical history row and `clientMessageId` per logical input. Queue source fields are provenance only; the experiment has no Channel adapter or reply-target implementation. The lane lock only links a new tail to its predecessor; an asynchronous launch signal starts previous-wait and operation execution after lock release, so synchronous SQL/fsync is never run while holding `laneGate`. Canonical append takes selected queue object identities and an owned staged snapshot under the state gate, allocates contiguous sequence/timestamp metadata, then performs Archive insertion and JSON commit outside both gates. Timestamp `0`/`-0` follows TypeScript's falsy timestamp rule; ordinary appends preserve `historyVersion` rather than treating it as a process generation. Precommit failure publishes no staged hot mutation and rolls back only newly inserted rows; byte-exact preexisting replays are retained. Postrename `AuthorityCommittedException` keeps Archive and JSON, publishes only that operation's queue/history/seq/meta delta, and reports the durability problem without rollback or provider/tool retry. Later ingress and Stop/meta changes stay hot and their queued saves run afterward. Queue-prefix and Stop-finalization notifications remain non-poisoning; other callback semantics are unchanged. Stop cancellation still happens outside the gate before its save wait.

`IChatService` returns an optional owned canonical assistant Message rather than a text shortcut. The fake chat builds the same narrow result shape. The Responses client converts supported reasoning, output text, refusal, function calls, phase, annotations, usage, concrete model identity, and request timing, then returns without persistence; persisted timing derives fractional `startedAt` from completion wall time minus monotonic duration. `LocalSessionTurnHost` alone strictly commits assistant and paired tool rows, executes a committed call through the injected executor, consumes newly queued ordinary input only after the tool row, and performs the next request under the same processor claim. Assistant-save failure prevents the effect; tool-row-save failure stops after any already-completed external effect and never reexecutes it or sends another request. The experiment has no effect receipt ledger.

The Responses request serializer filters exact `modelVisible:false`, preserves open JSON by cloning, and implements the current bounded TypeScript input projection for canonical system/text content, assistant phase grouping, reasoning replay, compatible annotations, function calls, and paired tool outputs. Multi-field parts preserve TypeScript's `system` → reasoning → `text` → function-call order, with commentary fallback for model messages containing calls. Stable call IDs, exact raw arguments, parse-error metadata, safe malformed-argument replay, and current shared tool-result formatting are retained. System formatting uses explicit ECMAScript whitespace and ASCII-boundary behavior rather than .NET `Trim`/Unicode `\b`, covering whitespace-only self-closing output, FEFF, NEL, and non-ASCII suffixes on Foxwarm tag names. Semantic inputs outside this slice fail explicitly: missing stable call IDs, images, native output-item replay, and legacy system normalization. The HTTP client uses explicit options only, streams through the existing collector, captures at most 64 KiB of non-success bodies, and propagates cancellation through send, read, and disposal. Empty completion creates no assistant.

The older bounded Slice B effect implementation is an injected `write_fixture` executor rooted in a test-owned temporary directory; the later interactive host separately advertises and executes its fixed `read`/`write` workspace tools. It validates the exact bounded object shape and plain filename, performs a UTF-8 atomic create-new write, and rejects existing files and symlinks. A create collision returns `file_exists`; another open/write/flush `IOException` returns `tool_io_error` without retry or deletion of a possibly partial file. Unknown tools, invalid paths/schema, and malformed parsed arguments produce paired errors with the original call ID and no effect. The directory boundary is not an OS sandbox. The default loop cap is 500 and tests can inject a smaller explicit cap; no recursive processor is created. Bounded error response serialization matches the actual shared `js-yaml` formatter for supported fixed errors and dynamic unknown/parse messages, including quote, comma, newline, tab, NUL, NEL, and other C0/C1 scalar escaping.

This remains bounded Message/persistence compatibility rather than a complete Session implementation. Slice D proves explicit-ID clean-idle two-process continuation. The interactive host additionally supports multiple concrete localhost Responses models with persisted effort and current-v1 synchronous layered compaction. Crash/power-loss and committed-busy recovery, catalog/Agent/Session discovery, child handoff, request journals, provider retry/routing, general registry/MCP/Node tools, image/hosted input, virtual/WS/failover models, async/background compact, full recall/vector search, waits, managed state, channels, Worker placement and production runtime integration remain excluded. Active history never reconstructs from Archive.

Active JSON remains the sole active-history authority. The supported subset preserves ordinary queue shapes, CTX-BLOCK metadata, `preservedFromBlockId`, and monotonic `nextBlockId`, while rejecting unsupported lineage/wait/managed/Worker state and images. Layered candidates/plans come solely from one active snapshot, respecting 30% newest rendered-history keep (without splitting existing call+tool pairs), 2,000-token raw eligibility and 20% raw replacement, source-block 3,000/5,000-token eligibility/force quotas, oldest 40% candidate window, and at most 15 planner rounds. Ranges follow display order rather than numeric block-ID order. Archive blocks preserve source block IDs, original seq/time ranges and optional memory facts; no Vector indexing or automatic Archive reconstruction follows. Only historical tool-output pruning reads and rechecks exact immutable Archive provenance; it publishes a pruned active row only if estimated context falls to at most 50% of the selected model limit, leaving the original reachable by exact paginated recall and HTTP. Staged Archive blocks/completion row are written before atomic JSON authority replacement; precommit rolls back only new rows, postrename retains/publishes committed state and throws. Hot publication changes only compaction-owned history/version/seq/block metadata, preserving concurrent queued ingress, Stop and model settings. Missing/corrupt JSON still fails closed, and busy/crash recovery remains unsupported.

## Tests and integration

`Foxwarm.SessionTurns.Tests` retains the in-memory queue/Stop/CTS suite and adds persistent staged-append barriers for concurrent acknowledged ingress, precommit retry, successful no-gap batching, Stop during a held assistant append, Archive conflict, exact-replay preservation, pre/postrename and post-directory-sync classification, caller-seq rejection, open ordinary-queue round trip, non-poisoning notification failure, and JSON-authority-only reopen/fail-closed behavior. Added regressions load nonzero `historyVersion`, inject a deterministic clock for missing/null/0/-0 timestamps, prove synchronous BeforeRename I/O does not hold `laneGate` while another thread performs Stop/Cancel/enqueue, and observe a default-trigger failure before one explicit recovery trigger. `Foxwarm.OpenAIResponses.Client.Tests` runs the real two-POST UTF-8 fixture effect through JSON/SQLite authority, requires rows 1..4/next 5 and actual TypeScript zero-insert exact replay, checks the actual TypeScript ordinary sequence/timestamp/historyVersion builder, and injects persistent assistant/tool-row precommit failures to prove no HTTP resend or effect replay. Its Slice D test runs two distinct child PIDs serially under one bounded test process tree, verifies A exit before B launch, three total localhost requests, persisted rows 1..6/next 7, no repeated file effect, final actual-TypeScript read/zero-insert replay, and missing/corrupt JSON fail-closed child loads with complete Archive and no extra HTTP. The new `host-e2e.py` is one local scripted-Responses integration driver (not a new unit-test suite): two concurrent Sessions and one same-Session queued turn, real incremental SSE, read/write and overwrite/escape outcomes, held-provider Stop, clean host restart with continued JSON/Archive sequences, and fail-closed missing/corrupt authority without a provider request. `Foxwarm.SessionPersistence.Tests` retains schema/rollback/fsync/reopen and strict JSON-number coverage; its C#→TypeScript fixture includes an ordinary open queue item. Existing request, conditional-memory, and streaming parity corpora remain unchanged.

The new one-shot scripted localhost/browser acceptance in the separate current-Chat experiment worktree exercises two configured concrete models/effort with in-flight switch and clean restart, automatic and manual L1→L2 compaction with a real invalid-plan correction, immutable raw and nested CTX expansion, prune-only recovery with middle-page recall, and held-planner cancellation followed by queued input. The existing host CLI and original Chat browser scenarios remain regression inputs.

The experiment is run manually from the solution or focused project. No Foxwarm service restart is required because these are experiment-only projects.
