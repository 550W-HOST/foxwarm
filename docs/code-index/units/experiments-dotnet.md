## Purpose

Contains limited, manual .NET migration experiments. The projects are outside the Node.js runtime and normal test dependency graph; source and tests remain the authoritative contract for each probe.

## Scope

- `Foxwarm.ConditionalMemory` ports pure conditional-memory helpers.
- `Foxwarm.MessageJson` is an owned `JsonObject` compatibility leaf for supported canonical messages and tool arguments.
- `Foxwarm.OpenAIResponses.Streaming` ports a transport-neutral Responses event accumulator and asynchronous SSE collector. It stops before HTTP request construction, authentication, retries/routing, timeout policy, WebSocket pooling, request journaling, Session ownership, and final canonical `Message` conversion.
- `Foxwarm.OpenAIResponses.Client` is the bounded localhost-capable HTTP slice over the collector. It owns supported Responses request serialization, one `ResponseHeadersRead` POST, bounded non-success capture, completed-output conversion, and the concrete `IChatService` adapter. It has no retry, routing, journal, tool, or runtime-configuration layer and never persists independently of its Session host.
- `Foxwarm.SessionTurns` is the first bounded translation of the Main-local `sessionWorkers:false` Session-turn seams. It keeps Session state, queue items, provenance-only queue sources, and canonical history rows over owned Message JSON; uses a short per-Session state gate plus an ordered asynchronous authority snapshot save lane; claims one processor atomically; owns one active cancellation handle; and binds an in-process fake chat host to one exact Session entry. Ordinary ingress awaits a best-effort save attempt before acknowledgement, and the processor makes another ordered best-effort snapshot attempt before selecting ordinary work. Busy claim, queue/history commit, fake-chat assistant append/persist, and busy release use strict saves. Stop cancels the transferred active request before awaiting its later best-effort save, and stop finalization commits accepted queued inputs to history without another fake model call.

`SessionTurns` consumes the complete leading ordinary prefix without source/platform/conversation splitting while retaining one canonical history row and `clientMessageId` per queue item. Queue source fields are provenance only; the experiment has no Channel adapter or reply-target implementation. Strict append and stop-finalization persistence failures use operation-scoped compensation for only the rows, history objects, timestamps, and state transitions owned by that operation; newer queue entries and independent stopping/meta changes remain intact. Completion and Stop races use narrow exact-handle ownership transfer with stale-clear protection. Queue-prefix and Stop-finalization batch notifications are invoked after strict persistence and outside rollback, but notification exceptions are recorded rather than poisoning committed processing; assistant, busy, and release callbacks retain their existing semantics. The first committed nonempty input controls parts preparation: a prebuilt message consumes that boundary without preparation, an empty row does not consume it, and a parts item prepares numeric `lastMessageTime` only when it is first. History-empty first-parts preparation also gets the canonical escaped session marker `<foxwarm-system kind="session" currentSessionId="..." />` after ECMAScript-whitespace collapsing; later parts after a leading prebuilt message receive no marker and do not change the timestamp. The test-only `InMemorySessionAuthorityStore` proves per-Session save ordering and snapshot reload/cloning only; it does not establish filesystem, SQLite, crash-recovery, or performance equivalence.

`IChatService` returns an optional owned canonical assistant Message rather than a text shortcut. The fake chat builds the same narrow result shape. The Responses client converts supported reasoning, output text, refusal, phase, annotations, usage, concrete model identity, and request timing, then returns without persistence; persisted timing derives fractional `startedAt` from completion wall time minus monotonic duration. `LocalSessionTurnHost` alone clones and strictly commits the assistant. Strict assistant-save failure compensates only that exact hot object and never reissues HTTP.

The Responses request serializer filters exact `modelVisible:false`, preserves open JSON by cloning, and implements the current bounded TypeScript input projection for canonical system/text content, assistant phase grouping, reasoning replay, and compatible annotations. Multi-field parts preserve TypeScript's `system` → reasoning → `text` order. System formatting uses explicit ECMAScript whitespace and ASCII-boundary behavior rather than .NET `Trim`/Unicode `\b`, covering whitespace-only self-closing output, FEFF, NEL, and non-ASCII suffixes on Foxwarm tag names. Semantic inputs outside this slice fail explicitly: tools, images, native output-item replay, and legacy system normalization. The HTTP client uses explicit options only, streams through the existing collector, captures at most 64 KiB of non-success bodies, and propagates cancellation through send, read, and disposal. Empty completion creates no assistant; function-call or unknown output semantics fail before any append.

This remains bounded owned Message JSON compatibility rather than a complete canonical Message implementation. Sequence metadata, archive integration, real persistence, crash recovery, explicit `childHandoffState` transitions, request journals/IDs, provider retry/routing, and other runtime-owned fields remain excluded. Explicit unsupported paths fail with named errors and do not mutate as completed: tools/tool loops, images/hosted tools, compact execution, retry, waits, managed state, channel delivery, Worker IPC or placement, filesystem/SQLite stores, and production runtime integration. No Archive-derived history reconstruction or child-handoff inference from history is used.

## Tests and integration

`Foxwarm.SessionTurns.Tests` uses deterministic task-completion barriers for strict-versus-best-effort persistence, the pre-selection best-effort snapshot, source-blind mixed-source prefix batching, preservation of newer ingress during failed append, operation-scoped stop-finalization compensation, one-processor claims, cross-Session concurrency, Stop cancellation-before-save, finish-window handoff, CTS lifetime races, non-poisoning queue notification failures, canonical marker escaping and timestamp boundaries, prebuilt/empty rows, callback reentry, unsupported paths, and ordinary chat failure. `Foxwarm.OpenAIResponses.Client.Tests` uses real loopback TCP/HTTP with bounded barriers for fragmented SSE, canonical assistant persistence, cancellation/connection close, HTTP and SSE errors, unsupported output, and assistant-save compensation. The request-input parity runner compares a committed corpus against the actual TypeScript serializer. Existing conditional-memory and streaming parity corpora remain unchanged.

The experiment is run manually from the solution or focused project. No Foxwarm service restart is required because these are experiment-only projects.
