## Purpose

Contains limited, manual .NET migration experiments. The projects are outside the Node.js runtime and normal test dependency graph; source and tests remain the authoritative contract for each probe.

## Scope

- `Foxwarm.ConditionalMemory` ports pure conditional-memory helpers.
- `Foxwarm.MessageJson` is an owned `JsonObject` compatibility leaf for supported canonical messages and tool arguments.
- `Foxwarm.OpenAIResponses.Streaming` ports a transport-neutral Responses event accumulator and asynchronous SSE collector. It stops before HTTP request construction, authentication, retries/routing, timeout policy, WebSocket pooling, request journaling, Session ownership, and final canonical `Message` conversion.
- `Foxwarm.OpenAIResponses.Client` is the bounded localhost-capable HTTP slice over the collector. It owns supported Responses request serialization, `ResponseHeadersRead` POSTs within one host-owned tool loop, bounded non-success capture, completed-output conversion, the concrete `IChatService` adapter, and one injected test-root `write_fixture` executor. It has no retry, routing, journal, general tool registry, or runtime-configuration layer and never persists independently of its Session host.
- `Foxwarm.SessionTurns` is the first bounded translation of the Main-local `sessionWorkers:false` Session-turn seams. It keeps Session state, queue items, provenance-only queue sources, and canonical history rows over owned Message JSON; uses a short per-Session state gate plus an ordered asynchronous authority snapshot save lane; claims one processor atomically; owns one active cancellation handle; and binds an in-process fake chat host to one exact Session entry. Ordinary ingress awaits a best-effort save attempt before acknowledgement, and the processor makes another ordered best-effort snapshot attempt before selecting ordinary work. Busy claim, queue/history commit, fake-chat assistant append/persist, and busy release use strict saves. Stop cancels the transferred active request before awaiting its later best-effort save, and stop finalization commits accepted queued inputs to history without another fake model call.
- `Foxwarm.SessionPersistence` is the independent C1 storage-format probe. It validates and preserves the bounded current-v1 ordinary authority document for one explicit Session ID, pins `Microsoft.Data.Sqlite` 10.0.12 for the exact current six-column `archive_messages` table, retains stored raw `message_json`, provides immutable replay/conflict/inserted-only rollback semantics, and writes authority JSON through temp-file fsync, rename, and Linux directory fsync with explicit post-rename failure classification. Linux directory-sync portability errors match the current TypeScript unsupported set instead of being presented as durable success. It does not reference or modify `SessionTurns`; the accepted B runtime remains in-memory pending C2.

`SessionTurns` consumes the complete leading ordinary prefix without source/platform/conversation splitting while retaining one canonical history row and `clientMessageId` per queue item. Queue source fields are provenance only; the experiment has no Channel adapter or reply-target implementation. Strict append and stop-finalization persistence failures use operation-scoped compensation for only the rows, history objects, timestamps, and state transitions owned by that operation; newer queue entries and independent stopping/meta changes remain intact. Completion and Stop races use narrow exact-handle ownership transfer with stale-clear protection. Queue-prefix and Stop-finalization batch notifications are invoked after strict persistence and outside rollback, but notification exceptions are recorded rather than poisoning committed processing; assistant, busy, and release callbacks retain their existing semantics. The first committed nonempty input controls parts preparation: a prebuilt message consumes that boundary without preparation, an empty row does not consume it, and a parts item prepares numeric `lastMessageTime` only when it is first. History-empty first-parts preparation also gets the canonical escaped session marker `<foxwarm-system kind="session" currentSessionId="..." />` after ECMAScript-whitespace collapsing; later parts after a leading prebuilt message receive no marker and do not change the timestamp. The test-only `InMemorySessionAuthorityStore` proves per-Session save ordering and snapshot reload/cloning only; it does not establish filesystem, SQLite, crash-recovery, or performance equivalence.

`IChatService` returns an optional owned canonical assistant Message rather than a text shortcut. The fake chat builds the same narrow result shape. The Responses client converts supported reasoning, output text, refusal, function calls, phase, annotations, usage, concrete model identity, and request timing, then returns without persistence; persisted timing derives fractional `startedAt` from completion wall time minus monotonic duration. `LocalSessionTurnHost` alone strictly commits assistant and paired tool rows, executes a committed call through the injected executor, consumes newly queued ordinary input only after the tool row, and performs the next request under the same processor claim. Assistant-save failure prevents the effect; tool-row-save failure stops after any already-completed external effect and never reexecutes it or sends another request. The experiment has no effect receipt ledger.

The Responses request serializer filters exact `modelVisible:false`, preserves open JSON by cloning, and implements the current bounded TypeScript input projection for canonical system/text content, assistant phase grouping, reasoning replay, compatible annotations, function calls, and paired tool outputs. Multi-field parts preserve TypeScript's `system` → reasoning → `text` → function-call order, with commentary fallback for model messages containing calls. Stable call IDs, exact raw arguments, parse-error metadata, safe malformed-argument replay, and current shared tool-result formatting are retained. System formatting uses explicit ECMAScript whitespace and ASCII-boundary behavior rather than .NET `Trim`/Unicode `\b`, covering whitespace-only self-closing output, FEFF, NEL, and non-ASCII suffixes on Foxwarm tag names. Semantic inputs outside this slice fail explicitly: missing stable call IDs, images, native output-item replay, and legacy system normalization. The HTTP client uses explicit options only, streams through the existing collector, captures at most 64 KiB of non-success bodies, and propagates cancellation through send, read, and disposal. Empty completion creates no assistant.

The only effect implementation is an injected `write_fixture` executor rooted in a test-owned temporary directory. It validates the exact bounded object shape and plain filename, performs a UTF-8 atomic create-new write, and rejects existing files and symlinks. A create collision returns `file_exists`; another open/write/flush `IOException` returns `tool_io_error` without retry or deletion of a possibly partial file. Unknown tools, invalid paths/schema, and malformed parsed arguments produce paired errors with the original call ID and no effect. The directory boundary is not an OS sandbox. The default loop cap is 500 and tests can inject a smaller explicit cap; no recursive processor is created. Bounded error response serialization matches the actual shared `js-yaml` formatter for supported fixed errors and dynamic unknown/parse messages, including quote, comma, newline, tab, NUL, NEL, and other C0/C1 scalar escaping.

This remains bounded owned Message JSON compatibility rather than a complete canonical Message implementation. Sequence metadata, archive integration, real Session persistence, crash recovery, explicit `childHandoffState` transitions, request journals/IDs, provider retry/routing, and other runtime-owned fields remain excluded. Explicit unsupported paths fail with named errors and do not mutate as completed: tools beyond `write_fixture`, general registry/MCP/Node/permission layers, images/hosted tools, compact execution, retry, waits, managed state, channel delivery, Worker IPC or placement, filesystem/SQLite Session stores, and production runtime integration. No Archive-derived history reconstruction or child-handoff inference from history is used.

The separate C1 persistence leaf does not change those runtime exclusions. Its active JSON is authoritative and its Archive rows cannot reconstruct active state. The supported authority subset rejects nonempty runtime queues and known unimplemented lineage/wait/managed/Worker/block state, including `preservedFromBlockId`, while preserving open unknown JSON. Fresh databases create only the exact current `archive_messages` schema; full TypeScript databases may contain their normal other tables, but C1 neither owns nor fills them. New Archive projections accept finite binary64 numbers plus exactly representable integral CLR values, format them through verified ECMAScript thresholds/exponents/negative-zero rules, and reject over-precise integers or CLR decimals before insertion. No schema version, catalog, cross-store transaction, crash repair, Session discovery, or two-process continuation is claimed.

## Tests and integration

`Foxwarm.SessionTurns.Tests` uses deterministic task-completion barriers for strict-versus-best-effort persistence, the pre-selection best-effort snapshot, source-blind mixed-source prefix batching, preservation of newer ingress during failed append, operation-scoped stop-finalization compensation, one-processor claims, cross-Session concurrency, Stop cancellation-before-save, finish-window handoff, CTS lifetime races, non-poisoning queue notification failures, canonical marker escaping and timestamp boundaries, prebuilt/empty rows, callback reentry, paired tool errors, post-tool queue ordering, loop limits, unsupported paths, and ordinary chat failure. `Foxwarm.OpenAIResponses.Client.Tests` uses real loopback TCP/HTTP with bounded barriers for fragmented SSE, a two-request call/effect/result/final loop, exact fixture bytes, canonical four-row order, one processor claim, cancellation/connection close with no effect, HTTP and SSE errors, invalid fixture names/existing files/symlinks, deterministic general I/O failures with a retained partial file, missing call IDs, assistant-save compensation before effect, and tool-row-save failure after one non-replayed effect. `Foxwarm.SessionPersistence.Tests` validates authority open-field preservation and unsupported-state fences, exact SQLite schema admission, immutable replay/conflict/transactional rollback, inserted-only exact cleanup, ordinary-branch acceptance and lineage rejection, file-fsync/rename/directory-fsync failure boundaries, and normal reopen. Its actual TypeScript helper uses only fresh `FOXWARM_DATA_DIR` roots for TS→C# rewrite→TS and C#→TS reads; the latter also calls actual TypeScript `writeArchiveMessages` and requires an exact zero-insert replay. It records that TypeScript initialization may add its other Archive tables. Strict `JSON.stringify` differentials cover numeric property ordering, Unicode including U+2028/U+2029, literal escape text, quotes, backslashes, controls, `-0`, fixed/scientific thresholds with adjacent representable values, fractional values, extrema, and a bounded seeded finite binary64 sample without changing immutable equality to semantic JSON. The request-input parity runner compares a committed corpus, including bounded tool-error scalar escaping, against the actual TypeScript serializer. Existing conditional-memory and streaming parity corpora remain unchanged.

The experiment is run manually from the solution or focused project. No Foxwarm service restart is required because these are experiment-only projects.
