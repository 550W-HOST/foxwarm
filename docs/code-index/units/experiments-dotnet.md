## Purpose

Contains limited, manual .NET migration experiments. The projects are outside the Node.js runtime and normal test dependency graph; source and tests remain the authoritative contract for each probe.

## Scope

- `Foxwarm.ConditionalMemory` ports pure conditional-memory helpers.
- `Foxwarm.MessageJson` is an owned `JsonObject` compatibility leaf for supported canonical messages and tool arguments.
- `Foxwarm.OpenAIResponses.Streaming` ports a transport-neutral Responses event accumulator and asynchronous SSE collector. It stops before HTTP request construction, authentication, retries/routing, timeout policy, WebSocket pooling, request journaling, Session ownership, and final canonical `Message` conversion.
- `Foxwarm.SessionTurns` is the first bounded translation of the Main-local `sessionWorkers:false` Session-turn seams. It keeps Session state, queue items, source boundaries, and canonical history rows over owned Message JSON; uses a short per-Session state gate plus an ordered asynchronous authority snapshot save lane; claims one processor atomically; owns one active cancellation handle; and binds an in-process fake chat host to one exact Session entry. Ordinary ingress awaits a best-effort save attempt before acknowledgement. Busy claim, queue/history commit, fake-chat assistant append/persist, and busy release use strict saves. Stop cancels the transferred active request before awaiting its later best-effort save, and stop finalization commits accepted queued inputs to history without another fake model call.

`SessionTurns` preserves source-compatible batching (passive stream/conversation key plus `preferDirectReply`) while retaining one canonical history row and `clientMessageId` per queue item. Strict append and stop-finalization persistence failures use operation-scoped compensation for only the rows, history objects, timestamps, and state transitions owned by that operation; newer queue entries and independent stopping/meta changes remain intact. Completion and Stop races use narrow exact-handle ownership transfer with stale-clear protection. The committed observer is invoked after strict persistence succeeds and outside the rollback catch, so observer failure cannot roll back an already-persisted append or finalization. The first real parts item updates numeric `lastMessageTime`, and only history-empty first-parts preparation gets the canonical escaped session marker `<foxwarm-system kind="session" currentSessionId="..." />`; prebuilt and empty rows skip preparation. The test-only `InMemorySessionAuthorityStore` proves per-Session save ordering and snapshot reload/cloning only; it does not establish filesystem, SQLite, crash-recovery, or performance equivalence.

This remains bounded owned Message JSON compatibility rather than a complete canonical Message implementation. Sequence metadata, archive integration, real persistence, crash recovery, and other runtime-owned fields remain excluded. Explicit unsupported paths fail with named errors and do not mutate as completed: tools/tool loops, compact execution, retry, waits, managed state, channel delivery, Worker IPC or placement, filesystem/SQLite stores, and production runtime integration. No Archive-derived history reconstruction is used.

## Tests and integration

`Foxwarm.SessionTurns.Tests` uses deterministic task-completion barriers for strict-versus-best-effort persistence, preservation of newer ingress during failed append, operation-scoped stop-finalization compensation, source boundaries, one-processor claims, cross-Session concurrency, Stop cancellation-before-save, finish-window handoff, CTS lifetime races, post-commit observer failures, canonical marker escaping and timestamp boundaries, prebuilt/empty rows, callback reentry, unsupported paths, and ordinary chat failure. Existing conditional-memory and Responses parity projects/corpora remain unchanged.

The experiment is run manually from the solution or focused project. No Foxwarm service restart is required because these are experiment-only projects.
