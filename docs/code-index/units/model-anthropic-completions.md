# Unit: Anthropic Messages and Chat Completions adapters

Files: `dotnet/Foxwarm/Models/Anthropic/AnthropicCanonicalConverter.cs`, `dotnet/Foxwarm/Models/Anthropic/AnthropicMessagesService.cs`, `dotnet/Foxwarm/Models/Anthropic/AnthropicSearchHistory.cs`, `dotnet/Foxwarm/Models/Anthropic/AnthropicRequestSerializer.cs`, `dotnet/Foxwarm/Models/Anthropic/AnthropicStreaming.cs`, `dotnet/Foxwarm/Models/Completions/CompletionsCanonicalConverter.cs`, `dotnet/Foxwarm/Models/Completions/CompletionsChatService.cs`, `dotnet/Foxwarm/Models/Completions/CompletionsRequestSerializer.cs`, `dotnet/Foxwarm/Models/Completions/CompletionsStreaming.cs`

## Purpose

Serializes canonical Session messages, tools, images and system content for Anthropic Messages and OpenAI-compatible Chat Completions. Both adapters publish actual accumulated stream progress and return a provider-neutral result through the existing request owner and Session turn path.

## Stable methods and callers

- `AnthropicRequestSerializer.BuildRequest` and `ConvertHistory` build Messages payloads and wire-only role merges. `AnthropicMessagesService.ChatAsync` selects SSE or JSON from the prepared boolean `stream`, starts the journal attempt before transport, owns cancellation/watchdog/HTTP disposal and invokes the normal progress callback.
- `AnthropicEventAccumulator.Consume` reconstructs indexed ordered blocks, cumulative usage and stop metadata. `Complete` requires message start, closed blocks, a stop-reason field and terminal `message_stop`. `AnthropicSseCollector.CollectAsync` stops at that terminal event and flushes an unterminated final event at EOF.
- `AnthropicCanonicalConverter.ConvertAssistant`, `StopReason` and `Usage` share canonical conversion between JSON and SSE, including structured argument errors and thinking-token component accounting.
- Completions serializers/converter and `CompletionsChatService.ChatAsync` retain their own wire forms. `CompletionsEventAccumulator` and `CompletionsSseCollector` merge deltas, usage, stop reasons and tool fragments without adopting the Messages terminal law.

Callers: `SessionChatService`, `ConfiguredModelRequests`, `ModelRequestOwner`, retry/journal preparation and the `LocalSessionTurnHost` tool loop. Tool input is not executed by either collector. Canonical conversion uses the shared [per-call argument-error boundary](./session-domain.md#tool-argument-parsing); Messages passes native JSON inputs directly rather than reserializing malformed nonobjects before parsing.

## Contract and side effects

Messages defaults to `stream:true` and top-level ephemeral `cache_control`; explicit `extraFields` overrides remain authoritative. Nonboolean `stream` fails preparation before an attempt-start record or provider send. `stream:false` retains JSON conversion and five-minute header/body-byte idle handling by default. An explicit [one-shot CLI timeout](./core-delivery-cli.md#cli-behavior) replaces that idle default while the request owner bounds the complete attempt.

Streaming gets three minutes to first model activity, then the configured content-inactivity allowance (default one minute). Thinking/redacted-thinking open and close switch the inactivity allowance to at least ten minutes and back. Text, thinking and tool-input fragments reset semantic activity; pings, signatures, headers and usage do not. Progress snapshots contain visible text/reasoning and ordered tool arguments, never signatures or redacted data. Caller Stop, callback exceptions, terminal completion and failed partial streams dispose the owned transport.

Refusal and unsupported server/MCP-tool blocks are nonretryable/noncountable response failures. Native hosted web search and its continuation are described below. Output/context limits retain usable text and complete tools; malformed or nonobject tool inputs carry `argsParseError` and cannot execute. The normal turn host appends an `llm-stop` display-only notice after committing the assistant; that notice is excluded from later provider history. The request journal records the same truncation result without becoming Session authority. HTTP, malformed SSE and incomplete message boundaries remain attempt-scoped failures without a successful partial assistant append.

Canonical conversion retains empty signed thinking and `redacted_thinking` data; same-concrete replay preserves opaque evidence. Request-only concrete mismatch preparation removes signatures/redacted metadata without changing canonical history or Archive. Input usage includes finite cache-creation input tokens; cached-read usage remains separate. Thinking tokens are a component of total output, not an additional output total.

Chat Completions message-level `provider_specific_fields` and `extra_fields` are independent opaque objects stored as `providerMeta.providerSpecificFields` and `providerMeta.extraFields`, with the producing `sourceModelId`, including tool-call-only responses. Streaming recursively merges object/object members, skips null members at each merge step, and replaces other values, including arrays. Newly assigned objects retain nested nulls; non-object top-level deltas are ignored. These fields do not generate visible progress. History replay uses the captured [model history compatibility](./model-configuration.md) mapping for both fields without changing source attribution; request-level configured `extraFields` is separate. [Archive validation](./archive-message-store.md#side-effects-and-compatibility) owns persisted shapes.

Configured [text redaction](./model-text-redaction.md) wraps these adapters before serialization and restores ordinary progress/result text plus structured tool values. It leaves signed/redacted thinking and opaque provider metadata untouched.

## Native hosted web search

`webSearch: true` uses `web_search_20250305` with `name: web_search` beside the existing custom tool declarations. It needs no search beta header; the adapter retains its existing `anthropic-version: 2023-06-01` default and configured header overrides. The basic tool version avoids implicitly enabling dynamic filtering or code execution. Configured `allowedDomains` and `userLocation` translate to native fields; empty domains and blank location fields are omitted like Responses; Responses-only `type`, `toolChoice` and `searchContextSize` do not change Messages declarations. Final `extraFields` still wins. Purpose selection remains shared with the [hosted-tool request policy](./model-responses.md#d-responses-hosted-tool-purpose), including identical normal/compaction declarations.

JSON and SSE preserve `server_tool_use` for `web_search`, successful/error `web_search_tool_result` blocks, and cited/search-turn text runs as `providerMeta.anthropic.{sourceModelId,contentBlocks}`. Nontext native parts contain one original block; text runs contain their original ordered text blocks. The [text-run contract](#d-anthropic-text-runs) keeps provider fragmentation out of ordinary history consumers. `citations_delta` appends native citations; server input fragments use the existing JSON accumulator but never become executable `functionCall`s or local-tool progress. Server errors remain returned evidence, not transport retries. Exact encrypted result content, citation indices and signed thinking survive Session/Archive persistence. [Compaction exchange boundaries](./session-compaction.md) retain deferred native calls/results together. [Concrete-compatible replay](./model-common-wire.md) emits the original blocks and omits portable evidence additions from the native assistant content. Incompatible destinations receive ordinary text and explicitly untrusted URL evidence without native encrypted metadata. [Citation integrity](../threads/web-search-citations.md) governs display and portability.

`pause_turn` returns `ChatResult.ContinueTurn` only for the normal Session and foreground/background compaction scopes. The turn host commits the assistant and consumes its existing request budget. A separate result fact, `ProviderContinuationPending`, also covers deferred search beside client calls; it defers history-changing maintenance without skipping client-tool execution. The normal owner's single turn-scoped, nonpersisted condition delays ordinary queue consumption, retry consumption, Task reminders and ready-compaction application until the native turn completes. Cancellation checks retain priority. Ready work stays queued; a context-limit failure during required continuation follows the provider failure path rather than forcing a history rewrite. Dedicated planners use the same pending fact to suppress extra user feedback while still answering client tool calls. Native server blocks never become local tools. A malformed `pause_turn` demanding local calls fails without executing them. BTW and CLI/ToolScript single-shot requests keep the nonretryable/noncountable pause failure; search completed inside one response succeeds normally.

`AnthropicSearchHistory` shares search-block identity/pending-ID handling with compaction and request repair. A direct server call is answered by the next assistant response. That response abandons unanswered old calls while retaining its newly issued pending calls, including a turn that pauses again. Visible user input also abandons pending calls; tool-result rows do not. `RequestHistoryRepair` filters those blocks from request-owned copies and removes already-generated signed/redacted thinking after the changed block, including an abandoning model response because it was generated against the old prefix, but stopping before an abandoning user input. Only rows emptied by this repair are omitted; unrelated thinking-only history is not restricted. Thinking generated during recovery remains valid on later requests. Changed rows lose journal origin reuse, while canonical history/Archive remain intact. This is a bounded interruption repair, not a general solution for prefix-bound thinking after compaction or changed tools/system instructions.

Billing usage remains cumulative, with cache creation normalized as uncached input and cache reads kept separate. When `usage.iterations` is supplied, the last `type: message` entry supplies `contextTokens` with `contextTokensSource: reported-iteration`; compaction entries are excluded. Without a last-message iteration, SSE retains the measured `message_start` input plus cache-read/creation tokens, including prior encrypted context, and estimates only the appended response via the existing text/image estimator (`contextTokensSource: reported-input-plus-estimate`). JSON, or SSE without measured input, uses the full visible-history/system/tool estimate (`contextTokensSource: estimated`). Both estimates include portable URL evidence; newly returned encrypted page contents remain unavailable locally. Compaction thresholds and the WebUI context overview consume the separate context measurement, while cost and usage totals retain upstream billing counts. No per-search division or additional tool-charge pricing is inferred.

Protocol references: official [web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [server tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools), [beta Messages usage](https://platform.claude.com/docs/en/api/beta/messages), [thinking prefix checks](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks), and [API versions](https://platform.claude.com/docs/en/api/versioning).

## Design Decisions

- [2026-10-30] Chat Completions opaque objects deliberately accumulate recursively across streaming deltas, retaining earlier keys for continuation and replay. This differs from the retained TypeScript collector's latest-`provider_specific_fields`-object assignment.

### D-anthropic-text-runs

[2026-11-15] Consecutive Anthropic text content blocks become one canonical `part.text` by exact concatenation, without inserted separators, trimming or Markdown rewriting. Every nontext block bounds the run, including thinking/redacted thinking, hosted search calls/results, local calls and unsupported future content. Search-turn or cited runs retain the original blocks and producing model identity in part-level `providerMeta.anthropic.{sourceModelId,contentBlocks}`. Ordinary non-search tagged-thinking parsing retains its existing behavior.

Compatible native serialization expands those arrays in place, preserving citations and encrypted evidence in original order, including a single text-only native run. Incompatible destinations use the merged ordinary text through existing metadata filtering. Markdown, copy, Search and timeline rows consume canonical text runs; they do not group protocol blocks independently. Native citation readers aggregate only the run's saved text-block citations into one deduplicated Sources footer, without inventing inline IDs or offsets. JSON retains native metadata. The initial hosted-search singular-block metadata shape is replaced without a compatibility reader or migration; unrelated persisted reasoning and other provider formats are unchanged.
