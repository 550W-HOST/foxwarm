## D-hosted-request-routing

The runtimes host has separate public and mesh listeners. The public `Host` selects a tenant through the [hostname directory](./hosted-runtimes-host.md#d-hosted-runtimes-host). An unknown hostname gets a bare 404; an unavailable tenant gets a bare 503. Tenant authentication, policy and application routes run at the owner. The edge never interprets a tenant credential. The receiver resolves the original authority as well, so a signed tenant and request host must agree. Lookup removes one terminal DNS root dot; the forwarded and signed authority retains it. Rediscovery rechecks the original hostname binding. After waiting for lease lookup or activation, the edge checks again before dispatch to either a local or remote owner, even if the receiver’s directory has not yet refreshed. A missing or changed binding ends the held request with 404; its credentials never follow the hostname to a different tenant.

`RouteDirectory.ReadAsync` joins tenant state, the unexpired lease and its boot's mesh address. Waiters can share the same in-progress read but cancel independently; these reads use the application pool and never borrow a lease control connection. A live owner wins regardless of its rank. When there is no owner, the public edge tries the [placement candidates](./hosted-runtimes-host.md#d-hosted-placement) in order. A candidate only activates locally. A candidate with a full hot-owner byte budget declines new work; this does not displace an existing owner. Each candidate attempt lasts at most a renewal interval and the remainder of the original hold. The edge rereads the lease after a decline, a competing acquisition or a remote activation. Every dispatch enters `TenantActivations.TryAdmitExact`: the same tenant, receiver boot and epoch must match a published generation whose admission gate accepts the work. The admission lasts for the handler, including the lifetime of a stream or an upgraded socket.

A wake-up or recovery scanner calls `TenantRouter.MayStartAutonomousAsync(slug, graceElapsed, token)` before a local claim. The scan excludes tenants for which no eligible role is live before applying its row limit. The router checks for a live owner and local drain/capacity, then ranks eligible boots once: rank one before grace, any eligible local boot afterward. The scanner passes the original cause to the same `TenantActivations.ActivateAsync` used by on-demand requests. The winning generation reads its persisted wake-up row itself.

## D-hosted-mesh-authentication

The mesh uses HTTP/2 on its own `mesh.port`; `FOXWARM_ADVERTISE_ADDRESS` is its advertised host and port. `FOXWARM_MESH_SECRET_FILE` supplies a base64-encoded 32-byte shared key distinct from tenant credentials and encryption keys. This is hop authentication over a trusted cluster network, not encryption or body integrity. The public listener strips `Forwarded`, `X-Forwarded-*`, `Foxwarm-Mesh` and `Foxwarm-Mesh-*` before routing. Mesh-control headers are removed before tenant dispatch.

`MeshAuthentication` signs a fresh attempt with HMAC-SHA256 over length-prefixed fields: version, purpose (activate or dispatch), sender and receiver boot, tenant, epoch (empty for activate), timestamp, a 128-bit random nonce, method, original authority, and the raw target including query. Each boot accepts timestamps within 30 seconds of its clock and atomically remembers consumed nonces across the 60-second acceptance window. The window is capped at 262,144 entries per boot (about 4,369 admissions/s sustained across 60 s). After signature verification, dispatch and activation use separate partitions of the same window: 15/16 for dispatch and 1/16 for activation. A tenant may occupy at most 1/8 of the whole window for dispatch (32,768 entries, over ten times the default tenant request rate over 60 s) and 1/8 of the activation partition. This keeps control traffic and unrelated tenants available even when an owner is returning 429. The expiry heap retains the share with each 128-bit nonce; only expiry restores that capacity. The cap never evicts a still-valid nonce. A new nonce at capacity gets 503 without retry proof; an already accepted nonce remains a rejection. A retransmission of one attempt cannot enter twice. The owner signs a pre-dispatch refusal against the particular attempt; application status codes and rejection of an already-consumed nonce are never retry evidence.

## D-hosted-forwarding-outcomes

One edge deadline covers lookup, candidate attempts, queue and the wait for a mesh connection. An attempt uses YARP's direct `IHttpForwarder` and a boot-owned `HttpMessageInvoker`. Its handler uses no proxy, redirects, cookie container or decompression. On the selected connection the request-header encoding callback marks the boundary where bytes may be written. The edge reserves a hold permit before lookup and a separate permit before retaining upload bytes. Uploads stream on their first attempt. A refused upload can be repeated if untouched or completely retained within 64 KiB; a partially consumed or larger body cannot. Encoding is the conservative no-replay marker and ends the hold **deadline**, before the HTTP/2 write queue; the **permit** remains counted until owner response headers or attempt failure. `KeepAlivePingDelay` and `KeepAlivePingTimeout` on the mesh pool are 10 s each; the connection heartbeat detects a nonresponding peer. A HEADERS write not yet assigned a stream can still be queued behind a stalled socket write when keepalive fails the active streams. `PhysicalWriteTimeout` (20 s) closes the physical stream when a write to it has not completed, unblocking the writer and its queue. HTTP/2 flow-control waits and application response waits do not run this timer. A failed attempt after encoding is uncertain. A cancellation known before encoding is non-dispatch. The response's lifetime is independent of the hold deadline after encoding; a signed refusal can resume routing only within the original deadline. Once the request may have reached a tenant, no method is replayed, including GET, HEAD and OPTIONS. Without a downstream response, an ambiguous failure produces 502 with an unknown-outcome body. A response already started ends as an incomplete stream. An owner response whose complete body and trailers were copied remains final if only the upload copy subsequently failed. For a remote upload the public leg streams without the default 2 MiB limit; the owner retains its own default unless its application route explicitly changes it. A retry of a previously forwarded body enters the mesh listener even if this edge acquired the lease in the meantime, so the route gets a fresh owner-side limit feature.

## D-hosted-websocket-shutdown

The upgraded protocol is WebSocket. YARP relays negotiated frames, including the final data and the Close frame with status and reason, in either direction. A client Close can receive its acknowledgement. When a transport ends, the bridge finishes the other direction after delivering what the ending peer already sent; a loss without a Close frame is abnormal. The bridge never reconnects or replays frames. On the HTTP/2 mesh, a reset affects its stream; adjacent requests keep their connection. A clean client transport EOF starts `CloseGrace` (5 s): keep forwarding owner data until owner EOF or that bound, then dispose the owner stream. .NET extended CONNECT has no independent write half-close; the owner sees the end by the grace bound. A public transport that aborts instead of delivering clean EOF ends immediately. Close-frame handshakes remain byte-transparent.

## D-hosted-placement-requests

`ReplicaPlacementRequests` in `Foxwarm.Hosted.Lease` owns the operator’s placement transactions. Tenant requests lock tenant then lease, compare the immutable tenant ID, slug, owner boot and epoch, and require an active, unexpired grant. The nullable lease field `requested_action` holds `move` or `release`. An identical outstanding request is idempotent; a conflicting request does not replace it. A move needs a compatible live alternative. Request acceptance does not latch `draining_since`; the owner rechecks before it begins draining. Operator code may project these two columns, the current lease and exact-boot `replicas.draining`. The actions require the participating replicas to be upgraded and running the multi-tenant topology.

Administrative drain makes a healthy boot a last resort: `Placement.Candidates` first filters role, pin, reader floor, capacity and duplicate names, then chooses the non-draining tier if present. If no eligible non-draining boot exists, public demand and autonomous wake-ups can acquire on an administratively drained boot. A draining receiver also checks this preference under the lease lock. Maintenance requests a move only toward a non-draining destination, so a cluster of drained replicas does not shuffle tenants. SIGTERM stops local placement immediately and publishes `capacity.stopping`; heartbeat updates preserve that bit. Administrative drain keeps the public edge Ready so ingress can still reach a targetless resident; SIGTERM instead withdraws readiness. A resident without a move target keeps serving and remains eligible for ordinary idle release. `replicas.capacity.acceptingNew` is the sole capacity input for ranking; per-tenant counts and Provider problems are diagnostic. The current owner is routable irrespective of capacity. The next acquisition after a move excludes the former boot and clears the action. If the alternatives disappear after hand-back, a conditional update may lift that exclusion at the same released or expired epoch. A requested release lets the tenant sleep until demand returns.

`PlacementMaintenance` rechecks committed requests on notification and once per renewal interval. No target leaves a draining boot’s resident serving. Automatic rebalancing requires an idle runtime, no admitted work, and the same eligible preferred name continuously observed for 60 seconds at this epoch. A busy, full-target, or no-target observation resets the cooldown. Idle eligibility is checked once more when the admission gate latches. A move preserves the settled occurrence in an immediate wake-up inside the release transaction. A release notification prompts ordinary wake-up discovery; the periodic scan covers missed notifications. A delayed activation racing the old epoch must also pass the source exclusion under the lease lock.

The SIGTERM signal marks the boot unready and stops new admissions immediately, including while signal callbacks are still pending. An activation checks the signal under the lease lock and again before publication; a confirmed grant that crossed the stop is handed back without serving. The signal never cancels an acquisition commit. Previously admitted work retains its original grant. The cluster marks writable lease rows as draining together; a row locked by another transaction cannot keep its siblings from stopping. Every planned move is also carried by immutable tenant ID and epoch into its hand-back. The bulk marker only accelerates routing: a transient marker failure is logged and each confirmed tenant independently commits its settled schedule and releases on the control connection within the original deadline. A marker skipped by a row lock still schedules the move; an explicit release or lifecycle transition wins. Under the lease lock, hand-back checks the database clock once; schedule write and release commit together, or an expired active grant stays untouched for recovery. Shutdown joins an already-started retirement and its release acknowledgement within its original deadline. The lease remains renewable and final writes stay fenced by its original epoch. Each tenant can finish admitted work within the common 20-second grace; producer settlement, runtime shutdown, and hand-back then share the remaining 12-second stop/release allowance. Public and mesh listeners stay up for the handover and stop last. A missing hand-back stays subject to expiry/fencing. The Helm chart gives the process 45 seconds and uses stable StatefulSet ordinal names.

## Tests

`TenantReplicaTests.PlacementRaces`, `WakeupLifecycleTests.Drain` and `HandBackExpiryTests` cover the last-resort tier, process stop and readiness ordering, and atomic schedule hand-back at expiry. `PlacementRequestLockingTests` crosses the operator transaction with a real Installation-document writer and with an already-requested grant expiring while waiting. `TenantReplicaTests.Moves` exercises two fronts, no-target and disappearing-target recovery, admitted work, and a shared many-tenant stop. `WakeupLifecycleTests` covers settlement and busy snapshot recovery; `ReplicaProcessTests` covers real SIGTERM and continuous idle preference. `ForwardedWebUiTests` reconnects a subscriber through the surviving front after a move.

`TenantActivationsTests` pins a published generation, checks earlier and later epochs and a different boot, and verifies that a latched gate admits nothing. `MeshAuthenticationTests` checks the signed fields, time window, per-attempt refusal proof and concurrent consumption. `TenantReplicaTests` runs Kestrel on two public fronts and two mesh listeners; `ReplicaProcessTests` exercises the production entry, real leases and process failover.

`ForwardingProcessTests` runs the supported entry point with either managed Main or `FOXWARM_TEST_MAIN_EXECUTABLE`. It checks that tenant credentials are scoped by host, an HTTP/1 chunked Session creation keeps its requested ID across the HTTP/2 mesh, and a committed bodyless creation whose reply is lost creates exactly one Session. A real CLI Node sees the owner’s 1008 and switches from its invalid credential to pairing.

`ForwardedWebUiTests` uses the real scoped realtime and administrator terminal endpoints across a non-owner, checks a scoped terminal rejection, the owner’s upload limit and the hosted bootstrap URL with a path prefix. `MeshWriterTests` places a second request behind an actual blocked connection write, distinguishes expiry before encoding, and exercises a completed early owner response followed by an upload error and clean client EOF on a duplex stream.

The multi-tenant public front is the hosted entry. Deployments provide one mesh Secret to all general replicas and the optional master host; a cluster upgraded from the raw TCP-forwarding topology stops all previous boots before starting the new replica pool. Schema migration and operator tenant provisioning are separate. See [hosted packaging](./hosted-packaging.md).
