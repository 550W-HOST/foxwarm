## Purpose

`useChatConversationSync` owns one mounted session's committed history, queued preview, runtime/model snapshot, logical realtime subscription, message upload/send, and command submission. `Chat` owns presentation, settings requests, ASR, debug visibility, search, scroll/viewport state, and the desktop context overview scrollbar. The synchronization owner keeps active context separate from loaded original Archive rows; `continuousHistory.ts` provides raw-row filtering and immutable-original merge helpers. The independent axes, paging/window bounds and authority contract are canonical in [D-webui-continuous-chat-history](../threads/archive-and-recall.md#d-webui-continuous-chat-history).

Queue-origin history deltas update committed and queued timelines through one reducer action only when their canonical sequences are contiguous from the trusted frontier. A gap, incoherent state, or request-racing delta stages only a bounded missing sequence range and forces non-starvable authoritative reconciliation from the last contiguous sequence; neither the queue side nor the history side is rendered alone. History responses also replace both timeline sides atomically, including recovery when the transient delta was dropped. During tail-plus-prefix bootstrap, an assembled snapshot ending before a newer staged batch is retained as the complete older boundary and the batch is recovered with `afterSeq`, rather than forcing another full snapshot. The HTTP latest sequence remains authoritative even when older rows are not mounted, while concurrent live rows advance that boundary only through a contiguous sorted suffix; a later row cannot skip an unseen sequence. The authoritative latest-sequence/version frontier, not only mounted rows, fences delayed covered deltas while the prefix is pending.

## Export

- `useChatConversationSync(sessionId, webUiIdentityMode, historyMode, initialArchiveSeq?)` returns separate active/continuous display state, bounded `loadArchivePage`, and `sendMessage`, `sendSessionCommand`, `retryEarlierHistory`, and `mergeConfirmedSettings`. Mutable synchronization refs, timeline dispatch, and state setters stay private to that mounted owner. Settings callers merge only confirmed model/child-model/effort or node/cwd fields through the settings action; they do not control history or stream authority.
- default memoized `Chat` component; WebUI identity mode retains normal history, tool cards, live stream, and sending while hiding administrator controls/model picker/debug/ASR.
- `SessionDebugModal` owns the explicitly mounted diagnostic snapshot lifecycle, including fetch invalidation, serialization, and release on close; the shared `JsonInspectorDialog` owns editor and copy UI resources.
- `chatHistoryState.ts`, `chatViewportState.ts`, and `sessionHeader.ts` export pure tested reconciliation, viewport, and state/format helpers; `modelOptionsLoader.ts` owns latest-consumer publication gates, the parsed-result Promise cache for the three bootstrap endpoints, and the models-only refresh signal.
- `chatSessionSearch.ts` derives only rendered/searchable text fields from loaded committed top-level rows when the pane-local Search opens; `findSessionSearchMatches` performs literal query filtering, while `findSearchSurface`/`findRenderedMatchRange` locate the selected mounted text without mutating it. System-like rows use the shared preview descriptor, so a metadata-classified LLM retry search field contains its prefix-free body rather than the display-only `⚠️ LLM Error:` marker.
- `contextScrollbarModel.ts` exports pure committed-segment, estimate, context-usage, and row-boundary interpolation helpers used by the desktop overview and focused tests. Metadata-classified LLM retry notices use the system tone and collapsed thread-card height estimate, matching the timeline card and tool-group projection.

## Current handlers

- `useChatConversationSync.sendMessage({ text, attachments })`, passed to the composer as `handleSend`:
  1. rejects missing/empty/loading submissions;
  2. retains any active model-stream draft, leaving its request/stream reconciliation independent of send acceptance;
  3. uploads each stable `{ ref, file }` attachment to `POST /api/upload` with multipart filename `attachmentN_${originalFileName}` (also its bound Session ID in WebUI identity mode), failing the send if any upload fails;
  4. builds marker-bearing request parts plus the unchanged legacy `{ path, filename, mimeType }` upload entries (no backend ref field);
  5. creates one browser `clientMessageId` and appends an optimistic user row with the same ordinary appended descriptor shape used by canonical history; frontend presentation correlates the numeric filename prefix back to the marker;
  6. awaits `POST /api/sessions/:id/message`; non-2xx removes only an unreconciled optimistic row and returns rejected send so the composer retains its draft, while busy/queued success schedules targeted queue-preview refresh.
- Manually typed slash commands use the same POST route but omit optimistic history and `clientMessageId`, matching command dispatch's non-persisted user-input boundary.
- The synchronization owner’s `sendSessionCommand(command)` posts the command to the same message route without optimistic user history. Supported runtime controls also carry a bounded `controlRequestId` and consume correlated `session-control-feedback` events; HTTP acceptance alone does not establish semantic completion. The [runtime presentation contract](../threads/session-runtime-presentation.md#d-session-control-feedback) owns pending/accepted/error behavior; [.NET producer paths](../threads/dotnet-webui-boundary.md#runtime-controls-notices-and-communications) use the exact owner and existing realtime boundary.
- `updateSessionNode(nodeId, signal)` posts to the administrator Session node endpoint and merges the confirmed `currentNode`/`cwd` fields from its canonical Session response; it does not send a chat message or start a model request. The composer owns loading/error/abort presentation, while ordinary runtime Session-state events update the same selected Node. Picker semantics are canonical in [D-composer-session-node-picker](./webui-chat-composer.md#d-composer-session-node-picker).
- `handleStop`, `handleRunQueued`, and `handleContinue` send `/stop`, `/dequeue`, and `/continue` respectively. After Stop completes, the backend converts queued message/event previews into committed history rows without running them; normal SSE/history reconciliation removes the preview and inserts the canonical rows.
- There are no current message-index edit/delete/regenerate handlers in this component.
- The composer's microphone ASR uses the deployment-relative `/asr/stream` endpoint. `getAsrStreamUrl()` builds `${window.location.origin}${API_BASE_PATH}/asr/stream` and switches the HTTP(S) prefix to WS(S); it does not call `makeWebSocketUrl`. The former audio-file transcription UI and its Chat-side `/asr/transcribe` caller are removed; the server endpoint remains available independently.
- After ASR `ready`, a WebSocket close without a final or error terminates the recording through the composer error callback, preserving any partial draft text and unlocking editing. A completed final, deliberate cancel, and a preceding socket error suppress duplicate close errors. Before `ready`, an unexplained close still rejects transcriber startup.

## Synchronization functions

- `applySessionState` accepts canonical runtime state and updates its immediate reconciliation refs and rendered session snapshot together.
- `loadArchivePage(direction, beforePublish?)` validates a bounded response, lets the current view select its range synchronously before publication, then merges rows/boundaries through the existing owner. Earlier-page mounting is not gated on the request-time interaction version.
- `fetchHistory` owns bootstrap/full/after-sequence reconciliation, request coalescing, stream-race journals, queue/history atomic dispatch, and matching draft commit evidence. `scheduleHistoryRefresh` and `scheduleAtomicRecovery` share its bounded pending refresh.
- `subscribeRealtime` registers a logical subscription with the existing page transport, reconciles session/message/draft events, and handles deletion. The hook's mounted effect owns unsubscribe, timer cancellation, and history abort/invalidation; session replacement resets only synchronization state, leaving viewport cleanup with `Chat`.
- `sendMessage` owns upload, optimistic identity, acceptance/rejection, and busy-time queue refresh. `retryEarlierHistory` clears the earlier-history error and requests a full correction without exposing fetch modes to rendering.

## Per-session state and streaming

- Initial history loading uses the existing route in at most two requests: `tail=100` returns recent committed rows plus session/snapshot/queue metadata and an exact `{ latestSeq, historyVersion, prefixLength }` boundary, then one guarded prefix request fills the older rows when needed. A boundary conflict falls back to one full correction. Unqualified history remains the compatible full-snapshot form.
- Chat registers one logical session subscription with the page-scoped realtime transport and handles model/tool streaming, persisted message updates, canonical `session-state`, queue/history refresh, deletion, and connection status. The transport calls Chat's registration callback on `subscriptions-accepted`, after the server installs the subscription but before its asynchronous initial snapshot and buffered live events; Chat starts its coalesced history snapshot at that boundary. Reconnect re-registers every retained logical subscription, while a Chat added to an already-open split pane receives its own first registration without restarting unrelated Chats.
- A full exact-owner draft snapshot bootstraps the temporary synthetic message on every subscription/reconnect, followed by buffered version-2 coverage ranges at or above its sequence watermark. Fully covered ranges are ignored, contiguous/overlapping ranges are applied, and true gaps are visibly incomplete. Chat mirrors the draft in one synchronous ref-backed owner before scheduling React state. A history request cannot clear an already-active reset merely because no later token arrived while the request was in flight, but authoritative history corrects a dropped canonical `message` presentation when it contains a non-display-only, non-`updateExisting` provider model row whose persisted `__meta.llmRequestId` exactly matches the current transient draft's existing outer request ID; canonical tool-call-only model rows count. Timestamp equality is not generation evidence. A response cannot use an older row to clear a newer reset/request even when both timestamps share one millisecond. Drafts without the request ID remain conservative for history correction. Legacy cumulative live events remain readable. Responses snapshots and deltas additionally carry indexed reasoning summaries, message text/phase, image status and function-call placement; the draft reconstructs one reasoning part per output item in provider order, while other providers keep the flat reader. Version-2 reset and update events carry the owner's server `startedAt`; that timestamp remains only the live-message/old-pending compatibility gate, while legacy resets use no cross-clock gate. A committed Responses prefix trims only covered output indices while the same draft continues with later reasoning, image status, or tools; complete canonical rows clear it. History and reconnect snapshots reconcile the same `llmRequestId` by persisted half-open `llmSegment` ranges, not by text matching. Worker forwarding flushes earlier merged deltas before each canonical append and structural trim. [Canonical contract](../threads/streaming-pipeline.md#d-streaming-early-commentary-commit). Canonical ordering: [D-streaming-delta-and-bootstrap](../threads/streaming-pipeline.md#d-streaming-delta-and-bootstrap).
- Ordered stream reconstruction retains a reasoning output item even with no visible summary; an empty draft without an actual reasoning item still creates no reasoning card. The Timeline combines adjacent output-item display parts without changing the reconstructed source array. [Reasoning card contract](../modules/webui-timeline.md#d-webui-contiguous-reasoning-cards).
- The synthetic version-2 assistant message mirrors its `llmRequestId`; segmented Responses rows distinguish the first uncommitted output index, while the first segment retains the legacy request-only key. The corresponding canonical provider-model row reconciles into the same mounted React row at commit without replacing unchanged Markdown DOM; persisted seq/id remain the history and viewport authorities. Canonical selection contract: [D-webui-streaming-markdown-dom-stability](../threads/streaming-pipeline.md#d-webui-streaming-markdown-dom-stability).
- Persisted user events replace their matching optimistic row in place by `clientMessageId`; all persisted updates prefer stable client/seq/id metadata before legacy timestamp dedupe. A later failed POST removes only an unreconciled optimistic row. An in-flight history request replays newer SSE rows and preserves unmatched pending sends before it can commit. Post-request `session-state` fields and model-stream drafts stay stream-owned; a mismatched queue preview waits for one coalesced trailing reconciliation. A small pure frontier transition decides none/`afterSeq`/full from completeness, represented/server count, history version, trusted seq, queue mismatch, and gap evidence; message events advance or flag that seq frontier synchronously before React array reconciliation. Ordinary contiguous committed messages therefore cause no HTTP history request, while message-only gaps cannot depend on deferred state-updater execution. Deletion invalidates/aborts history and clears pending refresh work. Same-session triggers reuse the active request and request at most one trailing reconciliation; deletion, session replacement, and unmount abort it.
- Temporary command-response rows remain browser-local but are reinserted at their existing mounted-timeline anchors after internal history snapshots. They clear on page refresh/remount and remain excluded from persistence, model context, queue preview, archive/search, and ContextScrollbar committed history.
- Canonical `runtimeState` drives the timeline status with legacy busy fallback only when runtime state is absent. Active model/tool work retains composer Stop; waiting uses the sleeping fox and no Stop. Caption presentation follows [fox loaders](./webui-fox-loaders.md#behavior); queue count/actions and idle queue-only states follow the [bottom status layout](#d-chat-bottom-status-layout). Only canonical idle state may show an interrupted/failure status with Continue, derived from committed history by shared `packages/shared/src/sessionContinuation.ts` (a partial Responses segment remains interrupted despite visible commentary; the real metadata-only completion row closes it); temporary/optimistic/streaming rows and queued/nested timelines never drive it. The exact history contract and backend revalidation are canonical in [D-pipeline-control-commands](../threads/message-processing-pipeline.md#d-pipeline-control-commands).
- The Chat header `Find` action (accessible label `Find in chat`) uses cached display-text fields from already-loaded committed history. It does not index queued/temporary rows or fetch older history or CTX children. Ctrl/Cmd+F captures a current ordinary/contenteditable/input/textarea selection before focusing Search, while an empty selection leaves the existing query unchanged. Search ArrowUp/ArrowDown walks a bounded browser-local history, restoring the pre-history draft at the newest end; queries are recorded only on navigation/close boundaries. Ctrl/Cmd+F opens/focuses Search only for the active Chat; App passes the focused workbench Chat identity and popup/embedded single Chat defaults active. Canonical scope and search navigation: [D-webui-chat-session-search](../modules/webui-timeline.md#d-webui-chat-session-search).
- Conversation uses the same body/activity projection for committed history and explicit CTX children. ProcessingStatus remains the only live status owner, using the shared [caption presentation](./webui-fox-loaders.md#behavior) and [status layout](#d-chat-bottom-status-layout); Conversation exposes the same wait/dependency details as other modes; see [runtime presentation](../threads/session-runtime-presentation.md). Collapsed process details are outside pane-local Search; all ordinary committed assistant text remains outside process disclosures and uses the same Search projection as final replies. See [D-webui-timeline-view](../modules/webui-timeline.md#d-webui-timeline-view).
- Queue previews remain a separate render-only timeline and never enter committed messages. They disable time separators, which are derived from committed top-level history alone. Canonical separator timing and safe group boundaries: [D-webui-timeline-time-separators](../modules/webui-timeline.md#d-webui-timeline-time-separators).
- Sending new input preserves the current model draft through pending/accepted/rejected POSTs, queue refreshes, and canonical user appends. [Draft ownership contract](#d-webui-active-draft-send).

## Viewport behavior

- Search derives each committed match’s source index and owning group start; it mounts the full already-loaded timeline only if the selected row or required grouped/paired call is outside the newest 100 messages. Query edits update the counter immediately but briefly delay their automatic jump so transient prefixes do not mount old rows. An actual navigation detaches bottom-follow and positions its rendered Range in the existing scroller once; later stream/layout updates and closing Search retain ordinary viewport ownership.
- Bottom follow is an explicit latch; an active latch is captured as bottom even when passive reflow temporarily leaves a larger geometric gap. Upward wheel/keyboard/touch/scrollbar intent detaches before a token/layout update can undo it.
- Only actual-bottom tolerance or the bottom action re-enables follow. Bottom tolerance is measured in CSS pixels and accommodates fractional geometry. A new downward wheel gesture inside that tolerance ends an older pending upward intent, including a tiny leave that never crossed the tolerance. A fresh pointer gesture retires an earlier pending wheel leave without entering follow itself, allowing ordinary native-scrollbar return to use the same tolerance. Passive token/reflow events still cannot clear pending upward intent. All follow writes pass through one publisher that updates the existing synchronous refs and their React presentation. The bottom button is visible exactly when follow is false, including pending upward intent without a scroll event; distance does not independently decide visibility. Its explicit action clears pending viewport/resize/navigation corrections, stores bottom, rearms the observer generation and enters follow immediately.
- Reading state is in-memory by canonical session ID and history mode: either `bottom` or a stable committed-message anchor plus pixel offset. On continuous remount, `getChatViewportAnchorSeq` turns the saved row key into the initial bounded Archive location: two adjacent 100-row requests surround the anchor, without storing old pages. A loaded anchor outside the currently mounted window first mounts its bounded source window before native offset restoration. Active bottom navigation does not clear the continuous window. While a saved state awaits its source rows or the Workbench host's first usable pane layout, native/resize capture retains that state rather than replacing it with the temporary empty, tail, or unpositioned DOM; genuine new input cancels restoration through the existing interaction epoch.
- Restoration can expand the full timeline, uses idempotent row-offset correction, retains native browser scroll anchoring for committed history, excludes growing live text as described in [Timeline](./webui-chat-timeline.md#behavior), and is cancelled by new user scroll input. `HistoryCommit` takes the continuous-history prepend snapshot in React’s pre-mutation phase, using the current reader rather than a snapshot saved while HTTP was pending. Active context is already local and keeps its native-event planning snapshot before immediate full expansion; both paths use the same snapshot helper and existing restoration owner. For continuous window shifts it also captures both ends of the viewport plus its 500px upper/lower buffer, using source-extent markers independently of scroll-anchor ownership. It captures a small ordered set of visible and nearby stable row candidates because Tool grouping may remove the leading sliced response row after its hidden call predecessor mounts. Planning a prepend immediately detaches bottom follow and retires an older pre-host-resize correction, so its queued settling frame cannot replace the new reading position with bottom. It tries surviving candidates in order, then preserves the viewport by the exact scroll-height prepend delta when none survives; this transient recovery never substitutes a bottom state and adopts a newly visible stable anchor for later resize correction when available.
- One ResizeObserver watches both Timeline content and the native scroller, so idle viewport-only resizing and late content changes both reapply active bottom/anchor state. In the [stable Workbench content host](./webui-workbench-content.md#d-workbench-stable-content), `useContentBeforeResize` captures that same local state before a changed host size. Native reflow scroll events cannot replace the saved anchor during the observer/width-band settling frame, and fresh user scroll intent cancels the correction. The pre-host callback does not rearm a detached input generation until the native scroll handler has captured its resulting position. The host also exposes whether its slot geometry has been applied. Chat defers native restoration and missing-anchor fallback until that geometry is ready; the existing resize observer completes and releases pending saved-state restoration after sizing. This is a layout-readiness boundary, not an exact-offset success requirement for legitimate native edge clamps. Independent popup/embedded leaves have no provider and retain their normal observer path. A queued resize scroll that precedes that movement cannot acknowledge that generation; capture waits for native movement in the pending direction, using the existing input epoch and last native position.
- All Timeline views share manual-disclosure follow behavior. Natural-height measurement predicts the expanded card's top after alignment to the actual new bottom. An already detached reader keeps scrollTop; attached follow continues only if that aligned top stays visible, otherwise it is genuinely cancelled and a committed reading anchor is captured. Animation completion, new content and ResizeObserver do not revive cancelled follow. Native scroll anchoring is disabled only during the local height change; the existing parent slot protects measurement from temporary range shrinkage. [Canonical contract](#d-chat-tall-card-follow).
- The composer spacer tracks only real composer layout. The [bottom status layout](#d-chat-bottom-status-layout) keeps no-queue status transitions from changing the message column height and places actual queued message previews separately below the status region. Slash-command suggestions overlay above the form and therefore do not alter the spacer or disturb an attached bottom-follow viewport.
- View-specific scrollbar/minimap policy is owned by [Conversation scroll display](../modules/webui.md#d-webui-conversation-scroll-display). Chat owns the effective scroller data attributes in React and only mounts the minimap/overlay when enabled; ContextScrollbar receives the stored settings for its menu and has no attribute-writing cleanup. Desktop reserves the context-overview gutter outside both Timeline and Composer columns whenever the minimap is enabled; the track remains at the native scroll container's outer right edge. Shared width, centering, and native-scrollbar clearance are canonical in [D-webui-shared-content-width](../modules/webui.md#d-webui-shared-content-width). During the recent-tail bootstrap the gutter remains stable but the inaccurate overview contents and interaction stay unmounted until full history arrives. Explicitly disabling the minimap removes the gutter, while the saved native-scrollbar setting remains independently owned and unchanged. The overview represents full committed history even while Chat mounts only the newest timeline rows. Its custom pointer interaction requests a native-container scroll and uses the existing explicit-user-intent latch; it never creates a second scroll owner or writes during passive geometry updates.
- `contextScrollbarModel.ts` owns browser-safe message estimate text, stable logical segments, tool-response-to-preceding-call row association, and real-usage-plus-tail context accounting. It uses the shared lightweight estimator and the latest persisted model-message input/cache/output usage as its real anchor; later committed content is estimated. Metadata-classified LLM retry notices use the system tone and thread-card height estimate, keeping the context overview aligned with timeline presentation. `ContextScrollbar` uses rendered committed-row anchors and interpolation for the viewport marker plus one-shot DOM/token click and drag placement.

`workbenchPreview.e2e.mjs` covers idle Terminal creation and browser-height resizing with attached follow or a reading anchor, independent popup width reflow, and native upward wheel during continuous resize, with Chromium CPU throttling exercising queued pre-input resize scrolls and bounded event geometry in failure diagnostics. These probes retain Chat DOM/history initialization and issue no streaming updates.

## Design decisions

### D-chat-container-layout

[2026-10-01] Each mounted Chat uses its own content width for narrow/wide timeline, processing, queued-preview, context minimap, header labels, and composer layout. The named `foxwarm-chat` inline-size container owns CSS queries: 640px header labels, 768px desktop timeline/minimap, 1024px header hints, and 420px child-model trigger text. A root ResizeObserver publishes only the 768px timeline and 640px model-picker layout bands, measures synchronously before the first paint, and retains the last band while hidden at zero width. The portaled model picker receives the Chat's compact band for columns and preferred size while viewport geometry still bounds its fixed placement. App/workbench navigation, input-device behavior, and page-level mobile handling remain viewport-owned. Resizing does not introduce a new draft, subscription, or scroll owner. The focused `workbenchPreview.e2e.mjs` case covers real divider movement before release, simultaneous wide/narrow panes, equal content widths across browser widths, sidebar resizing, hidden/revealed content, and embedded/popup leaf layouts.

### D-chat-header-launch-actions

[2026-09-30; updated 2026-10-14] Chat retains one ordinary `Code` action with the global opening preference and no separate new-tab button. Terminal placement is owned by the [desktop panel contract](./webui-workbench.md#d-workbench-terminal-panel); the normal App supplies the header Terminal callback only on mobile and when the selected Node advertises usable PTY service capability.
