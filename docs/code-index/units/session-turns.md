## Purpose

Owns one Session's mutable state, exact-owner runtime operations, serialized turn execution, queue ingress, stop/dequeue controls, and model/tool turn contracts. Persistence ordering belongs to the save-lane and authority-store units linked below.

## Stable methods and callers

- `SessionRuntime.GetOwnerAsync`, `SubmitAndRunAsync`, `ContinueAsync`, `StopAsync`, `DequeueAsync`, `ForkCommandAsync`, and clear/control methods resolve the canonical owner and return typed lifecycle outcomes.
- `SessionOwner` exposes the owner metadata/state boundary and coordinates model request, tool loop, compaction, waits, and publication callbacks. `ExecutionNode` uses the manager's shared placement resolver with the owner's current Agent binding; `BuildDto` projects that effective Node and unchanged stored cwd for composer responses and realtime snapshots. Snapshot history uses the same resolver through [the WebUI contract](./dotnet-webui-core.md), including retained authority without a selection field. These reads do not save or manufacture authority fields.
- `SessionEntry.TryClaimProcessor`, `MarkBusy`, `BeginStop`, `ReleaseBusy`, and `Snapshot` guard live state and processor ownership under `stateGate`.
- `SessionIngress.EnqueueAsync` validates supported queue kinds, forces trigger semantics at the ingress boundary, admits through `SessionSaveLane`, and triggers the runner only when the owner is runnable.
- `SessionTurnRunner.CloseAdmission` synchronously fences ordinary/manual/trailing starts under the same gate as accepted processor registration. `ShutdownAsync` tracks those processors through settlement, allows five seconds of grace, requests lifecycle cancellation through each exact `SessionEntry`, then allows five more seconds before `SessionTurnDrainException`. It is idempotent and never reports a cancellation-ignoring owner as settled.
- `SessionTurnRunner.ProcessQueueAsync` claims one processor, runs `LocalSessionTurnHost`, appends canonical messages through the save lane, and finalizes busy/stopping state. `LocalSessionTurnHost` applies child-handoff state for consumed queue items during canonical append, resolves trusted send/task receipts before tool-row append, reads parent identity through the Main catalog-overlay resolver for child reminders and receipt handling, recognizes terminal `NO_ACTION` signals across text parts only when no continuation is possible, queues repeated unresolved-child reminders without a history-window suppression, and stops the outer loop after terminal tool batches.
- `LocalSessionTurnHost.ContinueAfterResultAsync` delegates continuation maintenance to the owner's compactor while retaining both queued-input safe points. The owner supplies failure propagation and compact commit outcomes; ordinary provider-time queued input and complete tool batches share this path. The turn cancellation token releases a required-compaction wait without cancelling independent planning; the dedicated shutdown exception also propagates through required continuation preparation.
- `SessionControl.StopAsync`/`DequeueAsync` signal cancellation and await the owner safe point rather than mutating queue state out of band.

Callers: `MessageRouter`, `SessionManager`, WebUI route handlers, task/timer tools, and model/tool services. The exact owner remains authoritative even when a route only needs a catalog projection.

## Contract and side effects

History snapshots capture the immutable root described in [history ownership](./session-domain.md#history-ownership); they do not clone the complete history. Canonical append stages new owned records and shares existing records. Read-only model selection, prompt/cache lookup, task visibility, and under-threshold continuation use narrow gated reads. The ordinary `ISessionChatService` path carries the exact captured root through `RequestChatService`; `SessionChatService` then materializes request-owned JSON with [immutable record provenance](./model-common-wire.md). The fallback `IChatService` boundary still receives a detached mutable projection. Committed notifications inspect immutable sequences before projecting only newly delivered records.

One processor claim may run per Session. Busy and stopping are distinct state: restart recovery can clear stale busy ownership, while stopping is an explicit lifecycle/control outcome. Queue admission persists before triggering; passive inter-Session items remain durable without automatically starting a turn. Stop can abort an in-flight request/tool loop but must still await the final authoritative save result. Lifecycle interruption is distinct: an already-selected input append settles, launched tool calls complete their paired rows, and an unfinished turn keeps its existing busy checkpoint and unconsumed later input. Unselected outer work remains queued without a new busy recovery obligation. Genuine final answers, successful terminal handoffs/waits and explicit Stop retain ordinary idle finalization; concurrent Run queued clears its Stop override but cannot start a new provider during closure. No synthetic shutdown error row or persisted shutdown marker is added. Existing startup busy recovery remains the only recovery path.

Tool execution carries source JSON values; ordinary history projection and trusted receipts follow [the tool contract](../threads/tools-permissions-and-exec.md#outbound-mcp-values-and-trusted-control).

Completed provider usage updates the existing authority `stats` totals and `lastUsage` in the same ordered canonical append transaction as its assistant row. The explicit result usage takes precedence over normalized message metadata; tool rows, unrelated input and ordinary saves do not recount history. A usage-only completion persists totals without inventing an assistant row. Pre-commit failure leaves hot totals unchanged; post-commit failure publishes the committed totals. Existing Session/catalog projections feed cumulative usage consumers without an additional stats API.

`DeferredQueueInput.Mark` records owner-observed delayed model-visible user inputs and events after provider execution, at retry/continuation consumption, and across Stop/Run queued. The `queuedInput` bit survives queue persistence and cloning. Canonical queue consumption adds a separate `queueInputHint` attribute to the existing opening source wrapper, skipping only leading self-closing session/channel/time metadata. It preserves the original hint, body, parts, attachments and client identity, and neither scans arbitrary body text nor fabricates a missing wrapper. Initial/pre-provider drains, compact wakes, hidden inputs and model/tool results are not marked merely by passing through a queue. Request reconstruction never rewrites old history.

Passive trusted rows remain durable and wait-neutral. The outer loop does not consume passive-only work after a wait; automatic triggering excludes passive rows. Idle explicit Run queued clears the wait and uses the existing processor once, without redefining passive work as automatically runnable. Busy Run queued retains the cancellation/safe-point override and complete tool-pair finalization.

The turn runner does not write raw JSON or Archive directly. It stages snapshots and canonical rows through [the save lane](./session-save-lane-core.md) and [the authority store](./session-authority-store.md), preserving pre/post-rename failure classification.

## Transient presentation and failure feedback

`SessionOwner.RuntimeSnapshot` composes bounded foreground, independent compaction, busy/stopping/queue and existing durable wait facts. Model-attempt callbacks replace foreground backoff; tool starts carry resolved identities and zero-based batch positions only after authorization. `BeginCompactPhase`/`EndCompactPhase` and tool cleanup use exact projection leases, so older completion cannot erase newer work. History, observation and bounded list/reconnect paths share this projection; no transient runtime object is stored as Session authority.

`LocalSessionTurnHost.ReleaseBusyAsync` captures the owner's current foreground projection before persistence and retires only that projection after a successful strict release, or immediately when already idle. `FinalizeStoppedAsync` applies the same retirement after its canonical finalization succeeds. Failed release retains the existing pre-commit rollback or committed-error behavior without retiring runtime state. Independent compaction is untouched; a later input cannot revive a successfully released run's final retry during pre-attempt preparation.

`SessionTurnRunner.ProcessQueueAsync` optionally signals admission after continuation validation and busy claim, before waiting for a provider answer or tool settlement. Its failure callback permits canonical notices for safe ordinary failures, but passes model-request failures as temporary presentation candidates: terminal retry persistence may already have failed best-effort without propagating that save exception. Existing terminal retry delivery/tail detection still suppresses represented failures. Escaped persistence failures use temporary typed presentation from the owner. Independent strict busy release remains required. This does not change processor, queue, launched-effect or journal semantics.
