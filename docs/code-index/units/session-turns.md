## Purpose

Owns one Session's mutable state, exact-owner runtime operations, serialized turn execution, queue ingress, stop/dequeue controls, and model/tool turn contracts. Persistence ordering belongs to the save-lane and authority-store units linked below.

## Stable methods and callers

- `SessionRuntime.GetOwnerAsync`, `SubmitAndRunAsync`, `ContinueAsync`, `StopAsync`, `DequeueAsync`, `ForkCommandAsync`, and clear/control methods resolve the canonical owner and return typed lifecycle outcomes.
- `SessionOwner` exposes the owner metadata/state boundary and coordinates model request, tool loop, compaction, waits, and publication callbacks. `ExecutionNode` uses the manager's shared placement resolver with the owner's current Agent binding; `BuildDto` projects that effective Node and unchanged stored cwd for composer responses and realtime snapshots. Snapshot history uses the same resolver through [the WebUI contract](./dotnet-webui-core.md), including retained authority without a selection field. These reads do not save or manufacture authority fields.
- `SessionEntry.IdentityLossToken` cancels a dispatched primitive-provider launcher when the exact owner becomes unavailable or retired. Ordinary Stop and normal process shutdown do not signal it; [provider exec](./tools-local-io.md#provider-exec) retains command/foreground lifetime separation.
- `SessionEntry.TryClaimProcessor`, `MarkBusy`, `BeginStop`, `ReleaseBusy`, and `Snapshot` guard live state and processor ownership under `stateGate`.
- `SessionIngress.EnqueueAsync` validates supported queue kinds, forces trigger semantics at the ingress boundary, admits through `SessionSaveLane`, and triggers the runner only when the owner is runnable.
- `SessionTurnRunner.CloseAdmission` synchronously fences ordinary/manual/trailing starts under the same gate as accepted processor registration. `ShutdownAsync` tracks those processors through settlement, allows five seconds of grace, requests lifecycle cancellation through each exact `SessionEntry` and the manager-supplied foreground ToolScript cancellation callback, then allows five more seconds before `SessionTurnDrainException`. The callback still runs when Stop or Run queued already took the entry's cancellation handle. It is idempotent and never reports a cancellation-ignoring owner as settled.
- `SessionTurnRunner.ProcessQueueAsync` claims one processor, runs `LocalSessionTurnHost`, appends canonical messages through the save lane, and finalizes busy/stopping state. `LocalSessionTurnHost` applies child-handoff state for consumed queue items during canonical append, resolves trusted send/task receipts before tool-row append, reads parent identity through the Main catalog-overlay resolver for child reminders and receipt handling, recognizes terminal `NO_ACTION` signals across text parts only when no continuation is possible, queues repeated unresolved-child reminders without a history-window suppression, and stops the outer loop after ending tool batches. `ITurnToolControl.CompleteBatchAsync` returns `TurnBatchEnding`: error-free finish-after-send is `Finished`, while error-free explicit waits and handoff waits are `Suspended`; recognized batch errors yield `Continue` under the [terminal-control contract](../behaviors/execution-and-waiting.md#explicit-wait-ends-an-otherwise-finished-turn). `ChatResult` carries that classification through runner finalization to the external-channel owner; it is not inferred from the generic stopping flag or persisted in Session authority. Fatal failures, user Stop and exhausted retries remain terminal, and an already handled final is not delivered again after release/maintenance failure.
- `SessionEntry.StructuredProgress` carries transient provider-neutral top-level model-start and batch tool-start/finish facts, including stable call IDs, names/statuses and model text, to the [external-channel presentation owner](./dotnet-external-channels.md). It does not alter canonical model/tool pairs or tool execution. Native-active targets combine model text with running tools instead of receiving duplicate intermediate text.
- `LocalSessionTurnHost.ContinueAfterResultAsync` delegates continuation maintenance to the owner's compactor while retaining the post-result queued-input safe points. Every provider-loop iteration also uses `AppendQueuedInputsAtSafePointAsync` before capturing request history, including after successful required planning; the ordinary queue append, deferred-input marking and notification owners remain shared. The owner supplies failure propagation and compact commit outcomes; ordinary provider-time queued input and complete tool batches share this path. The turn cancellation token releases a required-compaction wait without cancelling independent planning; the dedicated shutdown exception also propagates through required continuation preparation.
- `SessionControl.StopAsync`/`DequeueAsync` signal cancellation and await the owner safe point rather than mutating queue state out of band. Main-local `stop_session` uses that same exact-owner path for self targets: its settled receipt survives while subsequent unstarted batch/ToolScript calls are fenced. No Session-wide stopping guard is applied to independent script timers.

Callers: `MessageRouter`, `SessionManager`, WebUI route handlers, task/timer tools, and model/tool services. The exact owner remains authoritative even when a route only needs a catalog projection.

## Contract and side effects

History snapshots capture the immutable root described in [history ownership](./session-domain.md#history-ownership); they do not clone the complete history. Canonical append stages new owned records and shares existing records. Read-only model selection, prompt/cache lookup, task visibility, and under-threshold continuation use narrow gated reads. The ordinary `ISessionChatService` path carries the exact captured root through `RequestChatService`; `SessionChatService` then materializes request-owned JSON with [immutable record provenance](./model-common-wire.md). The fallback `IChatService` boundary still receives a detached mutable projection. Canonical append notifications project only the exact newly committed rows returned by that append. State/settings-only callbacks never scan history; cold admission and fork loading do not replay existing rows as new commits. This follows the original append ownership rather than assuming post-save continuations share a notification frontier.

Queue consumption and Stop finalization retain the save lane's exact canonical append result and route it through `SessionEntry.QueueHistoryAppended`, suppressing the ordinary `HistoryAppended` callback for those rows. Model/tool rows, ordinary notices, BTW and newly appended lifecycle rows retain individual exact-row notification ownership. The owner emits current state, then publishes one transient `QueueHistoryAppended` event with those rows and the captured post-consumption snapshot. WebSocket projection reuses the bounded queue preview from history; legacy SSE keeps individual message envelopes. This follows Source's queue append callback rather than requiring a client fallback for individual queue commits. The existing post-commit notification-failure boundary remains best effort and does not undo canonical rows.

`LocalSessionTurnHost` and `SessionRegistry` default to 5,000 provider-loop iterations per turn. Explicit positive constructor limits retain their existing bounds. Exhaustion raises `ToolLoopLimitException` after the last complete tool pair and continuation maintenance, without starting another provider request.

`SessionOwner.StartProcessing` starts a new foreground processor without flowing the triggering caller's execution context across its initial asynchronous boundary. Inter-Session sends and other background triggers must not carry ToolScript, invocation or mutation scopes into the recipient's later foreground tools, including a report that starts the original sender again. Normal nested ToolScript calls within the same processor retain their scopes. Admission, processor registration, readiness and drain tracking keep their existing order.

One processor claim may run per Session. Busy and stopping are distinct state: restart recovery can clear stale busy ownership, while stopping is an explicit lifecycle/control outcome. Queue admission persists before triggering; passive inter-Session items remain durable without automatically starting a turn. Stop can abort an in-flight request/tool loop but must still await the final authoritative save result. Lifecycle interruption is distinct: an already-selected input append settles, launched tool calls complete their paired rows, and an unfinished turn keeps its existing busy checkpoint and unconsumed later input. Unselected outer work remains queued without a new busy recovery obligation. Genuine final answers, successful terminal handoffs/waits and explicit Stop retain ordinary idle finalization; concurrent Run queued clears its Stop override but cannot start a new provider during closure. No synthetic shutdown error row or persisted shutdown marker is added. Existing startup busy recovery remains the only recovery path.

Foreground `SessionToolExecutor.BeginBatch` receives the actual canonical assistant row; `CompleteBatchAsync` receives the committed complete tool row. In-context compact admission/pairing and unpaired cleanup use that exact outer batch, with the outcome contract owned by [compaction](./session-compaction.md#deliberate-in-context-submission). Ordinary multi-tool execution, trusted terminal controls and queued-input ordering remain shared.

Tool execution carries source JSON values; ordinary history projection and trusted receipts follow [the tool contract](../threads/tools-permissions-and-exec.md#outbound-mcp-values-and-trusted-control).

Completed provider usage updates the existing authority `stats` totals and `lastUsage` in the same ordered canonical append transaction as its assistant row. The explicit result usage takes precedence over normalized message metadata; tool rows, unrelated input and ordinary saves do not recount history. A usage-only completion persists totals without inventing an assistant row. Pre-commit failure leaves hot totals unchanged; post-commit failure publishes the committed totals. Existing Session/catalog projections feed cumulative usage consumers without an additional stats API.

`InputWrapperMetadata` shares the narrow outer-wrapper attribute edit between deferred hints and new canonical seq stamping. `PrepareCanonicalAppend` stamps final seq before freezing new input rows; the child-boundary, lifecycle-suffix and compact-completion builders use the same helper after their own final allocation. It skips leading session/channel/time metadata, replaces only the outer source attribute, and never rewrites inherited/history-loaded records or nested quotations. Queue previews and request-only reminders receive no guessed seq.

`DeferredQueueInput.Mark` records owner-observed delayed model-visible user inputs and events after provider execution, at retry/continuation consumption, and across Stop/Run queued. The `queuedInput` bit survives queue persistence and cloning. Canonical queue consumption adds a separate `queueInputHint` attribute to the existing opening source wrapper, skipping only leading self-closing session/channel/time metadata. It preserves the original hint, body, parts, attachments and client identity, and neither scans arbitrary body text nor fabricates a missing wrapper. Initial/pre-provider drains, compact wakes, hidden inputs and model/tool results are not marked merely by passing through a queue. Request reconstruction never rewrites old history.

Passive trusted rows remain durable and wait-neutral. The outer loop does not consume passive-only work after a wait; automatic triggering excludes passive rows. Idle explicit Run queued clears the wait and uses the existing processor once, without redefining passive work as automatically runnable. Busy Run queued retains the cancellation/safe-point override and complete tool-pair finalization.

The turn runner does not write raw JSON or Archive directly. It stages snapshots and canonical rows through [the save lane](./session-save-lane-core.md) and [the authority store](./session-authority-store.md), preserving pre/post-rename failure classification.

## Transient presentation and failure feedback

The exact owner implements [D-streaming-delta-and-bootstrap](../threads/streaming-pipeline.md#d-streaming-delta-and-bootstrap) with separate latest and emitted transient snapshots. Provider progress always updates the cumulative subscription draft; the presentation emitter uses the fast 80 ms cadence for text, reasoning, part changes and function identity, and a fixed one-second cadence for raw arguments. Sequence numbers advance only for published changes. Argument offsets use the emitted baseline, while a late subscriber receives current collected arguments plus the existing sequence watermark. Unchanged ordered-part phases do not manufacture updates.

Owner timers are fenced by the current draft and timer identity under the draft gate. Reset, request completion/error/Stop cleanup and matching canonical publication flush the latest arguments and cancel pending timers; prefix trims flush before replacing the emitted baseline with the remaining output items. Old timer callbacks cannot publish into a later stream or after canonical completion. The existing request-progress/activity path remains unthrottled, and none of this state enters persistence. `SessionOwnerStreamingTests` qualifies deterministic cadence, coverage, snapshots, final/reset/Stop and commentary trim boundaries; the original-App payload fixture exercises the real provider-to-browser path.

`SessionOwner.RuntimeSnapshot` composes bounded foreground, independent compaction, busy/stopping/queue and existing durable wait facts. Model-attempt callbacks replace foreground backoff; tool starts carry resolved identities and zero-based batch positions only after authorization. `BeginCompactPhase`/`EndCompactPhase` and tool cleanup use exact projection leases, so older completion cannot erase newer work. History, observation and bounded list/reconnect paths share this projection; no transient runtime object is stored as Session authority.

`SessionTurnRunner` carries only a pending canonical `ModelRequestException` outcome into ordinary busy release. The optional boolean `meta.llmFailed` shares that strict snapshot and its precommit rollback/committed-error handling. `SessionMetadata` and `SessionRuntimeState.Build` project it through the owner and cold catalog; busy and declared waits retain precedence. Busy claim clears it for selected ordinary work or admitted Continue, and canonical queue consumption covers input arriving during a maintenance-only claim. Maintenance-only claims leave it intact. Clear removes it; fork constructs fresh metadata. Observable rules belong to [terminal foreground failure](../behaviors/messages-and-turns.md#terminal-foreground-request-failure-net).

`LocalSessionTurnHost.ReleaseBusyAsync` captures the owner's current foreground projection before persistence and retires only that projection after a successful strict release, or immediately when already idle. `FinalizeStoppedAsync` applies the same retirement after its canonical finalization succeeds. Failed release retains the existing pre-commit rollback or committed-error behavior without retiring runtime state. Independent compaction is untouched; a later input cannot revive a successfully released run's final retry during pre-attempt preparation.

`SessionTurnRunner.ProcessQueueAsync` optionally signals admission after continuation validation and busy claim, before waiting for a provider answer or tool settlement. Its failure callback permits canonical notices for safe ordinary failures, but passes model-request failures as temporary presentation candidates: terminal retry persistence may already have failed best-effort without propagating that save exception. Existing terminal retry delivery/tail detection still suppresses represented failures. Escaped persistence failures use temporary typed presentation from the owner. Independent strict busy release remains required. This does not change processor, queue, launched-effect or journal semantics.

## Tests

`SessionProcessorContextTests` uses ordinary real-Monty child creation and sends, a later child report, and loopback provider turns to verify that the report-triggered parent declares a direct wait with an exact persisted ID and fallback without a surplus request. Direct child creation is the non-script control; existing ToolScript terminal-wait tests cover legitimate nested wait arming.

`SessionTurnTests` exercises both default constructor paths past 500 iterations and through exact 5,000-iteration exhaustion with deterministic in-memory model/tool fixtures, plus the existing explicit two-iteration limit.

`CanonicalSequenceCueTests` covers final wrapper seq in active/Archive rows, nested/queued text retention and alternate child/fork builders.

`MainLocalToolsStopTests` checks self Stop through real batch and native ToolScript calls, truthful current-call receipts, ordered unstarted results, and an independent script timer that still executes while the foreground owner is stopping.

`SessionShutdownTests.Normal_manager_shutdown_cancels_foreground_pure_VM_work_after_grace` uses an ordinary loopback provider and native `run_script` to qualify normal manager shutdown directly and after Stop/Run queued, without replacing production grace/cancellation deadlines. Prior foreground controls do not preempt pure VM work; shutdown cancels its worker and preserves the existing queued-input policy.

`SessionShutdownTests.Normal_manager_shutdown_keeps_an_accepted_script_timer_independent_of_foreground_cancellation` holds a real scheduled slice in an owned exec while the same owner's foreground VM is cancelled. Shutdown waits for that timer's host return and later write before closing dependencies.
