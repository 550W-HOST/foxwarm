## Purpose and stable symbols

- `getRuntimeStatusView`, `describeRuntimeTool`, `describeRuntimeWaiting` form one pure status/semantic-tone/detail mapping for Chat, Sidebar and Architecture. Tool presentation uses resolved metadata, not JSON guesses from truncated human argument previews. MCP names do not acquire builtin read/node semantics.
- `RuntimeFox` chooses request/wait illustrations and separate trotting, gathering, looking-back, raised-paw, resting, drooping-ear and head-tilt poses. Request and Waiting retain their existing artwork; new silhouettes use consistent strokes and no overlaid prop badges. `animated:false` and reduced motion suppress motion; historical error cards are static. Authored optical frames normalize visible extents and stroke weight without stretching poses or measuring the live DOM; the runtime slot remains 24px. Shared pose CSS remains owned by [fox loaders](./webui-fox-loaders.md).
- An otherwise idle `processing` projection uses the shared neutral Running summary and withholds Interrupted/Continue. It does not change active classification, busy rings or idle-notification triggers; failure, waiting and compaction presentation retains priority.
- `ProcessingStatus` preserves explicit inactive `llm-failed` over old history diagnostics, offers eligible Continue, and keeps pending Continue until active progress. Shared summaries drive static danger indicators and omit running duration for failed Sessions; [terminal foreground failure](../behaviors/messages-and-turns.md#terminal-foreground-request-failure-net) owns the behavior.
- `ProcessingStatus` owns the single live status row and an anchored body-portaled details popover. Initial geometry is hidden until measured; focus follows visible positioning, Escape/outside interaction closes, and focus returns without scrolling. The popover chooses available above/below space and stays bounded on phones.
- `useProcessingCaption` owns request-local caption retention and the displayed tool's three-second minimum. `getStreamingCaptions` supplies eligible captions in output order; `extractOpenAIReasoningSummaryTitles` keeps the exact Reasoning card first-line gate. `getStreamingToolSummary` reads complete summary strings from structured JSON prefixes, including direct `exec`/`run_script`, node/builtin `call_tool` routing, and escaped `argsJson` prefixes. It excludes MCP lookalikes and embedded command/code text. Existing stream/call identities connect generation and execution; no history lookup, transport change or runtime mutation is involved. Chat keys ProcessingStatus by Session to discard its caption, timer and details state on navigation. Observable retention and interruption rules belong to [live caption continuity](../threads/session-runtime-presentation.md#d-runtime-caption-continuity).
- `QueuedMessageStatus` is the independent message-aligned queue count/action. Stop remains in the composer. Submission does not replace an authoritative active tool/request/wait status.
- `getSessionNotice`, `getLastSessionFailure`, `createLocalSessionNotice` recognize trusted display-only events and represent local delivery uncertainty without inventing provider-visible messages.
- `getImageGenerationNotice` recognizes structured hosted-image failure metadata, never assistant prose prefixes. Failed/incomplete streaming placeholders and canonical failure parts render an error card with collapsed bounded diagnostics in all timeline modes; ordinary assistant text remains prose. Search indexes and reveals the original model-part details. The card does not mark the whole Session failed or offer request retry. Model visibility and replay belong to [hosted image failure evidence](./model-responses.md#hosted-image-failure-evidence).
- `SystemEventCard` renders a short semantic event panel with native closed diagnostics. Text stays escaped, selectable and bounded. Search can reveal the original diagnostic surface.
- A final `llm-retry` notice whose retry metadata carries `cause` and `explanation` (key, access or model-ID rejection; see [configuration failures](../threads/model-routing.md#d-model-routing-configuration-failures)) uses the explanation as its summary and offers **Open model settings**. The action is presentation-only (`SessionNotice.action`, never read from persisted notice data) and appears only where Chat supplies `OpenModelSettingsContext`, which normal Chat provides from its Setup → Models callback outside WebUI identity mode. `llmErrorThreadCard.e2e.mjs` covers both cases.

The chat synchronization hook correlates control request IDs, retains pending Stop/Continue until authoritative progress, ignores unrelated acknowledgements, and separates no-op/uncertain feedback from canonical history. Existing source data, replay, permission and queue behavior remain owned by their domains.

Native fixtures verify actual theme ink, distinct poses, keyboard details/focus, full phone bounds, reduced motion, request-caption timer cleanup, Stop/Send and queue geometry, feedback correlation, and event visibility/search in every timeline mode. The live-caption cases in `chatHistoryLoading.e2e.mjs` wait for the committed runtime-state DOM before asserting color and pose; retained caption text alone cannot establish the generation/execution/next-request transition. Caption minimums are measured between the browser's own caption commits, recorded by an in-page observer, rather than from when the test observes a caption, so a slow renderer or test driver cannot shorten or lengthen the measured hold. Canonical contract: [Session runtime presentation](../threads/session-runtime-presentation.md).
