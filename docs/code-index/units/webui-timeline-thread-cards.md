## Purpose

Owns the thread-card family used by the chat timeline for CTX-BLOCK, Reasoning, Web Search, and heavy system-like messages: shared card chrome, height and overflow measurement hooks, and proven hosted web-search action normalization.

## Key Exports

- `ContextBlockCard` — renders CTX-BLOCK model messages as tool/reasoning-style thread cards with local expand/collapse state and the read-only WebUI archive expansion endpoint
- `useThreadCardOverflowFade(axis, enabled)` — observes one clipped thread-card content surface and exposes a tone-independent text mask only while measured overflow is present
- `ModelThreadCard` — shared Reasoning/Web Search thread-card chrome and expand/collapse interaction; optional header information follows the shrinkable preview. Reasoning token information stays fixed at the trailing edge even when expanded; WebSearch without information is unchanged.
- `ReasoningTokenBadge` — compact accessible Brain/token information shared by a tool or assistant-text recipient of an empty reasoning run; does not estimate or aggregate usage.
- `useThreadCardHeightTransition(expanded)` — one-shot measured height interpolation on local toggles; delegates viewport follow to Chat
- `WebSearchCard` — narrow renderer for persisted OpenAI Responses search/open-page activity
- `getContextBlockMetaFromMessage(message)` — pure helper that prefers structured `__meta.contextBlock` metadata and falls back to parsing legacy CTX-BLOCK text only when needed

## Behavior

- Reasoning cards and Grouped Reasoning-summary entries share the icon-plus-existing-count tag presentation in every Timeline mode, including processing and nested History/CTX paths. Tooltip/accessible labels retain counts; previews, expanded content, independent reasoning-token information and disclosure controls remain unchanged. [Canonical Reasoning contract](../modules/webui-timeline.md#d-webui-contiguous-reasoning-cards).

- Heavy/non-direct system-like messages and metadata-classified display-only LLM retry notices render as compact left-side thread cards sharing the ToolTag/ThreadLineButton structure used by tool and Reasoning cards. Their tag comes from `getSystemMessagePreviewDescriptor`: heavy `<foxwarm-system kind="...">` first, otherwise non-channel `<foxwarm-message type="...">`, otherwise `system`; an LLM retry uses the unified `LLM error ×N` tag, where N is its prefix-free logical body-line count. Collapsed previews can prefix inter-agent `From sourceSessionId`, session-boundary `event`, or event `type`; LLM retry previews and expanded bodies remove only the first-line `⚠️ LLM Error:` prefix when present; malformed retry text remains readable. When an inter-agent source is present only its ID is a SessionHashLink, so `From ` and `: ` remain ordinary text and link activation does not expand the card. Expanded body text remains raw/readable and links recognized public Session fields by field name through [D-webui-session-field-links](./webui-chat-shared.md#d-webui-session-field-links). Default chrome uses the shared blue processing-Reasoning palette while preview/body text remains slate. In the console component treatment, explicit system hooks use dedicated semantic info variables while both Reasoning tones are neutral. Icons remain mapped by kind: session-boundary uses SeparatorHorizontal, reminders/prompt/lifecycle kinds use their own stable semantic icons, and unknown system kinds use Bell (whereas unknown real tools use Wrench). Cards retain the same local `my-0.5` rhythm as other thread cards; `MessageRow` groups consecutive model/tool/heavy-system rows without its ordinary top-level separation, but direct user rows still begin/end a turn. Inline direct-user text still renders tag lines as small metadata while body lines remain normal text. The classifier distinguishes real direct channel wrappers (`type="channel"`) and lightweight time/session metadata from heavy/non-direct wrappers (`type="inter-agent"`, `timer`, `trigger`, etc.), pure system event tags such as wait timeouts, and heavy snapshot/system-prompt/external-input tags, so only the latter group plus metadata-classified LLM retry notices goes left through `SystemLikeMessageCard`.
- Standard System/Event/Inter-agent tags retain their existing body/header/background allocation but use the shared semantic System-tag foreground derivation and `infoBorder`; this restores built-in Default contrast while custom-theme results remain token-defined. The System thread line continues to use low-emphasis `systemAccent`. Console System tags retain input/system-border/system-accent plus their existing glow.
- Inter-agent cards with a non-empty source session retain only the linked `From session-id:` identity in their collapsed header; their message body appears below it in a result-style preview clamped with the shared three-line tool-result rule. Missing source metadata keeps the ordinary system-card preview without a dangling `From` label or colon.
- Model messages with `__meta.contextBlock` render as CTX-BLOCK thread cards, visually distinct from normal assistant bubbles but using the same `ToolTag` + `ThreadLineButton` pattern as tool/reasoning cards. The summary part is located by its index in `message.parts`, so a preceding part that renders no model content (an image or an unrecognized hosted Responses item) does not demote the block to an ordinary assistant card. The tag label is just `CTX-BLOCK`; the header line shows metadata (`B#`, level, raw sequence range, and time range when available). Collapsed summary Markdown is limited to five rendered text lines and gains a bottom fade only when measured content is actually clipped; collapsed cards still do not fetch or render archive children/raw messages. Clicking the collapsed surface or gutter expands; expanded cards show the complete summary and fetch/show children or raw messages, then collapse via the left gutter or header. Expansion is local React state keyed to the card; switching sessions/reloading clears it and does not modify the `messages` array.
- Tool call/result, Reasoning/Web Search, System/Event/Inter-agent, CTX-BLOCK, and toggled multi-row tool groups use a one-shot height transition. On the click, measure and pin the displayed card/group and its local in-flow parent slot; a layout effect after the React commit reads the natural target from the same card without reducing the scroller range, restores the start height, and releases the slot before paint. Explicit pixel heights then interpolate to the target. Temporary local clipping leaves room for disclosure gutter paint; end/cancel, rapid reversal, unmount, and reduced-motion restore auto height. A late cancel event from a previous transition cannot end the new transition before its own start. Native scroll anchoring stays disabled through the local transition; its cleanup does not change follow state. Streaming and async CTX loads do not retrigger animation. Chat owns viewport prediction (see [D-chat-tall-card-follow](./webui-chat.md#d-chat-tall-card-follow)).
- Collapsible timeline thread cards use the shared resize/content-aware overflow measurement hook for conditional disclosure fades. Clipped multi-line CTX, inter-agent System result, Tool result, and collapsed Tool JSON bodies fade at the bottom; clipped single-line CTX metadata, Reasoning/Web Search, System, and Tool call/header previews fade at the right edge. Short content has no fade. The mask fades content itself to the exact existing translucent/tone-specific surface, while fixed tags, controls, Tool read ranges, action buttons, click targets, and card backgrounds remain unchanged.
- Standard CTX-BLOCK, Reasoning/Web Search, processing Reasoning, and System cards retain their established semantic-plus-opacity composition. Console CTX-BLOCK uses panel/hover, both completed and processing Reasoning (plus Web Search) consume `reasoningSurface`/`reasoningSurfaceStrong`, and System retains its complete semantic system pair.
- CTX-BLOCK expansion has no mode switch: expanding fetches one layer. Block-backed blocks render child CTX-BLOCK messages that can be expanded recursively; message-backed/L1 blocks render their covered raw archive messages. Only the nested timeline is inset by `pl-2` after the card’s existing `pl-2`, leaving the CTX summary width unchanged. Multi-level CTX and tool-group disclosures retain independently clickable controls at the tighter inset, including mobile 14px and desktop 18px rails and chevron themes. Their bounding boxes may touch or overlap slightly; hit tests verify that intended center clicks do not toggle the other level.
- Persisted OpenAI Responses `web_search_call` metadata-only parts render at their exact position among model parts. Recognized `search` and `open_page` actions use the same completed neutral thread-card grammar as Reasoning, while URL citation annotations remain the separate Sources surface attached to final assistant text. Unknown hosted output items stay invisible in rendered mode and remain available through the existing whole-message JSON inspector.

## Design Decisions

### D-webui-thread-card-color-allocation

- [2026-09-03] Every thread-card family must keep a visibly distinct composed body/header allocation, but raw composition is treatment-specific. Standard preserves its longstanding opacity grammar. Console CTX-BLOCK shares panel/hover with neutral tools; completed and processing Reasoning plus Web Search use the named reasoning pair; System uses the named system pair. This preserves imported-theme semantics without changing Default's established appearance. Canonical token ownership: [D-webui-theme-final-surfaces](./webui-theme-system.md#d-webui-theme-final-surfaces).
- [2026-07-25] Heavy/non-direct timeline messages use the same compact thread-card grammar as Tool and Reasoning cards rather than a standalone rounded system box. Their tag is the heavy `<foxwarm-system>` `kind` when present, otherwise a non-channel `<foxwarm-message>` `type`, with `system` as the stable legacy/malformed fallback. Scan the full wrapper history before choosing: a heavy event wins over a mixed direct `channel` wrapper. Keep direct channel user messages as right-side user bubbles, and preserve subdued wrapper metadata, readable body/session links, images, responsive width/overflow containment, and nested rendering. In the default style, all System cards use the blue processing-Reasoning chrome, while their preview/body text stays slate; default Reasoning keeps its existing finished-slate versus active-blue distinction. In the console component treatment, explicit System hooks own the dedicated semantic info variables, while both finished and processing Reasoning cards use neutral panel/input/hover/border/text values with no info glow, border, or text (processing may use the stronger neutral hover surface). System icons remain mapped by kind: event and unknown system kinds use Bell, session-boundary uses SeparatorHorizontal, and recognized inter-agent/timer/trigger/background/onboot, reminder, prompt, snapshot, and session-lifecycle semantics have stable dedicated icons. Unknown real tool names continue to use Wrench. Only collapsed previews may add a non-empty `From sourceSessionId` prefix for inter-agent or event/session-boundary prefixes respectively; `From ` and the colon are plain text while only the source session ID is a hash link that does not expand the card. Expanded system text links recognized public Session fields by field name through [D-webui-session-field-links](./webui-chat-shared.md#d-webui-session-field-links), preserving all surrounding tag text and quotes. System cards retain the same local vertical rhythm as other thread cards. `MessageRow` treats heavy system cards as thread-like despite their persisted `user` role, so consecutive model/tool/system rows group without ordinary `mt-4`, while real direct user rows remain turn boundaries.
- [2026-07-27] In the collapsed/current inter-agent card, a known source session is a header identity (`From session-id:`) rather than part of a combined one-line summary. Its body is a separate result-style preview clamped with the shared three-line tool-result rule; the source-session link remains independently clickable without expanding the card. Missing source metadata keeps the ordinary system-card preview so no dangling `From` label or colon is introduced. The collapsed result and expanded body preserve the same effective body-text color/opacity in both standard and console component treatments. In expanded System text, only lines classified by `isSystemLikeText` (canonical XML metadata plus legacy system prefixes) are compact block rows; ordinary body text remains inline in normal `<pre>` flow with real newlines only between adjacent ordinary body lines. Do not emit standalone newline rows beside a metadata block. Expanded System cards retain their existing blue outer surface/ring and header chrome; in the console component treatment, the inner System-body `<pre>` is transparent and ring-free so the broad pre panel styling does not create a second surface.
- [2026-07-25] Collapsed thread-card headers use one shared 18px tag/preview row metric across Tool, Reasoning, heavy System/Event, and CTX-BLOCK cards. Keep the per-card tone and content semantics, but align tag boxes, single-line preview/call-summary text, and inline controls through the shared header classes rather than per-card offsets. In a `read` summary, the Code icon and truncated path occupy the shrinkable portion while the line-range suffix is fixed, visible, and immediately follows the path rather than filling the shared header. This alignment contract is covered at desktop/mobile and light/dark by `threadCardHeaderAlignment.e2e.mjs`.

### D-webui-hosted-web-search-card

[2026-08-13] Completed OpenAI Responses hosted web-search activity is a reasoning-like model timeline artifact, not a Foxwarm tool invocation. Render only proven persisted `web_search_call` action shapes in their original model-part order: `search` uses the primary query with the first non-empty query-list entry as a compatibility fallback, and `open_page` identifies the URL honestly. The `Web Search` card shares Reasoning's completed neutral/slate thread-card chrome, starts collapsed, and expands only to normalized query or page details. It must not synthesize function calls or responses, enter tool execution/status grouping, mutate provider replay metadata, or replace the separate URL-annotation Sources surface. Unknown or malformed hosted items remain invisible in rendered mode while the existing whole-message JSON inspector retains the original metadata.
[2026-09-19] A web-search card is content of the tool group that contains it, so its visibility follows the same collapsed-group rule as tool cards and folded reasoning: it is hidden exactly while the enclosing group is collapsed into its summary row, and shown whenever that group renders its content — including the kept-expanded final group, which never collapses into a summary row. Do not keep a suppression condition that ignores the kept-expanded flag: that silently hides the cards of a final group whose messages carry web-search activity and no visible text. Covered by `keepExpandedGroupWebSearch.e2e.mjs`.

`threadCardHeight.e2e.mjs` also covers a completed worker-shaped history containing one Conversation Activity and its principal reply: opening the process and a visible native tool preserves detached reading through one stream update and viewport resize. The height hook reports natural geometry; shared Chat follow state decides visibility-based cancellation without per-animation resume tokens. CTX archive boundaries are unchanged.
