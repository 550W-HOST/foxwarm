## Purpose

Renders a chat conversation as a vertical timeline of message bubbles, handling user messages, model responses (with markdown), tool call/response grouping, token usage badges, system-like messages, reasoning cards, and image parts. It supports collapsible tool groups, copy-to-clipboard, and responsive mobile/desktop layouts.

Row derivation, timing, and thread-card families are documented in [webui-timeline-rows](./webui-timeline-rows.md), [webui-timeline-usage-timing](./webui-timeline-usage-timing.md), and [webui-timeline-thread-cards](./webui-timeline-thread-cards.md).

## Key Exports

- `ChatTimeline` — default export, the main timeline component
- `getMessageStableKey(msg, idx)` — shared helper in `chatViewportState.ts` that generates a stable React key for a message
- `getMessageViewportAnchorKey(message)` — returns a stable viewport identity for non-temporary committed rows
- `ImageParts` — renders safe raster inline data or authenticated blob URLs and exposes unsafe formats as download-only attachments
- `getToolCallSearchText` / `getToolResponseSearchText` — the text shown by expanded Tool argument/result renderers, including full results beyond the collapsed preview limit; pane-local Search consumes these helpers.

## Behavior

- Messages use the shared stable identity helper for React reconciliation, including request/segment identity for streamed and canonical model rows. Manual tool expansion is keyed by that message identity and call ID, with an ID-less index scoped only to its own message. The mounted Timeline owns these choices so pairing and group-surface remounts cannot discard them; a Session replacement resets them.
- Live `AssistantTextCard` subtrees are excluded from browser-native scroll-anchor selection while `message.__meta.streaming` is true. A growing answer or collapsed Conversation preview must not pull a detached native-wheel reader forward merely because the browser anchors to that changing Markdown subtree. Canonical cards return to ordinary native eligibility; the scroller, committed rows, follow latch, and manual-disclosure owner are unchanged.
- Top-level rows backed by stable committed-message metadata expose `data-chat-message-anchor-key`; nested CTX-BLOCK rows and temporary/synthetic stream rows do not become viewport anchors. `Chat` scopes anchor lookup to the committed timeline so queued previews cannot replace a saved session position.
- Counted tool groups retain one keyed content wrapper inside a neutral in-flow measurement slot, including the final forced-open tail run. Historical groups show one neutral Tool-style outer card with the same counted-tag header in collapsed and expanded states; the header and its own `ThreadLineButton` toggle the group. A group's row membership does not make all surfaces of that message group-card content: ordinary model text/system/images and thinking before its first text that belongs to the preceding group render as normal row surfaces outside the card, including while this group is collapsed. A text-bearing model message retains its previously visible hosted Web Search card outside too; a text-free grouped Web Search card remains inside. The group's own tool/result/Reasoning/Event surfaces nest below the header with a `pl-2` inset when expanded, without an independent rail or duplicate summary. Tail runs keep their direct member rows without a group header/collapse control; when they become historical the default collapse still unmounts untouched group-owned cards while ordinary surfaces remain mounted. Explicit tool/group choices remain Session-local across these render-tree changes; [manual disclosure contract](./webui-tool-timeline.md#d-webui-tool-group-collapse). Grouped passes the shared neutral-success presentation to both expanded members and direct tail tools; Detailed retains its success palette. ToolScript subcalls inherit their parent’s presentation. Detailed view leaves ordinary rows unchanged. The first group-row viewport/scrollbar anchor key stays on the stable content wrapper at the first visible surface without a duplicate child anchor; other visible member row keys/anchors remain on one corresponding surface, and nested CTX timelines never register top-level anchors.
- Synthetic streaming tool cards show the latest one-second partial argument preview. Valid accumulated JSON uses normal readable labels; incomplete/invalid JSON stays visible as raw text and never enters canonical message history.
- A Responses metadata-only completion row with `parts:[]` renders no invented assistant text/card body; its real usage/timing badge follows the ordinary model-row path. Multiple segments retain independent stable row keys. [Canonical contract](../threads/streaming-pipeline.md#d-streaming-early-commentary-commit).
- Collapsed Tool result/body rendering samples at most the first 800 source characters through one shared helper before applying the independent three-line visual clamp and conditional bottom fade. Expanded Tool results continue to render the complete response. This 800-character body bound does not change the separate 160/200-character one-line Tool call/header argument previews.
- `MessageRow` decides layout (user right-aligned, model left-aligned), retains Rendered/Raw choices and opens complete-message JSON in the [shared inspector](./webui-editor.md#d-editor-json-inspection), and conditionally shows copy buttons.
- Conversation replies remove bubble chrome and retain lightweight source/copy controls beneath the reply; their user bubble text uses the body size. Process previews and expanded commentary use the same prose style as final replies without changing their process ownership. Other modes retain their original card styling.
- Ordinary assistant cards use an 8px inset on all four sides, while direct-user cards use 12px horizontally and 8px vertically in every theme. Switching an assistant card between Rendered and Raw preserves its outer inset; JSON inspection leaves that card/body mounted and unchanged.
- Ordinary assistant/model Markdown uses typed output from the shared renderer so complete top-level multiline display LaTeX and exact-language Mermaid fences can render through the shared per-block UI. Nested tokens remain in their original Markdown ancestry. Model text parts carrying OpenAI Responses URL annotations render a visible, deduplicated clickable Sources row beneath the rendered text with symmetric `my-2` vertical spacing; Raw keeps the original text, and the JSON inspector exposes complete original message metadata. These local controls coexist with, rather than replace, the assistant card's Rendered/Raw choices and whole-message JSON/copy actions. The canonical parsing, static/network-free Mermaid safety, raw-source, and lazy-loading contract is [D-webui-assistant-special-blocks](./webui-chat-shared.md#d-webui-assistant-special-blocks).
- Streamed assistant Markdown and expanded Reasoning map stable top-level lexer tokens to memoized sanitized-HTML leaves. Unchanged earlier blocks therefore retain browser selection and DOM identity while the growing or semantically reinterpreted token remains free to update. Canonical contract: [D-webui-streaming-markdown-dom-stability](../threads/streaming-pipeline.md#d-webui-streaming-markdown-dom-stability).
- Image parts accept legacy inline data for tolerant rendering and current `inlineDataRef.apiPath` URLs. URL construction uses `makeApiUrl`, preserving deployment subpaths and same-origin authentication. PNG/JPEG/GIF/WebP render with lazy `<img>` loading; active/unsafe formats never enter an image context and use a download link, while load failures show an explicit unavailable state. A model turn whose only content is an image still renders its message row, because image parts are rendered independently of text-part visibility and no empty-text model message is dropped or collapsed; mixed text-plus-image rows keep text before images. Canonical contract: [image blob lifecycle](../threads/image-blob-lifecycle.md).
- Direct-user `<attachment-ref ref="attachmentN" />` markers correlate in presentation with ordinary appended `foxwarm-image`/`foxwarm-file` descriptors whose preserved filename is `attachmentN_${originalFileName}`. The generated prefix is hidden while all original filename underscores remain; duplicate original names stay distinct by number. For images, only the immediately adjacent existing image part is consumed in position and excluded from trailing `ImageParts`; its compact preview reuses the normal image open action with keyboard activation, unsupported-MIME download link, and unavailable-image fallback. Split marker/descriptor parts share an inline formatting context so short `A [attachment] B` bodies remain one line in optimistic and persisted rows, including file-only source-wrapped history. When an image-bearing direct-channel history row uses separate standalone source-wrapper opener and closer system parts, visible metadata receives one presentation-only whitespace-preserving line break after the opener and before the closer; unified multiline wrappers keep their own canonical delimiters, and hidden metadata receives neither boundary break nor phantom space. A prefixed descriptor is consumed only when a matching marker exists outside a complete pasted-text block; otherwise prefixed and unprefixed legacy descriptors/images retain baseline rendering. Complete pasted-text payloads are opaque to marker matching and descriptor suppression, so quoted markers/descriptors remain exact pasted content. The convention is presentation-only and does not add trusted metadata or backend schema.
- Direct-user raw text and lightweight structured-system parts preserve their authored newline sequence with explicit line-break text styled to the line it terminates. Ordinary/empty lines retain the full body line box, while visible lightweight XML metadata and attachment descriptor lines keep their compact font and line height. The console/550A treatment explicitly removes its inherited `!important` message line-height from these user line-layout `<pre>` elements so split persisted parts (`system` opening tag, text body, image descriptor, closing tag) do not regain a full body-height strut around every small row. Consecutive, leading, and trailing authored blank lines retain visual and DOM text semantics; hiding a lightweight metadata line removes only that line and its delimiter rather than adding a blank gap or collapsing adjacent authored blank lines. Model and heavy system-card spacing are unaffected.
- Complete exact non-nested `<pasted-text>...</pasted-text>` wrappers inside direct-user text parts and complete source-wrapped direct-channel user `system` parts use the presentation and authority boundary in [D-webui-user-pasted-text-display](./webui-pasted-text.md#d-webui-user-pasted-text-display). The latter follow the same user-content renderer even without attachment correlations; standalone structured-system parts retain their existing renderer. Timeline classification excludes valid pasted content from heavy-system and metadata decisions while preserving surrounding authored whitespace.
- User and assistant message surfaces expose semantic CSS hooks (`foxwarm-user-message-bubble`, `foxwarm-user-message-text`, `foxwarm-assistant-message-card`, `foxwarm-assistant-message-markdown`, `foxwarm-assistant-message-raw`) so opt-in UI style layers can restyle the timeline while preserving message grouping, Markdown sanitization, and view-mode behavior.
- Timeline rows/cards and nested assistant, Reasoning, and CTX-BLOCK flex surfaces use `min-width: 0`/bounded widths so intrinsic Markdown content cannot widen the message or viewport. Top-level desktop model/tool/system rows fill 80% of the timeline, while user messages remain content-sized up to 80%; mobile and nested model/tool/system rows fill their timeline, and nested user messages cap at 85%. The built-CSS contract fixture is `packages/webui/test/messageWidth.e2e.mjs`, including persisted-`user` heavy/non-channel and nested system-card cases. The native Chat message scroller alone owns the defensive horizontal clip; shrinkable inner message-content, committed/queued, shared-timeline, row, and card boundaries remain overflow-visible so intentional negative-left thread gutters and external desktop usage-badge paint are not clipped. Shared Markdown CSS breaks long prose tokens and wraps fenced code with preserved whitespace. Assistant/model GFM tables follow [D-webui-assistant-markdown-tables](#d-webui-assistant-markdown-tables); the actual-Chat fixture `packages/webui/test/timelineOverflowBoundary.e2e.mjs` verifies capped tables scroll locally without widening the document, while `packages/webui/test/messageOverflow.e2e.mjs` continues covering ordinary overflow containment.
- `Chat` treats a same-session SSE state change in committed `messageCount` or persisted `historyVersion` like a queue-length change and schedules the existing coalesced history refresh. This lets Worker/local state correct both appended and same-count rewritten history through an exact history GET without placing message bodies in the state event.
- In Detailed/Grouped, display-only LLM retry notices retain their existing system thread cards, but ChatTimeline has no inline Retry/Continue action. Continue belongs only to the parent runtime-status bubble under [D-pipeline-control-commands](../threads/message-processing-pipeline.md#d-pipeline-control-commands).

`workbenchPreview.e2e.mjs` exercises the built App in Conversation with version-2 text deltas for explicit `final_answer` replies and unknown-phase previews, without disclosure clicks. It records native-scroller frames during genuine upward wheel input and continued output, rejects reverse motion after leaving the tail, and checks attached growth, explicit rejoin, and detached downward reading. The regression reproduces native anchoring in Chromium and Firefox; it asserts no elapsed duration or exact frame count.

## Design Decisions

### D-webui-assistant-markdown-tables

[2026-10-09] Assistant/model GFM tables retain native semantic table markup and use a local scroll wrapper generated in the existing Marked token-rendering pipeline before sanitization. Automatic column sizing is capped at `max(outer Markdown content width, 800px)`, not forced to a minimum: short tables remain content-sized. Headers and cells wrap normally, with long URLs, paths, and inline code allowed to break rather than forcing a cell beyond the cap. The wrapper owns horizontal scrolling when the capped table is wider than the message content, so neither message layout nor page width grows. Ordinary/user Markdown, business tables, prose, and fenced-code behavior remain unchanged. Nested message/flex surfaces must remain shrinkable rather than relying on a final overflow-hiding ancestor.

### D-webui-timeline-overflow-boundary

- [2026-08-18] Horizontal overflow defense belongs to the native outer Chat message scroller, whose existing content padding provides intentional paint and hit-test room. Keep inner message-content, committed/queued, shared `ChatTimeline`, message-row, and thread-card boundaries shrinkable with `min-width:0`/bounded widths, but do not clip their overflow: the external negative-left card gutter must remain clickable and the final desktop model row's external usage badge must retain its lower shadow/paint. Intentionally scrollable Markdown tables continue to own their local horizontal scrolling, while a malformed oversized child is still unable to widen the document through the outer scroller's clip. The shared `ThreadLineButton` keeps its left placement and 2px visual line alignment, but its responsive hit width is exactly 2px narrower than before: 14px below `sm` and 18px at `sm` and above, removing only the card/text-side strip across Tool, Reasoning/Web Search, System, and CTX-BLOCK cards.
- [2026-07-22] Preserve the longstanding responsive message-width contract from the initial WebUI: top-level desktop model/tool/system messages are `w-full` with a real 80% maximum; desktop user messages use intrinsic width with an 80% maximum; mobile model/tool messages and nested model/tool/system messages are full-width; nested user messages cap at 85%. The dynamic `widthClass` is the sole owner of the direct message wrapper's maximum width. Generic containment utilities must not add an unconditional `max-w-full` to that same element: Tailwind emits `.max-w-full` after `.max-w-[80%]`, silently overriding the 80% rule. Keep `min-w-0` and full-width shrinkable containment on the wrapper/row/timeline; the native message scroller owns defensive clipping under [D-webui-timeline-overflow-boundary](#d-webui-timeline-overflow-boundary).
- [2026-09-06] Ordinary assistant bubbles use a theme-independent 8px outer inset. Direct-user bubbles use 12px horizontally and 8px vertically. The assistant inset belongs to the message card itself and remains identical across Rendered and Raw views; opening JSON does not change the card; thread-card families keep their separate spacing contracts.
- [2026-07-14] Viewport restoration anchors only actual rendered, top-level committed message rows with stable metadata. Nested archive previews, queued previews, and temporary/synthetic streaming rows are excluded from persisted-in-memory viewport identity.

## Integration

- Consumed by a parent chat view that passes the `messages` array and display preferences (`isMobile`, `timelineView`, `showUsageBadge`, `showUserMessageMetadata`).
- Also reused by Chat for render-only queued preview messages below runtime status; queued previews explicitly disable time dividers and never enter committed history. Nested CTX previews also have no time dividers, while the top-level committed timeline derives them independently of tool-group expansion.
- Requires the current `sessionId` prop for CTX-BLOCK expansion fetches: `GET /api/sessions/:sessionId/context-blocks/:blockId/expand`.
- Delegates tool rendering to `ToolTimelineItems` components which handle individual tool call/response display.
- Relies on `chatShared` for markdown rendering, link handling, and message classification utilities shared across the chat UI.

Conversation renders all ordered process fragments through one existing nested Detailed timeline, including original Task, Inter-agent, System/Event and Timer cards. It has no secondary step classification or disclosure wrapper. Process-only tool defaults and scoped subdued Reasoning styling do not change the main Detailed/Grouped views. Expanded preview text is shown only by its native prose surface, not duplicated below the process; its existing Search target and DOM alias resolve to that exact native message surface rather than another earlier part with the same index. The process statistics retain identical left/right type sizes and header geometry while usage details open below.
