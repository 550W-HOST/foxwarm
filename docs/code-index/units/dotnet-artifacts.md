## Contract and callers

The hidden, discoverable builtin uses the original Source schema and action distinctions. Direct, unified and native ToolScript calls converge on `SessionToolExecutor.ExecuteArtifactAsync`; only `prepare`/`publish` select a file-source Node. `get` reads Main metadata. Invocation-captured current Node/cwd selects the source; an explicit other source does not inherit that cwd. Generic artifact authorization and independent concrete Node read authorization both precede ingestion. Existing target-owned paths, Node admission, legacy exact isolated rules and physical Main source boundaries remain authoritative. No source path or artifact ID grants new authority.

Main regular-file ingestion rejects an oversized stat before reading, then consumes at most the limit plus one byte. Primitive source reads use the existing `TargetFileContent` adapter with the same per-consumer limit/request cap and original initial-stat byte-count equality. Resident sources share ToolScript's [approved complete-content or correlated-transfer reader](./external-node-files.md#authorization-and-path-contract), then apply the artifact byte limit. Complete programmatic manifest content is used without rereading; raster replies carry image data rather than complete text and still transfer original bytes. This is not a new streaming bound or approval bypass. JSON input is at most 2 MiB; raster input is at most 12 MiB. Images retain original bytes, never provider-image optimization output.

`ArtifactPreparer` passes data to one short-lived Node child. Shared validators remain the closed chart/React/image owners. The original Main-only raster inspector and actual virtual-source React compiler in `src/artifacts` serve both Source and managed data transports rather than being reimplemented or included in the Shared/CLI Node build. React has at most two active managed compiler children, 128 MiB V8 old space, a 15-second child lifetime and 3 MiB compiled output. The narrow stdin/stdout transport has bounded request/output data; generated authored JavaScript is never executed in Main or Node. The child has no tool, Session or source-file authority. Browser sandbox behavior remains owned by the original renderer, including explicit Run and its existing network/CPU limitations.

## Persistence and reads

`ArtifactStore.PublishAsync` validates, serializes updates per artifact, preserves exact owner/type, checks expected previous revision and publishes resources before an exclusive immutable revision file. The Source layout is `state/artifacts/art_<32 lowercase hex>/<revision>.json`, with `receipt`, `document`, `createdAt`, optional `compiled` and resource descriptors; original resource bytes are `resources/<sha256>`. Resource size/digest is verified on read. The digest is a persisted resource identity/integrity contract, not an extra delivery fingerprint. Temporary files are removed on failure. Interrupted publication can leave unreferenced resource bytes, as in Source; no recovery/GC subsystem is introduced.

`ReadAsync`, `ResourceAsync` and `LatestRevisionAsync` preserve pinned historical revisions and exact receipt ownership. Missing/corrupt history is unavailable, not replaced by latest content. Session aliases, identity moves and catalog canonicalization do not adopt or rewrite artifacts. Backups must include this store alongside original history; active compaction does not remove it. Cross-Session publication, alias migration and retention policies are not supplied.

Preparation returns `preparedArtifact` plus a marker without a tail card. Publication returns `artifact` plus a marker. Metadata lookup returns textual metadata and marker only. The existing canonical function-response JSON and ToolScript result/subcall path retain these fields naturally; no extra receipt bus or trusted event type is added. `send_file` stays separate.

The two deployment-relative GET routes are `/api/sessions/{id}/artifacts/{artifactId}/{revision}` and `/resources/{resource}` beneath it. Both use existing authentication, live scoped WebUI binding and the exact requested stored owner on every read. IDs/markers are not capabilities; no signed public download bypass exists. Artifact records serialize as authored JSON, not Message transport envelopes: valid chart columns such as `messageJson` or `type`/`mimeType`/`data` retain their exact scalar values. The record route writes the stored JSON directly; global Message/image projection remains in place for history, queue, debug and other existing transport consumers. Successful responses are private/no-store and nosniff. Raster resources allow only safe original MIME types and a restrictive CSP. Unavailable responses reveal no private paths.

## Delivery

`Delivery.targets` is the single collector. It carries exactly the three generated Main data helpers under `lib/artifacts` plus the existing Shared validators, resolves installed esbuild/sharp production dependencies and target-native packages, and preserves the actual WebUI React/ReactDOM resolver tree, including scheduler and its transitive runtime dependencies. Root React is not a substitute. The Desktop project passes its consuming RID to this same collector. Ordinary compilation can omit an unavailable target closure; complete publication, including transitive project-reference resource collection, rejects that omission. The collector never installs packages, uses host caches or silently substitutes a different-platform native executable. A complete payload is usable independently of source checkout/cwd; Node remains the trusted data-compiler runtime. Platform qualification requires the actual target payload/runtime, not just a C# build.
