## Purpose

In hosted mode nothing a tenant configures (model `baseUrl`, MCP servers, OAuth metadata, channel endpoints, redirects) may make a replica connect to an internal destination: the database, object storage, the mesh, cluster services or cloud metadata. Kubernetes NetworkPolicy can't tell the operator tenant from a hosted tenant on one replica, so the guard is in the application. File mode's outbound behavior doesn't change.

## D-egress-factory

**Approved plan P2 §7.1 (E13).**

- **One factory.** `EgressHttp` is the only constructor of outbound HTTP handlers, HTTP clients and WebSocket connections in the Main server: `Handler(policy, purpose, options)`, `Client(...)`, `PinnedHandler(...)` (addresses resolved and checked once by the caller, OAuth discovery and tokens), `WebSocket()` and `ConnectWebSocketAsync(...)`. `EgressHandlerOptions` carries what call sites set: redirects, cookies, the connect timeout, the proxy (file mode only) and the file-mode handler type.
- **Guarded handlers.** A `SocketsHttpHandler` with `UseProxy = false` (an environment proxy would otherwise carry the connection past the check) and a `ConnectCallback` that resolves the host itself, checks every address, and connects to a checked address without resolving again. One denied address refuses the connection, so a name can't mix a public and an internal answer. The callback runs for every new connection, so redirects and later lookups (rebinding) are checked each time. An IPv4-mapped address is connected as IPv4.
- **WebSockets.** A guarded policy always connects through a guarded invoker: the caller's invoker if it has one (Responses, ASR), otherwise one the factory builds and disposes after the handshake, as `ClientWebSocket`'s own connect does.
- **HTTP/3** would bypass the connect callback (QUIC); no site requests it and the source rule keeps it that way.
- **TLS stays offline.** On Linux, chain building fetches a missing intermediate from the certificate's AIA URL with the runtime's own HTTP client, outside the connect callback. Guarded handlers (ordinary, pinned and the WebSocket invoker) set an explicit `CertificateChainPolicy` that is SslStream's default (no revocation check, root excluded, system trust, server-authentication EKU) with `DisableCertificateDownloads`; host names are checked as before. A server that sends an incomplete chain then fails as `EgressCertificateException`: "Can't verify the TLS certificate of {host}: the server didn't send its full certificate chain, and this deployment doesn't download missing certificates." (approved, 2026-11-27). File mode keeps the runtime's TLS defaults.
- **Denial** is `EgressDeniedException` thrown from the connect callback, before any byte is sent, inside the caller's usual exception (`HttpRequestException`, `WebSocketException`, `McpOAuthException`). Its text (approved, 2026-11-27) is "Can't connect to {host}: its address is blocked by this deployment's network policy." and never names a resolved address. Callers whose errors carry an inner reason show it (`EgressFailure.Reason`): Setup's model list and model test, MCP connection errors, OAuth errors, channel status, text-redaction detection, model failures.
- **Refusals are final.** A model target the policy refused isn't retried and isn't counted against route health; a failover route moves to its next eligible target at once (`ModelAttemptFailure.PolicyRefusal`, `ModelRequestOwner`). The alternative must satisfy the redaction requirement as the refused leaf settled it, and a target that selection returns while refused (the all-ineligible fallback) ends the request with the refusal instead of being tried again. The Responses WebSocket handshake does the same. A channel reports the refusal once through channel health and stops reconnecting until it is reconfigured or the runtime restarts (Telegram and Weixin polling, Matrix sync and recovery, QQ Bot gateway, WeWork socket). Initial startup doesn't retry a refused start (`ManagedChannels.StartWithRetryAsync`), and Matrix fails its start on a refused versions request before scheduling the others; DNS failures, timeouts and server errors keep their startup retries. A refused Weixin reply is a sending failure and polling continues. A refused QQ Bot part upload keeps the refusal as its cause, without the presigned URL.

## D-egress-policy

**Approved plan P2 §7.1; operator semantics as below (EG proposal, 2026-11-27).**

- **Profiles.** `EgressPolicy.Unguarded` is file mode: every site builds exactly the handler it built before. `Hosted` denies the default internal set; `Operator` allows it. Both apply the deployment's `egress.deny` and their own allow exceptions. The policy is `RuntimeCapabilities.Egress`, fixed at runtime construction; `RuntimeCapabilities.Hosted` defaults to `Hosted` without deployment rules, and the hosted entry adds the deployment's.
- **Effective address space.** Rules and candidates compare as `EgressAddresses.Effective` gives them: an IPv4-mapped address as its IPv4 address, a scoped IPv6 address without its scope. A deployment rule inside `::ffff:0:0/96` becomes the IPv4 network it maps; a wider IPv6 rule stays IPv6.
- **Translations and tunnels.** A translation stands for the IPv4 host it carries; a tunnel reaches an IPv6 site through an IPv4 router, which is a different host.
  - *Well-known NAT64* (`64:ff9b::/96`, RFC 6052, last 32 bits) is a translation: its IPv4 peer is checked against the default set, `egress.deny` and the allow lists, so IPv6-only clusters keep NAT64 egress, `64:ff9b::a00:1` is 10.0.0.1, and an IPv4 exception covers the peer's NAT64 form.
  - *Local-use NAT64* (`64:ff9b:1::/48`, RFC 8215) leaves the prefix length and the place of any embedded address to the operator, so no IPv4 identity is derived from it: both guarded profiles deny the whole range. An operator running a translator there allows its prefix, giving up the IPv4 checks for it.
  - *6to4* (`2002::/16`, RFC 3056) is a tunnel: deny rules and the default set still see the router's IPv4 address (conservative), but an IPv4 exception never allows a `2002::/16` address; the site takes an IPv6 exception.
  - Teredo and ISATAP carry IPv6 inside IPv4 without translating the application's connection, so nothing is decoded; a deployment that routes such prefixes internally denies them.
- **Host exceptions** compare in the form they are resolved in (`EgressAddresses.HostKey`): IDNA ASCII and lower case, with the root label kept, for configured entries and connection hosts alike. `api.example.com.` is absolute; `api.example.com` and `mock-llm` are resolver-relative and go through the replica's search list. An exception matches only a host of the same form, and the guarded policy resolves exactly that form (`EgressPolicy.ResolveAsync`), so a relative exception can't authorize an absolute name's answers or the reverse. The root rule applies after IDNA conversion, so an ideographic full stop (U+3002) ends a name as a dot does.
- **Default deny set** (`EgressAddresses.IsInternal`): `0.0.0.0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16` (metadata included), `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, `224/3` (multicast, reserved, broadcast); `::/16` (unspecified, loopback and every IPv4-compatible form), `fc00::/7`, `fe80::/10`, `ff00::/8`. IPv4-mapped addresses are checked as the IPv4 address. It is the set `McpOAuthHttp` already used, now shared.
- **Deployment rules** (`egress` in the deployment configuration, `EgressRules`): `deny` adds CIDRs or addresses for both guarded profiles (cluster pods and services, the database, object storage, the mesh); `allow.hosted` and `allow.operator` list CIDRs, addresses or exact host names that profile may reach anyway. A host exception skips the address check for that name. Malformed entries refuse startup naming the entry.
- **Purposes.** `Model`, `Mcp`, `Channel` use the profile's rules. `Deployment` (the ASR service, which the deployment configures) uses the operator rules even in a hosted runtime.
- **OAuth** (`McpOAuthHttp.PinnedClientAsync`) checks the policy first, so a refused endpoint gets the denial text, then keeps its own rule (an unrelated private endpoint is refused unless same-origin or both loopback) with its earlier classification, without NAT64 or 6to4 decoding. In file mode its connector is the base one (`EgressHttp.FilePinnedConnectAsync`): a socket of each address's own family, the address unchanged, default socket options.
- **Channel clients' lifetime.** `ChannelHttpClients` belongs to the runtime. A Telegram polling loop holds it (`Hold`) until its closing offset sync ends, so runtime disposal neither cancels that admitted sync nor waits for it; the clients are disposed when the last hold ends.
- **Explicit policies.** Product constructors of outbound clients take the policy as a required parameter (`McpClient`, `McpOAuthService`, `AsrProxy`, `ResponsesWsTransport`, `ProviderHttpRequest.CreateClient`, `ConfiguredModelRequests.CreatePreparedService`/`CreateService`). `ModelRequestOwner` takes it too; its WebSocket transport carries the same runtime's policy. Channel adapters take the runtime's. Tests build owners through `TestModelOwners.Create`, which passes file mode's.

## D-tenant-limits

Plan P2 §7.2. A hosted tenant's limits are enforced at the admission points that already exist; where a point already queues, the limit queues too. File mode has no limits and every point admits as before.

- **Record and source.** `TenantLimits` (in `Limits/`, outside `Hosted/` because product code of both builds reads it) holds the defaults: hot-owner bytes 512 MiB, busy turns 8, ToolScript runs 2, 50 requests per second with bursts of 100, 64 WebSockets, uploads 100 MiB, blobs 10 GiB, resident Nodes 10, remote execs 8, MCP servers 16, channels 8, access identities 32, webhooks 16. The operator-owned `tenants.limits` column overrides keys of these names (positive whole numbers, sizes in bytes); a malformed one refuses the tenant's start naming the key; `agentStoreBytes`, `agentStoreFiles`, `agentFileBytes` and `dbStatements` set the Agent store and transaction limits. The [operator API](./hosted-operator.md#settings-and-placement) rejects unknown keys on writes. A runtime reading the column ignores keys it does not recognize. It is `RuntimeCapabilities.Limits`: null in file mode, the defaults in `RuntimeCapabilities.Hosted` and `RuntimeCapabilities.Operator` (§7.2 gives the operator profile no limit defaults of its own), and for either profile the tenant's own from the hosted entry (`TenantPolicy.ReadAsync` at activation, applied over `RuntimeCapabilities.For`). A change to the row retires the generation; the next activation uses the new limits.
- **State.** `TenantAdmission` is one runtime's admission state (slots, budgets, counters), owned by its `SessionManager` (`Admission`). `ReplicaLimits.Process` holds the replica's shares across runtimes: hot-owner bytes (70% of the memory the GC reports, which follows the container limit) and 32 ToolScript processes.
- **Hot-owner bytes** at owner admission (`SessionManager.LoadOwnerAsync`). An owner is estimated at 256 KiB plus ten times its history JSON (the sizing probe's ratio), re-estimated by the idle sweep outside its gate. A cold load reserves from the persisted history size (`ISessionAuthority.PersistedHistoryBytesAsync`: the segment rows' bytes, or the authority file's size) before it reads anything, then takes one of the tenant's four hydration slots, so waiting loads hold no history; concurrent lookups of one Session share its load. Over the tenant's budget, the load releases only the tenant's own least recently used idle owner (`IdleReleaseBlocker` null, whatever its quiet period); over only the replica's, the least recently used idle owner of any tenant. Releasing never blocks: when an idle sweep holds its gate, the sweep is the one releasing. Publication has a short, nonrenewable grace. Read-only lookups update victim order. Commands, tools and WebUI actions acquire the current owner before the first effect; WebUI body routes do so after reading the body. `SessionManager.OwnerUse` prevents idle retirement without changing deletion, moves or shutdown. SSE installs its subscriber while pinned; retirement also checks subscribers at its final fence. An effect already started is never replayed. The load then waits for room, looking again when a charge shrinks or ends, when a turn ends, and at least every second, checking its 30 s deadline and its cancellation on every pass, and fails with `TenantLimitException` (`hotOwnerBytes`). An owner alone in its budget is always admitted. A created Session is charged without waiting and releases idle owners while over; created and forked Sessions are this bounded exception to waiting. The charge becomes the resident owner's when it enters the registry and is returned only when the load or creation ended before that. Every removal of a resident owner (idle release, deletion, disposal) returns its charge; an identity move keeps it. Shutdown and composition rollback return the runtime's charges and unregister its releaser, including when a final save fails. Publication refunds a late creation charge if terminal cleanup has already closed admission. At startup a limited runtime defers required owners that do not fit, starts runnable processors once their prerequisites are ready, then tries each deferred owner once per pass and waits for capacity before the next pass. The next pass waits until the smallest rejected reservation fits or a deferred owner is already resident. A periodic eligibility check can notice expired publication grace or a disconnected subscriber without rereading the deferred catalog rows and sizes. A large blocked owner cannot starve a smaller one. Deferred exec-completion delivery runs after activation; the exec registry retains an undelivered completion for its next reconciliation.
- **Busy turns** before the busy claim (`SessionTurnRunner`, through `SessionRegistry.TurnAdmission`): a Session waiting for a slot stays not busy and keeps its queued input, and Stop and shutdown end the wait through the Session's cancellation registration. A waiting processor publishes its processing state as it enters admission, enabling the composer Stop button, slash command and public HTTP control. The slot is returned after the processor releases its claim. Standalone compaction from a user control or idle timer also takes a slot before claiming busy and returns it at settlement. A compaction initiated inside a turn's tool call shares that turn's slot until both settle. Closing ingress cancels only outstanding standalone admission waits. Standalone settlement returns the slot, busy claim and processor even when phase publication fails, and rechecks queued work after cancellation.
- **ToolScript runs**: each top-level run's Monty process (one per running segment) takes a tenant slot and then a replica slot (`MainToolScript.AdmitProcess`); a nested run uses its root's slot, which the root holds while it waits for the nested call. A tenant at its own limit holds no replica slot while it waits. The slot is returned even when the worker's disposal fails.
- **Requests and WebSockets** at owner admission: the first middleware after WebSocket negotiation in the tenant's pipeline (`RequestLimits`), so every route counts, whichever front or edge forwarded the request. A token bucket answers 429 with `Retry-After`; one WebSocket over the limit gets 429 before it is accepted.
- **Upload size**: the WebUI upload route takes the tenant's limit (1 GiB in file mode) and names it in its error, whether the request's declared length, the file or the streamed body passes it. The declared length and, in hosted mode, the streamed body may exceed the file limit by 1 MiB of multipart framing; the file itself is held to the exact limit, so a file just under it is never refused for its framing. A declared length past that is refused from the headers, before any body is read. In hosted mode the request body is limited as it streams, to the file limit plus 1 MiB of multipart overhead, whatever length it declares.
- **Unattached WebUI files.** Each hosted generation shares two multipart parser slots between WebUI attachments and configured HTTP speech transcription; each request body is bounded as above and its slot stays occupied through framework spool disposal. Before copying a parsed file, the generation reserves its size against twice its effective single-file limit. Small and empty files cost at least one 4 KiB block (or one single-file limit if smaller), bounding both bytes and entries. Refused admission returns HTTP 429. A failed creation releases its reservation even if cleanup fails. If a partial file was created, it stays charged until deletion succeeds; a cleanup failure schedules expiry. Consumption, revocation and 24-hour expiry release space after any open reader closes. The generation removes pending files on retirement and clears interrupted writes when a new generation opens the tenant’s directory. A move can therefore require the user to attach a file again. File-mode staging does not use these limits.
- **Blobs** at write admission of new images and artifacts (`BlobQuota.Store`, one per store, around the runtime's image and artifact stores and every Session authority's image writer: queue ingress, tool results, cold-load migration). Usage is measured once from the stores (`IBlobUsage`: the PostgreSQL rows' sizes or the S3 listing); a failed measurement fails the write as a storage error and the next write measures again. Each write reserves its bytes before it starts, against the measured usage plus what was added and is reserved since, and is charged once when it creates its content; a known duplicate or a known failed write returns the reservation. An unknown PostgreSQL COMMIT is charged and makes the baseline stale. An uncertain S3 create keeps a per-key charge until HEAD settles it, even if an intervening listing cannot see it yet; see [Hosted blobs](hosted-blobs.md). Concurrent creates of one key share the first write. An artifact reserves its new resource bytes and revision together; a revision reusing the same raster pays only for the manifest. Past 80% the operator log warns once; new content that would exceed the limit is refused (`blobBytes`), and a refused tool-result image becomes the tool's failure. Content already stored under its key needs neither new bytes nor a baseline measurement. Writes a commit needs and migrations of durable content run under `BlobQuota.AllowOverLimit`: admitted over the limit, and counted. Existence checks are asynchronous (`IBlobStore.ExistsAsync`), so admission never blocks a thread on S3 or PostgreSQL.
- **Nodes**: pairing (`ApprovedNodeRegistry.Create` and `Approve`) stops at the resident Node limit; Provider Nodes keep their per-grant quotas. The exec limit counts tool calls in flight to resident Nodes through Main (`NodeConnectionHub.ExecuteAsync`); a call takes its slot at dispatch, after a legacy batch edit has read its source, and calls over the limit queue.
- **Configuration counts** when the configuration is saved: MCP servers when one is added (`McpConfiguration.UpdateAsync`), channels, access identities (all of them) and webhook identities when the app configuration is validated for saving (`ModelConfiguration.RequireConfigurationCounts`), against the counts of the document the save replaces, read asynchronously under the save's serialization. A save may keep or lower a count already above its limit (an imported installation), but not raise it past the limit.
- **Errors** are `TenantLimitException`, an `InvalidOperationException` that names its key. Sizes in their texts are formatted by `TenantLimits.Size` (whole GiB or MiB when exact, otherwise one decimal). Texts (2026-11-27): upload "This file is larger than the {size} upload limit."; blobs "Images and artifacts have reached this installation's {size} storage limit.", and the operator log's warning "Images and artifacts use {used} of this installation's {size} storage limit."; MCP servers "This installation already has {max} MCP servers, the most it can have. Remove one before adding another.", and Nodes the same with "Nodes"; configuration counts "This installation can have at most {limit} {noun}; this configuration has {count}."; hot owners "Too many Sessions are active right now. Try again when one has finished."

## D-tenant-settings

- `TenantSettings` reads the operator-owned `tenants.settings` column's `journal` object: `enabled` (default true) and `retentionDays` (a positive whole number, or null for unlimited). Other keys are other owners'. The tenant's retention overrides the deployment's `journal.retentionDays`; without it the deployment's applies, and unset stays unlimited, as in P1 (decided 2026-11-27).
- **Journal off** (`PgLlmJournalStore.Recording`, behavior in [hosted journal](./hosted-journal.md)): requests get an ID and run as usual, no request content is written, the usage-ledger and redaction rows still are, and the wire diagnostics (`ModelInteractionDiagnostics`) write nothing for success or failure.
