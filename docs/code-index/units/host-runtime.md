# Unit: Host startup, configuration, and HTTP ingress

Files: `dotnet/Foxwarm/HostPaths.cs`, `dotnet/Foxwarm/TriggerHttp.cs`, `dotnet/Foxwarm/AssemblyInfo.cs`, `dotnet/Foxwarm/ConfigurationYaml.cs`, `dotnet/Foxwarm/HttpServer.cs`, `dotnet/Foxwarm/HttpServerSettings.cs`, `dotnet/Foxwarm/Program.cs`, `dotnet/Foxwarm/MainHost.cs`, `dotnet/Foxwarm.Desktop/Program.cs`, `dotnet/Foxwarm.Desktop/DesktopWindow.cs`, `dotnet/Foxwarm.Desktop/Foxwarm.Desktop.csproj`, `dotnet/Foxwarm.Desktop/README.md`, `dotnet/scripts/publish-desktop.sh`, `dotnet/Foxwarm/Skills.cs`

## Purpose

Composes the .NET executable, captures environment/configuration, builds ASP.NET middleware, and exposes health, auth, admin, WebUI, and Code entry points.

## Stable methods and callers

- `Program.cs` preserves the console/Code-helper entry and captures environment/settings. `MainHost.CreateAsync` shares the in-process Session/terminal/runtime/router/HTTP/WebUI composition with the Windows desktop; the console uses `MainHost.StartAsync` plus `MainHost.WaitForShutdownAsync` rather than ASP.NET `RunAsync`'s implicit disposal. Disposal closes admission and drains exact Session owners before stopping HTTP/terminals and disposing dependencies. The Desktop observer waits through the same shared host boundary.
- `Foxwarm.Desktop` is a framework-dependent `net10.0-windows`/`win-x64` WinForms host using WebView2 SDK 1.0.4258.31. It owns a per-user named mutex across login sessions (`NamedWaitHandleOptions` with `CurrentUserOnly=true`, `CurrentSessionOnly=false`), one window/tray, one embedded Main host and one WebView2 profile. Close hides; Open restores; Exit drains/disposes; Windows shutdown is not hide-to-tray.
- `HttpServer` owns prefix normalization, token/cookie auth, static WebUI entry, `/health`, `/admin/shutdown`, and registration of Code/WebUI/external Node routes.
- `HostPaths.Capture` selects a known installation base (`FOXWARM_APP_ROOT` or the executable directory), separately from binary resources. No shell-cwd or ancestor search selects state. Data precedence is `FOXWARM_DATA_DIR`, installation `data_dir`, then application root; retained explicit experiment-data selection remains readable. Data/pointer and configured paths resolve installation-relative with home expansion. App config is `FOXWARM_CONFIG_PATH`, then `CONFIG_PATH`, then selected `state/config.yaml`; explicit config paths resolve installation-relative. Models remain selected `state/models.yaml`. `ModelConfiguration.Paths` captures configured Agents/skills and `MCP_CONFIG_PATH` / `paths.mcpConfigPath` once for existing consumers. The ordinary policy workspace is the configured Agents directory.
- `HttpServerSettings.CaptureAsync` captures port 3001, bind `0.0.0.0`, WebUI and Trigger enabled by default, public address, and the existing administrator token when HTTP is needed. `FOXWARM_HTTP_PORT` / `FOXWARM_BIND_ADDRESS` provide explicit host overrides; existing experiment overrides remain for retained callers. `ConfigurationYaml` parses source-compatible YAML; `Skills` enumerates configured Agent skills.

## Contract and side effects

HTTP authorization happens before state-changing routes and static application content; `/api/auth` exchanges the administrator or a configured WebUI identity token for its role-preserving HttpOnly cookie. Public Node setup templates/source assets do not carry credentials; `/node_ws` uses its own approved Node credentials or pairing token, never the administrator cookie/token. Ordinary HTTP/WebUI requests are not restricted by their `Origin` header; the token and cookie are the login boundary. The token has no environment-variable override, and a blank or invalid token file fails startup without replacement. Request body limits, WebSocket keepalive, deployment-relative prefixes, and derived browser cookie behavior are host boundaries. ApplicationStopping and admin shutdown synchronously close Session admission; neither disposes executor, ToolScript, MCP, Node, WebSocket or shared writer dependencies. `MainHost` waits for Session drain before dependent teardown. A foreground drain timeout reaches cross-platform `Environment.FailFast`, terminating only Main without a process-tree kill or false successful drain. Before ASP.NET installs its console lifetime during start, external process termination retains its existing crash-like startup semantics. See [Main-local lifecycle shutdown](../threads/session-lifecycle.md#d-lifecycle-main-local-shutdown).

The .NET entry no longer requires experiment roots or disjoint authority/workspace trees. It does not switch the repository root launcher: `package.json` still builds/starts TypeScript Main. Agent metadata and retained physical-layout compatibility are owned by [the Session domain unit](./session-domain.md#agent-directories-and-retained-layouts).

HTTP is required by enabled WebUI, Trigger, or an access identity with an MCP surface. With all three disabled, Main uses the normal Generic Host lifetime without Kestrel/listener or administrator-token initialization; Session recovery, core and timers retain their owners. App saves still validate against the current existing token file without creating one. When HTTP exists, Node/MCP/OAuth surfaces remain independent of WebUI. `POST /trigger` is administrator-authenticated, accepts `{text, sessionId?}`, defaults to the existing `main` target, and returns Source success/error JSON. It does not create a missing Session. Runtime wraps a real Trigger event and uses the existing strict external save-lane admission; failure is not acknowledged as success. Application stopping fences admission before drain. ONBOOT file execution remains retired; old queued events remain readable.

The separate test container documented in `test/README.md` publishes this executable and the current WebUI through `test/Dockerfile` and `test/docker-compose.yml`. Its Linux x64 image includes native Monty with notices, built Shared/CLI Node archive inputs, tracked Code extensions, the PTY helper and local Git. Official Code workbench assets use an optional read-only Compose override; optional HEIF libraries are not installed. Host build outputs, state and workspace are excluded from the Docker context. This packaging does not switch the root launcher or expand the implementation's phase boundaries.

Resource signatures supplement administrator credentials only at explicitly marked file/global/Session-blob GET/HEAD endpoints. Global/path issuance and unrelated routes retain the administrator gate; see [WebUI file downloads](./dotnet-webui-files-images.md).

Protected `GET /api/auth/session` returns the role/features used by the original administrator or restricted WebUI root when WebUI is enabled. HTTP-enabled Main reserves the instance token before Session startup; the shared [access runtime](./dotnet-access-identities.md) validates configuration and selectively fences scoped HTTP/WS/SSE work. Independent Node, Code and OAuth capability paths retain their prior authority.

[Outbound MCP OAuth routes](./dotnet-mcp-oauth.md) use the same administrator boundary. Only exact GET `/api/mcp/oauth/client.json` and `/api/mcp/oauth/callback` bypass it. The fixed callback GET reflects no parameters and exchanges no code; its first-party authenticated JSON completion preserves Strict-cookie behavior after cross-site consent. OAuth callbacks derive from captured startup app `url`, not Host or the ordinary address fallback/override; deployment prefixes remain intact.

## Desktop boundary

`CaptureDesktopAsync` retains file-token validation, enables WebUI and selects IPv4 loopback independently of configured server port/bind/public URL. It reads the last successfully bound port from `state/desktop-port`, defaulting to zero. The desktop saves the actual successful port after startup so ordinary restarts retain the WebUI origin and browser preferences. Kestrel's normal socket factory first binds that remembered endpoint; only `AddressAlreadyInUse` retries the socket bind at port zero. This does not recreate Main, replay Session startup, probe/adopt the occupant, or migrate browser preferences across origins. The startup callback updates the shared public address before the desktop consumes it. Console port/public-prefix validation remains unchanged. The native host posts the token only to that owned endpoint's existing `/api/auth`, transfers the returned HttpOnly/Strict cookie into its owned WebView2, and never includes the token in navigation or arbitrary requests. Top-level external navigation/popups go to the default browser; off-origin HTTP resource loads are blocked. There is no host-object/message bridge.

Default desktop home is `%LOCALAPPDATA%\Foxwarm\Desktop`, with separate `data` (host authority and owned `webview2` profile) and `workspace` subdirectories; existing data/workspace overrides support isolated development. The ZIP contains the built original WebUI, managed/native Windows dependencies, templates and notices, not runtime/state/credentials. Desktop and ASP.NET Core .NET 10 x64 shared frameworks plus WebView2 Evergreen are required. The repository's Linux PTY target is skipped for Windows RIDs even when built on Linux.

Windows Main includes native PowerShell exec, ConPTY terminals/Code helper entry and the pinned ordinary native Monty worker; see their local-IO, terminal and ToolScript units. Optional official Code workbench/HEIF/external-service assets are not supplied. Vector dependencies follow the existing optional owner contract. The identity ledger retains flush-to-disk and atomic replacement on Windows; directory synchronization uses the pre-existing `Unsupported` result. Successful normal restart tests do not qualify power-loss durability.
