## Purpose

Composes the .NET executable, captures environment/configuration, builds ASP.NET middleware, and exposes health, auth, admin, WebUI, and Code entry points.

## Stable methods and callers

- `Program.cs` preserves the console/exec-helper/Code-helper entry and captures environment/settings. `MainHost.CreateAsync` shares the in-process Session/terminal/runtime/router/HTTP/WebUI composition with the Windows desktop and the [macOS host](./desktop-macos.md); the console uses `MainHost.StartAsync` plus `MainHost.WaitForShutdownAsync` rather than ASP.NET `RunAsync`'s implicit disposal. Normal post-listener channel startup is independent and retained by the managed channel owner, not awaited by Main's remaining startup lifecycle. ApplicationStopping synchronously closes channel publication and begins ingress stop; disposal joins the original initialization/retry cleanup before dependencies close. It does not abandon initialization or impose a new network deadline. Disposal closes admission and drains exact Session owners before stopping HTTP/terminals and disposing dependencies. The Desktop observer waits through the same shared host boundary.
- `Foxwarm.Desktop` is a `net10.0-windows10.0.19041.0`/`win-x64` WinUI 3 host using the Windows App SDK WinUI component 2.6.5 and WebView2 SDK 1.0.4258.31. It owns a per-user named mutex across login sessions (`NamedWaitHandleOptions` with `CurrentUserOnly=true`, `CurrentSessionOnly=false`), one window/tray, one embedded Main host and one WebView2 profile. Close hides; Open restores; Exit drains/disposes; Windows shutdown is not hide-to-tray. While the tray adapter is live, the registered `TaskbarCreated` message re-adds its icon after Explorer recreates the taskbar, preserving the previous NotifyIcon recovery behavior.
- `HttpServer` owns prefix normalization, token/cookie auth, static WebUI entry, `/health`, `/admin/shutdown`, and registration of Code/WebUI/external Node and webhook routes.
- `HostPaths.Capture` selects a known installation base (explicit launcher metadata or the executable directory), separately from binary resources. No shell-cwd or ancestor search selects state. Data precedence is `FOXWARM_DATA_DIR`, installation `data_dir`, then application root. Data/pointer and configured paths resolve installation-relative with home expansion. App config is always selected `state/config.yaml`; no app-config filename override participates. Models remain selected `state/models.yaml`. `ModelConfiguration.Paths` captures configured Agents/skills and `MCP_CONFIG_PATH` / `paths.mcpConfigPath` once for existing consumers. The ordinary policy workspace is the configured Agents directory.
- `HttpServerSettings.CaptureAsync` captures port 3001, bind `0.0.0.0`, WebUI and Trigger enabled by default, public address, and the existing administrator token when HTTP is needed. Port comes only from captured YAML `bot.httpPort` or the default, and the listen address only from `bot.httpHost` or the IPv4 wildcard default (2026-11-12). `HttpServerSettings.ListenAddress` accepts only an IPv4 or IPv6 literal in canonical form (no host names including `localhost`, abbreviated IPv4, zone IDs or brackets), so Kestrel binds exactly one socket without name resolution; an invalid value fails startup like an invalid port. Public address comes from captured YAML `url`, or else from the listener: `127.0.0.1` for a wildcard listener, the listen address itself (bracketed for IPv6) otherwise, so Code, OAuth callbacks and the runtime MCP endpoint stay reachable on a loopback or single-interface listener; Node bootstrap without a `url` keeps suggesting the browser's address. No environment port, bind or public-address override participates. Desktop ignores all three settings. `ConfigurationYaml` parses source-compatible YAML; `Skills` enumerates configured Agent skills.

## Contract and side effects

Main runs with workstation concurrent GC (`ServerGarbageCollection=false` in `Foxwarm.csproj`, overriding the Web SDK's Server GC default). Main is a long-lived, mostly I/O-bound single process; Server GC's per-core heaps and large gen0 budgets let transient allocation bursts commit several GiB before collection. The in-process Desktop host already uses the plain SDK's workstation default. Operators can still override the mode through standard .NET runtime configuration.

Configured Vector initialization is optional in both local and child placement; the [Vector owner](./vector-owner.md) retains the unavailable service without blocking unrelated Main startup. A failure is logged as an error; cancellation or unavailability while the Vector service is already stopping (Main shut down during its startup) is one informational line instead. Global Catalog/Archive/identity failures remain fatal; [Session-local recovery failures](./session-manager-bootstrap.md#local-recovery-failure-boundary) leave only their owners unavailable. The global boundary follows the [placement failure boundary](../threads/process-topology-and-rpc.md#vector-placement).

HTTP authorization happens before state-changing routes and static application content. `HttpServer.IsBrandAsset` restricts manifest/icon serving to exact bundled filenames under the WebUI resource directory, after authentication. Administrator and scoped WebUI identities can fetch these assets by GET; unrelated files remain inaccessible. StaticFiles supplies their MIME types and `Cache-Control: private, no-cache`. The manifest link sends credentials, and its start URL, scope and icons remain deployment-relative. Browser login follows [the frontend cookie ownership contract](./webui-login.md#d-login-cookie-ownership). Existing valid raw and derived administrator cookies remain accepted; scoped credentials resolve through the live access snapshot.

Public Node setup templates/source assets do not carry credentials; `/node_ws` uses its own approved Node credentials or pairing token, never the administrator cookie/token. Ordinary HTTP/WebUI requests are not restricted by their `Origin` header; the token and cookie are the login boundary. The token has no environment-variable override, and a blank or invalid token file fails startup without replacement. Request body limits, WebSocket keepalive, deployment-relative prefixes, and retained raw/derived cookie reads are host boundaries. ApplicationStopping and admin shutdown synchronously close Session admission; neither disposes executor, ToolScript, MCP, Node, WebSocket or shared writer dependencies. `MainHost` waits for Session drain before dependent teardown. A foreground drain timeout reaches cross-platform `Environment.FailFast`, terminating only Main without a process-tree kill or false successful drain. Before ASP.NET installs its console lifetime during start, external process termination retains its existing crash-like startup semantics. See [Main-local lifecycle shutdown](../threads/session-lifecycle.md#d-lifecycle-main-local-shutdown).

Normal Main does not read experiment instruction/data/workspace/skills/WebUI/Monty environment controls or the retired application-root environment setting. Agent memory, configured YAML paths and installed resources retain their ordinary owners. Explicit in-process workspace and binary constructor parameters remain available to their actual callers. The .NET entry does not require disjoint authority/workspace trees. The repository package/source controls now select it through the [managed Main entry](./source-main-entry.md); its foreground parent-stop and Windows background controls use the same ordinary host lifetime/drain. Explicit `--tui` fails before configuration/startup, and persisted `bot.enableTUI` logs an ignored diagnostic without blocking ordinary startup. Delivery resources and the C# model/archive entry are owned by [Core delivery and CLI](./core-delivery-cli.md). Agent metadata and retained physical-layout compatibility are owned by [the Session domain unit](./session-domain.md#agent-directories-and-retained-layouts).

HTTP is required by enabled WebUI, the legacy `bot.enableTrigger` listener flag (default true), or an access identity with an MCP or webhook surface. With all of them disabled, Main uses the normal Generic Host lifetime without Kestrel/listener or administrator-token initialization; Session recovery, core and timers retain their owners. App saves still validate against the current existing token file without creating one. When HTTP exists, Node/MCP/OAuth surfaces remain independent of WebUI. `POST /trigger` is administrator-authenticated, accepts `{text, sessionId?}`, defaults to the existing `main` target, and returns Source success/error JSON. It does not create a missing Session. Runtime wraps a real Trigger event and uses the existing strict external save-lane admission; failure is not acknowledged as success. Application stopping fences admission before drain. It is deprecated by [D-host-inbound-webhooks](#d-host-inbound-webhooks): still registered only while `bot.enableTrigger` is true, it adds an RFC 9745 `Deprecation` header and logs one process warning. It stays a deprecated alias for at least one release and until the user confirms its removal. ONBOOT file execution remains retired; old queued events remain readable.

The [shared production/test Docker recipe](./public-main-docker.md) publishes complete native Main through the existing resource graph; the native Linux release package is described in [release packages](./release-packages.md#native-linux-package). Its data, optional native/assets, stop/restart and platform boundaries are delivery-owned; image qualification does not promote public Main or adopt old native jobs.

Resource signatures supplement administrator credentials only at explicitly marked file/global/Session-blob GET/HEAD endpoints. Global/path issuance and unrelated routes retain the administrator gate; see [WebUI file downloads](./dotnet-webui-files-images.md).

Protected `GET /api/auth/session` returns the role/features used by the original administrator or restricted WebUI root when WebUI is enabled. HTTP-enabled Main reserves the instance token before Session startup; the shared [access runtime](./dotnet-access-identities.md) validates configuration and selectively fences scoped HTTP/WS/SSE work. Independent Node, Code and OAuth capability paths retain their prior authority.

[Outbound MCP OAuth routes](./dotnet-mcp-oauth.md) use the same administrator boundary. Only exact GET `/api/mcp/oauth/client.json` and `/api/mcp/oauth/callback` bypass it. The fixed callback GET ignores any accompanying Lax cookie, reflects no parameters and performs no flow mutation or code exchange. Its first-party authenticated JSON completion enforces request-origin and live-flow checks; legacy Strict-cookie clients still work when the initial cross-site GET omits the cookie. Inbound MCP uses its own Bearer-only principal and exposes no browser-cookie OAuth authorize/consent flow. OAuth callbacks derive from captured startup app `url`, not Host or the ordinary loopback address fallback; deployment prefixes remain intact.

After ordinary host/channel startup, `MainHost` schedules [date-directory log rotation](./dotnet-log-rotation.md) immediately and every ten hours over the selected logs root and real Agent exec roots; shutdown drains this owner before dependent disposal.

The actual console and Desktop entries opt into the shared Main-host-owned [file diagnostic producer](./dotnet-webui-logs.md). Its startup-captured destination also backs the existing administrator Logs route/topic; CLI/helper/Vector child protocol entries return before process Console capture. Normal host drain precedes its final stop record and disposal. Fatal Session construction, composition and host-start errors are recorded before capture is disposed; canonical Program preserves nonzero exit and safe stderr fallback for earlier configuration/logging failures. The fatal record retains stage, exception class and typed status rather than raw configuration or vendor text.

## HTTP response compression

`HttpServer` installs ASP.NET response compression after prefix normalization, routing and WebSocket detection, before authentication and static/endpoint responses. Native Brotli/gzip negotiation, `Vary`, MIME selection, existing `Content-Encoding` and `Content-Range` checks own encoding behavior. HTTPS compression is enabled without changing TLS termination or proxy trust. The MIME baseline is ASP.NET's compressible text/JSON/XML/JavaScript/CSS/HTML/WebAssembly set plus SVG; SSE is explicitly excluded. Compression streams without a whole-body threshold buffer and removes eligible bodies' original `Content-Length`.

`HttpResponseCompressionProvider.ShouldCompressResponse` applies response-purpose exclusions at the first write: existing `WebUiDownloadResource` metadata, final `Content-Disposition`, the existing exact public Node bootstrap predicate, `/mcp`, and WebSocket upgrades. Thus path/global/Session-blob transfers retain their bytes and known lengths for download progress, including previews and HEAD. Signing/issuance JSON remains eligible. Node scripts/templates and streamed `source.tar.gz` retain their existing output design; no archive total length is fabricated. Code's raw FS read remains octet-stream and unencoded through native MIME selection. Existing range handling is unchanged.

WebUI login (`SendFileAsync`), index and static assets, Code editor/extension text assets, ordinary APIs (including history/continuous history, debug-file inspection JSON, CTX, lists/settings/Tasks/Nodes, ASR status/transcription and Code metadata), artifact manifest JSON, health/Trigger and OAuth text/JSON responses share this rule. Compressed raster/media/archive/font payloads and the Shell transport's `application/x-foxwarm-shell` poll body are outside the MIME allowlist; Shell acknowledgements have no body. Artifact resources currently allow only safe raster. Session SSE, inbound MCP's SSE and JSON, and WebSocket frames remain uncompressed. Independent external-channel callback listeners and outbound HTTP clients do not use Main's middleware.

## Design decisions

### D-host-inbound-webhooks

**User-approved design (2026-11-08) for third-party inbound events.** External services (GitHub, Cloudflare, monitors) cannot hold the administrator token and do not post `{text}`; each source needs its own secret, scope and untrusted-input framing. Polling ToolScript timers remain the alternative when a source cannot push or the instance is not publicly reachable.

[2026-11-08] Each source is an `access.identities.<id>` entry declaring only `surfaces.webhook` with a fixed existing target `session`, `verify` (`github` HMAC-SHA256 of the raw body in `X-Hub-Signature-256`; `{header: <name>}` exact secret, e.g. Cloudflare `cf-webhook-auth`; or `bearer`) and optional GitHub `events`. `POST {prefix}/webhooks/{id}` bypasses administrator middleware for exactly that route shape, with the route's tolerance for the letter case of `webhooks` and one trailing slash (the identity ID is matched exactly), and never accepts the instance token or cookie. Unknown identities and every request that is not verified get the same 401 before any other answer, so the status does not reveal which IDs exist or how they verify. Header/Bearer secrets are checked before the body is read. A GitHub body must be read before its HMAC can be checked, so that unauthenticated buffering is bounded: a missing or malformed `X-Hub-Signature-256` is refused unread, a declared body over 1 MiB is refused unread, at most 8 unverified reads per identity and 32 overall run at once, and any body read stops after 10 seconds (GitHub's own timeout) and drops the connection. An oversized or late GitHub body cannot be verified and therefore gets the same 401; verified Header/Bearer senders get 413 or 408. Verified GitHub `ping` and events outside `events` return 200 without delivery and before the rate limit. Every other verified request consumes a fixed per-identity token bucket (burst 60, 10 per minute; 429 with `Retry-After`) because GitHub does not retry and event allowlists are the volume control. Bodies must be UTF-8 JSON or text (415), non-empty, and valid when declared JSON. The target resolves through catalog aliases and is never created; an unavailable target or closed admission returns 503.

A delivery is a `Trigger` queue item admitted through strict external save-lane admission, answered 202 only after commit. GitHub `X-GitHub-Delivery` receipts (`<identity>/<delivery>`) live in their own bounded Session meta key, newest 64, separate from remote-exec completion receipts; a repeat returns 200 `duplicate` without queueing. The frame reuses `foxwarm-system kind="external-input"` with escaped `webhook`, optional `event`/`action`/`deliveryId`, time and hint in a system part, the payload as its own text part (first 64 KiB on a UTF-8 scalar boundary plus a server-owned truncation notice part, with framing look-alikes neutralized by the shared [`SessionBoundary.ExternalInput`](./session-domain.md#d-session-external-framing-lookalikes)), and a closing system part. A delivery grants no tool, read, reply or Session-creation authority; the receiving Session acts under its own policy. Requests cannot choose another target. Models cannot create webhook identities: `set_config` (the model-reachable config writer) refuses a candidate that adds a webhook identity or changes an existing one's token or surface, compared with the saved file, while keeping or removing one is allowed; Setup saves and direct file edits remain the user's way to configure webhooks. The administrator `/trigger` route remains a deprecated alias for at least one release and until the user confirms its removal; `bot.enableTrigger` keeps its listener meaning until a later decision. The CLI Node local trigger is a separate loopback mechanism and is unchanged.

[2026-11-08, phase 2] `wake: false` (message action only) admits the same delivery as passive queued input: it is saved and read with the Session's next turn but does not start a turn or end a wait, for sources that only need to be seen eventually. Because nothing consumes that backlog until the next turn, admission counts the webhook's unread passive items in the target queue under the save-lane gate (so the bound survives restarts): beyond 32 items or 256 KiB of payload text a delivery is admitted with its metadata and a server-owned payload-omitted notice instead of its payload, since GitHub does not retry a refusal (the replacement keeps the passive wake marker that ingress set, so it neither starts a turn that would read the backlog early nor escapes the count); at 1,000 unread items further passive deliveries get 429 and are counted, not listed. `action: toolscript` with `script` (`code` or `filePath`, optional `node`, `args`, `timeoutSecs`) instead runs an unattended owner-bound ToolScript in the target Session through the same dispatcher as ToolScript timers: no model request, history append or automatic notification; the script decides what to report. `mode` is not accepted, so a run is always a foreground slice, and `args.webhook` is reserved for `{id, event, action, deliveryId, receivedAt, contentType, payload}`, where `payload` is the parsed JSON value or the text. Runs are serialized per identity in a FIFO bounded at 32 waiting deliveries (429 `Retry-After: 60` when full), so a burst cannot start concurrent handlers; 202 means queued, not run. A waiting run rechecks that the identity's configuration is unchanged and otherwise fails. Handler runs are not Session queue items, so their GitHub receipts (newest 64) and waiting runs are process memory: shutdown fails runs that have not started, and a delivery redelivered after a restart runs again. A failed run releases its receipt, because manual redelivery is GitHub's only retry; queued, running, completed and paused runs keep it.

`WebhookActivity` keeps per-identity diagnostics in process memory: the newest 20 verified deliveries with outcome, HTTP status, event/action/delivery ID, Session and handler run ID/error, plus the count and time of failed verifications, which are never listed individually. Administrator `GET /api/webhooks` projects configured webhook identities with their public URL, target resolution, verification kind, events, action and script summary, never secrets or script `args`; `GET /api/webhooks/{id}/runs/{runId}` returns a handler run record only when that identity's history references it. Changes raise the realtime `webhooks-changed` notice, coalesced to at most one per second; requests that fail verification only update the counter and raise none, so unauthenticated traffic does not reach administrator clients. This is status for System › Webhooks, not an audit log, and it resets on restart. Session manager shutdown drains handler lanes after the timer scheduler and before ToolScript closes.
