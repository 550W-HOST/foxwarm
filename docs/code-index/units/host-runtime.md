# Unit: Host startup, configuration, and HTTP ingress

Files: `dotnet/Foxwarm/HostPaths.cs`, `dotnet/Foxwarm/TriggerHttp.cs`, `dotnet/Foxwarm/AssemblyInfo.cs`, `dotnet/Foxwarm/ConfigurationYaml.cs`, `dotnet/Foxwarm/HttpServer.cs`, `dotnet/Foxwarm/HttpResponseCompressionProvider.cs`, `dotnet/Foxwarm/HttpServerSettings.cs`, `dotnet/Foxwarm/Program.cs`, `dotnet/Foxwarm/MainHost.cs`, `dotnet/Foxwarm.Desktop/Program.cs`, `dotnet/Foxwarm.Desktop/DesktopWindow.cs`, `dotnet/Foxwarm.Desktop/Foxwarm.Desktop.csproj`, `dotnet/Foxwarm.Desktop/README.md`, `dotnet/scripts/publish-desktop.sh`, `dotnet/Foxwarm/Skills.cs`, `dotnet/Foxwarm.Tests/Channels/WebUiStartupTests.ResourcePaths.cs`, `dotnet/Foxwarm.Tests/Channels/WebUiStartupTests.HttpCompression.cs`, `dotnet/Foxwarm.Tests/Channels/HttpCompressionTests.cs`

## Purpose

Composes the .NET executable, captures environment/configuration, builds ASP.NET middleware, and exposes health, auth, admin, WebUI, and Code entry points.

## Stable methods and callers

- `Program.cs` preserves the console/exec-helper/Code-helper entry and captures environment/settings. `MainHost.CreateAsync` shares the in-process Session/terminal/runtime/router/HTTP/WebUI composition with the Windows desktop; the console uses `MainHost.StartAsync` plus `MainHost.WaitForShutdownAsync` rather than ASP.NET `RunAsync`'s implicit disposal. Normal post-listener channel startup is independent and retained by the managed channel owner, not awaited by Main's remaining startup lifecycle. ApplicationStopping synchronously closes channel publication and begins ingress stop; disposal joins the original initialization/retry cleanup before dependencies close. It does not abandon initialization or impose a new network deadline. Disposal closes admission and drains exact Session owners before stopping HTTP/terminals and disposing dependencies. The Desktop observer waits through the same shared host boundary.
- `Foxwarm.Desktop` is a framework-dependent `net10.0-windows`/`win-x64` WinForms host using WebView2 SDK 1.0.4258.31. It owns a per-user named mutex across login sessions (`NamedWaitHandleOptions` with `CurrentUserOnly=true`, `CurrentSessionOnly=false`), one window/tray, one embedded Main host and one WebView2 profile. Close hides; Open restores; Exit drains/disposes; Windows shutdown is not hide-to-tray.
- `HttpServer` owns prefix normalization, token/cookie auth, static WebUI entry, `/health`, `/admin/shutdown`, and registration of Code/WebUI/external Node routes.
- `HostPaths.Capture` selects a known installation base (explicit launcher metadata or the executable directory), separately from binary resources. No shell-cwd or ancestor search selects state. Data precedence is `FOXWARM_DATA_DIR`, installation `data_dir`, then application root. Data/pointer and configured paths resolve installation-relative with home expansion. App config is always selected `state/config.yaml`; no app-config filename override participates. Models remain selected `state/models.yaml`. `ModelConfiguration.Paths` captures configured Agents/skills and `MCP_CONFIG_PATH` / `paths.mcpConfigPath` once for existing consumers. The ordinary policy workspace is the configured Agents directory.
- `HttpServerSettings.CaptureAsync` captures port 3001, bind `0.0.0.0`, WebUI and Trigger enabled by default, public address, and the existing administrator token when HTTP is needed. Port comes only from captured YAML `bot.httpPort` or the default; ordinary Main always binds IPv4 wildcard. Public address comes from captured YAML `url` or the loopback fallback. No environment port, bind or public-address override participates. `ConfigurationYaml` parses source-compatible YAML; `Skills` enumerates configured Agent skills.

## Contract and side effects

Configured Vector initialization is optional in both local and child placement; the [Vector owner](./vector-owner.md) retains the unavailable service without blocking unrelated Main startup. Authoritative Catalog/Archive load and migrations remain fatal under the [placement failure boundary](../threads/process-topology-and-rpc.md#vector-placement).

HTTP authorization happens before state-changing routes and static application content. Browser login follows [the frontend cookie ownership contract](./webui-login.md#d-login-cookie-ownership). Existing valid raw and derived administrator cookies remain accepted; scoped credentials resolve through the live access snapshot.

Public Node setup templates/source assets do not carry credentials; `/node_ws` uses its own approved Node credentials or pairing token, never the administrator cookie/token. Ordinary HTTP/WebUI requests are not restricted by their `Origin` header; the token and cookie are the login boundary. The token has no environment-variable override, and a blank or invalid token file fails startup without replacement. Request body limits, WebSocket keepalive, deployment-relative prefixes, and retained raw/derived cookie reads are host boundaries. ApplicationStopping and admin shutdown synchronously close Session admission; neither disposes executor, ToolScript, MCP, Node, WebSocket or shared writer dependencies. `MainHost` waits for Session drain before dependent teardown. A foreground drain timeout reaches cross-platform `Environment.FailFast`, terminating only Main without a process-tree kill or false successful drain. Before ASP.NET installs its console lifetime during start, external process termination retains its existing crash-like startup semantics. See [Main-local lifecycle shutdown](../threads/session-lifecycle.md#d-lifecycle-main-local-shutdown).

Normal Main does not read experiment instruction/data/workspace/skills/WebUI/Monty environment controls or the retired application-root environment setting. Agent memory, configured YAML paths and installed resources retain their ordinary owners. Explicit in-process workspace and binary constructor parameters remain available to their actual callers. The .NET entry does not require disjoint authority/workspace trees. The repository package/source controls now select it through the [managed Main entry](./source-main-entry.md); its foreground parent-stop and Windows background controls use the same ordinary host lifetime/drain. Explicit `--tui` fails before configuration/startup, and persisted `bot.enableTUI` logs an ignored diagnostic without blocking ordinary startup. Delivery resources and the C# model/archive entry are owned by [Core delivery and CLI](./core-delivery-cli.md). Agent metadata and retained physical-layout compatibility are owned by [the Session domain unit](./session-domain.md#agent-directories-and-retained-layouts).

HTTP is required by enabled WebUI, Trigger, or an access identity with an MCP surface. With all three disabled, Main uses the normal Generic Host lifetime without Kestrel/listener or administrator-token initialization; Session recovery, core and timers retain their owners. App saves still validate against the current existing token file without creating one. When HTTP exists, Node/MCP/OAuth surfaces remain independent of WebUI. `POST /trigger` is administrator-authenticated, accepts `{text, sessionId?}`, defaults to the existing `main` target, and returns Source success/error JSON. It does not create a missing Session. Runtime wraps a real Trigger event and uses the existing strict external save-lane admission; failure is not acknowledged as success. Application stopping fences admission before drain. ONBOOT file execution remains retired; old queued events remain readable.

The [shared production/test Docker recipe](./public-main-docker.md) publishes complete managed Main through the existing resource graph. Its data, optional native/assets, stop/restart and platform boundaries are delivery-owned; image qualification does not promote public Main or adopt old native jobs.

Resource signatures supplement administrator credentials only at explicitly marked file/global/Session-blob GET/HEAD endpoints. Global/path issuance and unrelated routes retain the administrator gate; see [WebUI file downloads](./dotnet-webui-files-images.md).

Protected `GET /api/auth/session` returns the role/features used by the original administrator or restricted WebUI root when WebUI is enabled. HTTP-enabled Main reserves the instance token before Session startup; the shared [access runtime](./dotnet-access-identities.md) validates configuration and selectively fences scoped HTTP/WS/SSE work. Independent Node, Code and OAuth capability paths retain their prior authority.

[Outbound MCP OAuth routes](./dotnet-mcp-oauth.md) use the same administrator boundary. Only exact GET `/api/mcp/oauth/client.json` and `/api/mcp/oauth/callback` bypass it. The fixed callback GET reflects no parameters and exchanges no code; its first-party authenticated JSON completion preserves Strict-cookie behavior after cross-site consent. OAuth callbacks derive from captured startup app `url`, not Host or the ordinary loopback address fallback; deployment prefixes remain intact.

After ordinary host/channel startup, `MainHost` schedules [date-directory log rotation](./dotnet-log-rotation.md) immediately and every ten hours over the selected logs root and real Agent exec roots; shutdown drains this owner before dependent disposal.

The actual console and Desktop entries opt into the shared Main-host-owned [file diagnostic producer](./dotnet-webui-logs.md). Its startup-captured destination also backs the existing administrator Logs route/topic; CLI/helper/Vector child protocol entries return before process Console capture. Normal host drain precedes its final stop record and disposal. Fatal Session construction, composition and host-start errors are recorded before capture is disposed; canonical Program preserves nonzero exit and safe stderr fallback for earlier configuration/logging failures. The fatal record retains stage, exception class and typed status rather than raw configuration or vendor text.

## HTTP response compression

`HttpServer` installs ASP.NET response compression after prefix normalization, routing and WebSocket detection, before authentication and static/endpoint responses. Native Brotli/gzip negotiation, `Vary`, MIME selection, existing `Content-Encoding` and `Content-Range` checks own encoding behavior. HTTPS compression is enabled without changing TLS termination or proxy trust. The MIME baseline is ASP.NET's compressible text/JSON/XML/JavaScript/CSS/HTML/WebAssembly set plus SVG; SSE is explicitly excluded. Compression streams without a whole-body threshold buffer and removes eligible bodies' original `Content-Length`.

`HttpResponseCompressionProvider.ShouldCompressResponse` applies response-purpose exclusions at the first write: existing `WebUiDownloadResource` metadata, final `Content-Disposition`, the existing exact public Node bootstrap predicate, `/mcp`, and WebSocket upgrades. Thus path/global/Session-blob transfers retain their bytes and known lengths for download progress, including previews and HEAD. Signing/issuance JSON remains eligible. Node scripts/templates and streamed `source.tar.gz` retain their existing output design; no archive total length is fabricated. Code's raw FS read remains octet-stream and unencoded through native MIME selection. Existing range handling is unchanged.

WebUI login (`SendFileAsync`), index and static assets, Code editor/extension text assets, ordinary APIs (including history/continuous history, debug-file inspection JSON, CTX, lists/settings/Tasks/Nodes, ASR status/transcription and Code metadata), artifact manifest JSON, health/Trigger and OAuth text/JSON responses share this rule. Compressed raster/media/archive/font payloads and the Shell transport's `application/x-foxwarm-shell` poll body are outside the MIME allowlist; Shell acknowledgements have no body. Artifact resources currently allow only safe raster. Session SSE, inbound MCP's SSE and JSON, and WebSocket frames remain uncompressed. Independent external-channel callback listeners and outbound HTTP clients do not use Main's middleware.

## Desktop boundary

`CaptureDesktopAsync` retains file-token validation, enables WebUI and selects IPv4 loopback independently of configured server port/bind/public URL. It reads the last successfully bound port from `state/desktop-port`, defaulting to zero. The desktop saves the actual successful port after startup so ordinary restarts retain the WebUI origin and browser preferences. Kestrel's normal socket factory first binds that remembered endpoint; only `AddressAlreadyInUse` retries the socket bind at port zero. This does not recreate Main, replay Session startup, probe/adopt the occupant, or migrate browser preferences across origins. The startup callback updates the shared public address before the desktop consumes it. Console port/public-prefix validation remains unchanged. The native host posts the token only to that owned endpoint's existing `/api/auth`, then creates an HttpOnly/Strict cookie directly through its owned WebView2 CookieManager, scoped to that actual local endpoint with a 365-day UTC expiry and Secure only for HTTPS, and never includes the token in navigation or arbitrary requests. Top-level external navigation/popups go to the default browser; off-origin HTTP resource loads are blocked. There is no host-object/message bridge.

Default desktop home is `%LOCALAPPDATA%\Foxwarm\Desktop`, with separate `data` (host authority and owned `webview2` profile) and `workspace` subdirectories; an explicit data directory keeps its default sibling workspace for isolated development. The ZIP consumes Core's shared resource graph (`webui-dist`, skills, templates, Node and extension resources, native dependencies/notices), not runtime/state/credentials. Core-only CLI scripts/package metadata and its console apphost/runtimeconfig are omitted. Desktop and ASP.NET Core .NET 10 x64 shared frameworks plus WebView2 Evergreen are required. The repository's Linux PTY target is skipped for Windows RIDs even when built on Linux.

Windows Main includes native PowerShell exec, ConPTY terminals/Code helper entry and the pinned ordinary native Monty worker; see their local-IO, terminal and ToolScript units. Optional official Code workbench/HEIF/external-service assets are not supplied. Vector dependencies follow the existing optional owner contract. The identity ledger retains flush-to-disk and atomic replacement on Windows; directory synchronization uses the pre-existing `Unsupported` result. Successful normal restart tests do not qualify power-loss durability.

## Managed external channels

`MainHost` initializes the shared channel path, launches managed Telegram, Matrix, Weixin, WeWork and QQ instances independently after the host starts (see the [initial-start policy](./dotnet-external-channels.md#stable-symbols-and-callers)), stops ingress with each adapter's Source lifetime (Telegram/Matrix abort without handler joins; WeWork closes its separately configured callback/socket admission without joining Router/send handlers; Weixin joins its uncancelled current fetch/backoff/handler loop), and retains transport dependencies until accepted Session owners settle. The configuration installation lane returns real reload-all and per-instance partial outcomes to Setup and `set_config`; unchanged managed entries restart, WebUI/temporary MCP registrations survive, and unimplemented adapters remain explicitly unavailable rather than receiving a misleading restart recommendation. Startup-captured WebUI settings still require a restart. Channel section saves preserve string identities and numeric progress settings, and also accept the complete JSON-as-YAML app document already supported by full saves. See [external channels](./dotnet-external-channels.md).
