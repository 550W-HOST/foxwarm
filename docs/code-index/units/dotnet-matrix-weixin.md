## Purpose and callers

Implements the used unencrypted Matrix transport and Source Weixin text/login subset through [shared external channels](./dotnet-external-channels.md). `ManagedChannels` creates these adapters under the existing instance registry; both enter the generic Router, not Telegram's separate command hook. The Session, authorization, file/image, Node, attachment and automatic-delivery owners remain shared. WeWork, QQ and Main TUI remain separate unimplemented adapters.

## Stable symbols and wire contracts

- `MatrixChannel.StartAsync` follows the pinned `matrix-js-sdk` 41.0.0-rc.0 bootstrap used by the reference adapter: authenticated versions, background push rules/filter/sync and capabilities. The initial inline filter limits the timeline to ten; later requests use the created filter ID and transient `next_batch`. Feature selection uses the SDK's exact version-list/unstable-feature tests, not numeric version inference. Sync requests retain the state-after query and zero initial/catch-up versus 30-second normal polling timeout. Their local request budget is the query timeout plus 80 seconds (80 or 110 seconds); ordinary requests and uploads add no local deadline and retain caller cancellation. The default transport has no implicit HttpClient deadline. Unknown-token sync failures stop the loop; other failures use unauthenticated versions keepalives.
- `ProcessRoomState` autojoins bot invitations, retaining membership transitions per room. It also retains known empty-state-key `m.room.encryption` events from sync room state, state-after, invite state and timeline. Normal message sends refuse known encrypted rooms without a crypto backend, before entering the send scheduler; unknown and known unencrypted rooms remain sendable. No encryption lookup, E2EE or verification is added. `ProcessTimelineAsync` rejects backfill, wrong event type, own messages, timestamps older than adapter construction, duplicates in its capped 1,000-ID set and missing senders. Room, actual sender MXID and configured instance remain distinct. Only `m.text`, `m.image` and `m.file` enter ordinary User routing. No cursor or dedup set is persisted.
- `MediaUri` preserves the pinned SDK's default MXC validation and unauthenticated `/_matrix/media/v3/download/<server>/<id>` URL, even when the server advertises v1.11. Non-MXC/direct URLs are rejected and download requests carry no adapter token. This is not authenticated-media qualification or a protocol modernization. Media remains eager before Router authorization and calls the storage helper with the type `matrix`, not its named instance. Images use the canonical image owner; `m.file` remains a file even when its MIME is an image.
- `SendEventAsync` serializes message sends with stable per-message transaction IDs across attempts. Its used SDK retry contract retains four backoffs for eligible HTTP failures (2/4/8/16 seconds), stable transaction identity and queued-successor failure propagation. Server Retry-After applies only to SDK-classified rate limits: `M_LIMIT_EXCEEDED`, or HTTP 429 with missing/`M_UNKNOWN` code. The deprecated body retry delay applies only to `M_LIMIT_EXCEEDED`; ordinary server errors ignore either recommendation. Network/abort and ordinary client errors do not gain speculative retries. `SendTextAsync` adds the small Source bold/italic/code/newline conversion only for Markdown options: intermediate model text requests Markdown, while final text, direct text tools and command replies do not. File captions precede upload; upload uses the raw bytes, filename query and MIME, followed by the returned content URI plus filename/MIME/size. The shared event refusal retains that actual ordering: a refused caption prevents upload, while an uncaptioned file uploads before its event is refused. Typing sends true/3,000 milliseconds and remains best-effort.
- `WeixinApi.UpdatesAsync`/`SendAsync`/`SendTypingAsync` preserve the ilink routes, optional Bearer, route tag, AuthorizationType, Base64 decimal unsigned-32 UIN, UTF-8 byte length and `base_info` using `ProductVersion`. Poll timeout becomes an empty response with the previous cursor. Text sends check HTTP success, not a newly invented response-envelope success condition.
- `WeixinChannel.PollAsync` retains transient cursor, sequential awaited inbound handlers, two-second first/second failure and 30-second subsequent backoff. A `-14` expiry is logged/thrown inside the loop and caught there; it is not a fatal process exit. Stop sets only the outer-loop flag and joins that loop; it does not cancel the current fetch or backoff. The allocated-but-never-populated reference typing-ticket path remains an automatic no-op, not a new ticket-fetch feature. There is no binary media send/download or ASR implementation.
- `WeixinInbound.Parts` selects the first text or voice transcription, preserves the actual quoted-text rules and exact unsupported-media placeholders. These strings are ordinary untrusted User content. `WeixinApi.CacheContext` runs before Router authorization and shares a per-user map across configured instances and reloads for one Main lifetime. It is neither instance-keyed nor persisted; fresh Main requires inbound context again, and missing context fails explicitly.
- `StartLoginAsync`/`WaitLoginAsync` own in-memory five-minute QR sessions, fresh-key reuse/force, default bot type/base URL, optional route tag, 35-second status fetches, `scaned` wire spelling, confirmation token/owner/returned base URL, expiration and caller deadline behavior. A short caller deadline does not abort a status fetch already in progress. Login state is not a persistent recovery service.

## Configuration, Setup and lifecycle ordering

The actual authenticated, deployment-prefixed `/api/setup/weixin/login/start` and `/wait` routes reuse the existing HTTP/Setup access owner. Anonymous and scoped identities cannot start a login. Setup selects the first configured Weixin entry unless explicitly given a channel ID; the command selects the type-named default before the first matching entry.

`SaveWeixinLoginAsync` reuses the existing configuration validation, section builder and atomic writer. Setup merges the confirmed owner into the latest allowed-user list and uses the normal serialized installer/reload-all path. Command confirmation preserves the list, saves enabled/token/base/route fields and restarts only its selected adapter. Its Source direct-save/selected-restart caller does not acquire the Setup save-plus-apply lane: doing so would create a new cycle when Setup is joining the command's Weixin handler. Both paths use `PersistAppAsync` in this same owner, which orders app candidate read/merge, validation and atomic replacement across Setup, native `set_config`, whole/section app saves and command confirmation. This prevents concurrent disjoint successful logins from overwriting one another. The persistence section is released before access publication, listener cleanup or runtime reload/restart waits. Command confirmation does not publish unrelated access changes or acquire the whole Setup apply lane; existing Setup and `set_config` install/apply serialization remains unchanged. This is persistence ordering, not a new save-plus-apply transaction.

The managed runtime does not hold a universal async lifecycle semaphore while joining adapter work. Such a semaphore created a cross-instance cycle absent from Source when a stopped Weixin fetch returned `/channel stop <other-instance>` during reload. The normal configuration installer still serializes its own installations. This adds no reentrant dispatcher or second queue and does not detach ordinary Weixin handlers.

**Known Source limitation:** a Weixin command that stops or restarts its own polling instance, including confirmed command login selecting that same instance, can await its own handler through loop stop. That Source self-join is retained; removing the introduced cross-instance lock cycle is not a claim that self-restart now completes.

## Verification and limits

`MatrixChannelTests`, `MatrixSendContractsTests`, `WeixinChannelTests`, `WeixinLoginTests`, `WeixinCommitOrderingTests`, `WeixinLifecycleTests` and mixed `McpNotificationTests.ChannelReload` exercise local HTTP peers, actual Router/normal Main/Setup callers, direct/unified/native tools, media ownership, token/cache/timeout behavior, selected versus all reloads, partial starts and live temporary MCP preservation. The send-contract tests feed actual sync state before invoking shared text/file consumers and distinguish ordinary errors from SDK-classified rate limits. The commit-ordering test releases simultaneous normal Setup and shared-command QR confirmations and checks both saved tokens, Setup-only owner merge and unrelated YAML preservation. `dotnet/matrix-sdk-fixture.mjs` executes the actual installed pinned SDK to qualify hidden bootstrap/filter/sync/invite/transaction/retry/upload/typing/MXC semantics. `dotnet/channel-lifecycle-fixture-ts.mjs` executes the retained Source lifecycle owner for the cross-instance baseline.

`packages/webui/test/experimentHostMatrixWeixin.e2e.mjs` uses the original frontend QR controls with a prefixed normal Main, synthetic QR/ilink/Matrix/model peers, real platform attachment commands, sender metadata, send-only/direct native delivery, plain final and Markdown intermediate output, generated images, reload and fresh-process context loss. Controlled peers establish supported host/wire behavior, not real Matrix account eligibility, vendor permission, authenticated-media-only homeservers, Weixin account login entitlement or external network delivery. E2EE/device verification and newer Matrix media protocols are outside this subset.
