# Unit: .NET CLI browser adapter

Files: `dotnet/Foxwarm.CliNode/NodeBrowserTools.cs`, `packages/webui/test/dotnetCliNodeBrowser.e2e.mjs`, `packages/webui/test/dotnetCliNodeBrowserMain.e2e.mjs`

## Purpose and caller paths

The [headless CLI Node](./dotnet-cli-node.md) dispatches Session `browse_*` calls here after its ordinary owner split. `Execute` owns tool results; `EnsureBrowser` launches lazily; the [shared browser assembly](./dotnet-main-browser.md#shared-browser-assembly) obtains and writes the return-by-value clone using shared number/string formatting; `DisposeAsync` closes the process-owned browser only at final CLI shutdown. NodePrimitives stays BCL-only. Main shares the browser assembly, never this CLI manager.

## Behavior, dependency and image boundary

`NodeBrowserTools` owns one browser and insertion-ordered tab map per CLI process, not per Session or Agent. Launch is lazy, with `PUPPETEER_EXECUTABLE_PATH`, then `CHROME_PATH`, then the Source literal `/usr/bin/chromium-browser`; no BrowserFetcher or implicit download is used. Transport reconnect retains tabs. Final CLI disposal closes its browser without killing independent persistent execs.

Open and goto cache the requested URL; get refreshes URL/title and returns HTML unless a screenshot is requested; list reads cached metadata. Only exact `full` requests full-page PNG. Other truthy screenshot values produce viewport PNG and never write a supplied path. Click precedes the swallowed post-click navigation wait; fill sets DOM value and emits bubbling input, not change. Evaluate preserves Puppeteer's return-by-value clone followed by host-side JSON.stringify semantics, including undefined, nonfinite, Date and circular-result consequences. Page-owned JSON functions and prototype hooks do not participate in the host writer. Already parsed clone string/property tokens preserve UTF-16 units, including lone surrogates; CDP clone property order is retained. Main's separate [local browser wrappers](./dotnet-main-browser.md) retain their screenshot-file/body-text policies.

CLI screenshot replies carry bytes only. Ordinary Main discovery and `call_tool` dispatch keep policy, Session image registration, canonical blob references, provider hydration, crop/export, remote read and file delivery in their existing owners. Browser tools are discoverable Node capabilities, not default-injected tool definitions. Persistence/history retain canonical references rather than inline screenshot blobs.

The exact package pin is `PuppeteerSharp.Cdp [25.14.0]`, owned by BrowserSupport for the actual Main and CLI consumers, never NodePrimitives. Detailed native analysis has reported seven IL2026, seven IL3050, two IL2075 and one IL3000 upstream diagnostics; none are suppressed. The UBI 9 build recipe emits IL2104/IL3053 assembly summaries and IL3000, rather than enumerating each detailed warning. The package's generated resolver and fixed JSON DOM/DTO callers bound the serializer paths. Actual native single-ARIA and compound query-all selectors qualify both built-in delegate result signatures for this graph; retain these cases when dependencies/compiler/graph change. Arbitrary CLR callbacks/DTOs and future WebMCP events are not qualified. Explicit executable selection bypasses the warned BrowserFetcher location branch.

`dotnetCliNodeBrowser.e2e.mjs` has bounded `--evaluate-only` and `--shared-only` paths (the latter also executes both built-in ARIA signatures) for host strings/numbers/property order and loaded-page/mutable-page JSON/prototype hooks with baseline/restored controls. Its full path compares real Source and managed/native process effects for all five tools/eleven actions, screenshots, JS values, metadata, reconnect and missing/last-tab lifetime. `dotnetCliNodeBrowserMain.e2e.mjs` uses normal Source and C# Main model turns with the actual CLI, then proves next-request images, canonical history, crop/read/export/delivery and retained identity after an owned Main restart. The existing full Linux host corpus uses Chromium 145.0.7632.109 with an explicit executable. The separate [Linux x64 delivery probe](./dotnet-cli-linux-aot.md) additionally qualifies representative ARIA/evaluate paths with Debian 13 Chromium 155.0.8059.79 in a no-CLR container, not the full browser corpus or other platforms/distributions. Native process maps contain no CLR, and browser work needs no Node/Python implementation driver; Chromium and its real OS libraries remain prerequisites.
