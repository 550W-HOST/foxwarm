# Unit: Optional Archive lexical index

Files: `dotnet/Foxwarm/Vector/ArchiveSearchText.cs`, `dotnet/Foxwarm/Vector/SourceHanRanges.cs`, `dotnet/Foxwarm/Vector/ArchiveSearchSchema.cs`, `dotnet/Foxwarm/Vector/ArchiveSearchIndex.cs`, `dotnet/Foxwarm/Vector/VectorLexicalRuntime.cs`, `dotnet/Foxwarm/Vector/VectorLexicalLifecycle.cs`

## Purpose

Owns the opt-in disposable SQLite FTS derivative at `state/db/archive-search.sqlite`. This is not the authoritative Archive database. It supports dense/identifier/prose fusion without changing Archive or active history.

## Stable paths

- `ArchiveSearchText` applies Source-compatible well-formed Unicode, NFKC/full lowercase normalization, bounded literal FTS query compilation, and identifier/prose lanes. `SourceHanRanges` preserves the Source runtime's supplementary Han coverage.
- `ArchiveSearchIndex.Open` validates schema/version/tokenizer/triggers/identity. SQLite schema version 2 stores block/fact source start/end timestamps; normalizer version 2 uses the shared Unicode 17 lowercase tables. Existing schema-1 or normalizer-1 files are retained inputs that require the existing shadow rebuild, rather than being queried with incompatible metadata or normalization. Documents and their local progress checkpoint replace atomically; checkpoint failure rolls back the corresponding FTS changes. Session and cumulative fork predicates remain SQL-bounded. UTC half-open time predicates precede FTS ranking and limits; raw rows use canonical timestamps, while block/fact rows use hydrated source-range overlap rather than creation time.
- `VectorLexicalRuntime.Schedule` has an independent 50-message/block/five-minute non-sliding scheduler. Dense token thresholds do not force lexical progress. Forced retry, startup and shutdown flush through its serialized writer chain.
- Startup and shadow catchup use the Source branch-backed `LocalVectorMaxima` inventory. Retained physical-only old payload rows do not become forced scheduler identities; canonical branches continue to index through ordinary alias-aware Archive reads without inventing old checkpoints or deleting historical rows.
- `QueryAsync` requires configured lexical plus hybrid search. It reads bounded FTS hits under the lexical owner lock without query-time Archive inventory, statistics, identity or checkpoint snapshots. Ready partial hits remain useful during ordinary indexing lag. Unavailable/backfilling/rebuilding/query-error metadata lets recall choose its bounded transient fallback.
- `RenameAsync`, `ResetAsync` and `ForkAsync` maintain derived source identity and checkpoints; pre-initialization lifecycle calls operate without loading native LanceDB. Main-only presentation changes do not rewrite archived Agents.

## Shadow rebuild and recovery

A schema- or normalizer-version mismatch follows the same rebuild-required path as an incompatible derivative. While rebuilding, lexical query metadata reports unavailable/backfilling and no indexed hits; ordinary recall retains its existing bounded transient fallback. Archive, active history and dense storage remain under their existing owners.

A rebuild-required index preserves the old active file and writes `.next`. Runtime free-space admission uses the Source old-size-plus-64-MiB requirement. Catchup repeats against current authoritative maxima before promotion. File promotion uses `.bak`, validation and directory synchronization; failed promotion restores the old active file and keeps a resumable next generation. Startup can resume next, restore backup, reconcile pending resets and prune derived Sessions without making FTS a new authority. It adds no cross-storage transaction or permanent recovery ledger.

Lexical errors are observable derivative state, not a reason to fail a previously committed Session append/compaction. Cleanup stops deadlines and drains accepted writer work before database close. Maintenance uses SQLite's existing optimize/checkpoint path under the same owner serialization.

## Design decisions

### D-archive-search-index-dark-core

The lexical index is an optional rebuildable derivative, not another Archive authority. One explicit caller-owned SQLite connection stores schema/normalizer metadata, independent raw/block checkpoints, canonical source metadata, and an external-content FTS5 index using NFKC/lower trigram text plus bounded synthetic Han bigram tokens. Opening validates object types, canonical essential table/FTS clauses, required columns, and the unique document identity. The three derived synchronization triggers are defined once and sqlite_master SQL must equal those canonical normalized statements exactly, modulo case, whitespace, and terminal semicolons; extra side effects or reordered operations fail with rebuild-required before writes. Document/trigger/checkpoint changes share one lexical transaction; block replacement removes stale creating-block facts. Selective derived deletion resets the affected checkpoint axis, and block deletion removes its fact rows so authoritative reindex can repair the family. Safe query compilation classifies CamelCase from original bounded spelling before emitting normalized quoted MATCH text. Fork-capped lineage input deduplicates Session IDs and merges conflicting caps to the most restrictive effective values before enforcing the 64-Session bound. The [exact-owner indexing lane](#d-vector-dark-lexical-owner-indexing) and [hybrid-read path](./vector-recall.md#d-vector-persistent-hybrid-read-rollout) use this library; the original library-only rollout restriction has ended.

### D-vector-dark-lexical-owner-indexing

The derived lexical DB is a disabled-by-default exact-Vector-owner indexing lane. `vector.lexicalIndex:true` opens `state/db/archive-search.sqlite`, runs independent bounded raw/block/fact startup backfill and one-writer transactions, and fans accepted Archive hints to independent threshold/block/force/five-minute scheduling without changing dense return/error contracts. Force without hints snapshots current durable local Archive maxima; force targets coalesce monotonically and survive an active run as an immediate serialized follow-up, while newer non-forced suffixes retain ordinary batching. Failed forced work rearms through the bounded deadline path rather than immediate retry looping. When that retry deadline fires, its target snapshot expands through all ordinary hints already pending at that instant, so those sources share the original maximum-latency boundary; only suffixes arriving after the retry run starts receive a later deadline. Lexical open/index/maintenance failure records bounded code/time status and does not fail Lance readiness, Archive commits, or dense checkpoints. Status is additive. The opted-in [hybrid-read path](./vector-recall.md#d-vector-persistent-hybrid-read-rollout) consumes its bounded query metadata, and [lifecycle/shadow recovery](#d-vector-lexical-lifecycle-and-shadow-recovery) owns rename, fork and rebuild rather than disabling the lane merely because those operations occurred.

### D-vector-lexical-lifecycle-and-shadow-recovery

**Derived lifecycle design for the selected [optional hybrid index](./vector-recall.md#d-vector-persistent-hybrid-read-rollout).** Real Archive identity, fork caps and rebuildable derivative semantics constrain rename/rebuild. Shadow files and owner scheduling implement recovery of the derivative; they do not authorize changing authoritative messages or dense rows.

Both rollout flags remain default false; the opted-in derived lifecycle supports committed rename/fork and shadow recovery. Exact-owner rename serializes behind the lexical writer and transactionally rewrites Session/source-family/checkpoint identity when unambiguous; conflict/failure clears only affected derived identities, seeds authoritative target backfill, and never rejects dense/Archive lifecycle success. Pre-placement move rollback/failed-lifetime reset inspects every existing local lexical generation (`main`, `.next`, `.bak`) without creating a missing DB, transactionally clears requested identities in each valid generation, and removes only rebuildable corrupt/incompatible derived generations so startup cannot restore stale lifetime rows; permission/path failures remain untouched and unavailable. Failed Session/fork creation uses internal v4 derived-reset RPC/facade semantics to clear lexical documents/checkpoint plus dense rows/checkpoint so reused IDs inherit no derived lifetime. A reset during shadow rebuild queues behind the exact `.next` writer, transactionally deletes that identity, and retains a pending fence across promotion; promotion/catch-up reapplies resets, removes only derived IDs with no durable Archive branch/reservation, and allows a newly recommitted lifetime to backfill only after the reset deletion. Startup canonicalizes stored derived Session IDs through committed read-only Archive reservations while retaining IDs unknown to Archive outside this shadow-orphan reconciliation. Normal fork creation awaits the committed target baseline before suffix append; both lexical and dense target checkpoints use exact branch message/block caps, and no parent documents are copied. Incompatible schema plus bounded rebuildable SQLite corruption stays unavailable while a one-writer `.next` build resumes from committed checkpoints; permission/path/read-only/open errors remain unavailable without destructive rebuild. Promotion uses at most one `.bak`, directory durability, post-promotion validation, rollback, and later cleanup. Missing-space, rebuild, promotion, and lifecycle diagnostics are bounded codes; rebuild status exposes only readiness/backfill/rebuild/generation metadata. Archive and Lance state are never deleted or mutated by lexical recovery.
