## Purpose

Implements the first resident concrete sandbox-kind provider: one provider-owned Linux Docker container for one already-existing allowlisted Git worktree or checkout. The provider owns exact lifecycle, Docker identity, and per-generation execution artifacts while reusing canonical shared file and persistent-exec semantics.

## Key exports

- `DockerWorktreeNodeProvider` — list/lookup/default-cwd, create/ensure/inspect/destroy, complete file invocation, and canonical resident Docker `exec`.
- `DockerCommandRunner` / `NativeDockerCommandRunner` — bounded injectable Docker CLI boundary supporting fixed launchers such as `sudo -n docker`.
- `createWorktreeFileOperations` / `assertWorktreePath` — target-local root and symlink policy composed with shared file tools.

## Behavior

- Startup configuration fixes the Docker launcher arguments, image, allowed worktree roots, allowed network modes, state location/default, and resource limits. Lifecycle parameters may contain only `worktreePath` and an allowed `networkMode`; create/ensure require an exact Node ID.
- The host independently validates a standalone repository or registered linked worktree marker/admin/backlink/commondir relationship and sanitized `git worktree list`, rejects Docker mount delimiter/control characters, then records canonical worktree, marker type/path, Git administrative/common paths, image/network/container identity, uid/gid, creation metadata, and the complete state-location/container-behavior fingerprint in a bounded durable state file. Provider state is authority; Docker inspect must corroborate ID, full-identity digest name, labels, image, network, and user.
- One Node owns one canonical worktree. Ensure is idempotent only when immutable worktree/Git/image/network identity matches.
- One centralized Docker readiness interpretation drives list descriptors, create/ensure, inspect lifecycle results, and capability execution. Exact `running` with no paused/restarting/dead flag is ready; created/exited/stopped/paused is offline; restarting/dead/inconsistent/unknown/unavailable is error. Lifecycle details carry the same availability plus exact normalized Docker status.
- Create re-inspects the new exact container and removes it before failing if it never becomes execution-ready. Ensure preserves container ID/generation/artifacts, starts exact created/exited/stopped containers or unpauses exact paused containers, re-inspects, and returns ready only after proof. Other non-ready states fail without fabricated recovery.
- Containers are non-root numeric-host-user processes with init, read-only image root, no published ports, no Docker socket, all capabilities dropped, no-new-privileges, bounded memory/CPU/PIDs, and tmpfs scratch. The exact worktree and one exact generation artifact directory are writable; its exact `.git` marker and Git administrative/common paths are over-mounted read-only. Provider state is not mounted wholesale, and sibling Node/generation artifacts are absent.
- The descriptor advertises `read`, `write`, `edit`, `apply_patch`, and `exec`. The helper invokes shared file implementations with target-local operations and returns canonical inline-image shape. Mutation rejects traversal, paths outside the worktree, symlink components, unsafe create paths, invalid cwd, and `contentRef`; `read` additionally permits exact existing files inside the current generation artifact directory.
- Each generation owns one `createExecRuntime`/`PersistentExecManager`. Its scripts, registry, paths, logs, status, and cwd files stay in that generation directory. A provider-owned Linux `ProcessOperations` adapter accepts only the manager's exact Bash script, canonical worktree cwd, current container ID, and exact artifact paths. It invokes the fixed Docker launcher with `shell:false`, passes only `TERM`/`FOXWARM_EXEC_*` into the container, and retains a direct launcher child rather than using detached Docker exec. Best-effort live cwd uses bounded `docker top`, exact script-root lineage, and host `/proc` cwd inspection; the process view remains a truthful Docker-boundary limitation.
- Foreground formatting, timeout resolution/clamping, timeout-to-background, bounded excerpts, zero-byte/UTF-8 handling, registry/finalization, cwd notices/deferred batch updates, and retrying completion are shared canonical behavior. Completion queues a bounded background system event to the exact source Session through Main/session runtime authority. Managers initialize from persisted Node generations at provider startup, so finished work is reconciled without a later tool/list call.
- Provider initialization is an explicit awaited registry lifecycle after Session ingress/catalog readiness. It initializes active, destroy-intent, and retired generations and recovers committed destroy work; errors fail startup. Provider shutdown closes every reconcile timer/runtime idempotently.
- Running exec records persist the exact generated script path. Restart liveness and live cwd query exact container script lineage through bounded `docker top`; launcher PID death/reuse is not command truth. Failed top inspection uses an exact running-only container query: absent/stopped/exited is terminal, exact running remains retryable/fail closed, and mismatch fails closed. Native Main/CLI behavior remains unchanged.
- Inspect reports bounded worktree HEAD/branch plus container/network/generation/artifact identity and explicit containment limitations. Destroy removes only the corroborated provider-owned container and registration; a busy generation is durably retained as completion-only state until its registry empties. Shared registry-idle notification schedules exact cleanup after foreground finalization as well as background delivery. Restart initializes that retired generation, recreate uses a new callable generation, and idle cleanup shuts down/removes the retired runtime so maps/timers stay bounded.
- Main-side Git evidence uses fixed `GIT_DIR`/`GIT_COMMON_DIR`/`GIT_WORK_TREE`, disables system/global config, fsmonitor, hooks, external diff, pagers, optional locks, and submodule recursion, and preserves the index. It reads only registration plus HEAD/symbolic-ref identity, never status/worktree content, so attribute-selected clean/process filters cannot run. Forged pointers to unrelated repositories are rejected before Docker effect.
- Stale startup fingerprints, including canonical state authority and runtime uid/gid, list unavailable and fence default-cwd/capability execution. A same-provider runtime under another full identity fails closed and is never crash-gap cleanup. Inspect corroborates the old runtime and reports stale configuration without worktree-content evaluation; destroy can still remove the exact old runtime. Names include a digest of complete provider ID, exact Node ID, and config hash; exact labels support cleanup, not adoption, after ambiguous start or pre-state crash gaps.
- Destroy durably writes an exact private intent before Docker effect, then durably finalizes removal. File and directory fsync plus temporary cleanup make replacement suitable for recovery. List/create/ensure/destroy retry exact pending removal or finalize an already-absent exact runtime; mismatches remain pending and untouched.
- Abort signals fence queued effects, terminate bounded Docker launcher children, wait for their close, and trigger exact orphan reconciliation for ambiguous starts. Linux, Docker, image, helper, state, and identity failures fail closed and never fall back to master.
- The tracked sandbox invoke bundle is reproducible across primary checkouts and linked worktrees that share dependencies through symlinks: esbuild preserves the checkout-local symlink spelling and removes whitespace/source-location comments without minifying identifiers or emitting a sourcemap. The executable shebang remains intact.

## Tests

Deterministic fake-Docker/local-launcher tests cover lifecycle identity, centralized ready/offline/error reporting, stopped restart with stable identity/generation, paused unpause, restarting refusal, immediate-exit create cleanup, capability fencing, artifact mounts, config fencing, durable destroy recovery, file/exec semantics, environment/path fences, foreground/background/cwd/event behavior, awaited startup failure/success, exact script liveness despite launcher death/PID reuse, stopped-versus-running top failures, destroy-restart and concurrent-foreground retirement, generation replacement, retired cleanup, repeated recreate without runtime growth, provider shutdown, and denied artifact mutation. Target-local tests cover safe file creation plus traversal/symlink rejection. The bundle regression builds equivalent temporary checkouts at two depths through dependency symlinks, requires byte-identical output matching the tracked artifact, and rejects checkout-private paths, dependency source-location comments, or sourcemap references.
