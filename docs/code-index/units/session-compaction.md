## Purpose

Plans context compaction, repairs bounded plan files, commits new immutable Archive blocks/messages with replacement active JSON history, and exposes exact capped Archive navigation/control tools.

## Stable methods and callers

- `SessionCompactor.StartManualAsync`, `AutoAfterTurnAsync`, `BeforeContinuationAsync`, `ApplyCompletedAsync`, `SafePointAsync`, `StopAsync`, and `DrainAsync` own one transient per-Session operation, phase publication, cancellation, ready-wake application, and shutdown draining.
- `SessionCompactor.PlanAsync`/`CommitAsync` and `SessionSaveLane.CommitCompactionAsync` stage the compact snapshot, recorded concrete memory identity, Archive rows, and active history; `PersistentSessionAuthorityStore.CommitCompactionAsync` writes Archive blocks/messages before active JSON and compensates only rows inserted before a failed rename. After actual authority publication (also post-rename durability error), its best-effort hook schedules derived raw/block work and committed facts without changing the commit result.
- A successful planner run attaches a bounded `compaction.planner` diagnostic to the generated compact-completion message and the same Archive message row. The diagnostic contains only planner-appended rounds, tool names, invocation-local usage when reported, and newly appended planner messages; inherited Session history is not copied. Provider-free/display-only cleanup leaves the field absent.
- `SessionSaveLane.PublishCompactWakeAsync`, `RemoveCompactWakeAsync`, and `ReleaseStandaloneCompactAsync` order ready/standalone wake state. `QueueItem.CompactOwner` is in-process ownership only; JSON carries the source compact-commit marker, not a resumable background job.
- `CompactPlanRepairFile` uses the pure `Tools/ExactReplacement.Apply` helper for edit matching while retaining operation-local file identity, authorization and error handling.
- `ArchiveContextReader.Expand`, `ArchiveRecallTool`, `ArchiveControlTools`, `ContextBlockExpansion`, and `ContextPreviewRenderer` read committed local/effective lineage, exact ranges, block children, and source-labeled previews without mutating Archive rows.

Callers: `SessionOwner`/turn safe points, model prompt construction, `/compact` and stop controls, `SessionManager`, and WebUI context views.

## Safe-point and phase contract

A compaction operation captures admission mode and exact operation identity. Async planning publishes `ready` before wake insertion; applying a ready result occurs at a turn-host safe point before consuming the full visible ordinary batch, after complete tool pairing, before provider request construction, and during passive Stop finalization. Safe-point cancellation must not split a model/tool pair, inject fake input, cancel a declared wait, or replace a foreground draft with a background result. Standalone awaited Stop is a no-op for a held background planner. Host closure first drains/interrupts the normal turn (including a required planning wait), then separately cancels/drains planner lifetimes before dependencies are disposed.

`BeforeContinuationAsync` covers both complete tool batches and provider-time queued follow-ups. Each existing input-consumption safe point reports whether it committed compact work and propagates ready-apply failure when the prior provider total (cached + input + output) is strictly over the resolved context limit. A commit consumes that measurement rather than starting another round. After these safe points, usage at/below the effective threshold continues without requesting or requiring new compaction, including supported overrides above the model context limit. Above-threshold planning remains asynchronous below the context limit; above both limits, continuation waits for the exact pending run's planning-settled signal, then commits through its own safe point before another request. Readiness is published before the signal; the signal never waits for its owner's commit. Ordinary Stop/Run queued interrupts only the turn wait, including Stop recorded before waiting; planning remains independently owned. Shutdown-owned cancellation and the dedicated safe-point shutdown exception propagate to the runner's interrupted outcome, preserving busy and later input instead of passively committing it as Stop history. Failed, cancelled, incompatible, or unapplied required compaction ends an over-limit turn without another request, preserving admitted input and complete tool exchanges. Existing below-limit failure handling and Archive/JSON truth remain unchanged. The canonical threshold precondition is in [D-context-compact-scheduling-boundary](../threads/compaction-lifecycle.md#d-context-compact-scheduling-boundary).

The compact commit refreshes memory using the recorded live concrete model identity. The active per-Session JSON/history remains the only source for the next live turn. Compaction may replace/prune active history and queue-related prompt state, but immutable Archive rows and branch lineage are not rewritten or used to reconstruct missing active authority. Pre-rename failure leaves prior authority and rolls back only newly staged rows; post-rename failure retains/publishes committed history/memory/version and is classified committed/too-late.

Candidate accounting admits the first valid raw row after a forward sequence gap and advances sequence accounting for ignored lifecycle notices. A grouped call/response candidate is atomic, including a real completed response separated from its call by a display-only truncation notice. Raw grouping and automatic recent-tail boundary adjustment share the active-history exchange end: transparent presentation rows are crossed only across valid contiguous unique raw sequences, and a trailing notice without a real tool row does not extend a call-only source. Context blocks, preserved-source boundaries and other real barriers remain in force. Preserving any member expands to the complete candidate and excludes its tokens from the replacement quota. Previously preserved exchanges use actual issued/answered tool IDs across a contiguous active sequence span, allowing transparent display-only rows between actual members; partial removal remains rejected. No Archive reconstruction participates, and immutable rows remain unchanged.

Layered replacement drops display-only rows only from the consumed older segment. The current recent/concurrently appended suffix retains its display-only notices. Across the replacement history, only genuine model-visible old compact-completion notices are removed: the opening system wrapper must identify the completion (or match a supported legacy completion prefix), and the row must not also carry conversation, reasoning, tool, or image content. Quoted marker fragments inside inter-Session messages are not lifecycle events. The newly committed boundary uses the live actual parent identity and includes the Source reload hint for distinct trimmed skill names found in consumed direct `skill(action="load")` and persisted legacy `load_skill` calls. This scan neither reloads instructions automatically nor promises discovery through other dispatch forms; immutable Archive originals remain unchanged.

`CompactPrompt.Build` asks for compact source-bound summaries that preserve continuation needs, intent/authorization, consequential decisions, uncertainty and supporting identifiers while making recall needs recognizable. This writing guidance does not change plan/schema, retention, repair, friction or memory-fact behavior.

Plan submission uses the bounded `submit_compact_plan` shape with direct fields or operation-local `argsFilePath`; invalid direct input preserves raw provider argument text, while success/cancel/error/exhaustion paths clean up the transient repair directory. Repair guidance includes a bounded beginning/end preview of the current JSON artifact. Failed `apply_patch` repair calls use the shared `WorkspacePatch.Update` diagnostic: only the failing original hunk is returned, retaining anchor and edit prefixes within the 1,600-character bound; the pending file is not changed. The plan artifact is not Session/Archive history and is never resumed after restart.

The existing run publishes its operation ID, background mode, current phase and bounded retry facts into the owner runtime. Physical planner-attempt callbacks clear only that operation's retry state. Required planning waits install an exact foreground compact lease; background planning otherwise leaves foreground request/tool presentation intact. Final cleanup clears only the matching operation. Failed background plans publish typed notices at owner-safe application, not from the detached planner; failed apply/authority paths use temporary presentation rather than a second semantic append. Maintenance diagnostics and cancellation remain distinct from user-facing terminal failures.

## Deliberate in-context submission

`submit_compact_plan` has an opt-in top-level boolean `inContext:true`, documented only by the bundled `in-context-compaction` skill, not advertised in its schema. The ordinary default gate and dedicated planner/repair behavior remain unchanged. The current managed owner accepts authorized foreground direct and unified calls, including ordinary multi-tool batches; nested native ToolScript and unattended/external calls are outside this entry. Loading the skill is not authorization or enrollment. Session Worker process hosting is excluded.

`SubmitInContext` resolves the full active source region before the executing assistant row and admits one transient operation through the existing per-Session compact registry. `CompactCandidateBuilder.Build(inContext:true)` removes automatic keep-tail, oldest-block window, raw/block token eligibility and coverage quotas; `CompactPlanValidator` also permits a single non-stranded block. Structural identities, source kinds/levels, segment barriers, complete raw exchanges, preserve/remove membership and nonoverlap checks stay shared. A one-child block replacement creates a fresh next-level Archive block. No source comes from parsed wrapper/CTX text or inactive Archive reconstruction.

Acceptance is not application. `PairInContextSubmission` activates only the operation whose actual canonical tool response contains its accepted receipt and call identity. Continuing batches use the existing continuation safe point and propagation/over-limit rules. Terminal finish/wait batches get a post-canonical application opportunity before return, and `ChatResult.ContextCompacted` prevents post-turn maintenance from recounting that same usage measurement. Ordinary Stop retains passive-finalization ordering. `DiscardUnpairedInContextAsync` cleans only that batch's still-unpaired operation on failed publication; no planner, wake record, recovery file or new queue is created. Existing compact work conflicts rather than being replaced.

The commit retains compatible appended suffix/queue state and normal pre/post-rename truth. Cancellation/staleness adds no blanket stop rule; actual failures use existing temporary presentation and continuation conditions. Dedicated `argsFilePath` stays bound to its pending repair artifact; ordinary in-context calls accept direct fields only. There is no per-receipt completion query or new durable failure notice. Observe intended active replacements/removals together with the existing compact boundary, not acceptance or an unrelated later completion marker.

Targeted commits retain display-only rows outside selected source spans and derive skill-reload hints only from direct records actually removed, excluding preserved exchanges. Global removal of genuine pure old compact-completion notices remains shared. Automatic prefix cleanup and skill-hint behavior are unchanged. Immutable source rows and blocks remain recallable.

## Recall and lineage contract

`ArchiveRecallTool` also accepts `text_query` for one Session (default current), mutually exclusive with exact/semantic modes; `beforeSeq` is exclusive and literal-only. One native effective page (at most 100 selected records, with the existing per-lineage bounded reads) bounds each lookup; examination stops at the search-result limit (default 5, maximum 20), preserving older hits for continuation. Case-insensitive matching uses the shared meaningful content projection and CRLF-to-LF normalization, not serialized JSON or Vector. The reported extent follows examined rows across sequence gaps; the continuation retains result filters and preview settings. A one-row older existence read uses the same effective lineage caps. Literal reads resolve existing catalog identity and recheck authorization/canonical identity around the read without hydrating a target owner or creating state. Existing exact lookup retains its owner-admission path; retained/deleted-source navigation is not expanded.

`ArchiveRecallTool` keeps the exact selector subset (overview/help, frontier blocks, exact `B#N`/`block#N`, `msg:B#N`, and normalized `msg#A-B` ranges). `ArchiveContextReader` uses exact SQL ranges/child IDs and cumulative branch caps; it does not add hidden pages, whole-history prefixes, semantic archived-only target resolution or active-history reconstruction. Nonempty `vector_query` instead uses [semantic source selection](./vector-recall.md) before exact parsing or owner hydration, with bounded previews and existing canonical scope. Missing exact targets do not create Sessions, databases, or branch reservations. Tool-response previews preserve JSON arrays as well as the existing object/scalar model projection. Context previews preserve distinct source/active budgets and include headers/source labels within the total budget. Shared preview filtering normalizes CRLF to LF and trims the search haystack before literal/include/exclude filters and omitted-tool matching, following the Source renderer. Filter parameters, displayed bodies and persisted messages are not rewritten; this does not establish general Unicode or regex-engine equivalence.

Shared tool previews recognize a non-null root `error` or a retained top-level MCP `isError:true` flag. Failed MCP inspection preserves the protocol result and structured diagnostic instead of selecting an empty `content` array. Nested business fields do not classify a result as failed; success projections and canonical MCP normalization remain unchanged. `OutboundMcpResultsTests` exercises this through the actual SDK peer, turn host and persisted tool result, including a successful nested-business-field control and an existing root error.

Automatic response-only pruning commits only when the reconstructed live history estimate is strictly below 60% of the original estimate; the selected model window is not this decision's denominator. The save-lane commit rechecks that relative bound with concurrently admitted history before accepting the rewrite. Otherwise the existing layered planner runs. Genuine uniquely identified `skill(action=load, skillName=...)` responses, builtin `call_tool` forms, and persisted legacy `load_skill` readers are exempt from pruning. This does not register a live legacy alias. List calls, external dispatch, malformed arguments, ambiguous IDs, and unpaired responses remain eligible.

Manual `/compact tools` calls `PruneToolsManuallyAsync` on the same response-only pruning owner, bypassing only the automatic 60% reduction requirement. It preserves skill-load exemptions, recent-message boundaries, call arguments, unique-sequence/raw-Archive validation and compatible-prefix/new-suffix commits. Its result reports actual committed response/message counts and before/after estimates. Incompatible manual snapshots report no replacements; authority failures retain the ordinary pre/post-rename truth. It does not claim a model-compaction run, checkpoint Task context or invoke a provider. The existing automatic gate, lifecycle and planner fallback remain unchanged.

Plan operations may carry an integer `frictionScore` from 0 through 100. Missing/invalid scores are omitted without rejecting an otherwise valid plan. Accepted scores flow through immutable Archive block records, active context-block metadata, candidate prompts, exact recall, expansion, and previews; existing unscored blocks remain unscored. This is diagnostic metadata, not a changed pruning or retention policy.
