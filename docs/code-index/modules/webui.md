The React client is shared with the .NET host. Backend-specific access identities and route behavior below describe the retained TypeScript implementation; current .NET authentication and integration gaps are documented in the [.NET WebUI boundary](../threads/dotnet-webui-boundary.md).

## URL and transport boundaries

- `API_BASE_PATH` is the current page pathname (without trailing slash) plus `/api`.
- REST and compatibility EventSource paths append to `API_BASE_PATH`; current list/Chat realtime uses one `makeWebSocketUrl` connection.
- `makeApiUrl` returns a URL object; `makeWebSocketUrl` changes its protocol to `ws:`/`wss:`.
- Code routes remove the `/api` suffix and append deployment-relative `/vscode-web/`.
- Main WebUI and the persistent Code frame validate exact origin plus window source. Nested Foxwarm leaf iframes post to their parent with `'*'`; the outer Code extension validates exact source plus channel/version/random nonce (not `event.origin`), then sends outer-to-inner messages to the exact leaf `frameOrigin`. These bridges are not API URL transport.
- Top-level tab popups use a separate versioned same-origin URL mode. They mount one Chat, terminal, Agents, Search, Logs, Tasks, or Setup leaf without the workbench store; Code uses its existing standalone `/vscode-web/` URL. Popup target IDs may be URL parameters, but authentication tokens never are.
- Download and extension routes preserve reverse-proxy prefixes and do not assume site root.

## State ownership

- Mounted Chat owns one session's history and logical runtime subscription; the page realtime transport owns the physical connection.
- App/Sidebar/Architecture own their list data and logical subscriptions on the shared transport. Stream-triggered refreshes use fixed-delay, non-overlapping coalescing, while the session-list request gate remains latest-wins; the canonical contract is [D-webui-app-global-list-gate](../units/webui-app.md#d-webui-app-global-list-gate).
- Workbench store owns tab/pane/split layout; the shared [stable content host](../units/webui-workbench-content.md#d-workbench-stable-content) owns tab instances independently of that changing layout tree. Chat viewport state is ephemeral in-memory state keyed by canonical session ID.
- Browser-only theme packages/selection, chat/input display preferences, layout, draft, and Code preferences remain local; instance name/icon are server settings.

## Design decisions

### D-webui-shared-content-width

[2026-10-13] `index.css` owns the shared reading-column geometry: `--foxwarm-content-width` is 1100px, `.foxwarm-content-column` bounds and centers a padding-free column, and `--foxwarm-content-gutter` supplies 16px outer horizontal spacing. Non-full-width Chat Timeline, Composer, History's search/results column, and Tasks' Table/Board column use that contract; individual cards and modal dialogs retain their own padding and sizing. Composer always keeps the reading cap, even when Full width removes only Timeline's cap.

Desktop Chat reserves `--foxwarm-context-minimap-width` (32px) outside both columns before centering them, based on the existing minimap setting and the owning Chat's 768px layout band. Disabling the minimap removes both reservations; History and Tasks have no minimap reservation. Chat's existing content/scroller ResizeObserver publishes only the real native scrollbar gutter to `--foxwarm-chat-scrollbar-gutter`, so Composer also centers inside the scroller's usable width when a native scrollbar occupies space. Column sizing stays CSS-owned without another observer, React width state, or scroll owner. Tasks' filter row follows its main column, including the existing desktop inspector clearance; narrow details and New task remain independent modal layouts.

The focused `workbenchPreview.e2e.mjs` geometry case uses visible native scrollbars to check actual left/right edges through pane/window resizing and minimap changes, shared maximum widths, and narrow overflow containment. `tasksView.e2e.mjs` checks Table/Board widths and filter alignment beside the retained desktop inspector.

### D-webui-react18-runtime

[2026-09-19] The WebUI uses its locked React and ReactDOM 18.3.1 packages directly for JSX, hooks, and `createRoot`; Vite does not alias React to Preact. Browser component fixtures also resolve the WebUI's React 18 packages, including when their generated entry files live outside the package directory. Vite deduplicates `react` and `react-dom` so shared imports do not bring a second React runtime into the page. Server-side/CLI renderers retain their own dependency boundaries. This keeps production and browser tests on the same rendering semantics without changing application state, message, or tool contracts.

### D-webui-timeline-time-separators

[2026-09-27; updated 2026-10-11] In Detailed and Grouped, a quiet centered timeline text row compares the next ordinary committed message’s valid `__meta.llmRequestTiming.startedAt`, falling back to `__meta.timestamp`, against the preceding message’s persisted `__meta.timestamp`. The marker displays that same selected next-message time, so a long request does not become an idle gap; the preceding baseline never uses its request start or substitutes `completedAt`. Structured CTX-BLOCKs still use only `__meta.contextBlock.rawStartTimestamp` for both their time and the following comparison, never their creation time or request timing. No ingress wrappers, reconstructed intervals, tool execution timing, or render time are read. The first eligible visible row shows its clock; other eligible rows show only their clock when the selected time differs from the preceding baseline by at least 60 seconds or crosses the browser’s local calendar date. A CTX-BLOCK without a valid range-start timestamp shows no time row and breaks adjacent comparison instead of falling back to its creation timestamp; missing or invalid predecessors can show only the next valid clock, without estimating a gap. English 24-hour `HH:mm` applies today, `MMM d, HH:mm` otherwise (year across years); the tooltip includes full date, seconds, and time zone. No elapsed suffix or countdown is shown. Tool responses and whole Event wrappers contribute their adjacent persisted timestamp but have no independent divider; an eligible next model call can safely split a historical group only without separating a paired call/result. A divider is a keyed sibling outside collapsed content with no viewport anchor; nested CTX, queued previews, and temporary/synthetic stream or optimistic rows add none. API/token/Seq badge behavior and stored backend timing data remain unchanged.

In Conversation, an Activity disclosure and its immediately following reply form one time-separator display unit. No divider appears between them, whether the Activity is collapsed or expanded. Only the unit's first source can own its clock, with the same validity, minute-gap, and local-date rules. For segmented logical requests, the first prefix uses validated request timing from the same request anywhere in already-loaded history within the current CTX scope, rather than treating its generation time as idle. A later unit after a visible surface of that request (or an intervening user input while the request is already present) starts at that committed visible boundary, not the whole request's earlier origin. Unknown segment origins or boundary timestamps omit the clock; they do not borrow a later final body's time. Linking never crosses CTX, mutates persisted metadata, or fetches Archive. Other sources retain their own request-start/timestamp rule. A standalone Activity can also own its clock without waiting for a model body: a leading unit uses its first real input or trustworthy execution origin from already-loaded, CTX-local evidence, not Session creation or maintenance. Current requesting-model work can use its reliable live origin before the first provider part exists. A tool/event-first Activity can therefore own a unit clock even when its raw message was not independently eligible; an unknown start omits the unit clock rather than moving the later body's time before it. All raw persisted timestamps still contribute the adjacent comparison baseline. User rows, CTX cards, and independent image surfaces interrupt the pairing and retain their source rules; repeated surfaces from one source do not duplicate its clock. This does not merge, hide, or reorder body parts, change anchors/Search/stream identity, or alter the separate visible-text boundaries used for Activity elapsed/busy/waiting and counts. Actual nested CTX and queue timelines still have no dividers.

### D-webui-contiguous-reasoning-cards

[2026-10-01] Consecutive reasoning parts in one model message share one Reasoning card. All Reasoning tags show only their Brain icon; their full label and any `×n` count remain in the tooltip and accessible image name, including Grouped summaries and processing cards. Real-tool labels are excluded by explicit tool identity. Grouping follows original part adjacency, not the filtered visible list: text, system, tool, image, hosted activity, and unknown parts are barriers, and mixed-field parts retain their other visible output. Recognize a string `thinking` field (including empty), a typed reasoning-summary array, or known encrypted-reasoning metadata; generic provider metadata is not reasoning. Empty summaries still produce a real tag/card and count, without invented summary or visible encrypted content. The message's actual `reasoningTokens` appears once, on its first run, as `N tokens` with the Tool-duration text styling and `Message reasoning tokens` tooltip; zero is valid, absence adds no estimate. It is already included in output usage and is never added to totals again. Do not combine messages or borrow completion-suffix usage for an earlier committed prefix. Group disclosure and manual card height transitions remain unchanged; per-part DOM markers preserve exact Search ownership inside a merged card. This is presentation-only: canonical parts, replay, provider output order, history segmentation, and usage badges remain authoritative and unchanged.

### D-webui-chat-session-search

[2026-09-29; updated 2026-10-07] Chat offers pane-local Search over the current Session’s already-loaded committed top-level messages. Search opens from the Chat header or Ctrl/Cmd+F with a literal case-insensitive query, one current match counter, previous/next, and close; Enter, Shift+Enter, and Escape work inside its input. Before focusing Search, Ctrl/Cmd+F captures a non-empty selection from ordinary text, contenteditable, input, or textarea controls and uses it as the query; without a selection it retains the existing query. The active Search input supports ArrowUp/ArrowDown history navigation with a bounded, deduplicated browser-local history: entering history saves the current draft, returning past the newest item restores that draft, and entries are committed only at search navigation/close boundaries rather than on every keystroke. History is local to the browser context and does not add backend state. The browser Find shortcut is intercepted only when an actual Chat is active: in a split workbench only the focused active Chat registers the listener, while a standalone popup or embedded single Chat is active by default. It does not intercept Ctrl/Cmd+Shift+F, Alt combinations, composition, or a non-Chat active tab; repeating the shortcut focuses/selects the current query without duplicating Search. Opening Search builds a display-text projection once per history change and query edits only filter that projection; it performs no additional history or Archive requests and never counts queue previews, optimistic/streaming drafts, nested CTX archive content, image bytes, opaque reasoning, internal metadata, or non-text visual blocks. Ordinary Markdown is searched as rendered readable text; Tool arguments and complete expanded result text use the corresponding display formatters, not truncated preview content or a serialized card payload. An explicit jump temporarily reveals only the owning group/card (a CTX summary unclamps without fetching its archive), mounts an already-loaded older row only when that match or its needed group/call falls outside the current timeline window, detaches bottom-follow, and scrolls once with an exact-character browser text Range highlight. Forced disclosure does not alter manual expanded state or start the normal card-height animation; close/session replacement clears the instance’s highlight and never scrolls to the bottom. This pane-local feature adds no persisted query state, backend search index, or second scroll owner. The placeholder is “Search messages”; the search scope remains loaded messages while incomplete prefix loading continues.

### D-webui-timeline-view

[2026-10-11] Chat settings expose one browser-local Timeline view: Detailed, Grouped, or Conversation. Detailed replaces the former disabled Group tools setting; Grouped replaces its enabled setting and retains the existing historical groups, forced-open tool tail, and manual disclosure contracts. The internal API uses only `timelineView`. A valid `foxwarm_timeline_view_v1` value wins over `foxwarm_group_tools_v1`; absent/invalid new values read old false as Detailed and old true as Grouped. Mode changes write only the new key and synchronize other browser roots through the existing storage event owner. Ordinary, popup, embedded, restricted WebUI, History result, nested CTX, and Debug preference projections consume the same mode without new server/Session settings or access capabilities.

[2026-10-13 visual first phase] Conversation is a result-first, display-only projection. Direct user content and attachments remain visible in source order, including input arriving during work. One process disclosure aggregates commentary, tools, reasoning and internal inputs until a reply, new direct user input, CTX boundary or metadata-confirmed terminal retry. Runtime wakeups do not themselves split it. CTX remains a hard cut; no work ID, history rewrite, provider replay change, Archive scan or backend turn platform is added. Independent generated images remain accessible in their original position and may split disclosure surfaces.

Text classification links already-loaded `llmRequestId` and `llmSegment` records within each CTX scope. Explicit `commentary` stays in the process; explicit `final_answer` belongs to the reply. Without phase metadata, actual tool participation across the full loaded logical request folds narration; uncertain old text remains a readable ordinary body. Undecided streaming text starts as a process preview, not a reply that later disappears. Once a real reply is established, that preview gives way to the reply. A process with no reply retains its last readable text, including interruption/failure cases. This is not a promise of unchanged DOM placement during completion. The existing viewport/follow owner remains authoritative.

A complete, tool-free logical request whose ordinary text is exclusively explicit commentary closes a conservative **display segment**, including a metadata-only suffix when all segment ranges are loaded contiguously from zero. Its preview remains readable; a later substantive internal input opens a new process. This does not claim task success, final output or Stop. Compact maintenance may join the closed segment without starting a new work trigger. With no persisted historical work-end identity, some resumed commentary-only work is intentionally split rather than merging distant unrelated triggers. Missing segment coverage cannot establish this fallback closure.

Processes begin collapsed. Opening one renders its ordered original fragments once through the existing nested Detailed timeline: commentary appears as readable Markdown, and tools, reasoning, hosted search, Task notifications, inter-agent input, System/Event and Timer messages use their original components. There is no secondary step classification or disclosure wrapper. A tool's collapsed header retains its tag and concise command/path/arguments but mounts no result or progress content; one native-header click opens its full body. Native input, reasoning and search cards retain their own disclosure defaults. Only Conversation process Reasoning uses subdued normal-weight previews, muted text and weaker tag/background treatment; its original expanded content is unchanged. No generated summaries or copied tool-result previews are added. Only Conversation process tools neutralize successful tone; genuine errors remain distinct. Stable process/request identities retain manual expansion during stream updates, and disclosure controls preserve keyboard activation and aria-expanded. The row owner derives process membership; rendering reuses the existing Detailed projection. Conversation previews, expanded commentary and final replies share the same prose size, color, opacity and content inset; process nesting remains a separate layout level. Replies have no bubble border/background/shadow, user bubble text matches body size, and width preferences, Markdown structures, source/copy actions and timestamps remain available. Detailed and Grouped retain their established chrome and disclosure defaults.

Activity summaries show nonzero Worked / Waited durations (or Elapsed when only the total is trustworthy), followed by actual calls, child sessions, sent messages and received messages. Zero-valued facts are omitted; compact sent/received labels still mean messages. Without supported duration or count facts the label remains Activity; there is no special Reasoning title. Calls/results pair by tool-use ID, `call_tool` counts its resolved target once, and supported hosted search/open-page output items count as calls without being converted to function calls. Hosted item IDs prevent repeated output from recounting the same search. ToolScript `run_script` and `continue_script` each count as one ordinary top-level tool invocation. Activity does not expand their subcalls or inspect script code, return data, private runs, background completion, or live progress to reconstruct internal creations/sends. Existing ToolScript progress and linked-task completion behavior are unchanged.

Creation needs the builtin's actual created-session acknowledgment, including a created child whose task delivery failed. Sends need actual successful delivery evidence: explicit send acknowledgments, awaited child initial-message delivery, and the Task mutation receipt's per-operation `sentNotifications` count. Task transfers may deliver to two recipients; silent saves, self-skipped notices, absent recipients, and failed sends do not count. Child task assignment uses the same actual notification total once. Old direct receipts without delivery evidence remain unknown; these summaries are not a complete communication audit. Received communications use real internal inter-agent/task/MCP records, including [inbound MCP external/context frames](../units/src-mcp-inbound-session-service.md) and [outbound-server notification frames](../units/src-mcp-external-service.md), excluding ordinary input, authored XML quotations, and time/compact/reminder maintenance. The only external Conversation LLM error is the original last committed message of Chat's full current history, confirmed by the existing retry classifier. Chat supplies that history authority separately from its viewport slice and provisional stream rows. This one original card stays outside Activity; a later real message or CTX boundary returns the old notice to Activity. Nested archive/Activity and queue timelines do not infer a current-history tail. Tool failures never color or label the Activity summary as Error; expanded results retain their real error display. Activity details use compact technical-row spacing without applying the extra CTX nesting margin; actual CTX nested layout and ordinary user layout/metadata remain unchanged.

#### Activity timing: display-boundary scope

The elapsed range starts at the preceding visible user input or projected reply boundary and ends at the next such boundary, CTX, terminal retry or the recorded completion of the conservative commentary-only display cut above. The total elapsed range is independent from the displayed Worked/Waited sum. Request-aware body classification determines which model text is a reply boundary; folded commentary does not cut the process clock. Empty/whitespace model text does not render an empty conversation row or cut the range, and usage/phase metadata alone does not create Activity; real accompanying reasoning/tool records remain. A text-free completion can supply the conservative display cut above without becoming an empty reply. In particular, an inter-agent arrival after idle coordination does not reset the start to that hidden record. When no preceding visible boundary exists, the first genuine Task/inter-agent/channel input or trustworthy execution origin in the already-loaded CTX scope can start the range. Session creation, time tags, and maintenance are not fallback origins; unknown earlier work stays conservative. Existing visible boundaries retain their leading idle. No internal records means no fabricated waiting-only row. A requesting-model runtime with a reliable busy/request start can present current Worked time before the first provider part arrives; this non-disclosable surface is presentation-only and disappears when real Activity/output replaces it or the runtime stops working. Queued, waiting, idle, and unknown-start states do not create it. No history, queue, or persisted metadata is added. Independent visible images stay in place without cutting this text-based clock; if they split the technical disclosure surfaces, the range's duration appears once on its first Activity surface.

Final boundary clocks are persisted message timestamps, including a preceding boundary outside the viewport. Streaming text does not save its browser arrival as a history timestamp. A runtime-confirmed open Activity temporarily ends at current time and updates through a local display clock; committing its next visible boundary fixes the endpoint. Measured logical-request and synchronous tool intervals, plus the currently active runtime's known busy interval, are clipped to each range and unioned so parallel work and shared request segments do not double count. While tools run, the current runtime tool ID may confirm the latest pending call batch, whose receipt is published only after the whole batch (including adjacent parallel execs) finishes. Missing receipts alone do not invalidate that confirmed batch when the interval before live busy is already measured or contains only the existing short-overhead gaps. This does not extend measured busy intervals or turn larger unknown preceding work into waiting; missing older requests, completed receipts without execution timing, and retries retain their fallback. A bare busy flag or unrelated tool ID adds no such exception. Request/tool waits are busy, not CPU usage; background jobs, paused script lifetimes, and other Agents' work after a synchronous return are not continuous busy. Displayed waiting estimates the continuous non-busy gaps and does not require a `wait` invocation; it is not a wait-state audit. Each gap shorter than two seconds is omitted before summing, including leading and trailing gaps; exactly two seconds qualifies. The current two-second cutoff is a display-noise heuristic. Multiple short overhead gaps cannot combine into a displayed wait. Omitted overhead is not added to Worked, so displayed Worked plus Waited need not cover the total elapsed range.

Canonical compact-completion markers are untimed Session maintenance, including the exact generated completion-plus-goal-reminder row recognized by the continuation classifier. Their cards/details remain in Activity, but a maintenance-only disclosure/range receives no Worked, Waited, or Elapsed label or live clock, both at the tail and after a later user boundary. Maintenance is not execution or request-completion evidence; it neither cuts a real Activity nor changes its effective last work record. Genuine work/coordination retains its existing timing and leading idle, even when Continue is unavailable. The shared frontend helper is deliberately narrow: canonical system-only completion or the exact generated pair, not authored text, unrelated reminders, or records with extra real content. This changes no history, Continue availability, CTX truncation, or full-history tail-error presentation.

CTX cuts the range at its persisted message boundary and prevents borrowing execution evidence through the summary. A metadata-confirmed final LLM retry closes at its stored timestamp, even when the notice later returns to Activity. Existing normal Stop history has no durable stop timestamp; an idle unfinished tail without trustworthy completion/pause evidence stays counts-only rather than fabricating a stop time or growing a guessed interval. Missing endpoints likewise retain counts only. Known endpoints with missing/invalid request/tool evidence, unmatched partial segments, or unmeasured failed/retry work show Elapsed rather than labeling missing busy time as waiting. No backend wait-history rows, event accounting, Archive requests, or model-input changes are introduced.

### D-webui-tab-popout

[2026-09-21] Every workbench tab exposes `Move to new window`. A successful synchronous browser popup opens a real same-origin single-leaf URL and then removes the source tab through the ordinary layout-only store action; a blocked popup or cancelled Setup/Agents unsaved-state warning leaves the source tab unchanged. Popup windows do not mount or persist the normal workbench, do not synchronize state back, and do not restore the source tab when closed. Chat relies only on its existing browser draft persistence and does not transfer page-memory files. Terminal popout requires an existing terminal ID, reattaches to that backend PTY, and never uses the terminal-delete close path. Code uses its existing standalone launch URL rather than moving the embedded iframe.

### D-webui-node-aware-launchers

[2026-08-10] Main-WebUI Code and terminal launch options use the authenticated public node summary and preserve explicit node identity. Terminal choices require an online `vscode-pty` service; Code choices require online `vscode-fs`, while Git remains optional. Offline, incompatible, and stale selected nodes stay visible and disabled in selectors and are never silently replaced with `master`. Selecting a different node in either main launcher dropdown resets that dropdown's draft path to the neutral absolute POSIX root `/`; this is selection-driven draft behavior only, with no per-node path cache or persistence before submission. A Chat header terminal uses that session's `currentNode` and cwd without showing a selector; desktop lower-pane reuse requires the same normalized node and cwd. The main Code launch target remains a browser-local preference, while session/tool/commit Code actions retain their own node targets. Code still uses the single persistent multi-root workbench defined by [D-code-persistent-workspace](../threads/code-integration.md#d-code-persistent-workspace), and all remote operations retain the fixed-service boundary in [D-code-fixed-remote-services](../threads/code-integration.md#d-code-fixed-remote-services).

### D-webui-session-stream-ownership

### D-webui-history-bootstrap

[2026-08-02; updated 2026-09-06] The normal Chat bootstrap uses only the authenticated history route plus the per-session stream. The first registered load requests the newest 100 committed rows with the lightweight persistent system snapshot, queue preview, canonical session state, exact sequence frontier, history version, and guarded prefix length, then issues at most one request for that older prefix. The recent rows may paint immediately, but the context overview remains hidden until the complete committed history is present. Both responses share one request generation and replay newer committed stream rows before acceptance. The full debug-file payload is diagnostic data and must be fetched only after the user explicitly opens Debug, never as a mount or ordinary refresh dependency. Debug is a separately mounted modal lifetime: Open and each explicit Refresh fetch and serialize one immutable snapshot, while ordinary history, stream, model, and render updates neither reconstruct nor stringify it. Parsed payload, serialized text, copy state, request controller, and callbacks over those values remain modal-owned; Close, session replacement, and unmount abort or invalidate pending work and release that ownership, and reopening captures fresh state. The large Chat component must not own the serialized diagnostic text.

### D-webui-model-settings-navigation

The Chat model popup reuses the page-lifetime singleton `/api/models` result; opening it does not refresh model metadata. Its settings action activates the existing singleton Setup surface and requests focus for the Models YAML editor without creating a second instance: normal App uses the workbench callback, while Code-embedded Chat uses the nonce-bound fixed bridge to activate the Setup custom editor and deliver a one-shot focus signal. Neither path mutates the hash directly. A Models focus request is one-shot: the owner that receives it clears the request after its SetupView consumes it, so later remounts, tab switches, or ordinary Setup activations do not replay focus; each explicit picker request switches to Models and focuses again. A successful Models save and the picker’s explicit Refresh action invalidate only the current JavaScript context’s model cache and notify mounted Chat consumers to load the new shared result. Failed saves preserve the cache; ASR and command caches are unaffected. Existing latest-request gates prevent pre-refresh responses from replacing newer options. Separate popup windows and Code leaf iframes do not synchronize these caches; their Chat pickers can explicitly Refresh. This preserves workbench ownership, split-pane behavior, Code editor identity, and deployment subpaths.

### D-webui-settings-placement

### D-webui-identity-session-scope

[2026-10-08; updated 2026-10-10] A `webui` access identity grants browser chat, history, live events, and attachment uploads within `access.identities.<identityId>.surfaces.webui.sessions`. Each entry is either an exact Session ID or `<agent>/*` with an ASCII-letter/digit/underscore/hyphen Agent name; bare `*` and other wildcard patterns are rejected. Exact bindings resolve committed aliases and continue following the same Session across moves. Agent scopes cover that Agent's current and future Sessions by actual catalog ownership, including the unprefixed IDs of the `main` Agent; they never compare ID prefixes. Requested aliases resolve to the current canonical Session before ownership is checked, so an old alias under a scoped Agent cannot authorize a Session moved out of that Agent. Missing or ambiguous references do not grant access. Auth and restricted Chat selection lists project currently accessible canonical IDs on each request, not a permanent login-time expansion. HTTP reads and attachment/message ingestion recheck the same scope at their existing authorization boundaries; WebSocket and compatibility SSE output also recheck current scope before Session payloads are sent, ending stale canonical streams after moves. Other WebUI routes and streams remain administrator-only; the restricted identity root cannot mount workbench, popup, embedded, Setup, Code, terminal, sidebar, model, debug, or management surfaces. WebUI identity messages reject leading slash and mention-prefixed slash commands before router dispatch, and uploads bind the file to the same identity and Session before ingestion. Existing administrator instance-token behavior is unchanged. The identity grants no agent execution/tool permissions: tool results in an accessible Session remain ordinary unredacted chat content. Browser image blobs require both an accessible Session and a reference in its committed history; arbitrary filesystem downloads remain administrator-only.
