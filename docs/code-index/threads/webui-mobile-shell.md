# Thread: Mobile WebUI shell

## Scope and owners

- Shell and retained desktop workbench: [workbench](../units/webui-workbench.md), `App.tsx`.
- Mobile home and bounded Session rows: [session list](../units/webui-session-list.md).
- Shared `MobilePageHeader` and `ContentHeader`: [small components](../units/webui-small-components.md).
- [Tasks](../units/webui-tasks.md), [Setup](../units/webui-setup-view.md), and [history search](../units/webui-history-search.md) retain their existing data owners.
- Browser preferences: [settings menu](../units/webui-settings-menu.md).

## Design decisions

### D-mobile-shell-presentation

[2026-10-16] A root viewport below 768px uses a separately designed mobile shell. This policy is distinct from a narrow desktop Chat pane's container-responsive layout. Mobile hides the workbench tab strip without deleting tabs, layout, or processes. Sessions, Tasks, Search, and Settings are in-place primary tabs with one retained bottom navigation; visiting a tab does not create a desktop workbench page. Visited pages stay mounted, and returning from Chat retains the selected primary tab and its local state.

The navigation is centered, capped at 440px, and sits 12px above the bottom safe band of the app shell. Navigation and the Sessions New session action stay fixed-positioned and keep their ordinary 12px/88px offsets plus in-scroller clearance; their effective inset comes from the [bottom geometry owner](#d-mobile-shell-bottom-geometry), which measures the safe band from the shell's lower edge rather than from the fixed-position viewport. It uses a rounded translucent material matching the composer, not an opaque full-width footer. All four pages share the same element and material. Reserve the last content/action clearance inside the actual scroller, not in an opaque outer strip. Reduced transparency disables blur and uses an opaque semantic surface; forced colors use native readable boundaries.

Primary page headers have transparent backgrounds and progressively masked backdrop blur. Content scrolls behind them. `MobilePageHeader` observes its positive rendered height and publishes a parent-local CSS offset; hidden zero-sized pages do not erase the previous measurement. Initial content clears the blur tail. Search is a circular action that reveals a compact input, and Session display choices share a separate circular dropdown. Tasks and Settings expose their existing filters/sections through their corresponding controls. No page-wide colored header plate is added.

Chat has an independent circular Back action that clears the hash and returns to the retained primary page without closing workbench tabs. Browser Back traverses Session-link history separately, following [App route publication](../units/webui-app.md#app-behavior). Chat has a centered single-line Session name without a surrounding plate, and a small right-hand action capsule. New Session uses the existing creation path and current Agent. Find, Code, and Terminal remain in the Session menu. A long title truncates visually while retaining its accessible text. Search expansion participates in measured header clearance, and connection notices remain readable below the floating controls.

[2026-10-17] The mobile workbench pane retains the safe-area, fixed visual-viewport shell around its layout slot, just as the retained primary pages retain their own shell. `main.tsx` publishes visual-viewport height and top offset; the shell consumes both and applies top/left/right safe-area spacing. Root height alone handles shrinking but does not compensate viewport panning. The stable content host follows the measured slot through the existing layer-relative geometry owner, without another keyboard offset or a change to content ancestry. Keyboard dismissal restores the full pane and composer position.

The workbench's floating Chat header does not apply those safe-area insets again inside the already-inset slot. Independent Chat leaves retain their header-owned spacing because they have no safe-area shell. Actual header controls, not just the header wrapper or aligned portal rectangles, must clear the status area exactly once. Composer bottom spacing follows the [bottom geometry owner](#d-mobile-shell-bottom-geometry).

### D-mobile-shell-bottom-geometry

[2026-11-18] Installed iOS 26 web apps using `viewport-fit=cover` with the black-translucent status bar report `100dvh`, `innerHeight` and `visualViewport.height` short by the top safe-area inset (WebKit bug 301108); only `100lvh` is the screen height, and the band below the short viewport shows only the `html` background. Below 768px and at rest, the installed iOS shell (`navigator.standalone === true`, marked on the root as `data-foxwarm-ios-standalone`) therefore grows the app height by `min(100lvh - 100dvh, safe-area-top)`, so `html`/`body`/`#root` and the fixed mobile shells (Chat pane and primary home pages) reach the physical screen bottom. Where dvh already is the full height the extension is zero. Ordinary browser tabs, Android, desktop and desktop app windows are not marked; the 768px and wider layout is excluded because its document is not fixed and a taller root could scroll it.

The bottom-geometry block in `index.css` is the single owner of the effective bottom inset; consumers read its variables instead of `env()`. `--foxwarm-app-viewport-extension` is how far the shell reaches below the fixed-position viewport. `--foxwarm-app-safe-area-bottom` is the safe band at the shell's lower edge, also used for in-scroller clearance. `--foxwarm-app-fixed-safe-area-bottom` measures that band edge from the fixed-position viewport's bottom, which is what `bottom` on the fixed navigation and New session action resolves against. `--foxwarm-chat-composer-safe-area-bottom` gives the Chat composer `max(1rem, safe-area-bottom)` of lower padding in the installed iOS shell, so its form ends one bottom inset above the screen bottom; other paths keep 1rem.

While `main.tsx` pins the shell to the visual viewport (`data-foxwarm-viewport-pinned`, keyboard or zoom), the shell ends at the visible area: the extension and the installed shell's bottom safe band are zero, and the composer rests 1rem above the keyboard. The home controls stay fixed rather than absolutely positioned in the shell, so a pinned shell does not lift them above the keyboard. This supersedes the earlier home-local `max(0px, safe-area-bottom + 100dvh - 100lvh)` treatment, which kept every control inside the short viewport and left the lower band empty.

### D-mobile-list-and-chat-preferences

[2026-10-16] Mobile Session ordering defaults to Flat/recent activity and uses `foxwarm_session_list_mobile_view_mode_v1`; desktop preferences remain separate. Flat rows omit the tree disclosure placeholder but retain 12px content inset, aligned for selected and unselected rows. Pin/Unpin belongs in each row's menu on both desktop and mobile.

Both viewport families default to Conversation when no valid preference exists. Mobile stores explicit choices in `foxwarm_mobile_timeline_view_v1`; desktop uses `foxwarm_timeline_view_v1` and honors the legacy grouping boolean (`true` selects Grouped, `false` selects Detailed) only when no valid desktop mode exists. Shared preferences still synchronize across roots, but one viewport family's Timeline selection does not overwrite the other. Per-request usage, reasoning-token badges, and assistant Rendered/Raw/JSON/Copy action rows are hidden only by the root mobile policy; measurements and desktop preferences are retained. The ordinary composer hint is absent on mobile; missing-Session error text remains visible.
