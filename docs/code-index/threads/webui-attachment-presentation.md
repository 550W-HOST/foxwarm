# Thread: WebUI attachment presentation

## Scope

Observable draft/upload/history/provider/delivery distinctions are owned by [files, images, and attachments](../behaviors/files-images-and-attachments.md). This thread retains grid/reference projection, modal interaction and receipt-qualification mechanisms across [composer](../units/webui-chat-composer.md) and [timeline](../units/webui-chat-timeline.md). Atomic serialization and draft/File ownership remain in [D-composer-inline-attachments](../units/webui-chat-composer.md#d-composer-inline-attachments); image URL/MIME authority remains in [image blob lifecycle](./image-blob-lifecycle.md).

## D-attachment-grid-and-inline-references

[2026-10-16] Desktop and mobile display image/file previews in a grid above the text area. The editor contains compact baseline-aligned `FILE 1`, `FILE 2` references instead of image cards. Pasted-text blocks remain inline. Grid numbers and FILE labels use the same current display order; surviving canonical `attachmentN` identities are never rewritten merely to update these labels.

`ComposerAttachmentGrid` owns thumbnail object URLs, revoking them on replacement/unmount. It does not own the File or a second draft. Preview and Remove delegate to the editor's imperative operations. Remove uses the same atomic mutation/undo boundary; missing Files retain reattachment behavior, and an attachment-only draft remains sendable. Failed upload/POST retains the draft; only acceptance clears it. Grid overflow is bounded on small screens.

Sent and queued user rows place the file grid above, outside, the user text bubble. Small FILE references remain at the authored positions inside text. Clicking an image reference uses the shared [full-screen viewer](#d-fullscreen-image-preview). Generated transport descriptor prefixes are hidden only when correlated with a matching real reference; pasted-text payloads are opaque to this matching. Legacy unassociated images still render. No persisted message or canonical clipboard source is rewritten by layout.

Queued preview transport can deliberately omit image bytes and supply a separate MIME placeholder part. A correlated placeholder is displayed as the attachment's Queued state, not as user prose or a fabricated image URL. Committed missing images use an unavailable state. Images with real data retain ordinary lazy loading, same-origin scoped URLs, unsafe-format download fallback, and contain-fit thumbnails that do not crop wide screenshots into an apparently blank tile.

## D-fullscreen-image-preview

[2026-10-16] Image thumbnails and inline FILE references open one shared full-viewport preview on desktop and mobile. Composer images, sent/received history and tool images, generated images and delivered reply images use the same native modal surface; clicking a preview never navigates to an image URL or opens another browser tab. The initial image fits without cropping. Actual size enables native scrolling for detailed inspection. Filename, Download and Close remain available outside the scrolling image area; safe areas are respected on narrow and landscape screens.

The native dialog traps focus, supports Escape/platform cancellation and restores the connected opener without scrolling. Clicking empty fit-mode background also dismisses it. Page scroll locks are reference-counted and restored on cleanup. Existing scoped authenticated blob URLs, editor-owned object URLs and reply download callbacks retain their ownership; the viewer grants no new file access and does not change history, uploads or draft/File identity. Only PNG/JPEG/GIF/WebP render inline. Unsupported formats stay download-only, and missing draft images retain the reattachment flow. Image/decode and download failures remain in the viewer instead of navigating to an error page. Implementation: [shared image preview](../units/webui-image-preview.md).

[2026-10-17] Touch input pinches the image around the fingers' midpoint and pans the enlarged image with one finger, without zooming or dragging the underlying page. Ending or cancelling a gesture does not toggle the image or dismiss the dialog; a subsequent deliberate tap and the existing fit/actual-size, close and download actions remain available. Mouse and keyboard inspection retain native scrolling.

Image panning follows pointer movement one-to-one in CSS pixels, independent of image magnification or screen pixel density. Subpixel movement accumulates rather than being lost between scroll updates. The viewer disables native text/image selection and touch callouts so holding and then dragging remains an image gesture. Context-menu suppression is limited to touch input; desktop mouse and keyboard image menus retain native Copy/Save actions, and right-click does not toggle zoom.

[2026-11-26] User decisions on common image-viewer interactions. Ctrl/⌘ + wheel zooms continuously around the pointer, and so does trackpad pinch (Chromium's ctrl + wheel, WebKit's gesture events), within the touch range of fit to the larger of intrinsic size or eight times fit; a plain wheel keeps native scrolling. The left mouse button drags an enlarged image one-to-one in CSS pixels, and the click that ends a drag does not toggle the size. ←/→, previous/next buttons at the sides of the image (shown on hover or focus, always on touch screens) and, at fit, a horizontal touch swipe switch between all images of the current Session in conversation display order: user attachments, tool images, generated images and delivered reply images; the header shows the position ("3 / 12"). A draft image switches only among the draft's own images. The sequence stops at both ends. Click still toggles fit/actual size and an empty-background click still closes; there are no keyboard zoom keys. Under a window frame the viewer is a full-window layer whose header is the window's title row ([D-window-frame](../units/webui-window-frame.md#d-window-frame)).

Coordinator decisions for the same change: the sequence is built from the timeline's row model, not mounted DOM, from the history the WebUI has loaded (no extra history requests). It counts the images the current view presents, including those in collapsed tool cards, collapsed groups and folded Conversation activity; rows the view omits do not count. Formats the viewer doesn't render inline and draft images without their File are skipped; image artifacts and question-answer attachments (which repeat the original message's image) open alone. Every image keeps its own URL, download route and ownership: the opener's image keeps its own props and download state, other delivered images use their own signed path download, and draft images use object URLs made from the editor-owned Files only while the viewer is open. Switching resets the view, aborts the previous image's viewer-owned download request and keeps focus on the control that switched; a new image's load or decode error stays in the viewer. ←/→ keep native scrolling while an enlarged image is wider than its area. Closing returns focus to the original opener.

## D-reply-file-deliveries

[2026-10-16] Successful `send_file` deliveries addressed to the current Session or its exact WebUI target render in a compact, left-aligned reply file grid after that reply span, before queued previews and runtime status. Delivery appears immediately and follows later reply text without depending on process disclosure or completion. Desktop/mobile and all main timeline views share the surface; nested process timelines do not duplicate it. Each input-bounded reply span keeps its own files. The renderer creates no canonical message and fetches no extra history.

Only successful delivery receipts qualify, never arbitrary file writes, model-authored links, failures, or other destinations. The versioned, bounded [receipt DTO](../units/shared-file-delivery.md) carries a stable delivery ID, target, original name/MIME/size, source Node, and Main-owned download path. Remote files already use the existing Main cache; the current selected Node is not a download-routing authority. Delivery IDs deduplicate replays, not filenames. Old direct send records may use a paired send intent plus a structured absolute `fullPath`; the renderer never parses success prose or stdout and does not invent missing sizes. Underlying file retention is unchanged; this is not a new immutable file store or cross-Session inbox.

Safe raster files support lazy thumbnails and a keyboard-accessible preview with Download. Large known images skip automatic thumbnails. Other formats are download-only. Path downloads retain original-name disposition, HEAD support, no-sniff raster-only inline responses, and attachment disposition for active formats. Explicit download actions use [short-lived download capabilities](../modules/webui.md#d-webui-download-capabilities), while unsigned authenticated previews remain supported. A missing/unavailable download reports an inline error without navigating away. Refresh and timeline-mode changes reconstruct file grids from loaded canonical records; source files can still become unavailable. Shared gallery keys preserve an open preview when a live reply finishes.

Implementation is owned by [reply files](../units/webui-reply-files.md), [file delivery](../units/shared-file-delivery.md), and [WebUI channel](../units/dotnet-webui-core.md).
